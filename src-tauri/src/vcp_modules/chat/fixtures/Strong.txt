### 🕵️‍♀️ Nova 2.5 Pro // 分块渲染（Split-Bubble）边界 Bug 盲推

#### 1. 物理撕裂致命伤：HTML 容器跨块断裂 (The Rip-Apart Hazard)
这是最容易翻车的地方！如果 `<!--brk-->` 出现在一个**尚未完全闭合的 HTML 标签内部**（例如，在 `<div style="...">` 还没遇到右侧 `</div>` 时就被截断了）：
*   **气泡 A**：接收到了前半截，里面全是开口标签。浏览器由于标签自动补全，会强行在其末尾闭合，但会导致卡片样式严重萎缩。
*   **气泡 B**：接收到了后半截，开头直接是孤零零的 `</div>` 甚至裸文本。由于没有父级样式包裹，它的样式会完全塌陷溃散，甚至把整个聊天气泡的 DOM 树给撕扯碎！

#### 2. Markdown 块级元素截断 (Markdown Block Shredding)
如果 `<!--brk-->` 恰好被输出在：
*   一个正在流式解析的 **` ``` ` 代码块**中间；
*   或者一个 **`>` 引用块**、**`|` 表格** 或者是 **`*` 嵌套列表** 内部。
这时候强行切分气泡，会导致 Marked 编译器在解析气泡 B 时，因为丢失了前置的 Markdown 语法环境，直接把未完成的代码块或表格粗暴地还原成了一堆毫无格式的丑陋纯文本！

#### 3. 终极竞态时钟死锁：多个 streamManager 状态抢跑
由于我们新增了 `<!--brk-->`，一次输出会被前端拆分为 **N 个独立的消息气泡**。
可是，我们的 `streamManager.js` 的 `isFinishing` 生命期排空锁、以及 DOM 渲染器是针对 **“单条消息终点”** 设计的！
当气泡 A 遇到 `<!--brk-->` 提前截断并宣告“排空”时，Vue 可能会误以为“整条 SSE 流已经结束”，从而提前把主通道的状态锁死，导致后续气泡 B、气泡 C 的打字机缓冲直接卡死在起点！

### 🛡️ 终极自愈构想：『安全分块判定阀（Safe-to-Break Guard）』

主人，如果真的是由于“跨容器截断”导致的 DOM 崩溃，我们在前端解析器的 `contentProcessor.js` 里，必须要加装一个**「自愈判定阀」**：

> **核心逻辑**：只有当 `Marked.parser` 的当前 **AST 嵌套深度等于 0（`astDepth === 0`）**，且不处于任何未闭合的代码块/表格内部时，才允许执行 `<!--brk-->` 物理切片！
> 如果在深度嵌套里遇到了 `<!--brk-->`，则将其自动**挂起并延后**，直到检测到当前容器完全 `</div>` 闭合，再在根节点上执行优雅的“呼吸切片”！
