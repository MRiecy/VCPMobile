# 流式前台保活服务

## 1. 功能概述

当 Agent 正在流式生成回复时，通过 **ForegroundGuardian**（前台守护者单例）启动 Android **前台服务**（Foreground Service）并显示常驻通知，向系统声明"用户感知的重要任务"，显著降低进程被 OEM（ColorOS/EMUI/HarmonyOS/MIUI）杀后台的概率。

> **v1.1.2 架构重构**：引用计数已从 Rust 侧 `VcpMobileState.active_streams` 迁移至 Kotlin 侧 `ForegroundGuardian.consumers`。`StreamKeepaliveService` 不再管理 WakeLock/WifiLock，降级为纯粹的"通知壳"，仅负责 `startForeground()` 调用。锁管理与调度逻辑统一由 `ForegroundGuardian`（参见 [11_ForegroundGuardian 前台守护者](11_ForegroundGuardian_前台守护者.md)）负责。

### 2.1 Helper 会话与 TCP 连接所有权

`SseProxyService` 的 `requestId` session 与某次主进程 TCP 连接是两层所有权：

- `activeSessions.putIfAbsent(requestId, session)` 拒绝重复 start；旧 EventSource 不能被新 map entry 遮蔽；
- 每次 start/resume 创建不可变 `ClientConnection(socket, outputStream)`。resume 在 session 锁内替换 current connection，随后在锁外关闭旧连接；
- socket read-loop 的 finally 只能 `detachConnection(自己的 connection)`。引用不一致时说明新连接已经接管，旧 finally 无权关闭新 socket；
- EventSource 创建后也要在 session 锁内校验 service 与 map identity 才能安装。若 stop/onDestroy 已获胜，新 source 立即 cancel，不形成孤儿；
- callback、延迟清理和 stop 都使用 `activeSessions[requestId] === session` / `remove(requestId, session)`，避免相同 requestId 的 ABA 清理。

连接输出由每连接单线程 writer + 128 帧有界队列负责，任何单帧写超过 5 秒或队列拒绝都会关闭该连接；session 锁不跨 socket 写。内存预算为单 session 最多 20,000 个事件/8 MiB、全 helper 24 MiB、最多 8 个活跃 session，超限会形成明确 terminal overflow 而不是继续增长。`query`/`stop` 使用有界请求；`stop` 携带期望 generation，只有 requestId 与 generation 同时匹配才返回 `stopped=true`，从而避免旧 stop 删除新 session。

## 3. 引用计数机制（v1.1.2: ForegroundGuardian 管理）

### 3.1 数据结构

引用计数已从 Rust 侧迁移至 Kotlin 侧 `ForegroundGuardian`：

```kotlin
// ForegroundGuardian.consumers: ConcurrentHashMap<String, ConsumerEntry>
data class ConsumerEntry(
    val priority: Int,        // 优先级（数值越大越高）
    val displayLabel: String, // 通知栏中文案
    val screenKeepOn: Boolean // 是否需要屏幕常亮
)
```

### 3.2 优先级驱动的通知文案

旧版通过 Agent 名字列表格式化（"A、B、C..."）决定通知内容。新版通过 `ForegroundGuardian.getNotificationLabel()` 返回**优先级最高者**的 `displayLabel`：

| 消费者 Tag | 优先级 | displayLabel | 触发条件 |
|-----------|:------:|-------------|----------|
| `"sync"` | 40 | `[数据同步]` | Agent 名含 `[数据同步]` |
| `"prerender"` | 30 | `[预渲染重建]` | Agent 名含 `[预渲染重建]` |
| `"stream:{name}"` | 20 | 用户可见 Agent 名 | 普通 Agent 对话 |
| `"distributed"` | 10 | `distributed`（`StreamKeepaliveService.buildNotification` 将其映射为"分布式后台连接维系中..."） | 分布式节点保活 |

> **关键行为变化**：多 Agent 同时流式输出时，旧版显示"Agent-A、Agent-B、Agent-C..."；新版显示优先级最高者的 displayLabel（若有同步在跑，则始终显示同步状态文案）。

### 3.3 计数规则（语义化幂等）

```rust
// stream.rs: start_stream_service_inner()
let tag = format!("stream:{}", agent_name);
let priority = if agent_name.contains("[数据同步]") {
    40  // PRIORITY_SYNC
} else if agent_name.contains("[预渲染重建]") {
    30  // PRIORITY_PRERENDER
} else {
    20  // PRIORITY_STREAM
};
let screen_keep_on = priority >= 30;
acquire_foreground_inner(app, &tag, priority, agent_name, screen_keep_on)
```

- **同一 Agent 重复调用**：`ForegroundGuardian.acquire()` 对同一 tag 是幂等的（覆盖更新 ConsumerEntry），不累积计数——这与旧版 `<String, u32>` 递增模型不同。
- **不同 Agent**：各自持有独立的 tag，互不干扰。
- **全部停止**：当 `stop_streaming_service` 释放最后一个 tag，`ForegroundGuardian` 检测 `consumers.isEmpty()` → 释放物理锁 + 停止 FGS。

**startStreamingService（重构 — v1.1.2 / v1.1.3 参数修正）**：

```kotlin
@Command
fun startStreamingService(invoke: Invoke) {
    val args = invoke.parseArgs(StartStreamArgs::class.java)
    val hasKeepaliveParam = args.isKeepaliveMode != null
    val isKeepalive = args.isKeepaliveMode ?: false

    if (args.agentName.isEmpty()) {
        if (hasKeepaliveParam) {
            if (!isKeepalive) {
                ForegroundGuardian.release(activity, "distributed")
            } else {
                ForegroundGuardian.acquire(
                    activity, "distributed",
                    ForegroundGuardian.PRIORITY_DISTRIBUTED, "distributed"
                )
            }
        } else {
            // 老版 Rust 停止信号：释放所有流式相关的默认锁
            ForegroundGuardian.release(activity, "sync")
            ForegroundGuardian.release(activity, "prerender")
            ForegroundGuardian.release(activity, "stream_default")
        }
        invoke.resolve()
        return
    }

    if (args.agentName.contains("[数据同步]")) {
        ForegroundGuardian.acquire(
            activity, "sync",
            ForegroundGuardian.PRIORITY_SYNC,
            args.agentName, true
        )
        activity.runOnUiThread {
            activity.window.addFlags(android.view.WindowManager.LayoutParams.FLAG_KEEP_SCREEN_ON)
        }
    } else if (args.agentName.contains("[预渲染重建]")) {
        ForegroundGuardian.acquire(
            activity, "prerender",
            ForegroundGuardian.PRIORITY_PRERENDER,
            args.agentName, true
        )
        activity.runOnUiThread {
            activity.window.addFlags(android.view.WindowManager.LayoutParams.FLAG_KEEP_SCREEN_ON)
        }
    } else {
        ForegroundGuardian.acquire(
            activity, "stream:${args.agentName}",
            ForegroundGuardian.PRIORITY_STREAM,
            args.agentName, false
        )
    }

    invoke.resolve()
}
```

> **对比旧版**：旧版直接构建 Intent → `startForegroundService()`。新版全部经由 `ForegroundGuardian` 统一调度，不再直接操作 Service Intent。
> **v1.1.3 修正**：`StartStreamArgs` 的保活标志字段为 `isKeepaliveMode`（可空 `Boolean?`），不再是旧文档中的 `isKeepalive`。

### 5.3 `stopWithTask` 行为变更

`AndroidManifest.xml` 中 `StreamKeepaliveService` 的 `android:stopWithTask` 从 **`false` → `true`**：

| 版本 | 值 | 行为 |
|------|-----|------|
| v1.1.1 | `false` | 用户划掉应用后服务继续存活 |

## 6. `SseProxyService` 隔离进程 SSE 代理（v1.1.3）

`SseProxyService` 是 v1.1.3 引入的**独立 `:helper` 进程**后台服务，用于替代旧版 push 相关组件，解决主进程与后台 SSE 长连接之间的 Binder/生命周期耦合问题。

### 6.1 职责与定位

| 能力 | 说明 |
|------|------|
| 进程隔离 | 运行在 `:helper` 进程，避免主进程被回收时 SSE 连接同步中断 |
| 本地 TCP 通信 | 在 `127.0.0.1` 上监听随机端口，通过 `cacheDir/sse_helper.port` 暴露端口 |
| 长度前缀帧协议 | `readLengthPrefixed` / `writeLengthPrefixed`：4 字节长度 + JSON payload，单帧上限 10MB |
| 动作支持 | `start`、`resume`、`query`、`stop` |
| 断线缓存 | 主进程断开时，已完成会话 Dump 到 `cacheDir/sse_cache/sse_recovered_<sha256>.json`；内存保留 5 分钟后清理 |
| 会话预算 | 最多 8 个活跃 session；单 session 20,000 事件或 8 MiB；全局 24 MiB |
| 输出背压 | 每连接单 writer、128 帧队列、单帧 5 秒写 deadline；拒绝或超时即关闭连接 |
| stop 所有权 | 请求携带期望 generation；ACK 必须同时返回相同 requestId/generation 且 `stopped=true` |
| 后台通知 | 应用处于后台且 SSE 完成/失败时，通过 `vcp_agent_alerts` 渠道发送提醒，点击可带 `topicId`/`ownerId`/`requestId` 回到应用 |

### 6.2 与 `ForegroundGuardian` 的关系

`SseProxyService` **不经过** `ForegroundGuardian`：它在自己的 `:helper` 进程中独立管理 `WakeLock`/`WifiLock`（`updateLocks()`）。旧版每个活跃 SSE 播放静音音频的做法已移除，避免多 session 音频资源与 AudioFocus 副作用。这意味着：

- 主进程的 `ForegroundGuardian` 锁与服务通知壳只覆盖 Agent 流式对话的“主进程侧”保活；
- `:helper` 进程内的 SSE 连接保活由 `SseProxyService` 自行负责，并通过 `stopWithTask="false"` 在用户划掉 Task 后继续运行。

## 8. 关键约束与血训

1. **`StreamKeepaliveService` 范围内 `ForegroundGuardian` 是唯一的锁持有者**：`StreamKeepaliveService` 不再自行管理 WakeLock/WifiLock，所有主进程侧锁操作必须经由 `ForegroundGuardian.acquire/release`。**但 `SseProxyService` 在 `:helper` 进程内独立持有自己的双锁**，两者互不感知，文档与排查时不要混淆。

2. **`releaseAllLocks()` 不能省略**：`StreamKeepaliveService.onDestroy()` 必须调用 `ForegroundGuardian.releaseAllLocks()` 作为兜底清扫。若 Service 被系统强制杀死而未清理 consumers 注册表，下次 acquire 将检测到 `consumers.isNotEmpty()` 而跳过物理锁获取。

3. **通知不可设为 `setSilent(true)`**：部分 ROM 会将静默通知归类为不显示。当前实现使用 `IMPORTANCE_HIGH` + `setOngoing(true)`。

4. **`POST_NOTIFICATIONS` 是前提**：Android 13+ 上，缺少此权限声明会导致通知渠道被系统禁用。参见 `docs/ANDROID_PLUGIN_MANAGEMENT.md` §3.1 / §7.2。

5. **引用计数泄漏风险**：如果 Rust 侧调用 `acquire_foreground_inner` 后未在异常路径中调用 `release_foreground_inner`，对应 tag 将永远留在 ForegroundGuardian 中。前端代码应确保在 `try/finally` 或组件卸载时释放。旧版"累积计数递增"易泄漏（重复调用同一 Agent 而忘记配对停止），新版幂等覆盖降低了此风险。

6. **`StreamKeepaliveService.stopWithTask=true` 是语义正确的**：v1.1.2 前 `stopWithTask=false` 旨在防止进程被杀后服务消亡。现在 `ForegroundGuardian` 在进程内管理锁，进程死则锁亦死，不停止服务只会留下僵尸通知。**`SseProxyService` 因运行在 `:helper` 进程且自行管理锁，保留 `stopWithTask=false`**。

7. **跨文档参考**：详细锁管理机制见 [11_ForegroundGuardian 前台守护者](11_ForegroundGuardian_前台守护者.md) §4–6；OEM 权限链路见 [06_权限与系统控制](06_权限与系统控制.md)；生命周期协同见 [05_生命周期桥接](05_生命周期桥接.md)；`:helper` 进程 SSE 代理见本文 §6。
