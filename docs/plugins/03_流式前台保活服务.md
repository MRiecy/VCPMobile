# 流式前台保活服务

## 1. 功能概述

当 Agent 正在流式生成回复时，通过 **ForegroundGuardian**（前台守护者单例）启动 Android **前台服务**（Foreground Service）并显示常驻通知，向系统声明"用户感知的重要任务"，显著降低进程被 OEM（ColorOS/EMUI/HarmonyOS/MIUI）杀后台的概率。

> **v1.1.2 架构重构**：引用计数已从 Rust 侧 `VcpMobileState.active_streams` 迁移至 Kotlin 侧 `ForegroundGuardian.consumers`。`StreamKeepaliveService` 不再管理 WakeLock/WifiLock，降级为纯粹的"通知壳"，仅负责 `startForeground()` 调用。锁管理与调度逻辑统一由 `ForegroundGuardian`（参见 [11_ForegroundGuardian 前台守护者](11_ForegroundGuardian_前台守护者.md)）负责。

## 3. 引用计数机制（v1.1.2: ForegroundGuardian 管理）

### 3.1 数据结构

引用计数已从 Rust 侧迁移至 Kotlin 侧 `ForegroundGuardian`：

```kotlin
// ForegroundGuardian.consumers: ConcurrentHashMap<String, ConsumerEntry>
data class ConsumerEntry(
    val priority: Int,        // 优先级（数值越大越高）
    val displayLabel: String, // 通知栏中文案
    val screenKeepOn: Boolean // 是否需要屏幕常亮
)
```

### 3.2 优先级驱动的通知文案

旧版通过 Agent 名字列表格式化（"A、B、C..."）决定通知内容。新版通过 `ForegroundGuardian.getNotificationLabel()` 返回**优先级最高者**的 `displayLabel`：

| 消费者 Tag | 优先级 | displayLabel | 触发条件 |
|-----------|:------:|-------------|----------|
| `"sync"` | 40 | `[数据同步]` | Agent 名含 `[数据同步]` |
| `"prerender"` | 30 | `[预渲染重建]` | Agent 名含 `[预渲染重建]` |
| `"stream:{name}"` | 20 | 用户可见 Agent 名 | 普通 Agent 对话 |
| `"distributed"` | 10 | `[分布式后台保活]` | 分布式节点保活 |

> **关键行为变化**：多 Agent 同时流式输出时，旧版显示"Agent-A、Agent-B、Agent-C..."；新版显示优先级最高者的 displayLabel（若有同步在跑，则始终显示同步状态文案）。

### 3.3 计数规则（语义化幂等）

```rust
// stream.rs: start_stream_service_inner()
let tag = format!("stream:{}", agent_name);
let priority = if agent_name.contains("[数据同步]") {
    40  // PRIORITY_SYNC
} else if agent_name.contains("[预渲染重建]") {
    30  // PRIORITY_PRERENDER
} else {
    20  // PRIORITY_STREAM
};
let screen_keep_on = priority >= 30;
acquire_foreground_inner(app, &tag, priority, agent_name, screen_keep_on)
```

- **同一 Agent 重复调用**：`ForegroundGuardian.acquire()` 对同一 tag 是幂等的（覆盖更新 ConsumerEntry），不累积计数——这与旧版 `<String, u32>` 递增模型不同。
- **不同 Agent**：各自持有独立的 tag，互不干扰。
- **全部停止**：当 `stop_streaming_service` 释放最后一个 tag，`ForegroundGuardian` 检测 `consumers.isEmpty()` → 释放物理锁 + 停止 FGS。

## 4. Rust → Kotlin 调用（v1.1.2: 语义化接口）

### 4.1 acquire_foreground_inner —— 申请前台锁

```rust
pub fn acquire_foreground_inner<R: Runtime>(
    _app: &AppHandle<R>,
    tag: &str,           // 唯一业务标识（如 "stream:Agent-A"）
    priority: i32,       // 优先级（40/30/20/10）
    label: &str,         // 通知栏文案
    screen_keep_on: bool,// 是否保持屏幕常亮
) -> Result<(), String> {
    #[cfg(target_os = "android")]
    {
        let state = _app.state::<VcpMobileState<R>>();
        let handle = state.plugin_handle.lock().map_err(|e| e.to_string())?;
        let plugin_handle = handle.as_ref().ok_or("Plugin handle not initialized")?;
        plugin_handle
            .run_mobile_plugin::<serde_json::Value>(
                "acquireForeground",
                serde_json::json!({
                    "tag": tag,
                    "priority": priority,
                    "label": label,
                    "screenKeepOn": screen_keep_on
                }),
            )
            .map_err(|e| format!("run_mobile_plugin failed: {}", e))?;
    }
    Ok(())
}
```

// start_stream_service_inner → 委托 acquire_foreground_inner
pub fn start_stream_service_inner<R: Runtime>(
    app: &AppHandle<R>,
    agent_name: &str,
) -> Result<(), String> {
    let tag = format!("stream:{}", agent_name);
    let priority = if agent_name.contains("[数据同步]") {
        40
    } else if agent_name.contains("[预渲染重建]") {
        30
    } else {
        20
    };
    let screen_keep_on = agent_name.contains("[数据同步]")
        || agent_name.contains("[预渲染重建]");
    acquire_foreground_inner(app, &tag, priority, agent_name, screen_keep_on)
}

// stop_stream_service_inner → 委托 release_foreground_inner
pub fn stop_stream_service_inner<R: Runtime>(
    app: &AppHandle<R>,
    agent_name: &str,
) -> Result<(), String> {
    let tag = format!("stream:{}", agent_name);
    release_foreground_inner(app, &tag)
}

## 5. Kotlin 侧实现

### 5.1 `VcpMobilePlugin.kt` 中的命令路由

**acquireForeground（新命令 — v1.1.2）**：

```kotlin
@Command
fun acquireForeground(invoke: Invoke) {
    val args = invoke.parseArgs(AcquireForegroundArgs::class.java)
    ForegroundGuardian.acquire(
        activity,
        args.tag,
        args.priority,
        args.label,
        args.screenKeepOn
    )
    invoke.resolve()
}

data class AcquireForegroundArgs(
    val tag: String,
    val priority: Int,
    val label: String,
    val screenKeepOn: Boolean = false
)
```

**startStreamingService（重构 — v1.1.2）**：

```kotlin
@Command
fun startStreamingService(invoke: Invoke) {
    val args = invoke.parseArgs(StartStreamArgs::class.java)
    val name = args.agentName

    when {
        // 空名 + 保活模式 → 分布式标签
        name.isEmpty() && args.isKeepalive == true ->
            ForegroundGuardian.acquire(context, "distributed",
                PRIORITY_DISTRIBUTED, "distributed")

        // 空名 + 非保活 → 释放全部同步/渲染/流式标签（遗留停止信号）
        name.isEmpty() -> {
            ForegroundGuardian.release(context, "sync")
            ForegroundGuardian.release(context, "prerender")
            ForegroundGuardian.release(context, "stream_default")
        }

        // 同步 Agent
        name.contains("[数据同步]") ->
            ForegroundGuardian.acquire(context, "sync",
                PRIORITY_SYNC, name, screenKeepOn = true)

        // 预渲染 Agent
        name.contains("[预渲染重建]") ->
            ForegroundGuardian.acquire(context, "prerender",
                PRIORITY_PRERENDER, name, screenKeepOn = true)

        // 普通 Agent
        else -> ForegroundGuardian.acquire(context, "stream:$name",
            PRIORITY_STREAM, name, screenKeepOn = false)
    }
    invoke.resolve()
}
```

> **对比旧版**：旧版直接构建 Intent → `startForegroundService()`。新版全部经由 `ForegroundGuardian` 统一调度，不再直接操作 Service Intent。

### 5.2 `StreamKeepaliveService`（v1.1.2 简化）

#### 通知构建

```kotlin
private fun buildNotification(label: String): Notification {
    val contentText = when {
        label.contains("[数据同步]") -> "正在与云端服务器进行高精度同步..."
        label.contains("[预渲染重建]") -> "正在优化与加速本地响应缓存..."
        label == "distributed" || label.contains("分布式") -> "分布式后台连接维系中..."
        label.contains("[后台保活]") -> "VCP 正在后台保持活跃连接..."
        else -> "思考中……"
    }
    val cleanTitle = label
        .replace("[数据同步]", "").replace("[预渲染重建]", "")
        .replace("[后台保活]", "").trim()

    return NotificationCompat.Builder(this, CHANNEL_ID)
        .setContentTitle(if (cleanTitle.isEmpty()) "VCP Mobile" else cleanTitle)
        .setContentText(contentText)
        .setSmallIcon(applicationInfo.icon)
        .setOngoing(true)
        .setContentIntent(openPendingIntent)
        .build()
}
```

> **关键变化**：`buildNotification` 现在接收 `label` 参数（来自 `ForegroundGuardian.getNotificationLabel()`），而非旧版的 `agentName`。文案增加了 "分布式后台连接维系中..." 和 "[后台保活]" 两种新场景。

### 5.3 `stopWithTask` 行为变更

`AndroidManifest.xml` 中 `StreamKeepaliveService` 的 `android:stopWithTask` 从 **`false` → `true`**：

| 版本 | 值 | 行为 |
|------|-----|------|
| v1.1.1 | `false` | 用户划掉应用后服务继续存活 |
| v1.1.2 | `true` | 用户划掉应用后服务随 Task 停止 |

**变更理由**：ForegroundGuardian 已接管全部锁管理。进程被划掉后锁即消亡，残留的前台服务无实际保活作用，反而显示僵尸通知。

## 7. 关键约束与血训

1. **ForegroundGuardian 是唯一的锁持有者**：`StreamKeepaliveService` 不再自行管理 WakeLock/WifiLock。所有锁操作必须经由 `ForegroundGuardian.acquire/release`。直���操作 API 会导致 ForegroundGuardian 状态不一致（例如认为"无消费者"而提前释放锁）。

2. **`releaseAllLocks()` 不能省略**：`StreamKeepaliveService.onDestroy()` 必须调用 `ForegroundGuardian.releaseAllLocks()` 作为兜底清扫。若 Service 被系统强制杀死而未清理 consumers 注册表，下次 acquire 将检测到 `consumers.isNotEmpty()` 而跳过物理锁获取。

3. **通知不可设为 `setSilent(true)`**：部分 ROM 会将静默通知归类为不显示。当前实现使用 `IMPORTANCE_HIGH` + `setOngoing(true)`。

4. **`POST_NOTIFICATIONS` 是前提**：Android 13+ 上，缺少此权限声明会导致通知渠道被系统禁用。参见 `docs/ANDROID_PLUGIN_MANAGEMENT.md` §3.1 / §7.2。

5. **引用计数泄漏风险**：如果 Rust 侧调用 `acquire_foreground_inner` 后未在异常路径中调用 `release_foreground_inner`，对应 tag 将永远留在 ForegroundGuardian 中。前端代码应确保在 `try/finally` 或组件卸载时释放。旧版"累积计数递增"易泄漏（重复调用同一 Agent 而忘记配对停止），新版幂等覆盖降低了此风险。

6. **`stopWithTask=true` 是语义正确的**：v1.1.2 前 `stopWithTask=false` 旨在防止进程被杀后服务消亡。现在 ForegroundGuardian 在进程内管理锁，进程死则锁亦死，不停止服务只会留下僵尸通知。

7. **跨文档参考**：详细锁管理机制见 [11_ForegroundGuardian 前台守护者](11_ForegroundGuardian_前台守护者.md) §4–6；OEM 权限链路见 [06_权限与系统控制](06_权限与系统控制.md)；生命周期协同见 [05_生命周期桥接](05_生命周期桥接.md)。
