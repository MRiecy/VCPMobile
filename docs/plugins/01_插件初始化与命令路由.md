# 插件初始化与命令路由

## 1. 功能概述

`lib.rs` 是 `tauri-plugin-vcp-mobile` 的**唯一入口**。职责：

1. 定义插件共享状态 `VcpMobileState<R>`
2. 注册全部 **38 条** Tauri 命令（v1.1.2 新增 6 条：`acquire_foreground`, `release_foreground`, `request_auto_start_permission`, `request_power_management_permission`, `check_auto_start_permission`, `get_free_disk_space`）
3. 在 `setup` 钩子中完成 Android 原生插件注册，并将 `PluginHandle` 注入状态

> **设计原则**：`lib.rs` 只负责"路由与状态"，所有业务逻辑下沉到 `screen`、`stream`、`system` 三个子模块。

---

## 2. 代码结构

```
src-tauri/plugins/vcp-mobile/src/lib.rs (~50 lines)
├── VcpMobileState<R>
│   └── plugin_handle: Mutex<Option<PluginHandle<R>>>  (Android only)
├── init<R>() -> TauriPlugin<R>
│   ├── invoke_handler: 注册 38 条命令（含 v1.1.2 新增 6 条）
│   └── setup: 注册 Android 插件 + manage 状态
```

## 3. 共享状态详解

### 3.1 `VcpMobileState<R>`

```rust
pub struct VcpMobileState<R: Runtime> {
    #[cfg(target_os = "android")]
    plugin_handle: std::sync::Mutex<Option<tauri::plugin::PluginHandle<R>>>,
    #[cfg(not(target_os = "android"))]
    _marker: std::marker::PhantomData<fn() -> R>,
}
```

| 字段 | 类型 | 用途 | 访问方式 |
|------|------|------|----------|
| `plugin_handle` | `Mutex<Option<PluginHandle<R>>>` | Android 原生插件句柄 | 只能通过 `mobile_plugin_handle()` 取得 clone |

#### v1.1.2 变更：`active_streams` 字段已移除

旧版 `VcpMobileState` 包含 `active_streams: Mutex<Vec<(String, u32)>>` 字段，用于 Rust 侧流式服务引用计数。v1.1.2 将此逻辑迁移至 Kotlin 侧 `ForegroundGuardian.consumers`（`ConcurrentHashMap<String, ConsumerEntry>`），以优先级系统取代计数系统。详见 [11_ForegroundGuardian 前台守护者](11_ForegroundGuardian_前台守护者.md)。

### 3.2 PluginHandle 的短锁所有权

- `PluginHandle::run_mobile_plugin` 会同步等待 Kotlin `resolve/reject`，因此绝不能在持有全局 mutex 时调用；一个延迟的 Root/文件命令否则会把全部原生命令串死；
- `mobile_plugin_handle()` 只在锁内 clone `PluginHandle`，随即释放 guard。`screen` / `stream` / `system` 再在锁外调用 Kotlin；
- mutex 只保护 `Option<PluginHandle>` 的读取，锁内没有 IPC、文件、网络或等待操作，因此继续使用 `std::sync::Mutex`。

### 3.3 桌面端兼容

非 Android 编译目标下，`plugin_handle` 字段被替换为 `_marker: PhantomData`，确保泛型参数 `R` 被使用，避免编译错误。

## 4.1 build.rs 命令列表同步

`build.rs` 中的 `COMMANDS` 数组用于 Tauri 插件构建阶段生成权限清单与前端类型定义，必须与 `lib.rs` 中 `generate_handler!` 注册的命令名保持一致：

```rust
const COMMANDS: &[&str] = &[
    "set_keep_screen_on",
    "clear_keep_screen_on",
    "start_stream_service",      // ⚠️ 命名不一致：lib.rs 中实际注册为 start_streaming_service
    "stop_stream_service",       // ⚠️ 命名不一致：lib.rs 中实际注册为 stop_streaming_service
    "check_all_permissions",
    "request_android_permission",
    "move_task_to_back",
    "pick_file",
];
```

**当前差异**：
- `start_stream_service` / `stop_stream_service` 与 `lib.rs` 中的 `start_streaming_service` / `stop_streaming_service` 命名不同步（缺少 `ing`），可能导致权限生成不匹配。
- 缺少 `get_battery_status` 与 `open_file_native`，需补充以保持与 `generate_handler!` 完全一致。

## 5. Setup 流程

```rust
.setup(|app, _api| {
    #[cfg(target_os = "android")]
    let plugin_handle = _api.register_android_plugin("com.vcp.mobile", "VcpMobilePlugin")?;

    app.manage(VcpMobileState::<R> {
        #[cfg(target_os = "android")]
        plugin_handle: std::sync::Mutex::new(Some(plugin_handle)),
        #[cfg(not(target_os = "android"))]
        _marker: std::marker::PhantomData,
    });

    Ok(())
})
```

> **v1.1.2 变更**：`active_streams` 字段已移除 — 引用计数迁移至 Kotlin 侧 `ForegroundGuardian`。`app.manage()` 现在仅注入 `plugin_handle`。

### 5.1 `register_android_plugin`

- **包名**：`"com.vcp.mobile"` —— 对应 Kotlin 侧的 package 声明。
- **类名**：`"VcpMobilePlugin"` —— 对应 Kotlin 侧的 `@TauriPlugin class VcpMobilePlugin`。
- **返回**：`PluginHandle<R>`，后续通过 `run_mobile_plugin(command, payload)` 调用 Kotlin 方法。

### 5.2 `app.manage()`

将 `VcpMobileState` 注入 Tauri 应用状态容器。任何 command handler 都可以通过 `app.state::<VcpMobileState<R>>()` 获取共享状态。

```

    ▼

    │            ▼
    │       Kotlin VcpMobilePlugin
    │            │
    │            ▼
    │       ForegroundGuardian (引用计数 + 双锁)
    │            │
    │            │ startFgs / updateFgs / stopFgs
    │            ▼
```

## 7. 关键约束

1. **`plugin_handle` 为 `Option`**：在 `setup` 之前或桌面端运行时可能为 `None`。业务代码中必须 `.ok_or("Plugin handle not initialized")?` 处理。

2. **命令扩展方式**：新增命令需要在 `invoke_handler` 数组、`build.rs` 的 `COMMANDS` 数组、`permissions/*.toml` 权限声明和 `guest-js/index.ts` 中同步添加。v1.1.2 新增的 6 条命令均已完成四重注册。

3. **引用计数已不在 Rust 侧**：不再通过 `active_streams` 管理引用计数。所有流式锁/保活操作必须经由 `acquire_foreground_inner` / `release_foreground_inner`（Rust 侧）→ `ForegroundGuardian.acquire` / `release`（Kotlin 侧）。

4. **与规范文档的交叉引用**：关于插件命令被静默拒绝的情况，参见 `docs/ANDROID_PLUGIN_MANAGEMENT.md` §7.1。

## 7.1 CLI 进程宿主是哑执行器（边界契约）

`cli` 模块（`src/cli.rs` 桥 + `android/.../cli/CliProcessHost.kt`）不是 Tauri command，而是应用层 `vcp_modules::cli` Runtime 的进程宿主。其边界契约：

- **只报进程事实，不分类原因**：`inspectCliProcess` 只回 `state`（running/exited/missing）、`exitCode`、stdout/stderr 字节与截断位、`backgroundLeaseLost` 事实位。超时、取消、失败的原因分类全部由 Rust Runtime 的 `TerminalIntent` 体系完成。
- **不做 deadline 击杀**：Kotlin 收到的 `timeoutMs` 只喂 `ForegroundGuardian` 前台锁的自动释放，不用于进程击杀；绝对 deadline 归 Rust monitor（`ensure_deadline_intent` / `monitor_decision`）。
- **lease-loss 不自行收口**：前台租约丢失时 Kotlin 只把 `backgroundLeaseLost` 置位；Rust monitor 观察到该事实后写入 `TerminalIntentTarget::Interrupted`，经既有 `cancelCliProcess` 通道收口进程树。更早版本的"Kotlin 侧 lease-loss 自动 containment"已移除。
- **进程树终止是唯一写操作**：`cancelCliProcess` 是 Rust 驱动整树终止的唯一动词（SIGTERM → grace → SIGKILL，幂等），返回值 `found/termSent/killSent/groupGone` 均为事实，`found=false` 不构成 containment 证据（`process_host_confirmed_containment` 要求 `found && groupGone`）。
