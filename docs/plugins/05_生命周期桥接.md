# 生命周期桥接

> 2026-10-18：Android 生命周期代码位于 `lifecycle/`，`LifecycleBridge` 只持有 event sink，`NativeEvents` 持有原生 Channel 与默认网络观察者。双端另有独立的**视觉恢复**入口：Android `webview/NativeWebViewResume` 在真实后台返回时用单份旧画面覆盖 WebView，前端经 `connect_webview_resume` / `complete_webview_resume` 确认文档与布局，原生再等待绘制提交后揭幕；`ResumeCoverView` 仅负责遮罩呈现。`vcp-webview-resume` DOM 事件只携带视觉 token，不改变 Rust 生命周期。Android 用 PixelCopy、VisualStateCallback 与后续绘制提交；iOS 用 UIKit 快照与 `takeSnapshot(afterScreenUpdates: true)`。实现与资源边界见 [阶段记录](../../plan/vcpmobile-ios-compatibility-research/phase-5/04-双端前后台视觉恢复.md)。

## 1. 功能概述

通过 Android `DefaultLifecycleObserver` 观察主应用进程的 `ProcessLifecycleOwner`。`LifecycleBridge` 把 resume 归为 `active`，把 pause/stop 归为 `background`，连续相同状态只生成一次 transition；再经注入的 `(String, JSObject) -> Unit` sink 送给 `NativeEvents`。Rust bootstrap 在核心 owner 就绪后调用插件 `events::subscribe`，原生 Channel 把事件送入 `lifecycle_controller.rs::enqueue_native_lifecycle_event`，最后由 Rust 发布 `vcp-lifecycle-changed`。

> **当前通道**：`ProcessLifecycleOwner → LifecycleBridge → event sink → NativeEvents / Channel → Rust NativeEvent → 生命周期 owner → Tauri Event → Vue Store`。原生事实不依赖 WebView JS 执行；Channel 回调只提交事实、安排工作，不等待业务或再次调用原生 API。`plugin.trigger/listen_any` 是旧传输实现。

Activity 的 pause/resume 回调另行驱动当前 Window 的常亮与视觉恢复；它们不替代进程级业务 phase。`:helper` 服务位于另一个进程，其 SSE 会话及保活资源也不由主 Activity 的销毁决定。

## 2. 代码结构

```
src-tauri/plugins/vcp-mobile/android/.../lifecycle/
├── LifecycleBridge.kt : DefaultLifecycleObserver
│   ├── attach(activity: Activity, eventSink: (String, JSObject) -> Unit)
│   │     └── activity.runOnUiThread {
│   │           核对当前 sink 身份，再向 ProcessLifecycleOwner 添加观察者
│   │         }
│   ├── onResume(owner: LifecycleOwner)   ← 进程进入前台
│   ├── onPause(owner: LifecycleOwner)    ← background transition
│   ├── onStop(owner: LifecycleOwner)     ← 与连续 pause 合并，不再生成第二次 transition
│   ├── snapshot()                       ← 当前 phase / nativeSequence，snapshot=true
│   ├── onConfigurationChanged(newConfig) ← 深色/方向配置变更（由 VcpMobilePlugin 调用）
│   ├── onLowMemory()                     ← 低内存（方法存在，当前未接入主动触发源）
│   └── emit(event, detail)               ← event sink，不持有整个 Plugin
└── NativeEvents.kt
    ├── registerNativeEvents              ← 安装唯一 Channel，回放 lifecycle/network，再 resolve
    ├── emitNativeEvent                   ← 主线程发送 { event, payload }
    └── destroy                          ← 释放 Channel 引用及网络观察者
```

### 2.1 依赖

```kotlin
// build.gradle.kts
implementation("androidx.lifecycle:lifecycle-process:2.7.0")
```

插件声明 `lifecycle-process:2.7.0`；最终应用依赖版本仍以当前 Gradle 解析结果为准。该库提供 `ProcessLifecycleOwner`，汇总进程内 Activity 状态，并合并短暂的 Activity 切换/重建。桥接器响应这个 owner 的回调，不把任意单个 Activity 的 `onPause` 直接当作业务后台事件。

### 2.2 历史实现演变

下表只保留 v1.1.1 至 v1.1.3 的历史背景；当前传输已改为 §1 的 Native Channel，当前 payload 见 §3。

| 维度 | v1.1.1 | v1.1.2 / v1.1.3 |
|------|--------|-----------------|
| 观察对象 | `activity.lifecycle` | `ProcessLifecycleOwner.get().lifecycle` |
| 回调接收 | 每个 Activity 独立触发 | 进程级统一触发 |
| 配置变更 | 可能导致重复回调 | 免疫 Activity 重建 |
| 传输方式 | `evaluateJavascript` 注入 `vcp-lifecycle` | `plugin.trigger("lifecycle")` → Rust → `app.emit("vcp-lifecycle-changed")` |
| 事件类型 | resume/pause/stop/config-changed/low-memory | resume/pause/stop/config-changed（`low-memory` 方法保留但未接入） |

## 3. 事件类型与触发时机

| Kotlin 触发 | NativeEvent 名 | Payload | Rust 处理 |
|-------------|----------------|---------|-----------|
| `onResume` | `lifecycle` | `{ "phase": "active", "nativeSequence": n, "snapshot": false }` | 接纳新序号后安排前台 transition |
| `onPause` / `onStop` | `lifecycle` | `{ "phase": "background", "nativeSequence": n, "snapshot": false }` | 连续相同状态只递增一次序号，再安排后台 transition |
| 注册 Channel 时的 `snapshot()` | `lifecycle` | `{ "phase": "active" 或 "background", "nativeSequence": n, "snapshot": true }` | 补齐注册前的事实；无 transition 时初始序号可以为 0 |
| `onConfigurationChanged` | `configuration` | `{ "isDarkMode": true/false }` | 解析为 `NativeEvent::Other`，不改变 phase、不生成前端生命周期事件 |
| `onLowMemory()` | `memory-pressure` | `{}` | 解析为 `NativeEvent::Other`；此桥接方法当前没有主动调用源 |

`nativeSequence` 由 Kotlin companion 中的进程级 `AtomicLong` 生成，Activity/桥接实例替换不归零，读取 snapshot 不递增。Android 只产生 `active/background`；共享类型中的 `inactive` 由 iOS 提供，Rust 将其作为交互/渲染状态，不将其当作后台租约请求。

## 4. 前端与 Rust 联动

前后台切换事件流如下：

```
[Kotlin LifecycleBridge + NativeEvents]
         │
         ▼ Channel { event: "lifecycle", payload: NativeLifecycleEvent }
[Rust events::subscribe] ──► enqueue_native_lifecycle_event
         │                    ├── 拒绝旧 nativeSequence，再分配 transitionEpoch
         │                    └── 在 transition 锁内应用 phase 与资源调和
         ▼ app.emit("vcp-lifecycle-changed", LifecycleSnapshot)
[Frontend useAppLifecycle()] ──► applyLifecycleSnapshot → 渲染暂停 / 既有流恢复逻辑
```

**Rust 状态控制器管理**：

- `is_app_in_foreground`：查询全局前台状态（状态保存在 Tauri `LifecycleState` 托管结构中，替代原静态 Atomic 变量）。
- `enqueue_native_lifecycle_event`：先由 `NativeLifecycleOrdering` 拒绝重复/倒序原生序号，再预留 Rust `transitionEpoch` 并 spawn；两个序号职责不同。
- `apply_lifecycle_transition`：持有 `LIFECYCLE_TRANSITION_LOCK`，淘汰尚未执行的过期 transition；接纳后写入快照并 emit，同 phase 的首次快照也会发布。已开始的资源调和在锁内完整结束。
- Android 与 iOS 的 VCPLog 和 VCPInfo 在前台或聊天期间持续维护，后台空闲时保留已有连接并暂停主动心跳和重连。回前台立即探活或重拨。Android 分布式节点按配置和运行状态单独申请 5 分钟租约。

详见 [vcp_log_service（modules/21）](../modules/21_基础设施杂项.md) 和 [vcp_info_service（modules/23）](../modules/23_RAG灵视中心.md)。

## 5. 事件格式标准

```kotlin
// NativeEvents 在主线程发送；payload 由 LifecycleBridge 的 sink 提交。
nativeEventChannel?.send(JSObject().apply {
    put("event", event)
    put("payload", payload)
})
```

- 原生 envelope 使用 `event/payload`；生命周期 payload 使用 `phase/nativeSequence/snapshot`。Rust `events.rs` 以 tagged enum 反序列化。
- `LifecycleBridge` 将 `String`/`Boolean`/`Int`/`Double`/`Long` 放入 JSObject；不传 Android 对象或业务状态。
- 与 `KeyboardInsetsManager` 的 `evaluateJavascript` 方案分离，原生事实送达 Rust 不依赖 WebView 执行 JS。

Rust 发给 Vue 的 `LifecycleSnapshot` 另外包含 `transitionEpoch`；`get_system_snapshot` 返回同一 owner 的快照并将 `snapshot` 标为 `true`。Vue 按 `transitionEpoch` 接纳较新值，迟到的 snapshot 不能覆盖已收到的新 transition。

## 6. 前端订阅机制

前端统一使用 `useAppLifecycle` Composable 钩子订阅事件：

```typescript
// useAppLifecycle.ts
const stopListening = await listen<LifecycleSnapshotDto>('vcp-lifecycle-changed', (event) => {
  if (!disposed) lifecycleStore.applyLifecycleSnapshot(event.payload);
});
if (disposed) {
  stopListening();
  return;
}
unlisten = stopListening;
await lifecycleStore.hydrateSystemStatus();
```

订阅先于快照读取，卸载时释放 listener，迟到安装的 listener 立即释放。浏览器 `visibilitychange` 只决定渲染暂停，不覆写原生 phase。流恢复继续通过同一个 `reconcileInterruptedStreams` owner，检查 READY、文档可见、phase 与已有恢复任务；iOS 还等待首个真实原生 active 快照。

## 7. 生命周期绑定

```kotlin
// VcpMobilePlugin.kt
class VcpMobilePlugin(private val activity: Activity) : Plugin(activity) {
    private val lifecycleBridge = LifecycleBridge()

    override fun load(webView: WebView) {
        super.load(webView)
        webViewRef = webView
        keyboardInsetsManager.attach(webView)
        lifecycleBridge.attach(activity, nativeEvents::emitNativeEvent)
        // ...
    }

    override fun onDestroy(activity: AppCompatActivity) {
        // ...
        lifecycleBridge.detach()
        super.onDestroy(activity)
    }

    override fun onConfigurationChanged(newConfig: Configuration) {
        super.onConfigurationChanged(newConfig)
        lifecycleBridge.onConfigurationChanged(newConfig)
    }
}
```

上述片段仅展示绑定关系；`nativeEvents` 是 Plugin 组合的 `NativeEvents` owner，`@Command registerNativeEvents` 保留在 Plugin，委派到它。原生 Channel 注册由 Rust bootstrap 发起，不能与 WebView `load()` 或视觉恢复握手混为一次业务启动。

### 7.1 `attach()` 流程

```kotlin
fun attach(activity: Activity, eventSink: (String, JSObject) -> Unit) {
    this.eventSink = eventSink
    activity.runOnUiThread {
        if (this.eventSink === eventSink) {
            ProcessLifecycleOwner.get().lifecycle.addObserver(this)
        }
    }
}
```

- **`ProcessLifecycleOwner.get()`**：返回进程级生命周期持有者（来自 `lifecycle-process` 库）。
- **`eventSink`**：仅持有发送事件的函数；不读取 Plugin 的 Activity、WebView 或其他能力。detach 清除 sink，使迟到的安装任务失效。
- **`runOnUiThread`**：确保 UI 线程上注册观察者（Android 生命周期框架线程安全要求）。
- **`addObserver(this)`**：将 `LifecycleBridge`（即 `DefaultLifecycleObserver`）注册到进程生命周期。

### 7.2 观察者清理

```kotlin
fun detach() {
    eventSink = null
    lastForegroundState = null
    if (Looper.myLooper() == Looper.getMainLooper()) {
        ProcessLifecycleOwner.get().lifecycle.removeObserver(this)
    } else {
        Handler(Looper.getMainLooper()).post {
            ProcessLifecycleOwner.get().lifecycle.removeObserver(this)
        }
    }
}

override fun onDestroy(owner: LifecycleOwner) {
    detach()
    super.onDestroy(owner)
}
```

`detach()` 在 `VcpMobilePlugin.onDestroy()` 中被显式调用，先停止事件交付，再在主线程移除 observer；`nativeSequence` 不被重置。`onDestroy(owner)` 也调用 detach，但不能依赖进程生命周期必定发出 destroy 来替代 Plugin 的清理。`NativeEvents.destroy()` 另外释放 Channel 引用与默认网络观察者。

## 8. 与 `KeyboardInsetsManager` 的对比

| 维度 | `KeyboardInsetsManager` | `LifecycleBridge` |
|------|------------------------|-------------------|
| 监听目标 | `WindowInsets` 变化 | **进程**生命周期 |
| 注册方式 | `ViewCompat.setOnApplyWindowInsetsListener` | `ProcessLifecycleOwner.get().lifecycle.addObserver` |
| Kotlin 侧事件名 | `vcp-keyboard-inset` | `lifecycle`（Native Channel envelope） |
| 前端最终事件名 | `vcp-keyboard-inset` | `vcp-lifecycle-changed` |
| 触发频率 | 高（键盘动画） | 极低（前台/后台切换） |
| 当前传输 | WebView DOM CustomEvent | event sink → 原生 Channel → Rust owner → Tauri Event |

## 9. 关键约束

1. **绑定与订阅分工**：当前 `load()` 接通进程 observer 与 sink；READY 后 Rust 安装唯一长期 Channel，Kotlin 注册时回放 lifecycle/network 再 resolve。不能在每次视觉恢复或普通 Feature 挂载时重新建立业务订阅。

2. **`lifecycle-process` 依赖必需**：`ProcessLifecycleOwner` 是生产代码直接使用的依赖；没有实现自动回退到 Activity 生命周期的路径。

3. **生命周期配对**：Plugin 销毁时清除 sink、Channel、网络回调和 observer；切换 Activity/WebView 不建立新的业务状态 owner。Activity 视觉回调、主进程业务 phase 与独立 helper 服务会话保持各自所有权。

4. **统一事实入口**：原生 Channel 提交 phase，Rust 负责调和并发布快照；前端可见性只影响渲染。真实 Events 注册失败留存在 `ServiceFailureNotices` 至进程结束，不因 WebView 重建丢失，也没有进程内自动重试入口。

5. **两级排序**：Kotlin 生成 `nativeSequence`；Rust 先拒绝重复/倒序序号，再在 spawn 前预留 `transitionEpoch`。transition 取得同一个 `LIFECYCLE_TRANSITION_LOCK` 后淘汰未执行的过期请求；已经开始的调和在锁内完整完成，不在副作用中途因新 epoch 退出。

6. **Android 分布式租约的后台区间**由 cancellation token 标识。5 分钟计时到期后，控制器在 transition mutex 内检查 token，再停止分布式客户端并释放租约。若先回前台，控制器取消 token。

7. **前台恢复**会唤醒两路 WebSocket 的监听器并冲刷本地日志缓存。Android 分布式节点如因后台计时到期而停止，则单独按设置恢复。
