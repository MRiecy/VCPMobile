# 生命周期桥接

## 1. 功能概述

通过 Android `DefaultLifecycleObserver` 监听**进程级**生命周期变化（resume / pause / stop），将事件发送至 Rust 核心层进行状态更新与 Linger 任务调配。Rust 随后通过标准的 Tauri Event 通信通道广播 `vcp-lifecycle-changed` 事件，前端通过统一的 `useAppLifecycle` Composable 钩子订阅事件。

> **单通道安全设计**：废弃了传统的 `evaluateJavascript` 注入。前后台切换的物理信道收拢为：**Android Platform -> plugin.trigger() -> Rust Core (更新状态 & 调度 Linger) -> app.emit() -> Vue listen()**。此举消除了 WebView 挂起时 JS 注入排队导致的 ANR 及内存竞争风险。

## 2. 代码结构

```
src-tauri/plugins/vcp-mobile/android/.../LifecycleBridge.kt (~75 lines)
├── LifecycleBridge : DefaultLifecycleObserver
│   ├── attach(activity: Activity, plugin: VcpMobilePlugin)
│   │     └── activity.runOnUiThread {
│   │           ProcessLifecycleOwner.get().lifecycle.addObserver(this)
│   │         }
│   ├── onResume(owner: LifecycleOwner)   ← 进程进入前台 (emit)
│   ├── onPause(owner: LifecycleOwner)    ← 进程进入后台 (emit)
│   ├── emit(detail)                     ← 通过 plugin.trigger 发送至 Rust
```

### 2.1 新增依赖

```kotlin
// build.gradle.kts
implementation("androidx.lifecycle:lifecycle-process:2.7.0")
```

`lifecycle-process` 库提供 `ProcessLifecycleOwner`，追踪整个应用进程的生命周期（而非单个 Activity）。当首个 Activity 恢复时进程进入前台，最后一个 Activity 暂停时进程进入后台。

### 2.2 与旧版的关键差异

| 维度 | v1.1.1 | v1.1.2 |
|------|--------|--------|
| 观察对象 | `activity.lifecycle` | `ProcessLifecycleOwner.get().lifecycle` |
| 回调接收 | 每个 Activity 独立触发 | 进程级统一触发 |
| 配置变更 | 可能导致重复回调 | 免疫 Activity 重建 |
| 事件类型 | resume/pause/stop/config-changed/low-memory | resume/pause（精简） |

## 3. 事件类型与触发时机

| 事件名 | 触发时机 | Payload | 前端典型用途 |
|--------|----------|---------|-------------|
| `vcp-lifecycle` | `onResume` | `{ "state": "resume" }` | 恢复 WebSocket 连接、刷新未读消息、调用 `set_app_foreground_state(true)` |
| `vcp-lifecycle` | `onPause` | `{ "state": "pause" }` | 暂停动画、保存草稿、调用 `set_app_foreground_state(false)` |

> **v1.1.2 精简**：移除了 `onStop`、`onConfigurationChanged`、`onLowMemory` 三个事件。进程级生命周期不区分 pause/stop；深色模式由前端 CSS 媒体查询检测；内存告警改用更细粒度的平台 API。

## 4. 前端与 Rust 联动

前后台切换事件流如下：

```
[Kotlin LifecycleBridge]
         │
         ▼ (plugin.trigger("lifecycle", payload))
[Rust Lifecycle Listener] ──► set_app_foreground_state_internal(is_foreground)
         │                         ├── 调配 Linger 倒计时任务
         │                         └── 调整 VCP Log 脉搏心跳频次
         ▼ (app.emit("vcp-lifecycle-changed", payload))
[Frontend useAppLifecycle()] ──► 响应: 挂起/恢复渲染动画、自动检查并拉起未读流式断线重连
```

**Rust 状态控制器管理**：
- `is_app_in_foreground`：查询全局前台状态（状态保存在 Tauri `LifecycleState` 托管结构中，替代原静态 Atomic 变量）。
- `set_app_foreground_state_internal(false)`：进入后台 -> 开启 10 分钟 VCP Log Linger 取消倒计时，5 分钟分布式保活 FGS 冷却关闭倒计时。
- `set_app_foreground_state_internal(true)`：切回前台 -> 立即中止全部冷却定时器；如已冷断开，则执行重连。

详见 [vcp_log_service（modules/21）](../modules/21_基础设施杂项.md) 和 [vcp_info_service（modules/23）](../modules/23_RAG灵视中心.md)。

## 4. 事件格式标准

```kotlin
private fun emit(eventName: String, detail: Map<String, Any?>) {
    val json = serializeValue(detail)
    val script = "window.dispatchEvent(new CustomEvent('$eventName', { detail: $json }))"
    webViewRef?.evaluateJavascript(script, null)
}
```

与 `KeyboardInsetsManager` 共用相同的 `serializeValue` / `escapeJson` 实现，保持序列化行为一致。

## 5. 前端订阅机制

前端统一使用 `useAppLifecycle` Composable 钩子订阅事件：

```typescript
// useAppLifecycle.ts
unlisten = await listen<{ state: string }>("vcp-lifecycle-changed", (event) => {
  const state = event.payload.state;
  if (state === 'pause' || state === 'stop') {
    lifecycleStore.isBackground = true;
  } else if (state === 'resume') {
    lifecycleStore.isBackground = false;
    streamStore.checkAndRecoverInterruptedStreams(); // 自动流式断线恢复
  }
});
```

## 5. 生命周期绑定

```kotlin
// VcpMobilePlugin.kt
class VcpMobilePlugin(private val activity: Activity) : Plugin(activity) {
    private val lifecycleBridge = LifecycleBridge()

    override fun load(webView: WebView) {
        super.load(webView)
        lifecycleBridge.attach(activity, webView)
    }
}
```

### 5.1 `attach()` 流程（v1.1.2: ProcessLifecycleOwner）

```kotlin
fun attach(activity: Activity, webView: WebView) {
    webViewRef = webView
    activity.runOnUiThread {
        ProcessLifecycleOwner.get().lifecycle.addObserver(this)
    }
}
```

- **`ProcessLifecycleOwner.get()`**：返回进程级生命周期持有者（来自 `lifecycle-process` 库）。
- **`runOnUiThread`**：确保 UI 线程上注册观察者（Android 生命周期框架线程安全要求）。
- **`addObserver(this)`**：将 `LifecycleBridge`（即 `DefaultLifecycleObserver`）注册到进程生命周期。

### 5.2 观察者清理

```kotlin
override fun onDestroy(owner: LifecycleOwner) {
    super.onDestroy(owner)
    try {
        ProcessLifecycleOwner.get().lifecycle.removeObserver(this)
    } catch (e: Exception) {
        Log.w(TAG, "Failed to remove lifecycle observer", e)
    }
}
```

`onDestroy` 在进程生命周期结束时触发，清理观察者注册。`try-catch` 确保即使 Activity 已被回收也不会崩溃。

## 6. 与 `KeyboardInsetsManager` 的对比

| 维度 | `KeyboardInsetsManager` | `LifecycleBridge` |
|------|------------------------|-------------------|
| 监听目标 | `WindowInsets` 变化 | **进程**生命周期 |
| 注册方式 | `ViewCompat.setOnApplyWindowInsetsListener` | `ProcessLifecycleOwner.get().lifecycle.addObserver` |
| 事件名 | `vcp-keyboard-inset` | `vcp-lifecycle` |
| 触发频率 | 高（键盘动画） | 极低（前台/后台切换） |
| v1.1.2 变化 | 无 | 升级为进程级观察 + 桥接 Rust `set_app_foreground_state` |

## 7. 关键约束

1. **`Plugin.load(webView)` 时机**：`attach()` 必须在 `load()` 中调用，确保 WebView 已初始化。参见 `docs/ANDROID_PLUGIN_MANAGEMENT.md` §7.3。

2. **`lifecycle-process` 依赖必需**：移除 `lifecycle-process:2.7.0` 会导致 `ProcessLifecycleOwner` 不可用，生命周期事件将回退为 Activity 级别（可能丢失前后台消抖优势）。

3. **`onDestroy` 清理是防御性的**：进程级观察者在进程存活期间一般不需要手动移除，但为防内存泄漏，`onDestroy` 中仍做 `removeObserver` 清理，外包 `try-catch` 避免 Activity 已回收时崩溃。

4. **统一信道通信**：前端不直接发起 `set_app_foreground_state` 命令，而是由 Android 发送 plugin event，Rust 接收并处理后，通过 tauri event 发射给前端，防止两端状态不一致。
