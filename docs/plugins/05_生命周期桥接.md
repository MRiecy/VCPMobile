# 生命周期桥接

## 1. 功能概述

通过 Android `DefaultLifecycleObserver` 监听**进程级**生命周期变化（resume / pause / stop），经 `plugin.trigger("lifecycle", payload)` 发送至 Rust 核心层。Rust 在 `lib.rs` 中监听内部事件通道 `vcp-mobile://lifecycle`，由 `lifecycle_controller.rs::set_app_foreground_state_internal` 调配 Linger 任务，最终通过标准 Tauri Event `vcp-lifecycle-changed` 广播给前端。

> **单通道安全设计**：`LifecycleBridge` **不再**使用 `evaluateJavascript` 直接向前端注入 JS。前后台切换的物理信道收拢为：
> **Android Platform -> Kotlin `plugin.trigger("lifecycle")` -> Rust `listen_any("vcp-mobile://lifecycle")` -> `set_app_foreground_state_internal()` -> `app.emit("vcp-lifecycle-changed")` -> Vue `listen()`**。
> 此举消除了 WebView 挂起时 JS 注入排队导致的 ANR 及内存竞争风险。

## 2. 代码结构

```
src-tauri/plugins/vcp-mobile/android/.../LifecycleBridge.kt (~96 lines)
├── LifecycleBridge : DefaultLifecycleObserver
│   ├── attach(activity: Activity, plugin: VcpMobilePlugin)
│   │     └── activity.runOnUiThread {
│   │           ProcessLifecycleOwner.get().lifecycle.addObserver(this)
│   │         }
│   ├── onResume(owner: LifecycleOwner)   ← 进程进入前台
│   ├── onPause(owner: LifecycleOwner)    ← 进程进入后台
│   ├── onStop(owner: LifecycleOwner)     ← 进程停止（仍会被触发）
│   ├── onConfigurationChanged(newConfig) ← 深色/方向配置变更（由 VcpMobilePlugin 调用）
│   ├── onLowMemory()                     ← 低内存（方法存在，当前未接入主动触发源）
│   └── emit(detail)                      ← 通过 plugin.trigger("lifecycle") 发送至 Rust
```

### 2.1 新增依赖

```kotlin
// build.gradle.kts
implementation("androidx.lifecycle:lifecycle-process:2.7.0")
```

`lifecycle-process` 库提供 `ProcessLifecycleOwner`，追踪整个应用进程的生命周期（而非单个 Activity）。当首个 Activity 恢复时进程进入前台，最后一个 Activity 暂停时进程进入后台。

### 2.2 与旧版的关键差异

| 维度 | v1.1.1 | v1.1.2 / v1.1.3 |
|------|--------|-----------------|
| 观察对象 | `activity.lifecycle` | `ProcessLifecycleOwner.get().lifecycle` |
| 回调接收 | 每个 Activity 独立触发 | 进程级统一触发 |
| 配置变更 | 可能导致重复回调 | 免疫 Activity 重建 |
| 传输方式 | `evaluateJavascript` 注入 `vcp-lifecycle` | `plugin.trigger("lifecycle")` → Rust → `app.emit("vcp-lifecycle-changed")` |
| 事件类型 | resume/pause/stop/config-changed/low-memory | resume/pause/stop/config-changed（`low-memory` 方法保留但未接入） |

## 3. 事件类型与触发时机

| Kotlin 触发 | 内部 trigger 名 | Rust 处理后 emit | Payload | Rust 行为 / 前端典型用途 |
|-------------|----------------|------------------|---------|--------------------------|
| `onResume` | `lifecycle` | `vcp-lifecycle-changed` | `{ "state": "resume" }` | 切回前台：取消 Linger 倒计时、释放 `vcp_log` 前台锁、停止分布式前台保活；若此前已冷断开，则恢复 VCPLog/分布式连接 |
| `onPause` | `lifecycle` | `vcp-lifecycle-changed` | `{ "state": "pause" }` | 进入后台：开启 10 分钟 VCP Log Linger + 5 分钟分布式冷却，并申请 `vcp_log` 前台锁 |
| `onStop` | `lifecycle` | `vcp-lifecycle-changed` | `{ "state": "stop" }` | Rust 与 `pause` 同样视为后台 |
| `onConfigurationChanged` | `lifecycle` | `vcp-lifecycle-changed` | `{ "state": "config-changed", "isDarkMode": true/false }` | Rust 当前不消费；前端如需要可直接监听 `vcp-lifecycle-changed` |

> **v1.1.3 修正**：`LifecycleBridge` 仍然保留 `onStop`、`onConfigurationChanged` 以及 `onLowMemory()` 方法；其中 `onStop` 和 `onConfigurationChanged` 会实际触发并发往 Rust，`onLowMemory()` 当前未接入主动调用源。

## 4. 前端与 Rust 联动

前后台切换事件流如下：

```
[Kotlin LifecycleBridge]
         │
         ▼ (plugin.trigger("lifecycle", payload))
[Rust Lifecycle Listener] ──► set_app_foreground_state_internal(is_foreground)
         │                         ├── 调配 Linger 倒计时任务
         │                         └── 调整 VCP Log 脉搏心跳频次
         ▼ (app.emit("vcp-lifecycle-changed", payload))
[Frontend useAppLifecycle()] ──► 响应: 挂起/恢复渲染动画、自动检查并拉起未读流式断线重连
```

**Rust 状态控制器管理**：
- `is_app_in_foreground`：查询全局前台状态（状态保存在 Tauri `LifecycleState` 托管结构中，替代原静态 Atomic 变量）。
- `set_app_foreground_state_internal(false)`：进入后台 -> 开启 10 分钟 VCP Log Linger 取消倒计时，5 分钟分布式保活 FGS 冷却关闭倒计时。
- `set_app_foreground_state_internal(true)`：切回前台 -> 立即中止全部冷却定时器；如已冷断开，则执行重连。

详见 [vcp_log_service（modules/21）](../modules/21_基础设施杂项.md) 和 [vcp_info_service（modules/23）](../modules/23_RAG灵视中心.md)。

## 4. 事件格式标准

```kotlin
private fun emit(detail: Map<String, Any?>) {
    val plugin = pluginRef?.get() ?: return
    val triggerData = JSObject()
    for ((key, value) in detail) {
        when (value) {
            is String -> triggerData.put(key, value)
            is Boolean -> triggerData.put(key, value)
            is Int -> triggerData.put(key, value)
            is Double -> triggerData.put(key, value)
            is Long -> triggerData.put(key, value)
        }
    }
    plugin.trigger("lifecycle", triggerData)
}
```

- 事件名固定为 `"lifecycle"`；Rust 侧通过 `listen_any("vcp-mobile://lifecycle")` 接收。
- 仅传递 `String`/`Boolean`/`Int`/`Double`/`Long` 五类基础类型，避免 JSObject 序列化异常。
- 与 `KeyboardInsetsManager` 的 `evaluateJavascript` 方案分离，防止 WebView 冻结时事件丢失。

unlisten = await listen<{ state: string }>("vcp-lifecycle-changed", (event) => {
  const state = event.payload.state;
  if (state === 'pause' || state === 'stop') {
    lifecycleStore.isBackground = true;
  } else if (state === 'resume') {
    lifecycleStore.isBackground = false;

## 5. 生命周期绑定

```kotlin
// VcpMobilePlugin.kt
class VcpMobilePlugin(private val activity: Activity) : Plugin(activity) {
    private val lifecycleBridge = LifecycleBridge()

    override fun load(webView: WebView) {
        super.load(webView)
        webViewRef = webView
        keyboardInsetsManager.attach(webView)
        lifecycleBridge.attach(activity, this)
        // ...
    }

    override fun onDestroy(activity: AppCompatActivity) {
        // ...
        lifecycleBridge.detach()
        super.onDestroy(activity)
    }

    override fun onConfigurationChanged(newConfig: Configuration) {
        super.onConfigurationChanged(newConfig)
        lifecycleBridge.onConfigurationChanged(newConfig)
    }
}
```

### 5.1 `attach()` 流程（v1.1.2: ProcessLifecycleOwner）

```kotlin
fun attach(activity: Activity, plugin: VcpMobilePlugin) {
    activityRef = WeakReference(activity)
    pluginRef = WeakReference(plugin)
    activity.runOnUiThread {
        ProcessLifecycleOwner.get().lifecycle.addObserver(this)
    }
}
```

- **`ProcessLifecycleOwner.get()`**：返回进程级生命周期持有者（来自 `lifecycle-process` 库）。
- **`pluginRef`**：持有 `VcpMobilePlugin` 弱引用，`emit()` 通过它调用 `plugin.trigger(...)`。
- **`runOnUiThread`**：确保 UI 线程上注册观察者（Android 生命周期框架线程安全要求）。
- **`addObserver(this)`**：将 `LifecycleBridge`（即 `DefaultLifecycleObserver`）注册到进程生命周期。

### 5.2 观察者清理

```kotlin
fun detach() {
    val activity = activityRef?.get()
    if (activity != null) {
        activity.runOnUiThread {
            try {
                ProcessLifecycleOwner.get().lifecycle.removeObserver(this)
            } catch (_: Exception) {}
        }
    } else {
        try {
            ProcessLifecycleOwner.get().lifecycle.removeObserver(this)
        } catch (_: Exception) {}
    }
    activityRef = null
    pluginRef = null
}

override fun onDestroy(owner: LifecycleOwner) {
    detach()
    super.onDestroy(owner)
}
```

`detach()` 在 `VcpMobilePlugin.onDestroy()` 中被显式调用；`onDestroy(owner)` 作为进程级生命周期的兜底再次清理。`try-catch` 确保即使 Activity 已被回收也不会崩溃。

## 6. 与 `KeyboardInsetsManager` 的对比

| 维度 | `KeyboardInsetsManager` | `LifecycleBridge` |
|------|------------------------|-------------------|
| 监听目标 | `WindowInsets` 变化 | **进程**生命周期 |
| 注册方式 | `ViewCompat.setOnApplyWindowInsetsListener` | `ProcessLifecycleOwner.get().lifecycle.addObserver` |
| Kotlin 侧事件名 | `vcp-keyboard-inset` | `lifecycle`（内部 plugin trigger） |
| 前端最终事件名 | `vcp-keyboard-inset` | `vcp-lifecycle-changed` |
| 触发频率 | 高（键盘动画） | 极低（前台/后台切换） |
| v1.1.2 / v1.1.3 变化 | 无 | 升级为进程级观察 + `plugin.trigger` → Rust → `app.emit` |

## 7. 关键约束

1. **`Plugin.load(webView)` 时机**：`attach()` 必须在 `load()` 中调用，确保 WebView 已初始化。参见 `docs/ANDROID_PLUGIN_MANAGEMENT.md` §7.3。

2. **`lifecycle-process` 依赖必需**：移除 `lifecycle-process:2.7.0` 会导致 `ProcessLifecycleOwner` 不可用，生命周期事件将回退为 Activity 级别（可能丢失前后台消抖优势）。

3. **`onDestroy` 清理是防御性的**：进程级观察者在进程存活期间一般不需要手动移除，但为防内存泄漏，`onDestroy` 中仍做 `removeObserver` 清理，外包 `try-catch` 避免 Activity 已回收时崩溃。

4. **统一信道通信**：前端不直接发起 `set_app_foreground_state` 命令，而是由 Android 发送 plugin event，Rust 接收并处理后，通过 tauri event 发射给前端，防止两端状态不一致。

5. **前后台 transition 必须具备单一所有权**：`LifecycleBridge` 对连续 `pause/stop` 做原生去重并携带递增 epoch；Rust 在 spawn 前预留全局 transition epoch，随后使用同一个 `LIFECYCLE_TRANSITION_LOCK` 串行执行。任何 await 后提交前都要复核 epoch，迟到的后台任务不得覆盖新 foreground 状态。

6. **linger 到期动作也属于 transition**：10 分钟日志断连和 5 分钟 Distributed 停止在 delay 后必须先获取同一 transition mutex，再复核 epoch，并把 disconnect/stop、断连标志与 Guardian lease 释放放在同一所有权区间。这样 timer 先执行时 resume 能看到断连标志并补偿重连；resume 先执行时旧 timer 因 epoch 失效退出。

7. **恢复依据只在成功提交后消费**：前台恢复先 `load` 断连标志，不在 await 前 `swap(false)`；仅当前 epoch 完成对应重连后才清除，避免被新的后台 transition 抢占时永久丢失恢复意图。
