# 26｜日记中心

## 1. 入口与懒加载

右侧通知栏 2×2 工具区左下角的胶囊按钮调用 `overlayStore.openDiaryCenter()`，不改写 `RightDrawer` 的展示意图；全局页面栈只新增一个 `diaryCenter` 类型，并由页面层覆盖侧栏。

`FeatureOverlays.vue` 使用 `diaryMounted` 首次打开锁存：首次打开前不请求 Diary chunk；首次打开后保留组件实例，以维持 SlidePage 退场动画、文件夹和滚动位置。reader、editor、composer 和 manager 都是页面内部状态，不进入全局 pageStack。

当前聊天 `DiaryBlock.file_name` 表示 DailyNote 请求中的可选文件名后缀，不是服务端最终分配的文件名。因此本版本不从聊天块伪造深链，也不根据 Agent 名称猜测文件夹；只有未来工具结果能可靠关联并给出最终 `folder + fileName` 时，才可接入现有精确 key 打开能力。

## 2. 单 Store 所有权

`useDiaryStore` 是唯一业务状态所有者：

- resources：folders、notes、document；
- search：普通/语义 mode、scope、query、results、limited 与索引提示；
- editor：baseline content/hash、draft、save state；
- management：selected keys、tombstones、mutation outcome；
- composer：DailyNote 表单与提交状态；
- request ownership：folders/notes/document/text/semantic generation 与 requestId。

正文、搜索结果和草稿只在内存中。Pinia persist 只保存 `hiddenFolders`、`collapsedCategories`、`folderOrder`。本机隐藏默认空，是可逆的发现性过滤，不是权限，也不会修改 LightMemo 服务端排除规则。

所有读请求在 success、error、finally 三处同时检查 generation 与完整 target。A→B→A 的旧请求不能覆盖新结果或提前清除 loading。

## 3. 页面与返回顺序

页面只注册一个持久内部历史项 `Diary:Internal`，feature-local Sheet 使用 `Diary:Sheet`，重命名层使用 `Diary:Dialog`。返回顺序为：

```text
Confirm / Dialog
  -> Sheet
  -> saving 拒绝返回
  -> dirty editor/composer 确认
  -> preview/editor
  -> reader
  -> selection
  -> search
  -> Page:diaryCenter
```

dirty 返回通过 microtask 延后打开 Confirm，避免系统 popstate 尚未补回被拒 entry 时颠倒浏览器历史。保存与创建的远端核验期间不可关闭。

## 4. 浏览、搜索与阅读

- 文件夹按“名称以 `簇` 结尾”分为“思维簇”，其余归入“日记 / 知识库”；
- 文件列表复用 `useVirtualList`，真实固定行高 84px，key 为 `folder + NUL + file`；
- 普通搜索输入 275ms debounce；语义搜索只在显式提交时请求；两者 owner、错误和取消互相独立；
- scope 始终显示“本文件夹 / 全部”；
- LightMemo chunk 在 Rust 归一化为文件结果，前端再应用本机隐藏过滤；
- 普通搜索结果打开后，仅在正文文本节点做字面量高亮；代码、脚本、样式、textarea 与既有 mark 不改写；
- reader 连续滚动、正文可原生选择，代码和表格局部横向滚动。

正文是产品定义的可信内容类，唯一 `v-html` 输入来自 `renderDiaryMarkdownWithHighlight(document.content, term)`。高亮 helper 只在渲染后的离线 DOM 中插入 textContent `mark`，文件名、folder、摘要、错误和语义元信息全部使用 Vue 文本绑定，不进入该边界。

## 5. 编辑与管理

编辑器是单栏 Markdown textarea，预览是显式状态，不做左右分栏。保存使用不可变 snapshot：用户在请求期间继续输入时，成功只更新该 snapshot 的 baseline，较新的输入仍保持 dirty。

可见状态包括 `dirty/saving/saved/error/conflict/uncertain`。冲突和不确定状态提供复制草稿、加载远端和二次确认后的强制覆盖；任何失败均保留草稿。

文件管理包括：

- 阅读页单项重命名、移动、删除；
- 长按进入批量选择，批量移动/删除保留 partial result；
- 成功删除/移走的源 key 加入 tombstone，迟到 list/get 不会让它复活；
- 文件夹管理支持本机隐藏/恢复、折叠、Sortable 拖拽顺序和服务端空目录删除；
- Composer 收集日期、署名、folder、可选文件名后缀、Tag、Content，并打开服务端返回的实际 key，不使用固定延时猜测。

创建请求没有可预知的最终 key。收到 `DIARY_CREATE_UNCERTAIN` 时 Composer 保留输入、禁用直接重试，并要求先返回列表刷新核对；退出确认也明确说明“远端可能已创建”。插件明确拒绝则是可修正、可重试的 `DIARY_TOOL_ERROR`。这样避免响应丢失后重复生成两篇日记。

## 6. 视觉与测试

Diary 内容区只使用主题变量和实色表面，无 backdrop blur、卡片海、厚影或整行入场动画。Sheet 使用 `z-sheet`，重命名层使用 `z-dialog`，页面继续使用动态 `LAYER_PAGE_BASE + stackIndex`。触控按钮最小 48px，根节点和滚动区均标记 `no-swipe`。

前端专项测试位于 `src/tests/unit/diary/`，覆盖：

- 文件夹/文档/搜索 A→B→A、输入即时失效、普通/语义独立取消与旧 finally；
- 保存 snapshot、冲突草稿、远端草稿迟到保护、创建不确定禁重试与有界 tombstone；
- dirty、saving、clean editor 返回；
- raw HTML 正文、Unicode 安全的字面量高亮与文本元信息边界；
- Rust command、TS invoke、普通 Tauri/Android permission 分界；
- 真正的 first-open 懒加载和右抽屉关闭顺序。
