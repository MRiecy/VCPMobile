# 15. 设置系统总览

## 1. 概述

### 1.1 领域定位

`features/settings/` 组织全局设置入口和配置编辑页面。设置值由所属领域管理：Rust 配置的正式快照归 `settingsStore`，聊天偏好归 `features/chat/preferences/`，主题归 `themeStore`，更新偏好归 `updateStore`。

该领域边界严格限定为：

- **设置视图容器**：`SettingsView.vue` 作为 SlidePage 级全屏页面，承载全部设置子页面
- **设置原子组件**：`src/components/settings/` 下的可复用控件与布局原语；详见设置原子组件文档
- **设置数据流**：`settingsStore` 持有 Rust 领域快照；身份、连接、高级、语音和风格指导页各自持有字段投影会话
- **外观子系统**：`ThemePicker.vue` + `ThemeLivePreview.vue` + `themeStore` 负责主题草稿/确认及 CSS 变量注入
- **聊天偏好**：`ChatPreferencesPage.vue` 调用 `useChatPreferencesStore`，聊天消费方不依赖设置页挂载

该领域**不**涉及：
- 智能体个体的配置编辑（由 `features/agent/` 的 `AgentSettings.vue` 负责）
- 群聊参数配置（由 `features/group/` 的 `GroupSettings.vue` 负责）
- 消息持久化本身（由 `features/chat/` 负责）

### 1.2 设置原子组件一览

`src/components/settings/` 提供以下常用组件，完整画布模板与选择菜单见 [设置原子组件与主题系统](../../components/21_设置原子组件与主题系统.md)：

### 1.4 所有权与调用方向

```text
SettingsView → catalog → 当前页面
                       ├─ 身份/连接/高级 → 页面编辑会话 → settingsStore → Rust 配置
                       ├─ 聊天偏好 → chatPreferences Store ← ChatView / 渲染 / 消息触感
                       ├─ 主题 → themeStore
                       └─ 关于/更新 → updateStore
```

设置首页不持有整份 AppSettings 草稿，也不直接读取/保存业务配置。普通 Section 读取只读字段并发出用户编辑事件，页面把事件交给自己的会话；主题与即时偏好使用所属领域的 setter。

### 1.5 核心设计原则

1. 页面分类用于组织用户入口，领域决定设置的归属和生命周期。
2. 正式快照唯一归 `settingsStore`；编辑会话只持有本页叶字段，按领域提交带版本与基线的 patch。
3. 保存成功表示配置已持久化，连接、同步、更新任务的实际状态由原 owner 提供。
4. 即时偏好先完成持久化再发布状态；失败保留旧值并反馈。
5. 强制隐藏只释放本次访问，不启动保存；已经提交的任务仍可在其 owner 内完成。

## 2. 设置视图（SettingsView.vue）

### 2.1 外壳与页面目录

设置通过 `FeatureOverlays` / `SlidePage` 打开，默认层级取 `LAYER_PAGE_BASE`。壳根据 `catalog.ts` 渲染七个首页入口，另有关于页下的开发者子页：

| ID | 当前页面 | 布局 |
|----|----------|------|
| `identity` | `IdentitySettingsPage` | list |
| `connection` | `ConnectionSettingsPage` | list |
| `theme` | `ThemePicker` | viewport |
| `rendering` | `ChatPreferencesPage`，标题“聊天偏好” | list |
| `advanced` | `AdvancedSettingsPage` | list |
| `guide` | `GuideCenterSection` | list |
| `about` | `AboutSection` | immersive |
| `developer` | `DeveloperSettingsPage`，仅关于页解锁后进入 | list |

异步组件在目录模块级创建稳定引用；当前访问通过组件 ref 取得可选 `beforeLeave`。目录不存放实例保存函数。加载期间可返回；加载失败显示重试或返回，不拿上一次页面实例代替当前页面。

列表布局的间距分三层管理：`SettingsView` 的 list 滚动宿主提供顶部 12px、左右 12px 和底部 `calc(var(--vcp-safe-bottom, 0px) + 32px)`；页面用纵向 flex/gap 排列分组与加载、错误、保存提示；`SettingsSection` 管理标题、主体和 footer 之间的 8px 间隙。区块自身不带外边距，最后一组不会与宿主留白重复叠加。安全区为零时仍有独立的 32px 内容留白，fallback 不承担最小间距。

连接、高级与聊天偏好页使用默认卡片分组；身份、帮助和开发者页保留既有卡片或折叠结构。`viewport` 主题页和 `immersive` 关于页保留各自滚动与安全区职责，不套用 list 的 padding。

### 2.2 返回与隐藏

头部返回、页面 `back`、Escape 和硬件返回汇入 `useSettingsNavigation.requestLeave`。没有离开钩子的页面同步关闭；编辑页同步向 ModalHistory 返回 `false`，单飞等待 `beforeLeave()`，成功且访问仍匹配时注销子页 modal。失败保留页面和草稿。

`activeVisit` 与 `displayedVisit` 分别表达活动访问和退场画面，序号阻止旧异步结果或旧动画回调关闭新访问。外层 `isOpen=false` 立即注销子页 modal，并令页面 `active=false`；退场资源经对应 transition 的 `after-leave` 释放，不使用猜测动画长度的清理定时器。

页面在 `active=false` 时释放编辑会话，关闭 ModelSelector、头像裁剪、导入确认及未交付 picker。再次进入建立新的会话。外部强制隐藏不会自动保存未提交草稿。

### 2.3 关于页资源

关于页使用沉浸式布局，自己的返回按钮仍走同一离开入口。流体背景仅在关于页活动时运行；隐藏同步停止活跃工作，退场画面由既有资源保留。

“功能介绍”六连击（相邻间隔不超过 1.2 秒）开启本机开发者模式，第六次只解锁，之后点击进入开发者选项。状态经 `developer/store.ts` 持久化；离开页面清除未完成的点击计数，开发者页可关闭模式。开发者页返回关于页时保留同一个 SettingsSubPage modal，硬件返回补回该历史条目，下一次返回才关闭关于页；外层隐藏只注销一次。试听面板已迁至 `developer/HapticsDebugPanel.vue`，仅展示当前平台的效果，并丢弃离开后的迟到结果。

## 3. 设置数据流

### 3.1 加载与正式快照

应用启动链路会读取 `settingsStore`；编辑页挂载后通过 `useSettingsPageSession.reload` 在原串行队列中刷新。已有合法快照时可以立即建立会话，刷新失败保留快照和草稿并显示错误。没有正式快照时不构造可保存的默认表单，页面提供加载、错误和重试入口。

`read_settings` 返回 `ConfigSnapshot { data, domains }`：`data` 是八领域嵌套配置，`domains` 包含各领域的 revision、结构版本、健康状态和字段问题。`settingsStore.settings` 只是该正式快照的 data 投影，不另存一份可写设置。主题、聊天和更新偏好的 localStorage 所有权不变。

`fetchSettings` 与 `updateSettings` 共享串行队列，入队前深拷贝请求。Store 同时监听 `vcp-config-changed`，按领域 revision 接纳响应/事件，迟到旧版本不能覆盖新值。保存结果区分 `saved`、`rejected`、`conflict`；只有 saved 提示“设置已保存”。读取发现局部恢复问题时提示检查，对应页面显示详细字段问题，读取不代表原文已被修复。

### 3.2 编辑与重基

身份、连接、总结、语音、风格指导页面分别使用显式字段集合。路径如 `identity.userName`、`server.adminUsername`、`voice.asr.language`；一个页面可以编辑多个领域。子区块通过 `edit(patch)` 或模型输入事件提交用户意图，页面调用 `session.edit(key, value)`。

会话持有 base、draft、每字段 editRevision、领域 revision 与 pending 批次。新正式快照到达时，只让未编辑且不在提交中的字段跟随；dirty 字段保留用户输入和实际编辑基线。pending 与 editRevision 保护“提交 1 后又改回旧值 0”的时序；领域版本和 baseValues 用于 Rust 检测真实并发修改。

### 3.3 保存与离开

`save()` 只提交本页 dirty 字段，并合并保存过程中的再次显式保存要求；普通输入不会自动让队列无限追赶。结算读取当前 Store 快照，字段没有后续编辑才接受正式值。失败保留草稿与错误，不自动循环重试。

同领域的其他字段发生变化时，Rust 可依据 baseValues 合并；同一字段变为第三个值时返回 conflict。会话保留用户输入并显示具体字段错误，再次编辑才重新确认该字段的基线。`SettingsDomainIssues` 提供坏字段恢复默认与需要确认的领域修复；领域修复明确列出会影响的范围，不能用正常自动保存暗中重置整个领域。

`prepareLeave()` 冻结新输入和页面动作，等待已有保存并补存当前 dirty；成功且不再 dirty 才允许离开。首个快照尚未取得的页面可以离开。总结模型保留输入触发保存、blur 兜底和选择器选择后保存，外部重基不再被 watch 误判为用户输入。

### 3.4 依赖配置的操作

| 操作 | 顺序与范围 |
|------|------------|
| 检查模型发现 | 等待页面保存，捕获返回快照的 URL / Key / mode，再测试 |
| 表情库重建 | 等待连接配置提交成功，再执行原重建命令 |
| 导出配置 | 等待保存，再由 `export_config_domains` 从一份已提交快照按 Rust 备份规则投影 |
| 导入配置 | 原生选择、Rust 解析、确认；冻结动作并 `settlePending`，一次提交所选领域 patch，再只接受覆盖的本页字段 |
| 打开同步面板、清缓存 | 保持独立操作，不保存无关字段 |

诊断/导出的冻结只覆盖保存和快照捕获，网络或文件 IO 期间可以继续编辑。导入等待既有保存完整结算，不用新的 `save()` 顺便提交原本未请求的 dirty 字段；失败恢复输入并保留草稿。已隐藏页面不启动保存之后的任务，也不接纳迟到 UI 结果。

### 3.5 持久化与运行结果

Rust 在 `config_domains` 中按领域存储 JSON；旧 `settings/global` 只做一次事务搬运，归档原文后移除，之后不双读双写。保存成功不能替代 WebSocket 已连接、同步完成或原生文件已交付等结果；提交后网络协调与配置保存使用不同锁。

备份仍为 `.vcpcfg.json` v2，改用嵌套 `domains` 加独立 `preferences`，保留 v1 文件单向转为领域补丁，拒绝开发期旧平铺 v2。Rust 字段规则决定身份、连接、总结模型和语音等可备份范围，不再由前端维护第二份白名单。缺项不覆盖；SQLite 部分一次事务提交，主题和四项聊天偏好仍由原 localStorage owner 分别应用并报告结果。备份不包含侧栏排序、同步日志/预渲染选项、开发者模式、更新偏好、头像或克隆样本音频。

## 4. 主题与聊天偏好

### 4.1 单一主题源与身份

主题资产通过 eager `import.meta.glob('../../assets/themes/*.ts', { eager: true })` 编译进应用，共 13 个 `ThemeModule`。候选、当前值和成功持久化均使用现有 `.ts` basename；旧中文名或 `.css` 名只在 `normalizeThemeModuleKey()` 输入边界映射，不恢复 CSS loader 或第二套主题身份。

### 4.2 局部草稿、实时预览与横向选择

打开主题页后，`ThemePicker` 用实际 `currentTheme` 初始化局部 `draftThemeKey`，并把候选卡滚到横向 snap rail 中央。点击卡片或横滑停止只更新草稿。`ThemeLivePreview` 同时读取候选 dark/light 变量，以局部 `--preview-*` style 展示两块预览；安全壁纸解析只接受仓库 basename，不允许远程 scheme、目录或上跳。

候选阶段不会改变 `document.documentElement`、`currentTheme`、`extraCss` 或 `localStorage`。页面卸载即丢弃草稿；外部已应用主题变化时，clean 草稿跟随，dirty 草稿保留。

### 4.3 明确确认与失败回滚

只有“确认应用主题”调用 `applyThemeFile(draftThemeKey)`。Store 先归一化并验证模块，再准备变量和 `extraCss`，最后写入规范 TS key；任一步失败都会恢复旧根变量、Store refs、style 文本与持久化值。组件保留候选并显示可重试错误，重复确认由 `isApplying` gate 抑制。

`initTheme()` 仍先应用当前主题，再通过 `requestIdleCallback` 在空闲时填充候选元数据；Vite HMR 只重新应用已经 applied 的 TS 模块，不会把未确认草稿注入全局。

### 4.4 独立的聊天偏好页面

聊天偏好已迁至 `features/chat/settings/ChatPreferencesPage.vue`，ThemePicker 只处理主题。设置页与聊天长按快捷入口共同调用 `useChatPreferencesStore` 的呈现 setter，渲染器直接读取这个 Store。

| 偏好 | 默认值 | 消费位置 |
|------|--------|----------|
| `presentationMode` | `bubble` | ChatView 与 MessageRenderer |
| `smoothStreamingEnabled` | `false` | 普通 Markdown AST 的有限揭露；仍受减少动态效果等真实条件限制 |
| `messageHapticsEnabled` | `true` | 原发送消息与流结束触感调用，共用一个开关 |
| `collapseToolsWhileStreaming` | `false` | 工具调用/结果详情的流式默认展开策略 |

消息震动经 `triggerMessageHaptic` 进入原生插件：Android 发送 TICK、正常完成 CLICK，iOS 发送 light/0.5、完成 light 默认强度。触发时机由聊天 owner 决定，取消、失败和历史恢复不发完成反馈；原生失败不阻断聊天，也不回退为另一种 Web 震动。开发者试听复用相同 message 意图，API 已提交不表示硬件一定播放。流式折叠只控制工具块，Thought 默认行为保留。用户手动展开/收起后，该 ToolBlock 实例不再被默认策略覆盖。

Android API 33+ 的触感按 `VibrationAttributes.USAGE_TOUCH` 交给系统服务处理用户设置，不再读取已弃用的 `HAPTIC_FEEDBACK_ENABLED` 提前拒绝。旧版仅直接调用 `Vibrator` 的自定义波形路径保留必要的触感开关检查；`performHapticFeedback` 自身负责视图与系统策略。开发者面板显示真实的提交结果和原因，不用 Web API 成功替代原生调用结果。

工具块使用短递增 VNode key，在同一消息中按工具次序逐字段比较语义，相同内容延续旧 key；不把正文或 base64 序列化到 key。Markdown 合并或终态 hash 变化可以保留本次手动选择；工具插入/删除导致次序变化时，无法同位匹配的块按新结构恢复默认，完整卸载后也重新默认。不把交互状态写入消息或长期偏好。

## 6. 数据流时序

### 6.1 打开与编辑

```text
打开设置 → catalog 分类列表（无业务配置草稿）
进入编辑页 → 依据 Store 正式快照创建字段会话 → 串行刷新
用户输入 → Section emit edit → 页面 session.edit → 本页 draft
外部正式快照 → rebase → clean 字段跟随，dirty/pending 字段保留
```

### 6.2 保存与依赖动作

```text
返回 / 依赖动作 → 当前页面会话 save
    → 捕获 dirty 字段、baseValues、领域 revision 与 editRevision
    → settingsStore 入队前复制 → update_settings → saved / rejected / conflict
    → 会话按当前 Store 快照结算，后续编辑不被覆盖
    → 返回：clean 且仍为本次访问才关闭
    → 动作：保存成功且仍 active 才使用确定 snapshot 执行
```

导入使用 `settlePending → buildSettingsUpdate(已验证领域字段) → updateSettings → acceptImport(覆盖字段)`。它与普通 save 具有不同的覆盖含义，未被导入的 dirty 字段保留。

### 6.3 主题切换的时序（ASCII）

```
用户点击/横滑到候选 "themes-bear-holiday.ts"
    │
    ▼
draftThemeKey 更新 + dark/light 局部预览更新
    │
    ├──► currentTheme / root vars / localStorage 保持不变
    │
用户点击“确认应用主题”
    ▼
themeStore.applyThemeFile("themes-bear-holiday.ts")
    │
    ├──► normalize + validate bundled ThemeModule
    ├──► 注入 dark/light vars 与 extraCss
    ├──► 更新 currentTheme/currentThemeInfo
    └──► 最后持久化规范 TS key
            ├── 成功：draft 变 CLEAN，“主题已应用”
            └── 失败：恢复旧视觉/refs/key，候选保留供重试
```

### 7.3 SettingsTextField 的安全输入机制

`SettingsTextField` 实现了移动端罕见的**安全输入模式**（`isSecure`）：

```ts
// src/components/settings/SettingsTextField.vue (L32-L35)
const isActuallyMasked = computed(() => {
  return props.isSecure && isMasked.value && !isFocused.value;
});
```

- 默认遮罩：使用 CSS `-webkit-text-security: disc` 将字符显示为圆点（类似原生 `type="password"`）
- 聚焦自动显式：输入框获得焦点时临时解除遮罩，方便用户核对输入内容
- 失焦自动遮罩：离开输入框后恢复遮罩
- 手动切换：右侧提供眼睛图标按钮，允许用户主动切换显隐

此设计用于遮罩 `server.apiKey`、`log.key`、`sync.token`、`server.adminPassword` 等敏感凭证，同时兼顾移动端小屏幕下的输入校对体验。输入遮罩不代表 SQLite 或导出文件已加密。

## 8. 设计决策与注意事项

### 8.1 为什么使用字段会话

每页只编辑自己拥有的字段；正式快照变化通过重基接纳，不能整体覆盖草稿。只读 draft 与显式 edit 入口使用户编辑 revision 可追踪，避免嵌套 props 双向绑定绕过会话。

### 8.2 返回与失败

返回等待本次编辑结算。保存失败展示错误并停留；强制外部隐藏则只清理本次访问。两者是不同入口，不能在隐藏 watcher 或卸载钩子里补存，也不能让旧保存回调关闭新页面。

### 8.3 本地偏好的持久化

| 数据 | key | 管理方 |
|------|-----|--------|
| 当前主题文件名 | `vcp-theme-name` | `themeStore` |
| 当前主题模式 | `vcp-theme-mode` | `themeStore` |
| 消息呈现模式 | `vcp-chat-presentation-mode` | `chatPreferences` |
| 流式平滑动效 | `vcp-smooth-streaming-enabled` | `chatPreferences` |
| 消息震动 | `vcp-message-haptics-enabled` | `chatPreferences` |
| 流式工具折叠 | `vcp-collapse-tools-while-streaming` | `chatPreferences` |
| 自动检查更新 | `vcp_auto_update_check`（`on/off`） | `updateStore` |

聊天与更新共用 `core/preferences/localPreference.ts` 的窄 IO，领域保留各自编码、默认值和异常解释。聊天 Store 同步恢复，不依赖主题初始化或设置页打开；相同值不写存储，写失败保留旧状态。自动检查更新保留“只有 off 表示关闭”的既有读取规则。

### 8.4 分布式入口边界

全局设置不再承载分布式连接、状态或 `VCPMobileCLI` 预检。连接参数仍作为应用配置参与备份，但编辑、连接状态与工具授权统一由独立插件中心负责。

### 8.5 关于页面的特殊头部处理

`catalog` 将关于页声明为 `immersive`。壳对被沉浸页面覆盖的头部和首页使用 inert，关于页自己的 `back` 事件仍进入 `requestLeave`，不直接修改导航状态。

### 8.6 运行时副作用的单 owner

Rust 的持久保存任务在数据库 commit、缓存发布并释放 writer 后执行 hook。hook 发出配置事件，将日志/分布式变更类别累积到 pending 位图并推进 generation，再调度独立的运行时协调任务。

协调任务取得自己的锁后淘汰等待中的旧 generation，读取最新已提交配置并交给 VCPLog、VCPInfo 和分布式 owner。pending 类别不会被后一种配置修改抹掉；该网络锁不再挡住无关配置保存。连接失败不撤销或反报已成功的数据库提交。克隆样本旧引用回收也只在提交后安排，由样本 owner 再核对当前引用。

### 8.7 设置原子组件的变体系统

`SettingsCard` 支持 4 种视觉变体，在不同 Section 中承担不同的语义角色：

| 变体 | 用途 | 使用场景 |
|------|------|----------|
| `default` | 标准卡片，半透明灰底 | 大部分设置分组（VcpCore、Sync 等） |
| `glass` | 半透明底色和边框，不使用 backdrop blur | `UserProfileSection` 的头像卡片 |
| `danger` | 红色边框+底色 | 危险操作区域（预留） |
| `warning` | 黄色边框+底色 | 警告操作区域（预留） |

`SettingsActionButton` 同样支持 4 种变体（`primary`/`secondary`/`danger`/`ghost`）与 3 种尺寸（`sm`/`md`/`lg`）。MaintenanceSection 的缓存清理和刷新入口使用 primary，并随页面冻结禁用。
