# 16. 设置子模块详解

## 1. 概述

### 1.1 领域定位

`features/settings/components/` 是 VCP Mobile 前端**全局设置中心**的原子 UI 单元集合。组件按功能子域负责将用户输入转化为对 `settingsStore` 的写操作，或通过 Tauri IPC 触发 Rust 后端的维护/查询命令。

业务区块由各自设置页面装配；`SettingsView` 根据目录懒加载页面，不直接组织配置字段。设置仍使用 SlidePage 与既有覆盖层，不新增路由系统。布局遵循列表优先、灰度优先和 2px 强调条。

设置子模块不涉及任何聊天业务逻辑，其职责边界清晰限定为：
- **配置读写**：用户身份、服务器连接、同步参数、主题等持久化配置
- **维护操作**：附件 GC、缓存清理、预渲染重建等低频但关键的后台任务
- **信息展示**：版本号、开源协议、同步日志浏览

### 1.3 页面与区块关系

| 页面/领域 | 区块 | 状态所有者 |
|-----------|------|------------|
| IdentitySettingsPage | UserProfileSection | 本页身份字段会话；头像沿 assistant/avatar owner |
| ConnectionSettingsPage | VcpCore / Sync / ConfigBackup | 本页连接会话；独立维护/同步任务仍归原 owner |
| AdvancedSettingsPage | TopicSummary / Maintenance / ModelSelector | 本页总结会话与局部选择器 |

| AboutSection | UpdateSection | updateStore / Rust UpdateSession |

### 1.4 编辑与动作接口

身份、连接区块接收只读字段投影，通过显式 `edit(patch)` 事件修改会话；不直接写嵌套 props。总结区块使用 `modelValue` 和用户更新事件。页面负责加载、重基、保存、冻结和离开，壳只调用当前页面的 `beforeLeave`。

依赖已保存配置的动作接收 `commit: () => Promise<SettingsSaveResult>`，等待成功快照后执行。备份导入另接收 `applyImport(patch): Promise<void>`，由连接页面排空已有保存、提交导入并接受覆盖字段。

### 1.5 主题与聊天偏好的边界

ThemePicker 专门负责主题草稿/确认与局部预览，不再接收 `section` 切换消息配置。聊天偏好独立页面读取 `useChatPreferencesStore`，四项偏好通过先存储后更新状态的 setter 提交。呈现模式与聊天长按菜单共享选项及状态；消息震动默认开，流式折叠和平滑动效默认关。详细消费链见 [设置系统总览](15_设置系统总览.md)。

## 2. 核心设置模块

### 2.1 VcpCoreSettingsSection — VCP 核心配置

源码：`src/features/settings/components/VcpCoreSettingsSection.vue`。编辑 Chat URL、入口模式、API Key、VCP WebSocket URL/Key；URL 原文保留，最终 URL 由 Rust resolver 预览。

```ts
defineProps<{
  settings: Readonly<ConnectionFields>;
  active: boolean;
  disabled?: boolean;
  commit: () => Promise<SettingsSaveResult>;
}>();
defineEmits<{ edit: [patch: Partial<ConnectionFields>] }>();
```

URL/mode 变化经 120ms 延迟调用 `preview_chat_endpoint`；generation 丢弃过期结果，隐藏时清理待执行预览。检查模型发现先等待 commit 成功，再从返回 snapshot 捕获 URL、Key 和 mode 调用 `test_vcp_connection`。失败或等待中隐藏不会启动测试；测试期间输入变化令旧结果失效。

结果使用 `success/status/modelCount/modelDiscoveryAvailable`。Raw URL 不能推导模型发现地址时展示“跳过模型发现”，不把该结果表述为主聊天失败。状态反馈属于这次检查，不代替正式连接状态。

### 2.2 AI 与插件能力边界

全局设置不提供 AI 全局默认参数，也不重复展示分布式连接或 `VCPMobileCLI` 授权预检。Agent/Group 模型配置归各自编辑页；分布式工具配置归插件中心。

### 2.3 SyncSettingsSection — 同步配置

源码：`src/features/settings/components/SyncSettingsSection.vue`。Props 与 VcpCore 一致，输入通过 `edit` 事件交给连接页会话。

| 字段/动作 | 接口 |
|-----------|------|
| HTTP / WebSocket URL | `syncHttpUrl` / `syncServerUrl` |
| 同步 Token / 图床密钥 | `syncToken` / `fileKey` |
| 表情库修复 | 等待 `commit()` 成功，再调用 `regenerate_emoticon_library` |
| 全量神经同步 | `overlayStore.openSyncSession()`，只打开独立面板，不保存无关字段 |

表情库任务以本次 generation 接纳成功/失败；隐藏、卸载使结果失效并取消状态清理定时器。后端已发起任务仍继续由其 owner 执行。页面离开保存或导入期间，`disabled` 同时禁止输入和新动作。

### 2.4 UserProfileSection — 用户资料

**职责一句话**：管理本地用户身份标识（头像、用户名）及管理员接口鉴权凭据。

**源码位置**：`src/features/settings/components/UserProfileSection.vue`

**Props**：`settings: Readonly<IdentityFields>`、`active: boolean`、`disabled?: boolean`。用户名和管理员凭据通过 `edit(patch)` 交给 IdentitySettingsPage 的字段会话；头像仍由原生 picker、裁剪器和 assistant/avatar Store 管理。

**包含的表单字段与交互**：

| 字段 | 组件 | 绑定字段 | 修饰符 | 说明 |
|------|------|---------|--------|------|
| 头像 | `VcpAvatar` + `AvatarCropper` | — | `owner-type="user"` | 点击触发文件选择 → 裁剪器 → Blob IPC |
| 用户名 | `SettingsTextField` | `settings.userName` | — | 本地显示名称 |
| 管理员账号 | `SettingsTextField` | `settings.adminUsername` | `mono` | Basic Auth 用户名 |
| 管理员密码 | `SettingsTextField` | `settings.adminPassword` | `isSecure` + `mono` | Basic Auth 密码 |

**头像上传完整时序**：

```
用户点击头像区域
    │
    ▼
调用 pickFile("avatar")，打开 Android 系统图片选择器
    │
    ▼
Native 64 KiB 流式 staging
    ├── 读取尺寸但不分配全尺寸 Bitmap
    ├── EXIF 方向归一化
    ├── inSampleSize 采样至最长边 1120px WebP
    └── 返回受控临时路径
    │
    ▼
convertFileSrc(path) → <AvatarCropper :img="cropImg" />
    │
    ▼
用户在裁剪器中确认
    │
    ▼
onCropConfirm(blob: Blob)
    ├── isCropping = false
    ├── const arrayBuffer = await blob.arrayBuffer()
    ├── const bytes = new Uint8Array(arrayBuffer)
    ├── await assistantStore.saveAvatar(
    │     "user",           // ownerType
    │     "user_avatar",    // ownerId
    │     blob.type,        // mimeType
    │     bytes             // 业务层保持 Uint8Array；Tauri 内部转为 number[] JSON
    │   )
    └── assistantStore 内部调用 avatarStore.refreshAvatar("user", "user_avatar", hash)
```

**关键点**：
- 裁剪器输出最大 360×360、圆外透明的 PNG；Android 返回键只取消裁剪。
- 原图从不进入 JS 堆；取消、确认、`active=false` 和卸载都会释放 Native 工作副本。隐藏立即关闭裁剪器并经原 `cancelFileOperation` helper 取消 picker；迟到交付文件仍会删除，不能在设置隐藏后重新打开裁剪层。裁剪器卸载释放自己的 modal 和内部 Blob URL。
- 头像通过 `assistantStore.saveAvatar` 经 IPC 写入 Rust `avatar_service.rs`，以 SHA-256 为内容指纹并将二进制存入 SQLite `avatars` 表。
- 保存成功后由全局 `avatarStore` 统一失效并重读该 owner；页面关闭不会丢失刷新信号，旧异步读取也不能回灌缓存。
- 管理员账号密码用于远程获取表情包库等管理接口的 Basic Auth 鉴权（见 `SyncSettingsSection` 的 `fileKey` 和表情包修复）。
- 已确认的头像保存继续由 assistant/avatar owner 完成，不因页面隐藏反向取消已提交数据。

    │     → Rust 侧优雅关闭本地服务器
    └── emit("save-request")

**权限丢失自愈机制**：

```typescript
const checkPermission = async () => {
  const status = await invoke<{ overlay: boolean }>(
    "plugin:vcp-mobile|check_all_permissions"
  );
  hasOverlayPermission.value = status.overlay;

  // 若权限被手动撤销但开关仍为开启，自动重置
  if (!status.overlay && props.settings.enableAssistant) {
    props.settings.enableAssistant = false;
    await invoke("plugin:vcp-mobile|toggle_floating_ball", { show: false });
  }
};
```

此逻辑在 `onMounted` 和 resume 生命周期事件中均被调用，确保权限被系统撤销后不会出现"开关已开启但悬浮球不显示"的不一致状态。

**Agent 选择器**：

```html
<select v-model="props.settings.assistantAgentId"
        class="bg-transparent text-sm font-semibold opacity-60 ...">
  <option value="">未绑定 (使用默认)</option>
  <option v-for="agent in assistantStore.agents" :key="agent.id"
          :value="agent.id">
    {{ agent.name }}
  </option>
</select>
```

- 依赖 `useAssistantStore` 获取 Agent 列表
- 选择变更时触发 `emit("save-request")`（通过 `watch` 监听 `settings.assistantAgentId`）
- `assistantAgentId` 被 `floatingAssistant` Store 的 `resolveAgentId()` 读取，用于确定浮动窗口对话的目标 Agent
- 空值（`""`）表示使用系统默认 Agent

**关联设置字段**：

| 字段 | 类型 | 持久化 | 说明 |
|------|------|:----:|------|
| `enableAssistant` | `boolean` | SQLite | 浮动助手系统总开关 |
| `assistantAgentId` | `string` | SQLite | 浮动窗口默认绑定的 Agent UUID |

**生命周期恢复**：

```typescript
// AssistantSettingsSection.vue:79
watch(() => lifecycleStore.isBackground, async (newVal) => {
  if (!newVal) {
    // 应用回到前台
    await checkPermission();
    if (props.settings.enableAssistant && hasOverlayPermission.value) {
      await assistantStore.fetchAgents();
      await invoke("plugin:vcp-mobile|toggle_floating_ball", { show: true });
      await invoke("reconcile_local_server_cmd", { enable: true });

```

Android 应用从后台恢复时，自动检查权限状态并恢复悬浮球和本地服务器。这处理了以下场景：
- 用户在系统设置中授权覆盖层权限后切回应用
- 应用被系统杀死后重新启动（前台服务保护范围外的情况）
- 设备从省电模式恢复后重新激活悬浮球

**UI 样式特征**：

- 使用 `divide-y divide-black/5 dark:divide-white/5` 分隔两个设置行
- 悬浮球开关右侧附带金色 `Beta` 标签：`bg-amber-500/15 text-amber-600 border border-amber-500/25`
- Agent 选择器仅在 `enableAssistant === true` 时渲染（条件渲染 `v-if`），未启用时隐藏以减少视觉噪音

**与 Rust 后端的联动**：

| 组件操作 | Rust Command | 效果 |
|----------|-------------|------|
| 开启悬浮球 | `plugin:vcp-mobile\|toggle_floating_ball` (show=true) | Android 原生创建悬浮球 + WebView 准备 |

### 2.6 ConfigBackupSection — 配置备份

区块接收 `active`、`disabled`、`commit` 和 `applyImport`，不再接收活的 AppSettings 草稿。导出等待 commit 后将确定 snapshot 交给 `useConfigBackup.exportConfigBackup`，后者捕获已应用的主题和聊天偏好，按 v2 白名单编码，再调用原生文件导出。

导入仍为 `nativeFilePicker.pickFile('config') → parse_config_backup → 确认 → applyImport`；解析结束的 finally 释放临时文件。确认列出文件实际包含的范围和不可用主题；隐藏作废 operation、取消未交付的原生导入或导出、清除待导入 patch 并卸载确认框。iOS 导出也复用 prepare/reservation/cancel 接纳，关闭发生在 prepare 返回前时不再启动目录选择器。

ConnectionSettingsPage 的 applyImport 冻结输入和动作，先 `settlePending` 等待已请求保存，再提交已验证 patch。成功后只 `acceptImport` 被覆盖的本页连接字段，未被导入的 dirty 保留。失败解冻并保留尚未提交编辑，不用普通 save 替代排空。

v2 在原 16 项身份/连接设置中加入 `topicSummaryModel`，并以 `preferences.theme` 保存主题 key 和 light/dark/system，`preferences.chat` 保存四项聊天偏好。支持 v1/v2，缺项不覆盖，空总结模型保留默认语义；不含开发者模式、更新偏好或头像。SQLite 与 localStorage 分别由原 owner 保存，结果按范围报告，不把部分失败包装为全部成功。

新导出使用 `.vcpcfg.json`，兼容旧 `.vcpcfg`。Android 保存到 Download/VCPMobile 并查询实际 DISPLAY_NAME，导入以该目录为初始位置，默认筛选 JSON/配置类型；“选择旧版或其他文件”可放宽筛选。iOS 首次选择外部备份父目录并持久保存 bookmark，随后在授权内检测/创建 VCPMobile 子目录并协调写入，导入复用同一目录；授权失效才重新选择。所有文件最终仍由 Rust 校验内容、版本与 1 MiB 大小限制。

## 3. 系统维护模块

### 3.1 MaintenanceSection — 维护与清理

源码：`src/features/settings/components/MaintenanceSection.vue`。它接收 `active` / `disabled`，高级页离开保存期间禁止发起新动作；隐藏取消状态清理计时器并忽略迟到状态展示。

| 操作 | 入口 |
|------|------|
| 清理 WebView 缓存 | `clear_webview_cache`，平台文案随 Android/iOS 区分 |
| 刷新现有预渲染缓存 | `overlayStore.openRebuildSession('preRender')`，打开独立任务页 |

二者不保存无关的总结配置。已启动任务不因页面隐藏被宣称取消，实际执行状态仍归原 owner。

### 3.2 RebuildSessionView — 重建会话

**职责一句话**：现有预渲染缓存刷新的独占式执行页面，通过状态机管理 idle → running → completed/error 生命周期。

**源码位置**：`src/features/settings/components/RebuildSessionView.vue`

**状态机**：

```
                    点击"开始重建"
   ┌─────┐        ┌─────────┐
   │idle │ ──────►│ running │◄────────────────────────────┐
   └─────┘        └────┬────┘                             │
                       │                                   │
         ┌─────────────┼────────────────┐                 │
         │             │                │                 │
         ▼             ▼                ▼                 │
   ┌─────────┐   ┌──────────┐    ┌─────────┐            │
   │completed│   │  error   │    │running* │            │
   └────┬────┘   └────┬─────┘    └─────────┘            │
        │             │                                  │

        │                                                  │

**Props**：

```

**各状态 UI 表现**：

| 状态 | 视觉 | 交互限制 |
|------|------|---------|
| `idle` | 播放图标 + “开始刷新”按钮 + 说明文字 | 自由操作 |
| `running` | 进度条（`current/total`）+ 底部提示“刷新进行中 — 请勿退出” | `canDismiss = false`，全局遮罩阻止触摸 |
| `completed` | 绿色文字“预渲染缓存刷新完成” + “完成”按钮 | `canDismiss = true` |
| `error` | 红色文字显示错误信息 + "关闭"按钮 | `canDismiss = true` |

**与 Rust 后端的完整交互链**：

```
startRebuild()  (useRebuildSessionStore.ts)
    │
    └──► invoke('rebuild_all_pre_renders')
           └──► Rust: message_repository.rs
                1. 统计并读取已有 render_cache 对应消息
                2. 并行重新编译 AST 二进制
                3. content_hash 仍匹配时更新 render_cache
                4. emit('render_rebuild_progress', { current, total })
                5. Android 端在命令内部启停前台服务
```

**完成后刷新机制**：
- 刷新成功后 `needsReload = true`。
- 用户点击关闭时，确认现有预渲染缓存已更新。
- 确认后调用 `useDataReload().performFullReload()`：
  1. `clearHtmlCache()` — 清理 AST HTML 渲染缓存
  2. `fetchAgents()` / `fetchGroups()` / `avatarStore.refreshMetadata()` — 刷新实体与头像轻量元数据，hash 变化时定点失效 Blob
  3. `invalidateAllTopicCaches()` — 使话题列表缓存失效
  4. `loadHistoryPaginated()` — 若在当前话题中，重新加载消息及渲染缓存

## 5. 更新与关于模块

### 5.1 UpdateSection — OTA 更新检查

**职责一句话**：查询 GitHub Release 最新版本，管理下载进度与安装触发。

**源码位置**：`src/features/settings/components/UpdateSection.vue`

**自动检查偏好**：`updateStore.autoCheckEnabled` 是只读计算状态，`setAutoCheckEnabled` 先写 `vcp_auto_update_check` 的 `on/off`，成功后发布；失败保持原值并由当前设置入口提示。`useAutoUpdate` 直接读取此 Store。更新 Store 和聊天偏好共用 `core/preferences/localPreference.ts` 的异常捕获 IO，解码规则仍各自保留。iOS 不展示 APK 自动更新入口，继续应用外自签更新说明。

**状态机**（`UpdateStatus` Discriminated Union）：

```ts
type UpdateStatus =
  | { type: 'idle' }
  | { type: 'checking' }
  | { type: 'no-update' }
  | { type: 'update-available'; info: UpdateInfo }
  | { type: 'downloading'; progress: number; total: number | null }
  | { type: 'downloaded' }
  | { type: 'installing' }
  | { type: 'error'; message: string };
```

**状态流转图**：

```
                         点击"检查更新"
    ┌──────────────────────────────────────────────┐
    │                                              │
    ▼                                              │
┌─────────┐      ┌──────────┐                     │
│  idle   │─────►│ checking │                     │
└─────────┘      └────┬─────┘                     │
                      │                           │
         ┌────────────┼────────────┐              │
         ▼            ▼            ▼              │
    ┌─────────┐  ┌─────────────┐  ┌──────┐       │
    │no-update│  │update-avail │  │ error│       │
    └────┬────┘  └──────┬──────┘  └──┬───┘       │
         │              │            │           │
         │         点击"下载并安装"   │           │
         │              │            │           │
    4s后自动           ▼            │           │
    回到 idle    ┌───────────┐      │           │
                 │downloading│      │           │
                 └─────┬─────┘      │           │
                       │            │           │
                       ▼            │           │
                 ┌───────────┐      │           │
                 │installing │◄─────┘           │
                 └─────┬─────┘                  │
                       │                        │
                       ▼                        │
                 回到 idle ◄────────────────────┘
```

**核心流程详解**：

**1. 检查更新**：
```ts
const status: UpdateStatus = await updateStore.check();
```
- 状态唯一持有者是 Rust `UpdateSession`，前端 store 只做镜像：
  订阅 `vcp-update://status` 事件 + `get_update_status` 补拉
- Rust 请求 `api.github.com/repos/MRiecy/VCPMobile/releases/latest`
  （404 时降级 `/releases?per_page=1`）
- APK 资产按 `ends_with("arm64-v8a.apk")` 选择，`.apk.sha256` 旁车文件不会误命中
- 必须存在同名 `.sha256` 旁车文件（`sha256sum` 标准格式），缺失或畸形即报错
- 本地已有完整包且 SHA-256 匹配时直接进入 `readyToInstall`，不重复下载

**2. 下载并安装**：
```ts
await useUpdateDownloader().downloadAndInstall();
```
- `start_update_download` 不接受任何参数——URL 只来自 Rust 验证过的 GitHub API 响应
- Range 断点续传（保留 `.part`），单 chunk 停滞 30s 判死，指数退避最多 3 次
- 下载完成后流式 SHA-256 校验，不匹配则删除并可重试
- 下载期间 Rust 侧持有 ForegroundGuardian OTA 前台锁（`PRIORITY_OTA = 50`）
- 前端监听 store 进度，300ms 节流更新系统通知栏
- `install_update` 依次检查「安装未知应用」权限与签名证书连续性
  （APK 与自签名 SHA-256 比对），通过后触发 Android 系统安装器

**3. 降级策略**：
若应用内链路失败，弹窗提供「Release 页面」按钮：
- `openUrl(info.releasePageUrl)` — 浏览器打开 Release 页面手动下载

**UI 反馈矩阵**：

| 状态（`status.state`） | UI 表现 |
|------|---------|
| `checking` | 按钮 loading / "正在检查最新版本..." |
| `idle`（无更新） | success 提示当前版本号，4s 后自动消失 |
| `available` | 弹窗展示版本号（等宽字体）、APK 大小、Release Notes |
| `downloading` | 进度条 + 百分比 + 已下载/总大小，可取消下载或最小化弹窗 |
| `verifying` | 进度条满格 + "SHA-256 校验中" |
| `readyToInstall` | 设置行显示「已就绪，点击安装」 |
| `installing` | "正在拉起安装器..." |
| `failed` / 带 `error` | 错误框显示 `error.stage` 与信息；install 阶段提供「前往系统授权设置」 |

**3D Logo 交互逻辑详解**：

该组件实现了完整的 3D 视差 + 动画序列系统：

**1. 跟手模式（用户触摸/鼠标移动）**：
```ts
const handleMove = (e: MouseEvent | TouchEvent) => {
  animSessionId++;  // 打断任何正在进行的序列
  isMixing.value = true;
  transitionStyle.value = 'none';  // 0 延迟，极致跟手
  
  // 计算相对中心点的偏移
  const targetRotY = ((x - centerX) / centerX) * 150;
  const targetRotX = ((centerY - y) / centerY) * 80;
  
  // 硬限幅防止万向锁
  rotation.value.y = Math.max(-180, Math.min(180, targetRotY));
  rotation.value.x = Math.max(-90, Math.min(90, targetRotX));
  
  // 更新光晕位置
  glowPos.value = { x: (x / width) * 100, y: (y / height) * 100 };
};
```

**2. 自动动画序列（按下后 800ms 启动）**：
按下触发 8 段 CSS 变换序列：
- 向右缓慢旋转翻面（0→180°Y，2s）
- 向左缓慢旋转复原（180→0°Y，2s）
- 向左旋转 75° 展现左侧（1.2s）
- 快速向右翻转 75° 展现右侧（0.6s）
- 快速复原 + 扭动（0.4s + 3 次 100ms 微扭）
- 上下翻转 360° + 落地抖动（0.8s + 4 次修正）

通过 `animSessionId` 自增实现打断机制：用户再次触摸时立即取消序列，回归跟手模式。

## 9. 设计决策与注意事项

1. **页面字段会话**：
   每页只投影显式字段，通过 edit 记录用户 revision；新快照重基 clean 字段，dirty/pending 字段保留本地意图。SettingsView 不持有业务草稿；保存和动作通过可等待接口衔接。

2. **插件中心单入口**：
   全局设置不加载分布式连接状态或工具授权。`distributed*` 字段仍由通用设置持久化和配置备份承载，但编辑与运行态展示只在插件中心发生。

3. **RebuildSessionView 的独占式设计**：
   重建操作使用独立的 `SlidePage` 页面栈项（而非内联在 `MaintenanceSection` 中），是因为重建过程可能持续数分钟，需要阻止用户离开（`canDismiss = false` + 全局遮罩），且完成后可能触发全量数据重载，需要占据用户全部注意力。

4. **AboutSection 的深色/亮色深度覆盖**：
   关于页面使用 `WebGLFluidBackground` 作为全屏动态背景，其颜色与主题无关。因此该组件通过 `<style scoped>` 中的 `:deep()` 选择器，对子组件（`SettingsCard`、`SettingsRow`、`SettingsInlineStatus`、`SettingsActionButton`）进行深度样式覆盖，确保在亮色模式下文字可读、卡片有半透明毛玻璃质感。这是项目中少数允许深度选择器覆盖的场景。

5. **SyncLogBrowserCore 的亮色缺失**：
   该组件当前仅针对深色场景设计（固定 `text-white/70` 等色值）。若未来需要在亮色设置页中复用，需补充 CSS 变量适配或使用 `text-primary-text` 等语义化颜色类。

6. **UpdateSection 的状态机与降级**：
   更新状态由 Rust `UpdateSession` 唯一持有并经事件广播，前端只镜像；下载失败保留 `.part` 可续传重试，安装权限/签名问题按 `error.stage` 给出引导，最终兜底是打开 Release 页面手动下载。

7. **头像的有界内存处理**：
   Android 原生层先将外部 URI 流式 staging，并通过 `inJustDecodeBounds + inSampleSize` 生成最长边 1120px 的 EXIF 归一化 WebP；WebView 只裁剪该工作副本。最终圆形 PNG 在业务层保持为 `Uint8Array`，但 Tauri 对嵌套 IPC 参数仍会转成 `number[]` JSON；由于输出被限制在最大 360×360，该段峰值有界。启动/同步只批量拉取头像 hash/颜色/时间戳，二进制在进入视口前 300px 时按需读取、全局最多 2 路并发，并受 50 项 LRU 约束；离开预加载区的组件卸载 `<img>` 以释放解码位图。

8. **MaintenanceSection 的状态隔离**：
   清缓存状态属于区块，预渲染刷新属于独立 rebuildSession。页面冻结时两种新动作都禁止；既有任务的完成与页面可见性分别处理。

9. **SettingsTextField 的安全遮罩策略**：
    使用 `-webkit-text-security: disc` 而非 `<input type="password">`，是因为后者在移动端会自动触发键盘的"密码建议"和"自动填充"行为，干扰 API Key 等人工输入场景。`-webkit-text-security` 仅做视觉遮罩，不影响输入法行为。

10. **AssistantSettingsSection 的历史权限自愈与生命周期恢复（DORMANT ASSET）**：
    该组件已从 `SettingsView` 生产入口移除，悬浮命令、local-server handler 与 `SYSTEM_ALERT_WINDOW` 也已注销。以下仅记录未来可能复用的历史交互设计：
    覆盖层权限（`SYSTEM_ALERT_WINDOW`）可被用户在系统设置中随时撤销。`AssistantSettingsSection` 通过双重保障维持状态一致性：(a) `checkPermission()` 在 `onMounted` 时检测权限并重置不一致的 UI 开关状态；(b) 监听 `useAppLifecycleStore().isBackground` 在应用切前台时重新验证并恢复悬浮球。这确保用户不会遇到"开关开启但悬浮球消失"的困惑状态。
    该组件同时管理 `reconcile_local_server_cmd`——本地服务器的生命周期严格跟随悬浮球开关，避免空闲时占用端口 14202。
