# 16. 设置子模块详解

## 1. 概述

### 1.1 领域定位

`features/settings/components/` 是 VCP Mobile 前端**全局设置中心**的原子 UI 单元集合。该目录下的 12 个 Vue 组件各自对应 `SettingsView` 中的一个功能子域，负责将用户输入转化为对 `settingsStore` 的写操作，或通过 Tauri IPC 触发 Rust 后端的维护/查询命令。

这些组件全部作为 **SettingsView 的子页面插槽**被引用，不独立存在于路由系统中。其设计严格遵循项目"高密度线性布局"美学宪法：列表重于卡片、灰度优先、2px 高亮侧边条反馈、内敛交互（`active:scale-95` 为主）。

设置子模块不涉及任何聊天业务逻辑，其职责边界清晰限定为：
- **配置读写**：用户身份、服务器连接、同步参数、主题等持久化配置
- **维护操作**：附件 GC、缓存清理、预渲染重建等低频但关键的后台任务
- **信息展示**：版本号、开源协议、电池优化引导、同步日志浏览

### 1.4 核心设计原则

1. **设置副本模式**：`SettingsView` 维护打开基线与本地编辑副本，子组件通过 `v-model` 绑定。用户点击“返回”时对二者做 diff，再调用 `settingsStore.updateSettings(patch)`，避免频繁写盘及旧快照覆盖并发更新。
2. **操作即命令**：维护类操作（GC、缓存清理、重建）不修改设置副本，而是直接通过 `invoke` 调用 Rust Command，操作结果通过原子组件 `SettingsActionWithStatus` 回显。
3. **状态机隔离**：重建会话（`RebuildSessionView`）拥有独立的状态机（`idle | running | completed | error`），不耦合于 `settingsStore`，由 `useRebuildSessionStore` 统一管理。
4. **屏幕常亮守护**：所有可能长时间运行的维护操作（重建、GC）均通过 `withScreenKeep()` 包裹，防止 Android 息屏中断导致任务失败。
5. **前后台生命周期感知**：重建操作前后显式调用 `start_streaming_service` / `stop_streaming_service`，确保 Android 不会在后台中断长时间任务。

### 1.5 主题子页的直接组件边界

主题页不是 `features/settings/components/` 下的 Rust 设置 Section。`SettingsView` 直接挂载 `ThemePicker.vue`，并把 theme 子页设为 `overflow-hidden flex min-h-0`；`ThemePicker` 自己拥有唯一纵向滚动、横向 snap rail、主题草稿与确认。无状态 `ThemeLivePreview.vue` 只渲染候选 dark/light 局部变量。

主题确认区之后还有“气泡 / 统一 / 刊物”消息呈现第二入口。它直接调用 `themeStore.setPresentationMode` 并立即持久化，与 `settingsStore` 副本和主题草稿都不构成同一事务。

## 2. 核心设置模块

### 2.1 VcpCoreSettingsSection — VCP 核心配置

**职责一句话**：配置 VCP 后端 HTTP/HTTPS 接入点、WebSocket 日志通道及其鉴权密钥，并提供连接健康检查能力。

**源码位置**：`src/features/settings/components/VcpCoreSettingsSection.vue`

**Props**：

```ts
defineProps<{
  settings: AppSettings;
}>();

// Emit: save-request (触发父级先持久化当前输入)
defineEmits<{
  (e: 'save-request'): void;
}>();
```

**包含的表单字段**：

| 字段 | 组件 | 绑定字段 | 类型修饰 | 说明 |
|------|------|---------|---------|------|
| Chat 服务器 URL | `SettingsTextField` | `settings.vcpServerUrl` | — | 保存用户原始 HTTP/HTTPS 输入，不在前端改写 |
| Chat 请求入口 | 三项单选 | `settings.chatEndpointMode` | `standard` / `vcpTools` / `raw` | 标准 Chat、VCP 增强 Chat、原始完整 URL |
| API Key | `SettingsTextField` | `settings.vcpApiKey` | `isSecure` | 鉴权密钥，支持显隐切换 |
| VCP WebSocket URL | `SettingsTextField` | `settings.vcpLogUrl` | `mono` | 日志流地址，如 `ws://localhost:6005` |
| VCP WebSocket Key | `SettingsTextField` | `settings.vcpLogKey` | `isSecure` + `mono` | WebSocket 鉴权 Key |

**连接测试流程**：

1. URL 或入口模式变化时，组件调用 `preview_chat_endpoint`，展示 Rust resolver 计算的最终请求 URL；前端不实现第二套拼接算法。
2. 用户点击“检查模型发现”按钮。
3. 组件先 `emit('save-request')`，父级计算基线 diff 并通过 `update_settings` 合并当前输入。
4. 调用 `invoke('test_vcp_connection', { vcpUrl, vcpApiKey, chatEndpointMode })`。
5. Rust 侧复用中央 EndpointResolver：
   - 保留代理前缀、显式端口与 query，派生 `/v1/models`
   - Raw 任意端点无法安全推导时返回“模型发现不可用”，不误报 Chat 失败
   - 携带 `Authorization: Bearer {apiKey}` 请求头
   - 10 秒超时
6. 返回 `{ success, status, modelCount, models, modelDiscoveryAvailable }`。
7. 前端通过 `vcpPingStatus` 响应式对象驱动 `SettingsActionWithStatus` 回显结果。

**关键交互细节**：
- 测试前若 URL 为空，直接本地报错，不发起 IPC，减少无效网络开销。
- 状态文案示例：
  - `loading`: “正在检查模型列表...”
  - `success`: "连接成功！拉取到 42 个可用模型"
  - `error`: "验证失败, HTTP 状态码: 401" / 原始异常字符串
- 使用了 `status-multiline` 属性，错误信息允许换行显示。

**样式特征**：字段间使用 `space-y-5` 垂直分布，组间以 `border-t border-black/5 dark:border-white/5` 细线分隔，保持视觉呼吸感。

| 字段/操作 | 组件 | 绑定/触发 | 修饰符 | 说明 |
|-----------|------|----------|--------|------|

**表情包修复库流程**：

```
用户点击 REFRESH 按钮
    │
    ▼
emoticonStatus = { type: 'loading', message: '正在从远程服务器获取...' }
    │
    ▼
invoke('regenerate_emoticon_library')
    │
    └──► Rust: emoticon_manager.rs
         ├── 远程获取表情包 JSON 索引
         ├── 本地 SQLite upsert 表情元数据
         └── 返回: number (表情总数)
    │
    ▼
emoticonStatus = { type: 'success', message: '同步成功：共计 156 个表情' }
    │
    └──► 3s 后自动清空状态
```

**全量神经同步入口**：
- 不直接发起 IPC，而是调用 `overlayStore.openSyncSession()`。
- 该操作会将 `syncSession` 类型推入 `overlayStore.pageStack`，打开独立的同步会话面板。
- 同步会话面板内部包含 `SyncLogBrowserCore` 组件用于浏览历史日志。

### 2.4 UserProfileSection — 用户资料

**职责一句话**：管理本地用户身份标识（头像、用户名）及管理员接口鉴权凭据。

**源码位置**：`src/features/settings/components/UserProfileSection.vue`

**Props**：

```ts
defineProps<{
  settings: AppSettings;
}>();
```

**包含的表单字段与交互**：

| 字段 | 组件 | 绑定字段 | 修饰符 | 说明 |
|------|------|---------|--------|------|
| 头像 | `VcpAvatar` + `AvatarCropper` | — | `owner-type="user"` | 点击触发文件选择 → 裁剪器 → Blob IPC |
| 用户名 | `SettingsTextField` | `settings.userName` | — | 本地显示名称 |
| 管理员账号 | `SettingsTextField` | `settings.adminUsername` | `mono` | Basic Auth 用户名 |
| 管理员密码 | `SettingsTextField` | `settings.adminPassword` | `isSecure` + `mono` | Basic Auth 密码 |

**头像上传完整时序**：

```
用户点击头像区域
    │
    ▼
调用 pickFile("avatar")，打开 Android 系统图片选择器
    │
    ▼
Native 64 KiB 流式 staging
    ├── 读取尺寸但不分配全尺寸 Bitmap
    ├── EXIF 方向归一化
    ├── inSampleSize 采样至最长边 1120px WebP
    └── 返回受控临时路径
    │
    ▼
convertFileSrc(path) → <AvatarCropper :img="cropImg" />
    │
    ▼
用户在裁剪器中确认
    │
    ▼
onCropConfirm(blob: Blob)
    ├── isCropping = false
    ├── const arrayBuffer = await blob.arrayBuffer()
    ├── const bytes = new Uint8Array(arrayBuffer)
    ├── await assistantStore.saveAvatar(
    │     "user",           // ownerType
    │     "user_avatar",    // ownerId
    │     blob.type,        // mimeType
    │     bytes             // 业务层保持 Uint8Array；Tauri 内部转为 number[] JSON
    │   )
    └── assistantStore 内部调用 avatarStore.refreshAvatar("user", "user_avatar", hash)
```

**关键点**：
- 裁剪器输出最大 360×360、圆外透明的 PNG；Android 返回键只取消裁剪。
- 原图从不进入 JS 堆；取消、确认和组件卸载都会删除 1120px Native 工作副本，并回收裁剪器内部 Blob URL。
- 头像通过 `assistantStore.saveAvatar` 经 IPC 写入 Rust `avatar_service.rs`，以 SHA-256 为内容指纹并将二进制存入 SQLite `avatars` 表。
- 保存成功后由全局 `avatarStore` 统一失效并重读该 owner；页面关闭不会丢失刷新信号，旧异步读取也不能回灌缓存。
- 管理员账号密码用于远程获取表情包库等管理接口的 Basic Auth 鉴权（见 `SyncSettingsSection` 的 `fileKey` 和表情包修复）。
- 卡片使用 `SettingsCard variant="glass"`，在亮色主题下呈现半透明白色毛玻璃质感。

```typescript
  );
  hasOverlayPermission.value = status.overlay;

  // 若权限被手动撤销但开关仍为开启，自动重置
  if (!status.overlay && props.settings.enableAssistant) {
    props.settings.enableAssistant = false;
    await invoke("plugin:vcp-mobile|toggle_floating_ball", { show: false });
  }
};
```

此逻辑在 `onMounted` 和 resume 生命周期事件中均被调用，确保权限被系统撤销后不会出现"开关已开启但悬浮球不显示"的不一致状态。

**核心流程详解**：

**1. 检查更新**：
```ts
const status: UpdateStatus = await updateStore.check();
```
- 状态唯一持有者是 Rust `UpdateSession`，前端 store 只做镜像：
  订阅 `vcp-update://status` 事件 + `get_update_status` 补拉
- Rust 请求 `api.github.com/repos/MRiecy/VCPMobile/releases/latest`
  （404 时降级 `/releases?per_page=1`）
- APK 资产按 `ends_with("arm64-v8a.apk")` 选择，`.apk.sha256` 旁车文件不会误命中
- 必须存在同名 `.sha256` 旁车文件（`sha256sum` 标准格式），缺失或畸形即报错
- 本地已有完整包且 SHA-256 匹配时直接进入 `readyToInstall`，不重复下载

**2. 下载并安装**：
```ts
await useUpdateDownloader().downloadAndInstall();
```
- `start_update_download` 不接受任何参数——URL 只来自 Rust 验证过的 GitHub API 响应
- Range 断点续传（保留 `.part`），单 chunk 停滞 30s 判死，指数退避最多 3 次
- 下载完成后流式 SHA-256 校验，不匹配则删除并可重试
- 下载期间 Rust 侧持有 ForegroundGuardian OTA 前台锁（`PRIORITY_OTA = 50`）
- 前端监听 store 进度，300ms 节流更新系统通知栏
- `install_update` 依次检查「安装未知应用」权限与签名证书连续性
  （APK 与自签名 SHA-256 比对），通过后触发 Android 系统安装器

**3. 降级策略**：
若应用内链路失败，弹窗提供「Release 页面」按钮：
- `openUrl(info.releasePageUrl)` — 浏览器打开 Release 页面手动下载

| `checking` | 按钮 loading / "正在检查最新版本..." |

```ts
  const targetRotX = ((centerY - y) / centerY) * 80;
  
  // 硬限幅防止万向锁
  rotation.value.y = Math.max(-180, Math.min(180, targetRotY));
  rotation.value.x = Math.max(-90, Math.min(90, targetRotX));
  
  // 更新光晕位置
  glowPos.value = { x: (x / width) * 100, y: (y / height) * 100 };
};
```

**2. 自动动画序列（按下后 800ms 启动）**：
按下触发 8 段 CSS 变换序列：
- 向右缓慢旋转翻面（0→180°Y，2s）
- 向左缓慢旋转复原（180→0°Y，2s）
- 向左旋转 75° 展现左侧（1.2s）
- 快速向右翻转 75° 展现右侧（0.6s）
- 快速复原 + 扭动（0.4s + 3 次 100ms 微扭）
- 上下翻转 360° + 落地抖动（0.8s + 4 次修正）

通过 `animSessionId` 自增实现打断机制：用户再次触摸时立即取消序列，回归跟手模式。

### 6.4 与 UnoCSS 快捷类的配合

原子组件大量依赖 UnoCSS 原子类，同时也有少量自定义语义化类名（用于 `:deep()` 覆盖和 Scoped CSS）。典型配合模式：

```vue
<!-- SettingsTextField 内部 -->
<input class="w-full bg-black/5 dark:bg-white/5 p-3.5 rounded-2xl 
  outline-none border transition-all duration-200
  focus:border-blue-500/50 focus:bg-black/10 dark:focus:bg-white/10" />

<!-- SettingsCard 内部 -->
<div class="settings-card overflow-hidden transition-all duration-300
  border rounded-2xl shadow-sm px-3 py-4" />
```

组件内部不使用 UnoCSS 快捷类（如 `glass-panel`、`card`、`btn`），而是显式写出完整原子类。原因：
1. 设置组件需要精确控制每一个 Tailwind 原子类的响应式行为
2. 深色/亮色模式的 `dark:` 前缀需要显式声明，快捷类无法覆盖所有状态组合
3. `:deep()` 覆盖时需要匹配具体类名，快捷类的组合类会增加选择器复杂度

## 9. 设计决策与注意事项

1. **设置副本 vs 直接绑定 Store**：
   `SettingsView` 不直接让子组件 `v-model` 绑定 `settingsStore.settings`，而是维护本地编辑副本与打开基线。原因：避免输入时频繁持久化，并在点击“返回”时只提交实际 Patch。这样既保留批量编辑体验，也不会用页面打开时的旧全量对象覆盖其他模块的新值。

2. **AiLogicSettingsSection 的占位策略**：
   该组件在 `v0.9.14` 中仅渲染两个"暂未启用"行。Agent 级别的 Temperature / Max Tokens 配置目前仍由桌面端 `config.env` 控制，移动端尚未实现全局覆盖逻辑。保留该组件是为了 UI 架构的完整性，避免未来新增字段时破坏布局或需要重构路由分类。

3. **RebuildSessionView 的独占式设计**：
   重建操作使用独立的 `SlidePage` 页面栈项（而非内联在 `MaintenanceSection` 中），是因为重建过程可能持续数分钟，需要阻止用户离开（`canDismiss = false` + 全局遮罩），且完成后可能触发全量数据重载，需要占据用户全部注意力。

4. **AboutSection 的深色/亮色深度覆盖**：
   关于页面使用 `WebGLFluidBackground` 作为全屏动态背景，其颜色与主题无关。因此该组件通过 `<style scoped>` 中的 `:deep()` 选择器，对子组件（`SettingsCard`、`SettingsRow`、`SettingsInlineStatus`、`SettingsActionButton`）进行深度样式覆盖，确保在亮色模式下文字可读、卡片有半透明毛玻璃质感。这是项目中少数允许深度选择器覆盖的场景。

5. **SyncLogBrowserCore 的亮色缺失**：
   该组件当前仅针对深色场景设计（固定 `text-white/70` 等色值）。若未来需要在亮色设置页中复用，需补充 CSS 变量适配或使用 `text-primary-text` 等语义化颜色类。

6. **UpdateSection 的状态机与降级**：
   更新状态由 Rust `UpdateSession` 唯一持有并经事件广播，前端只镜像；下载失败保留 `.part` 可续传重试，安装权限/签名问题按 `error.stage` 给出引导，最终兜底是打开 Release 页面手动下载。

7. **头像的有界内存处理**：
   Android 原生层先将外部 URI 流式 staging，并通过 `inJustDecodeBounds + inSampleSize` 生成最长边 1120px 的 EXIF 归一化 WebP；WebView 只裁剪该工作副本。最终圆形 PNG 在业务层保持为 `Uint8Array`，但 Tauri 对嵌套 IPC 参数仍会转成 `number[]` JSON；由于输出被限制在最大 360×360，该段峰值有界。启动/同步只批量拉取头像 hash/颜色/时间戳，二进制在进入视口前 300px 时按需读取、全局最多 2 路并发，并受 50 项 LRU 约束；离开预加载区的组件卸载 `<img>` 以释放解码位图。

8. **MaintenanceSection 的状态隔离**：
   每个维护操作拥有独立的 `ref` 状态对象（`gcStatus`、`cacheStatus`），而非共享一个全局状态。这种设计允许用户同时触发多个操作（虽然 UI 上通常不会这么做），且错误信息不会互相覆盖。

9. **BatteryOptimizationGuide 的纯前端实现**：
   该组件完全基于 `navigator.userAgent` 字符串匹配，不调用任何 Rust Command。其数据（品牌、步骤）硬编码于组件内部，因为 OEM 电池优化路径通常随系统版本变化缓慢，无需后端动态配置。

10. **SettingsTextField 的安全遮罩策略**：
    使用 `-webkit-text-security: disc` 而非 `<input type="password">`，是因为后者在移动端会自动触发键盘的"密码建议"和"自动填充"行为，干扰 API Key 等人工输入场景。`-webkit-text-security` 仅做视觉遮罩，不影响输入法行为。

11. **AssistantSettingsSection 的历史权限自愈与生命周期恢复（DORMANT ASSET）**：
    该组件已从 `SettingsView` 生产入口移除，悬浮命令、local-server handler 与 `SYSTEM_ALERT_WINDOW` 也已注销。以下仅记录未来可能复用的历史交互设计：
    覆盖层权限（`SYSTEM_ALERT_WINDOW`）可被用户在系统设置中随时撤销。`AssistantSettingsSection` 通过双重保障维持状态一致性：(a) `checkPermission()` 在 `onMounted` 时检测权限并重置不一致的 UI 开关状态；(b) 监听 `useAppLifecycleStore().isBackground` 在应用切前台时重新验证并恢复悬浮球。这确保用户不会遇到"开关开启但悬浮球消失"的困惑状态。
    该组件同时管理 `reconcile_local_server_cmd`——本地服务器的生命周期严格跟随悬浮球开关，避免空闲时占用端口 14202。
