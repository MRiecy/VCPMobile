# 25｜日记中心远端服务

## 1. 边界与数据流

`src-tauri/src/vcp_modules/diary/` 是独立远端文件领域，不复用聊天消息中的 `DiaryBlock`，也不把日记写入移动端 SQLite 或 Sync V2。

```text
Vue diaryStore
  -> 普通 Tauri command
  -> DiaryServiceState
     -> Basic Auth: {VCP base}/admin_api/dailynotes/*
     -> Bearer:     {VCP base}/v1/human/tool
  <- typed DTO / DIARY_* stable error
```

远端 VCP 服务是文件事实源；Rust 负责配置快照、认证、URL 与路径校验、响应预算、schema 归一化、hash 冲突和 mutation 核验。Diary commands 的参数、返回值与日志均不携带 Basic/Bearer 凭据。管理员凭据仍由既有全局设置页维护，这不属于 Diary DTO。

## 2. 状态所有权

`DiaryServiceState` 只持有四类进程内基础设施：

- 一个禁止 redirect、10 秒 connect timeout 的 `reqwest::Client`；
- 一个覆盖完整 read-before/write/read-back 的全局 mutation mutex；
- 普通搜索与 LightMemo 各一个固定 owner slot；
- 最近一次 mutation 时间，用于“语义索引可能追平中”的提示。

搜索 owner 使用 `generation + requestId + CancellationToken + finished`。新 owner 先取消旧 owner并有界等待退出；旧 finalizer 只能清理自己，不能删除新 owner。实现不创建无界 request map。

## 3. Commands

| Command | 后端能力 |
|---|---|
| `diary_list_folders` | 文件夹列表 |
| `diary_list_notes` | 单目录文件摘要 |
| `diary_get_note` | 正文与 SHA-256 |
| `diary_search` / `diary_cancel_search` | 普通全文搜索与取消 |
| `diary_semantic_search` / `diary_cancel_semantic_search` | LightMemo 文件级语义结果与取消 |
| `diary_save_note` | baseline 检查、写入、读回核验 |
| `diary_rename_note` | 写目标、读回、删源的可恢复 transaction |
| `diary_create_note` | DailyNote Human Tool 创建并返回实际 key |
| `diary_move_notes` | 逐项移动结果 |
| `diary_delete_notes` | 逐项删除结果 |
| `diary_delete_empty_folder` | 仅删除服务端确认的空目录 |

这些命令在 `src-tauri/src/lib.rs` 注册，是普通 Tauri commands；不得加入 Android 插件的 `build.rs`、permissions 或 guest-js。

## 4. 安全与资源预算

- URL 仅接受无 userinfo 的 HTTP(S)，移除 query/fragment，只剥离末尾 `/v1/chat/completions`，保留反向代理前缀；
- folder/file 必须是单一路径段，拒绝空值、`.`、`..`、斜杠、反斜杠、盘符与控制字符；
- redirect 全部拒绝，避免凭据随跳转传播；
- 响应同时检查声明长度和流式实际累计长度；
- 正文解码后不超过 2 MiB，列表/搜索 JSON 不超过 8 MiB，错误正文不超过 64 KiB；
- Human Tool 使用官方 `「始ESCAPE」...「末ESCAPE」` 字段边界，并转义外层 Tool marker；大小写、`「」`/`{}` 混合括号及兼容 `EXP` 拼写的保留 sentinel 全部 fail closed，防止提前闭合字段；
- 远端错误只映射为有界安全摘要；Human Tool 插件错误不回传原文，疑似路径、URL 或认证材料的管理端摘要也被丢弃；日志不记录 Authorization、正文、密码或完整 URL query。

## 5. 写入结果语义

保存不是 blind overwrite：先读取远端 hash，与 baseline 比较，再 POST 并读回。网络超时、传输中断、2xx 畸形/超限响应或 5xx 后也只读回分类，不自动重试写入：

- 读回等于候选 hash：`verified=true`；
- 远端仍是 baseline：`DIARY_SAVE_UNCERTAIN`；
- 远端成为第三个版本：`DIARY_CONFLICT`；
- 无法读回：`DIARY_SAVE_UNCERTAIN`。

重命名在当前服务端无原子端点时采用“目标不存在探测 → 写目标 → hash 核验 → 删除源”。目标重名先拒绝；源删除失败或结果不确定时返回 `copied_source_retained`，按“新文件已验证、旧文件可能仍存在”处理，不宣称原子成功。

移动和删除保留逐项 `succeeded/errors`，HTTP 2xx 不会被提升为笼统的全成功。

DailyNote 创建无法通过预先计算的 key 做幂等重试。若传输/超时导致响应丢失，或 2xx 回执畸形、超限、缺少最终 key，后端返回 `DIARY_CREATE_UNCERTAIN`。Composer 保留输入并禁止原地直接重试，用户需先返回目标文件夹刷新核对，以避免生成重复日记。若插件明确返回结构化失败，则使用脱敏的 `DIARY_TOOL_ERROR`，允许用户修正输入后重试。

## 6. 测试

专项测试物理位于 `src-tauri/tests/unit/diary_service_tests.rs`，由生产模块在 `#[cfg(test)]` 下按路径挂载，因此既可访问私有纯逻辑，又不把测试正文放进业务源码。执行：

```text
cargo test --manifest-path src-tauri/Cargo.toml --locked --lib diary::diary_service::tests
```

覆盖：

- URL 前缀、Basic/Bearer 分流与 redirect 拒绝；
- 声明长度、无 `Content-Length` 实际流式超限、总超时与畸形 JSON；
- Tool ESCAPE 变体注入、DailyNote 嵌套/不确定 outcome、LightMemo 文件折叠与稳定排序；
- 普通/语义搜索 owner 取消和旧 finalizer；
- 搜索管理员配置 fail-closed；
- 保存 baseline/force/read-back 与 2xx 畸形回执、批量 wire/partial outcome、重命名完整/目标重名/删除源失败的 partial outcome。

部署联调仍需使用脱敏 fixture 验证实际 VCP 版本的成功/错误 JSON、索引追平时延和 Unicode 文件样本；测试不得保存真实凭据或私人日记。
