# 06_设置管理系统 (Settings Manager)

## 1. 概述

### 1.1 模块定位

`settings_manager.rs` 管理 SQLite 中的用户身份、连接、同步、分布式、对话辅助、语音、JEV 和排序配置。它提供一个持久化 owner、一份不可变配置快照，以及提交后的运行时通知。主题、聊天呈现、更新偏好等 localStorage 数据仍由前端各自的 Store 管理，不属于本模块。

### 1.2 源码导航

| 文件 | 职责 |
|------|------|
| `infra/settings_manager.rs` | IPC、Rust 读取入口、提交事件与运行时连接协调 |
| `infra/settings_manager/types.rs` | 九个领域、唯一默认值、枚举、IPC DTO 与字段描述类型 |
| `infra/settings_manager/schema.rs` | 从类型默认结构定义字段约束、完整/部分规范化、备份资格与生效时机 |
| `infra/settings_manager/repository.rs` | SQLite 规范化读写、版本冲突、缓存发布和取消边界 |
| `infra/settings_manager/migration.rs` | 旧 `settings/global` 的一次性搬运 |
| `infra/settings_manager/backup.rs` | v2 备份解析与可导出字段投影 |
| `migrations/0103_config_domains.sql` | 领域、恢复归档、搬运元数据三张表 |
| `crates/config-export/` | host 开发期契约导出工具，不启动应用或访问用户配置 |

### 1.3 调用方向

```text
Vue 编辑会话 → settingsStore → read_settings / update_settings
                                     ↓
                         SettingsState / repository
                          ↓                    ↓
                DbState 写事务           已提交快照
                                               ├→ Rust 业务读取
                                               ├→ vcp-config-changed
                                               └→ 日志/分布式协调
```

### 1.4 核心边界

- 类型、默认值与校验语义归 Rust；Vue 负责文案、布局和交互。
- 每领域一行 JSON，一次请求可以在一个事务中修改多个领域。
- 冷加载与保存统一规范为当前类型；坏叶、坏组使用默认值，合法兄弟保留，未知内容丢弃并持久化。
- 提交、缓存发布与提交后 hook 由同一持久任务完成，调用方离开不截断已接纳保存。
- 配置已保存和远程连接成功分别报告；网络协调锁不阻塞配置保存。

## 2. Settings 结构体字段详解

### 2.1 领域总览

`Settings` 使用嵌套类型，序列化键仍为 camelCase。下面是实际 JSON 路径，不再是旧的顶层字段：

| 领域 | Rust 类型 | 主要内容 |
|------|-----------|----------|
| `identity` | `IdentityConfig` | `userName` |
| `server` | `ServerConfig` | `url`、`apiKey`、`endpointMode`、管理员凭据、`fileKey` |
| `log` | `LogConfig` | VCPLog / VCPInfo 共用 `url` 与 `key` |
| `sync` | `SyncConfig` | `serverUrl`、`httpUrl`、`token`、`logLevel`、`prerenderEnabled` |
| `distributed` | `DistributedConfig` | 启用状态、WebSocket 地址、密钥与设备名 |
| `conversation` | `ConversationConfig` | `topicSummaryModel` |
| `voice` | `VoiceConfig` | `connection`、`asr`、`tts`、`guidance`、`vad` 五个子结构 |
| `jev` | `JevConfig` | 官方与 OpenRouter 分别存连接、Key、模型；共享超时、重试、代理与应用标识 |
| `navigation` | `NavigationConfig` | `agentOrder`、`groupOrder` |

语音子结构共用一个领域版本和存储行；校验按叶字段及关联组隔离。TTS 模式仅为 `builtin`、`clone`，默认 `builtin`；预制音色仅包含官方选项，默认 `voice: "冰糖"`。只有复刻音色以空 `cloneSampleId` 表示“无”，不增加第三种模式。声音库位于 `app_data_dir/voice_library`，配置只保存 `voice.tts.cloneSampleId`；删除声音资产不级联改写该字段，失效引用在使用时解析为“无”。Agent 的独立音色保存在 `agents.voice_config`，不属于全局配置领域；关闭独立音色时读取当前已保存的全局配置，不读取 Rust 初始默认值。

`currentThemeMode` 与 `set_theme` 已移除；真正主题仍归 localStorage。`lastAutomaticMaintenance` 不再是用户配置，维护模块使用原 `settings` 表中的 `last_automatic_maintenance` 独立记录。

### 2.2 默认值与字段规则

每个领域通过同一 `Default` 定义新安装、缺字段和异常值的默认值。`schema.rs` 遍历这些类型默认值产生叶字段清单，再补充枚举选项、数值/长度范围、`required`、`secret`、`backup`、`validationGroup` 与 `effect`。

存储和备份中的未知字段被丢弃；未知领域行在规范化事务中清除。直接命令中的未知字段路径或重复领域属于请求错误，仍返回 `rejected`。没有 `flatten extra` 或旧枚举别名作为另一套配置语义。

## 3. SettingsState 与并发控制

### 3.1 状态所有权

`SettingsState` 是可克隆的 Arc owner，内部保存：

| 成员 | 作用 |
|------|------|
| `cache: RwLock<Option<Arc<LoadedConfig>>>` | 同时缓存 `Arc<Settings>` 与带领域状态的 `Arc<ConfigSnapshot>` |
| `writer: Arc<Mutex<()>>` | 串行化冷加载、配置合并和唯一快照发布 |
| `runtime_generation: AtomicU64` | 丢弃等待中的过期运行时协调任务 |
| `runtime_pending: AtomicU8` | 累积日志与分布式待处理变更，避免后一次保存覆盖前一次待办 |
| `runtime_reconcile: Arc<Mutex<()>>` | 仅串行化运行时副作用，不参与配置保存入场 |

真正的 SQLite 写入入场仍由 `DbState::write_transaction` 管理，没有第二套物理数据库写队列。

### 3.2 读取与提交顺序

缓存命中只取读锁并克隆 Arc；冷加载取得 writer 后再次检查缓存。冷加载和保存取得 writer 后进入独立的 `tokio::spawn` owner，等待者被取消不会把已开始的数据库提交留在“DB 已更新、内存未发布”的中间状态。等待 writer 入场的调用仍可取消。

保存读取版本、规范化、检查字段基线、合并和写入均处于同一数据库事务；成功 commit 后发布缓存，再释放 writer、同步执行调度 hook。连接重建由 hook 启动异步任务，不在 writer 内等待网络。更改全局音色不再触发声音文件清理。

### 3.3 生命周期挂载

`lib.rs` setup 仍以 `app.manage(SettingsState::new())` 注册状态。业务模块使用 `read_config` 获得 `Arc<Settings>`；需要领域版本时使用 `read_config_snapshot`。业务消费者不直接读取配置表，也不维护第二份可写配置镜像。

## 4. 读取流程 (read_settings)

### 4.1 领域快照

`read_settings` 返回 `ConfigSnapshot`：

```text
data: Settings
domains:
  <领域名>:
    revision: 十进制字符串
    schemaVersion: 当前存储结构版本
```

版本以字符串经过 IPC，避免 JavaScript 整数精度丢失。冷加载为缺失领域建立当前默认记录；快照只携带配置和版本元数据，不再携带健康状态或恢复诊断。

### 4.2 当前类型规范化

| 情况 | 读取行为 |
|------|----------|
| 缺少已知字段 | 使用唯一默认值并保存规范结果 |
| 某叶字段类型/取值非法 | 坏叶使用默认值，合法兄弟保留；关联连接按同一组规范化 |
| 某分组/领域不是对象或存储 JSON 无法解析 | 对应分组/领域使用当前默认结构 |
| 单个 JSON 数值超出解析范围（如 `1e400`） | 按类型结构分别解析字段，只恢复异常字段，保留合法兄弟 |
| SQLite 配置内容实际为 BLOB 等非文本类型或非法 UTF-8 | 对应领域使用默认结构并写回，不把二进制强转为 JSON |
| 领域 schema 版本不同 | 按当前领域类型规范化并更新结构版本 |
| schema 标记类型异常 | 恢复当前结构版本，合法配置内容保留 |
| revision 类型异常、非正或耗尽 | 返回版本元数据错误并保留记录；不重置并发令牌，避免旧编辑误覆盖新值 |
| 数据库/IO 失败 | 返回存储错误，不伪装为配置损坏，不写默认值 |
| 网络不通或克隆样本缺失 | 由实际功能执行方报告，读取不删除用户配置 |

`normalize_records` 在冷加载和保存事务中调用 `normalize_domain`；只有规范结果或结构版本发生变化才推进 revision。事务提交后才发布快照，重复读取不会反复改写相同值。

### 4.3 一次性搬运

首次读取先检查 `config_metadata/global_domains_v1`。没有完成标记时，在一个 `DbState` 事务中：

1. 读取旧 `settings/global`，把完整原文归档到 `config_recovery` 的 `legacy.global`。
2. 把已知字段拆到原有八个领域，新增 JEV 独立使用默认值；维护时间搬到 `last_automatic_maintenance`。
3. 写入领域记录与完成标记，删除旧 `global` 行，提交事务。

已存在领域记录不会被首次搬运覆盖；搬运只转换字段结构，随后采用当前类型和默认值，不再解释旧端点开关、枚举别名或日志等级大小写。旧 JSON 无法解析时使用默认结构，原文只留在一次性归档。完成后不再读旧 `global`；原 `settings` 表继续服务缓存和任务状态。

## 5. 写入流程与存储表

### 5.1 唯一写入路径

普通编辑通过 `update_settings(request: ConfigUpdate)` 提交，配置导入通过 `import_settings_backup` 提交；两者复用同一个事务与发布 owner。异常值直接规范化，不再提供 `ConfigReset` 或手动领域修复入口。

```text
取得 writer
→ 持久任务接管
→ DbState 写事务
→ 读取记录、规范化并取得 revision
→ 规范化补丁、检查冲突、合并
→ 写所有受影响领域、递增各自 revision
→ 生成可发布快照
→ COMMIT
→ 发布缓存
→ 释放 writer
→ 发变更事件并调度运行时副作用
```

拒绝或冲突时不写入本请求的领域/群组补丁；事务中对既存配置的规范化仍可提交并发布。没有真实变化的补丁不递增版本。快照构造发生在 commit 前，缓存发布发生在 commit 后；真实数据库失败仍返回错误。

### 5.2 表结构

| 表 | 关键列 | 用途 |
|----|--------|------|
| `config_domains` | `domain` 主键、`schema_version`、`revision`、`value`、`updated_at` | 每领域一行 JSON |
| `config_recovery` | `id`、`domain`、`schema_version`、`revision`、`value`、`reason`、`created_at` | 仅保留一次性搬运的原文归档；正常规范化和保存不写入 |
| `config_metadata` | `key` 主键、`value` | 搬运完成标记 |
| 原 `settings` | `key` 主键、`value`、`updated_at` | 模型缓存、维护时间等既有非全局配置记录 |

SQLite 事务保证提交边界，不提供配置加密。凭据仍以字符串保存；配置导出也会包含获准导出的凭据。

## 6. 增量更新 (update_settings)

### 6.1 请求契约

`ConfigUpdate.patches` 每个领域最多一份 `DomainPatch`：

```json
{
  "patches": [{
    "domain": "voice",
    "expectedRevision": "4",
    "changes": { "asr.language": "zh" },
    "baseValues": { "asr.language": "auto" }
  }]
}
```

`changes` 是相对领域的叶路径映射，不是任意 JSON Merge Patch；`baseValues` 保存实际编辑基线。非设置页也通过同一契约写入，不能绕过版本与校验。

### 6.2 并发与校验

- revision 相同：在当前规范记录上合并修改。
- revision 不同：逐个修改字段核对基线；当前值仍等于基线可合并，当前值已等于目标值则幂等接受。
- 同字段被其他操作改为第三个值：返回 `conflict`、最新快照及字段问题，不静默覆盖。
- 未知字段路径或重复领域：返回 `rejected`，本请求补丁不落盘。
- 已知字段的非法值先规范为当前默认值，再参与冲突检查和保存，不建立长期恢复诊断。

语音风格指导统一使用 `voice.guidance.rules`，缺项的默认文本暂为“占位中”；用户显式保存的空字符串和空白均保持原值，不替换为默认规则。连接端点与凭据按关联组规范，避免端点回到默认地址而继续携带另一服务的密钥。

### 6.3 完整配置与部分补丁

`normalize_domain` 生成完整当前领域，补齐缺项并丢弃未知内容；`normalize_domain_patch` 保留未提供字段的缺席，只处理显式提供的叶或分组。命令的平铺叶路径通过 `normalize_changes` 使用同一规则。

备份缺项保留当前值；显式提供的坏组恢复该组默认值，受影响的连接组一起规范。首次恢复尚无配置时以当前默认值为底，不保留旧值别名或增加自动备份。

## 7. 默认值、校验与 TypeScript 导出

### 7.1 单一语义来源

`types.rs` 的领域 `Default` 同时供新安装、缺字段、异常规范化和开发期导出使用；不再维护独立的 `create_default_settings` 字段清单。

`schema.rs` 从嵌套默认结构发现字段，不在 Vue 重写字段白名单。枚举选项来自 Rust 枚举列表，VAD 范围来自原生共享配置常量。类型、范围、枚举、长度和关联规则统一用于读取、提交与备份规范化；执行功能所需的连接、样本存在性仍由实际业务入口检查。

### 7.2 显式生成

`crates/config-export` 是 host 开发工具，直接编译生产 `types.rs` / `schema.rs`，通过可选 `config-export` feature 使用 `ts-rs`：

```powershell
pnpm config:generate
pnpm config:check
```

输出为已提交的：

- `src/core/config/generated/config.ts`：领域类型、枚举、IPC DTO。
- `src/core/config/generated/defaults.ts`：`SETTINGS_DEFAULTS`。
- `src/core/config/generated/metadata.ts`：`SETTINGS_FIELDS`。

`config:check` 只检查是否过期，不写文件，并已接入 `pnpm check` 的首步。移动端默认构建不启用导出 feature；导出不启动 Tauri、不读取数据库、密钥或设备资源。前端 `core/config/fields.ts` 使用生成契约提供字段路径与补丁工具，页面仍自行定义展示顺序和交互。

## 8. 函数接口表

### 8.1 Tauri Commands

| 命令 | 输入 | 输出 |
|------|------|------|
| `read_settings` | 无 | `ConfigSnapshot` |
| `update_settings` | `{ request: ConfigUpdate }` | `ConfigSaveResult`：`saved` / `rejected` / `conflict` |
| `export_config_domains` | 无 | 当前已提交配置中允许备份的嵌套领域对象 |
| `export_group_preferences` | 无 | 本机群参数按群 ID 的完整映射 |
| `import_settings_backup` | `{ request, groupPreferences }` | 全局领域补丁与本机群参数在同一事务提交；提交后失效群缓存并通知活动裁决 |
| `parse_config_backup` | `{ path: string }` | 规范化领域/群补丁、待前端 owner 处理的 `preferences` 与 `exportedAt` |

群参数导出为完整快照，导入保留字段是否出现的信息：缺项保留当前值，首次恢复使用默认值为底；固定对象递归合并，数组和成员风格映射按字段替换。未包含的群不修改，已删除群的墓碑优先，未知群 ID 可保留待同步绑定。此部分不改变聊天同步 DTO。

应用命令统一注册在 `commands.rs` 的 `app_command_handler!` 中，由 `lib.rs` 调用；没有独立的恢复状态或手动重置命令。

### 8.2 Rust 内部读取

| 入口 | 返回值 | 用途 |
|------|--------|------|
| `read_config` | `Arc<Settings>` | 一次任务所需的跨领域一致配置 |
| `read_config_snapshot` | `ConfigSnapshot` | 需要配置及领域版本的调用方 |
| `SettingsState::apply` | `ConfigSaveResult` | 唯一持久提交与提交后 hook |

### 8.3 配置备份 v2

`.vcpcfg.json` 保持 version `2`，内容采用嵌套 `domains`、独立 `preferences` 及 `groupPreferences`；保留 v1 文件的单向导入转换，旧平铺 v2 不再接受。v1 只把实际提供的字段转为领域补丁，不注入缺失字段的默认值，也不恢复旧数据库读写路径。

`backup` 元数据决定导出和导入资格：当前包括身份、主服务器、日志、同步连接、分布式、总结模型、语音及 JEV；不包含侧栏排序，也不包含同步日志级别和预渲染选项。克隆样本仅保存 ID，不包含音频文件。

Rust 丢弃备份中的未知领域/字段和不可备份字段，已提供的非法值按当前类型默认；文件 JSON 损坏、应用/格式/版本不匹配、缺少领域容器或超过 1 MiB 仍报错。导出直接使用已规范的提交快照；导入通过 `import_settings_backup` 在同一 SQLite 事务中处理领域与群参数补丁，真实冲突和 IO 失败仍分别报告。

备份先读取元信息，再按各配置容器分别解码；`1e400` 等溢出值只影响所在字段，正常全局、群组和前端偏好值保留。已有首次搬运流程也按字段解析旧配置，非文本或非法 UTF-8 内容恢复当前默认，原始 SQLite 值直接归档以保留存储类型及字节；不增加新的兼容格式。

语音、JEV 和其他领域均使用同一规范化规则；例如 `voice.tts.mode` 仅接受 `builtin` / `clone`，其他值采用该字段默认值 `builtin`。预制 `voice.tts.voice` 的默认值为 `冰糖`，仅接受官方音色值，合法的已有音色值仍独立保留；不增加旧模式迁移分支。

语音 API 地址、JEV 两供应商的 API 地址与模型、JEV 应用名称持久默认均为空；`FieldDescriptor.preset` 从 Rust 运行预设生成，供界面占位提示使用。发起请求时，空字符串或纯空白按当前 JEV 供应商（语音固定 MiMo）取预设，非空值优先。已有有效值原样保留，包括与预设相同的值，不自动清空；显式空地址保留 Key，完整配置中缺失或类型错误的地址仍沿既有关联规则清除 Key。供应商切换只选择对应字段，不互相覆盖。

主题和聊天偏好由 `normalizeThemePreferencePatch` / `normalizeChatPreferencePatch` 使用各自当前默认值，缺项保留；显式坏 `preferences` 根交由两个 owner 各自默认化。它们仍使用 localStorage，结果分别报告，不能宣称与 SQLite 整份原子提交。

## 9. 提交后运行时联动

### 9.1 配置事件

成功提交后发出 `vcp-config-changed`，载荷为完整 `ConfigSnapshot`。前端 Store 按领域 revision 接纳新状态，迟到的旧领域版本不会覆盖新快照。事件是已提交配置通知，不证明网络连接或播放已成功。

### 9.2 日志、Info 与分布式

`classify_runtime_settings_changes` 比较旧快照与新快照：

- `log.url` / `log.key` 改变：调度 VCPLog 和 VCPInfo。
- 分布式启用状态改变，或启用时连接参数改变：调度分布式 owner。
- 其他配置变化不触发这些连接重建。

提交后将待处理类别 OR 入 `runtime_pending`，推进 generation 并调度任务。任务取得独立运行时锁、淘汰过期 generation，再提取累积待办并读取最新快照。等待期间多次保存的类别不会因后一任务只改变另一类别而丢失；运行时锁不会挡住 SQLite 保存。

连接 owner 仍负责真实连接状态；失败记录在各自路径，不把已完成数据库保存反报为失败。

### 9.3 语音与其他生效边界

| 配置 | 消费边界 |
|------|----------|
| 主连接、身份、总结模型 | 下一次相应请求 |
| 同步配置 | 下一次同步 |
| 语音连接 | 下一次语音任务 |
| ASR / 输入编码 | 下一次输入服务 |
| TTS / 风格指导 | 下一条回复或朗读任务 |
| VAD | 下一次通话 |
| 侧栏排序 | 已提交快照即时反映 |

`VoiceReplyPolicy` 从同一次已提交 `Settings` 冻结连接、继承默认值与注入规则。TTS 再按真实消息作者解析独立音色，并在同一消息内冻结，避免各分片混用配置。声音资产归声音库长期持有，退出设置或改变选择不回收资产，显式删除由声音库单独处理。

## 10. 维护入口

新增配置时先确定所属领域与消费时机，在 `types.rs` 增加类型和默认值，在 `schema.rs` 补充必要约束、备份与生效策略，再显式生成 TypeScript 契约。Vue 页面字段集合只负责该页能编辑什么，不作为另一份类型或默认值来源。

修改存储或 IPC 时，沿 `repository → settingsStore → 编辑会话/其他实际消费者` 检查；修改连接副作用时，沿提交 hook 和实际网络 owner 检查。新增数据库领域或字段不应恢复旧 `global` 双写，也不应把 localStorage 偏好悄悄搬入本模块。
