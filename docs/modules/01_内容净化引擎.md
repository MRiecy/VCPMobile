# 01_内容净化引擎（Context Sanitizer）

## 1. 概述

### 1.1 模块定位

`context_sanitizer.rs` 是 VCP Mobile 核心层（Rust 后端）的**上下文 HTML → Markdown 净化门面**，位于 `src-tauri/src/vcp_modules/chat/context_sanitizer.rs`。转换引擎已迁移至可复用模块 `src-tauri/src/vcp_modules/infra/html2md/`（基于 **htmd** crate —— turndown 的 Rust 移植 —— 内建 handler + VCP 自定义 handler 架构）；本门面保留 LRU+TTL 缓存、VCP 原始块直通、think 标签字面量保护与元思考链明文剥离，行为严格对齐桌面端 `contextSanitizer.js`。

### 1.2 职责边界

| 职责领域 | 具体行为 | 对应源码位置 |
|---------|---------|------------|
| HTML → Markdown 转换 | htmd 引擎（内建 handler 负责通用标签语义） | `infra/html2md/mod.rs` |
| 多媒体保留 | `img`、`audio`、`video` 标签原样保留为 HTML 片段 | `infra/html2md/vcp_handlers.rs`（img/media handler） |
| VCP 特殊块提取 | `data-raw-content` 零损提取、`TOOL_REQUEST`、`DailyNote` 标记透传 | `infra/html2md/vcp_handlers.rs`（pre handler） |
| 元思考链泡泡 | `div.vcp-thought-chain-bubble` 的保留/丢弃两态 | `infra/html2md/vcp_handlers.rs`（div handler） |
| 元思考链明文剥离 | 行锚定正则剥离 `[--- VCP元思考链 ---]` 与 `<think>` 块 | `strip_thought_chains` |
| VCP 原始块直通 | 成对 `TOOL_REQUEST`/`DailyNote` 标记内容整条原样返回 | `contains_raw_vcp_blocks` |
| think 字面量保护 | 协议讲解文本中的 `<think>` 标签转换前后占位/恢复 | `sanitize_core` |
| 缓存加速 | 基于 LRU + TTL 的净化结果缓存，避免重复解析 | `ContextSanitizer` |

### 1.3 调用入口

```text
Vue 3 前端（消息渲染层）
    ↓ Tauri IPC invoke
commands.rs（命令注册表，防爆栈 offload）
    ↓ 调用
chat_sanitize_content / chat_strip_thought_chains（#[tauri::command]）
    ↓ 调用
ContextSanitizer::sanitize_content(content, keep_thoughts)
    ↓ 空检查 → 原始块直通 → HTML 检查 → 缓存查询
sanitize_core：think 字面量保护 → html2md::convert → 字面量恢复 → 空行收敛
```

主要公共入口为 `ContextSanitizer::sanitize_content`（由 Tauri 命令 `chat_sanitize_content` 经 `app.manage(ContextSanitizer::default())` 注入的状态调用）。转换引擎 `infra::html2md::convert` 同时作为可复用公共接口，供未来导出等场景直接复用。

## 2. 核心类型与数据结构

### 2.1 CacheItem

```rust
pub struct CacheItem {
    pub value: String,      // 净化后的 Markdown 结果
    pub timestamp: SystemTime,  // 写入时间戳（用于 TTL 判定）
}
```

`CacheItem` 是缓存存储的基本单元。采用 `SystemTime` 记录写入时刻，在读取时通过 `timestamp.elapsed()` 与 TTL（Time To Live，存活时间）比对，实现惰性过期（Lazy Expiration）。

### 2.2 ContextSanitizer

```rust
pub struct ContextSanitizer {
    pub cache: Mutex<LruCache<String, CacheItem>>,
    pub ttl: Duration,
}
```

| 字段 | 类型 | 说明 |
|-----|------|------|
| `cache` | `Mutex<LruCache<String, CacheItem>>` | 线程安全的 LRU 缓存，键为哈希组合键，值为净化结果 |
| `ttl` | `Duration` | 缓存项最大存活时间，默认 3600 秒 |

`ContextSanitizer` 实现了 `Default` trait（默认容量 100 条，TTL 1 小时），由 `lib.rs` 启动时 `app.manage(ContextSanitizer::default())` 注入为全局状态。由于 Tauri 的命令处理模型为单线程事件循环，但内部使用 Tokio 异步运行时，`Mutex` 选用 `std::sync::Mutex` 而非 `tokio::sync::Mutex`，因为缓存操作极短，无需跨 await 点持有锁。

### 2.3 全局正则表达式（lazy_static）

| 正则名称 | 用途 |
|---------|------|
| `THOUGHT_CHAIN_REGEX` | 行锚定剥离 `[--- VCP元思考链: "title" ---]... [--- 元思考链结束 ---]`（multiline） |
| `CONVENTIONAL_THOUGHT_REGEX` | 行锚定剥离 `<think>/<thinking>...</think(ing)>`（multiline + 大小写不敏感） |
| `THINK_TAG_LITERAL_REGEX` | 匹配 `</?think(ing)?>`（大小写不敏感），转换前替换为占位符保护字面量 |
| `HTML_CHECK_REGEX` | 快速预检字符串中是否包含 HTML 标签 |
| `MULTI_NEWLINE_REGEX` | 将 3 个以上连续换行压缩为 2 个 |

所有正则均使用 `regex` crate（行锚定语义无需回溯能力，`fancy-regex` 已随重构移除），通过 `lazy_static!` 宏在首次访问时惰性编译。

**行锚定语义**（对齐桌面端 `stripThoughtChains`）：思维链起止标记必须各自独占一行才剥离；正文、行内代码里的 `<think>...</think>` 示例原样保留。这是与旧实现的刻意行为差异（旧实现为无锚定宽松剥离）。

## 3. 引擎架构与算法详解

### 3.1 htmd 引擎 + handler 架构（infra/html2md）

转换引擎为 `htmd::HtmlToMarkdown`（turndown 的 Rust 移植），底层解析器为 `html5ever`（与浏览器同套 HTML5 解析算法，`parse_document` 模式）。引擎以进程级静态实例存在（`OnceLock`，`keep_thoughts = true/false` 两态各一），handler 集合在构建期冻结，转换调用本身不可变共享、可安全并发。

```text
html2md::convert(html, keep_thoughts)
        │
        ▼
OnceLock<HtmlToMarkdown>（按 keep_thoughts 选引擎）
        │
        ▼
html5ever parse_document → RcDom 树
        │
        ▼
dom_walker 遍历 → 按标签分派 handler
        │
   ┌────┴─────────────────┐
   ▼                      ▼
VCP 自定义 handler      htmd 内建 handler
（img/audio/video/      （h1-h6/p/list/table/
 pre/div 思维链泡泡）     blockquote/code fence/...）
   │                      ▲
   └── 未命中时 fallback ──┘
```

关键机制（htmd 0.5.5 API）：

- `HtmlToMarkdown::builder().options(...).add_handler(vec![tags], handler).build()`；`add_handler` 按标签注册、后注册先命中，handler 内 `handlers.fallback(element)` 委托给注册顺序更早的 handler（即内建默认行为）。
- handler 闭包签名：`Fn(&dyn Handlers, Element) -> Option<HandlerResult>`；返回 `None` 表示该元素输出空。
- `Element { node: &Rc<markup5ever_rcdom::Node>, tag, attrs, markdown_translated, .. }`；`Handlers::walk_children(&Rc<Node>)` 递归转换子树。
- `Options` 对齐桌面 turndown 配置：默认即 Atx 标题 / 围栏代码块 / Pure 模式（未知标签剥标签留内容，与旧实现「默认透传」语义一致）；显式覆盖两项：`hr_style: HrStyle::Dashes`（对齐桌面 `hr: '---'`）、`bullet_list_marker: BulletListMarker::Dash`（对齐桌面 `bulletListMarker: '-'`）。

### 3.2 pre handler：特殊块零损提取

**目标**：对于已经过前端或其他系统预处理的 VCP 特殊块，避免二次解析导致格式损坏。

`pre` handler 位于 `infra/html2md/vcp_handlers.rs`，检查顺序（与桌面规则3+4 效果等价，沿用旧实现简化顺序）：

```text
pre 元素到达 handler
     │
     ▼
 class 含 vcp-tool-use-bubble / maid-diary-bubble？（大小写敏感）
     │
  ┌──┴───┐
  是      否
  │       │
  ▼       ▼
返回      有 data-raw-content 属性？
data-raw-    │
content   ┌──┴───┐
原文      是      否
（缺失    │       │
则返回    ▼       ▼
空串）  返回原文  textContent 含 <<<[TOOL_REQUEST]>>> / <<<DailyNoteStart>>>？
              │
           ┌──┴───┐
           是      否
           │       │
           ▼       ▼
        返回      fallback：内建 pre handler
        textContent （围栏代码块）
        原文
```

此设计确保即使 `data-raw-content` 内部的文本看起来像是 HTML/Markdown，也不会被二次解析或转义，实现**零损（Lossless）提取**。其余普通 `pre` 由 htmd 内建 handler 转为围栏代码块（含 `language-xxx` class 的语言识别）。

### 3.3 img / audio / video handler：多媒体保留

| handler | 处理逻辑 |
|---------|---------|
| `img` | 有非空 `src` → 输出 `<img src="{src}" alt="{alt}">`（保持原 HTML 形式，不转 Markdown 图片语法）；否则输出空 |
| `audio` / `video` | 元素自身含非空 `src` → `<{tag} src="{src}"></{tag}>`；否则遍历子节点取第一个 `<source>` 的 `src`（该 source 无 src 即输出空，对齐桌面 `querySelectorAll('source')[0]` 语义）；都没有 → 输出空 |

### 3.4 div handler：元思考链泡泡结构化

**触发条件**：`<div>` 的 class 名单包含 `vcp-thought-chain-bubble`（**大小写敏感**，对齐 JS `classList.contains` 语义；旧 Rust 实现的 `AsciiCaseInsensitive` 是与桌面端的偏差，已纠正）。非思维链 div 一律 `fallback` 交还内建块级 handler。

**行为分支**：

| `keep_thoughts` 参数 | 行为 |
|---------------------|------|
| `true` | 转换为 VCP 明文思考链格式（正文为子树的 Markdown 转换结果） |
| `false` | 整块丢弃（输出空） |

**结构化输出格式**：
```text

[--- VCP元思考链: "{data-thought-title}" ---]
{walk_children 转换结果}
[--- 元思考链结束 ---]

```

当 `data-thought-title` 属性为空时，标题部分省略，输出 `[--- VCP元思考链 ---]`。

### 3.5 通用标签与门面管线

通用 HTML 标签（`h1`–`h6`、`p`、`strong`/`b`、`em`/`i`、`ul`/`ol`/`li`、`blockquote`、`table`、`code`、`a`、`hr` 等）全部由 htmd 内建 handler 负责，语义对齐 turndown（列表项为 `-   ` 三空格前缀，与 turndown 输出一致；`hr` 渲染为 `- - -`）。

门面侧 `sanitize_core` 管线（`context_sanitizer.rs`）：

```text
输入 content
   │
   ▼
THINK_TAG_LITERAL_REGEX 全量替换为 VCPTHOUGHTTAGLITERAL{i}TOKEN
（防止解析器把协议讲解文本里的 think 标签当元素吞掉）
   │
   ▼
html2md::convert(protected, keep_thoughts)
   │
   ▼
逐个恢复 think 标签字面量
   │
   ▼
\n{3,} → \n\n，整体 trim
```

### 3.6 缓存策略（LRU + TTL）

#### 3.6.1 缓存查找流程

```text
sanitize_content 被调用
        │
        ▼
   content.trim().is_empty()?
        │
   ┌────┴────┐
   ▼         ▼
  是        否
   │         │
   ▼         ▼
直接返回   contains_raw_vcp_blocks(content)?（成对标记直通）
            │
       ┌────┴────┐
       ▼         ▼
      是        否
       │         │
       ▼         ▼
   原样返回  contains_html(content)?
                 │
            ┌────┴────┐
            ▼         ▼
           否        是
            │         │
            ▼         ▼
        直接返回  generate_cache_key(...)
                      │
                      ▼
              get_cached(&cache_key)
                      │
                 ┌────┴────┐
                 ▼         ▼
              命中       未命中/过期
                 │         │
                 ▼         ▼
             返回缓存值  sanitize_core(...)
                           │
                           ▼
                       set_cached(...)
                           │
                           ▼
                       返回新计算值
```

#### 3.6.2 缓存键生成

`generate_cache_key` 使用 `std::collections::hash_map::DefaultHasher` 对原始内容与 `keep_thoughts` 布尔值进行组合哈希：

```rust
let mut hasher = DefaultHasher::new();
content.hash(&mut hasher);
keep_thoughts.hash(&mut hasher);
let hash = hasher.finish();
format!("sanitized_{}_{}", hash, content.len())
```

键格式：`sanitized_{hash}_{len}`。追加 `content.len()` 是为了降低哈希碰撞导致的误命中概率（生日攻击防护）。

#### 3.6.3 TTL 惰性过期

`get_cached` 采用**读取时清理**策略：

```rust
if let Some(item) = cache.get(key) {
    if let Ok(elapsed) = item.timestamp.elapsed() {
        if elapsed < self.ttl {
            return Some(item.value.clone());
        }
    }
    cache.pop(key);  // 过期项在读取时弹出
}
None
```

此设计无需后台定时任务，但可能在缓存中长期积累已过期却未被访问的"僵尸项"，直到 LRU 容量淘汰将其驱逐。

## 5. 与桌面端/JS 的对齐

### 5.1 迁移背景

本模块最初是桌面端 `contextSanitizer.js`（JSDOM + Turndown）的 Rust 重构版。迁移动机：

1. **内存安全**：将 HTML 解析与正则处理从 JS 移至 Rust，避免移动端 V8 引擎的内存抖动。
2. **计算本地化**：减少跨 IPC 的大字符串传输，HTML 解析在 Rust 侧完成后，前端仅接收精简的 Markdown。
3. **统一缓存**：Rust 侧的 LRU 缓存可跨消息生命周期复用，JS 侧难以在页面刷新后保持缓存状态。

### 5.2 htmd 重构（本次）

转换引擎从「scraper 手写递归遍历」重构为「htmd 内建 handler + VCP 自定义 handler」：

- **htmd = turndown 的 Rust 移植**：通用标签语义（含转义、空白压缩、表格、嵌套列表缩进）直接继承 turndown 行为，消除手写遍历的覆盖盲区（如表格、有序列表、嵌套结构此前完全未处理）。
- **VCP 规则平移**：桌面端 5 条 turndown 规则逐一对应到 4 个自定义 handler；`Options` 对齐 turndown 配置（Atx / `hr: '---'` → `HrStyle::Dashes` / `bulletListMarker: '-'` → `BulletListMarker::Dash` / fenced / Pure 模式）。
- **新增桌面流程缺口**：`containsRawVcpBlocks` 前置直通、think 标签字面量保护，此前 Rust 版均未实现，本次补齐。
- **刻意纠正的偏差**：思维链泡泡 class 匹配从 `AsciiCaseInsensitive` 纠正为大小写敏感（JS `classList.contains` 语义）；`strip_thought_chains` 从松散跨行匹配纠正为桌面行锚定语义（起止标记须独占一行，行内示例保留）。
- **依赖收敛**：`scraper`、`ego-tree`、`fancy-regex` 直接依赖全部移除；`html5ever`/`markup5ever_rcdom` 回退 0.38 与 htmd 及 tauri 构建链（dom_query）统一为同一份。

### 5.3 已知差异

| 差异点 | 说明 | 潜在影响 |
|-------|------|---------|
| 通用标签输出不与旧实现字节一致 | htmd 有自己的空白压缩/转义/换行规范（如列表项 `-   ` 三空格前缀、`hr` 渲染为 `- - -`、文本中 Markdown 特殊字符自动转义） | 预期行为：输出语义等价且更贴近 turndown；缓存键基于输入内容，旧缓存自然失效 |
| 未配对 `<<<DailyNoteStart>>>` 裸文本 | `<DailyNoteStart>` 是不带方括号的合法标签名，会被 HTML5 解析器当未知元素吞掉（桌面 jsdom 行为相同） | 完整 DailyNote 块由 `contains_raw_vcp_blocks` 直通保护，不受影响；pre handler 中的 DailyNote 标记检查仅作镜像兜底 |
| HTML 解析器 | htmd 使用 `parse_document`（完整文档模式，html5ever） | 与旧 `parse_fragment` 在未闭合标签等边缘形态上的修复策略略有差异，均为规范 HTML5 算法 |
| 缓存机制 | 进程级 LRU + TTL | JS 侧通常无持久缓存，此为 Rust 侧新增优化 |

## 7. 性能考量

### 7.1 HTML 解析开销

`html2md::convert` 使用 htmd 内置的 `html5ever::parse_document` 对输入进行 HTML5 兼容解析，时间复杂度为 O(n)，其中 n 为输入字符串长度。引擎实例为进程级静态（`OnceLock` 惰性初始化，两态各一），handler 集合仅构建一次；每次转换的开销 = 一次解析 + 一次树遍历。对于典型聊天消息（< 10 KB），解析开销可忽略；但对于包含大量富文本的长消息（如带多篇附件引用的系统消息），需注意以下优化点：

| 优化机制 | 实现方式 | 效果 |
|---------|---------|------|
| 原始块直通 | `contains_raw_vcp_blocks` 前置检查，成对标记内容整条原样返回 | 避免对协议块执行任何解析 |
| 无 HTML 短路 | `contains_html` 正则预检，无标签时直接返回原字符串 | 避免对纯文本消息执行完整 DOM 解析 |
| 空内容短路 | `content.trim().is_empty()` 前置判断 | 消除空字符串的哈希与缓存开销 |
| 引擎复用 | 静态 `HtmlToMarkdown` 实例 + 冻结 handler 表 | 无重复注册/编译开销 |

### 7.2 缓存命中率与参数调优

默认配置（容量 100，TTL 3600 秒）基于以下假设设计：

- **容量 100**：在典型会话中，用户会在短时间内多次查看同一批历史消息。100 条缓存足以覆盖当前可视窗口及其附近上下文。
- **TTL 1 小时**：消息内容在发送后通常不可变，极长的 TTL 本身不会导致脏数据；设置上限是为了在极端长会话中允许内存 eventual 释放。

**缓存失效场景**：
- 同一条消息被连续渲染，但 `keep_thoughts` 参数切换（如用户展开/收起思考链）→ 生成不同缓存键，导致双份存储。
- 消息编辑功能引入后，内容变更但缓存键基于旧内容 → 需在外层（调用方）在编辑后手动使缓存失效，当前模块未提供 `invalidate` 接口。

### 7.3 锁竞争分析

`ContextSanitizer.cache` 使用 `std::sync::Mutex` 保护 `LruCache`：

```text
sanitize_content 调用
        │
        ▼
  get_cached: lock() → get() → unlock()
        │
        ▼
  sanitize_core / html2md::convert: 无锁（纯计算，引擎不可变共享）
        │
        ▼
  set_cached: lock() → put() → unlock()
```

在 Tauri 的单线程命令派发模型下，绝大多数场景为串行访问，锁竞争可忽略。若未来引入并发消息预加载，可考虑将 `Mutex` 替换为 `parking_lot::Mutex` 以降低锁开销，或采用 `tokio::sync::Mutex` 支持跨 await 的异步锁（但当前无此需求）。

### 7.4 正则性能

全部正则使用 `regex` crate（线性保证，无回溯引擎），`fancy-regex` 依赖已移除：

| 正则表达式 | 复杂度 | 适用场景 | 潜在风险 |
|-----------|--------|---------|---------|
| `HTML_CHECK_REGEX` | O(n) 线性扫描 | 快速预检 | 对包含 `<` 的纯文本（如数学公式）可能产生假阳性，但假阳性仅导致一次不必要的 HTML 解析，不影响正确性 |
| `THOUGHT_CHAIN_REGEX` / `CONVENTIONAL_THOUGHT_REGEX` | O(n) 线性（`regex` crate 无回溯） | 行锚定思考链剥离 | 独占行锚定大幅缩小匹配面；`[\s\S]*?` 惰性匹配由自动机实现，无灾难性回溯 |
| `THINK_TAG_LITERAL_REGEX` | O(n) 线性扫描 | think 字面量保护 | 仅匹配 `</?think(ing)?>` 短标签，开销可忽略 |
| `MULTI_NEWLINE_REGEX` | O(n) 线性扫描 | 空行压缩 | `\n{3,}` 为贪婪量词，但目标字符单一，无风险 |

### 7.5 内存使用特征

- **峰值内存**：解析阶段 htmd 构建完整 RcDom 树，峰值约为输入 HTML 大小的 2–4 倍（含节点结构开销）。对于 20 KB 输入，峰值内存约 40–80 KB，远低于移动端 OOM 阈值。
- **缓存内存**：每条缓存项存储完整净化后字符串。假设平均消息 2 KB，100 条缓存约占用 200 KB + 哈希表开销，整体 < 1 MB。
