# 00-现状审计与解耦根因分析

> 本文档审计 VCP Mobile 语音子系统与 Agent 设置的现状实现，揭示“全局语音单点绑定”及“克隆样本误删”两大结构性架构缺陷。

> 审计对象为重构前代码。2026-10-28 的最终决定与实现导航见 [05-实施决策与验证记录](05-实施决策与验证记录.md)。

---

## 1. 业务现状与痛点定位

目前 VCP Mobile（代号 Project Avatar）的语音子系统已具备了基于 MiMo 的全双工语音通信、TTS 合成与样本复刻能力，但所有配置均集中在全局设置（`VoiceSettingsPage.vue`）中：

```text
[当前缺陷架构]
全局设置 (VoiceSettingsPage)
  ├── API 连接 (apiBaseUrl, apiKey)
  ├── 语音识别 ASR (mimo-v2.5-asr, inputEncoding, language)
  ├── 语音检测 VAD (sensitivity, endSilenceMs)
  └── 语音朗读 TTS (全系统强制唯一)
        ├── voice.tts.mode: "builtin" | "clone"
        ├── voice.tts.voice: "冰糖"
        └── voice.tts.cloneSampleId: "sample_uuid"
              ▲
              │ 所有 Agent / 对话气泡 / 通话 强行共用一套音色！
Agent A (导师) ───────┘
Agent B (助手) ───────┘
Agent C (角色) ───────┘
```

### 核心痛点
1. **角色声学资产与全局配置割裂**：
   Agent 是对话与角色的核心载体。不同 Agent 拥有独立的人设、头像与系统提示词，但在语音合成上却被强制绑定到全局唯一音色。
2. **克隆模式（Voice Clone）作为全局配置的荒谬性**：
   克隆模式本质上是特定角色声音的样本复刻。将样本音频挂在全局设置下，导致只要切换全局克隆音频，所有 Agent 的发音音色全部被污染覆盖。
3. **Agent 设置面板排版陈旧**：
   目前的 `AgentSettingsView.vue` 依然采用旧版散乱的 `.card-modern` 卡片排版，未对齐最新的“方案 D: 微层阶台面式（外置小圆点章节头 + 8px 微圆角细框台面）”高密度生产力美学。

## 2. 后端代码深层缺陷审计

经对 `src-tauri/src/vcp_modules/chat/voice_service/` 与 `src-tauri/src/vcp_modules/agent/` 的源码审计，发现三大硬编码缺陷：

### 缺陷 A：克隆样本存储的“单点假设”与孤儿目录暴力擦除（致命隐患）
在 `src-tauri/src/vcp_modules/chat/voice_service/samples.rs` 中：
```rust
// samples.rs 第 31-45 行、第 78-100 行:
async fn recover(&mut self, root: &Path, selected: &str) -> Result<(), String> {
    ...
    for _ in 0..MAX_RECOVERY_ENTRIES {
        let Some(entry) = entries.next_entry().await... else { break; };
        let name = entry.file_name();
        // 🚨 致命缺陷：如果目录名不是全局选中的 selected (selected_sample_id)，
        // 直接视为 orphan 孤儿文件物理从磁盘删除！
        if name == selected {
            continue;
        }
        if let Err(error) = remove_sample_files(&entry.path()).await {
            log::warn!("[VoiceSample] orphan cleanup skipped: {error}");
        }
    }
}
```
* **后果**：Rust 后端强行假定系统内有且仅有一个全局克隆样本。一旦用户为多个 Agent 上传了各自的克隆音频，只要应用重启或朗读触发快照恢复，除全局当前选中的那一个音频外，**其余所有克隆音频都会被后端物理删除**！

### 缺陷 B：缺少克隆模型库（Voice Clone Library）的数据资产管理
* 目前 Rust 后端仅暴露了 `import_voice_clone_sample`（单次导入）和 `get_voice_clone_sample`（单次查询），**根本没有提供 `list_voice_clone_samples` 查询列表命令**。
* 无法在移动端建立长期的声音模型库资产索引。

### 缺陷 C：Agent 数据结构与 SQLite 存储缺失语音字段
* `src-tauri/src/vcp_modules/agent/agent_types.rs` 中的 `AgentConfig` 结构体：
  包含 `id, name, system_prompt, mobile_system_prompt, model, temperature, context_token_limit, max_output_tokens, stream_output, use_temperature, topics`，**没有任何 voice 字段**。
* SQLite `agents` 数据表在迁移脚本 `0100_baseline_v2.sql` 中未预留语音列，导致 Agent 专属音色无法落盘。

### 缺陷 D：TTS 调度管线（TTS Dispatcher）硬编码全局设置
* `src-tauri/src/vcp_modules/chat/voice_service/tts.rs` 中的 `start_narration` 和 `prepare_narration`：
  完全通过 `samples::snapshot_voice_settings(app, cancel)` 直接抓取全局 `settings.voice.tts`，完全不感知当前消息属于哪个 Agent。

## 3. 重构战略边界（Platform Boundary）

> [!IMPORTANT]
> **双端严格边界定义**：
> 本项目中的“双端”**100% 仅指 Android 与 iOS 移动端原生沙盒**。
> 本次重构严禁引入任何桌面端（Desktop / PC / VChat）同步逻辑，不增加同步协议负担，所有克隆声音文件均在移动设备本地文件系统独立安全管理。
