# 群设置与移动交互方案

审计日期：2026-10-19。角色：Balthasar（交互与美学）。

本文记录当前生产源码事实、Mobile 适配建议与待决策项，不代表功能已经实现，也不代表建议已获得逐项产品批准。本轮交付范围为完整审计与分阶段实施方案；未修改生产代码，未取得运行、Android 设备或 Apple 构建证据。VCPChat 非同步模块仅作为只读参考。

## 1. 核心结论

VCPChat 保留顺序发言、自然随机、邀请发言，新增第四种 `jev` 模式；JEV 没有替代或重命名旧自然随机。每种模式的配置已经收拢到 `modeSettings`，并为旧字段维持兼容投影。Mobile 仍是旧的平铺群设置模型，顺序模式没有独立排列界面，JEV 的服务设置、群策略、发起/继续、运行中插队和仲裁状态均未接入。

本轮应把群配置、聊天控制与现有群轮生命周期一起适配。单独增加一个 JEV 模式按钮，不能形成完整移动交互。同步 DTO 的字段扩展与保存保留机制是前置条件，不能用前端临时副本弥补数据通路的缺口。

## 3. 全局服务与本群 JEV 配置的边界

### 3.1 全局服务配置

VCPChat 当前可见的全局配置来自 [jev-service.js](E:/VCPChat/modules/settings/schema/jev-service.js) 4–115 行：

| 分组 | 字段 | 当前界面事实 |
| --- | --- | --- |
| 服务连接 | `jevEnabled`、`jevProvider`、`jevApiUrl`、`jevApiKey`、`jevModel` | 提供商为 TypeSafe / OpenRouter；Key 输入支持多个 Key |
| 可靠性与网络 | `jevTimeoutMs`、`jevMaxRetries`、`jevRetryBaseDelayMs`、`jevProxyUrl` | 表单默认依次为 30000 ms、2 次、500 ms；代理可选 |
| OpenRouter 元数据 | `jevHttpReferer`、`jevAppTitle` | 仅使用 OpenRouter 时发送；留空不影响调用 |

当前 VCPChat Key 字段说明为“本机 settings.json 保存；多个 Key 按请求轮询，同一请求重试不切换 Key”，见上述文件 38–44 行。Mobile 需要以其实际 Rust 服务实现校验最终规则，不能仅复制文案或套用聊天模型的 ModelSelector。

Mobile 建议新增 `jev` 配置领域，正式值仍归 Rust 配置仓库与 `ConfigSnapshot`，前端复用现有叶路径编辑会话、revision、校验与返回保存机制。群策略不进入该全局领域；全局连接信息不进入群组 DTO。不另建一个前端 localStorage 版的 JEV 服务配置。

这一建议接入的是现有基础设施：当前领域枚举见 [types.rs](../../src-tauri/src/vcp_modules/infra/settings_manager/types.rs) 160–201 行，字段策略同时表达 `backup` 和 `secret`，见 327–337 行。设置页面目录见 [catalog.ts](../../src/features/settings/catalog.ts) 5–42 行。实现时应基于届时生产代码复核，尤其当前工作树存在设置系统的其他未提交工作。

### 3.2 备份与密钥的默认建议

建议 JEV 本机配置遵循当前手动配置备份规则：显式加入可备份领域，API Key 标记为 `secret`，用户主动导出配置时随其他连接凭据进入备份；导入使用现有配置事务与字段校验。不要默认增加跨设备凭据同步，也不另建密码库或单独备份文件。

此建议依据当前生产行为，而不是测试断言：现有 [schema.rs](../../src-tauri/src/vcp_modules/infra/settings_manager/schema.rs) 69–77 行分别设置备份标志与 secret 标志；[backup.rs](../../src-tauri/src/vcp_modules/infra/settings_manager/backup.rs) 303–342 行按 `backup` 过滤并复制实际字段值，没有因 `secret` 自动排除内容。若用户希望 JEV Key 采用不同的备份策略，应作为明确例外决定。

JEV 全局服务配置是否加入本机备份，仍是本方案建议；不把这一建议当作用户已批准的产品决定。群组同步继续限定为群的业务配置，本轮不借机扩大为全局设置或密钥同步。

### 3.3 本群 JEV 策略

默认值和规范化依据 [jevDecisionMode.js](E:/VCPChat/Groupmodules/modes/jevDecisionMode.js) 11–21、34–60 行；真实表单加载/保存依据 [grouprenderer.js](E:/VCPChat/Groupmodules/grouprenderer.js) 585–593、882–892 行。

| `modeSettings.jev` 字段 | 默认值 | 约束与呈现含义 |
| --- | --- | --- |
| `navigatorPrompt` | 内置导航员提示词 | 空白会规范化为默认提示词；指导裁决，不替代成员的系统提示词 |
| `speakerThreshold` | 0.16 | 0–1；发言权重截断 |
| `continueThreshold` | 0.45 | 0–1；继续讨论阈值 |
| `stopThreshold` | 0.55 | 0–1；结束选项阈值 |
| `maxSpeakersPerRound` | 3 | 1–32；一次裁决最多入选人数 K |
| `maxAutonomousRounds` | 12 | 1–100；一次自治运行的最多裁决轮数 |
| `historyWindow` | 12 | 1–200；发送给 JEV 的最近消息数 |
| `continueDebounceMs` | 800 | 0–10000 ms；继续操作防抖 |
| `fallbackPolicy` | `stop` | 核心还接受 `top_speaker`；VCPChat 当前 UI 没有选项且保存硬写 `stop` |
| `memberStyles` | `{}` | 按成员 ID 记录自然语言触发风格 |

建议将导航员提示词、成员风格、K 与最大自治轮数放在主要设置区；三个阈值、JEV 历史窗口与防抖放入可展开的高级区，避免所有数值和长文本挤在首屏。`fallbackPolicy` 先按 VCPChat 当前 UI 使用 `stop`，不自动开放额外产品选项。

必须区分两个窗口：`historyWindow` 作用于 JEV 裁判，`contextMessageWindowSize` 作用于实际发言成员。群成员窗口不会删掉聊天记录，VCPChat 的当前界面说明为“仅限制发送给群成员模型的最近消息；不影响完整历史显示和话题总结”，见 [sidebar-surfaces.js](E:/VCPChat/modules/settings/schema/sidebar-surfaces.js) 60–63 行。建议 Mobile 保持这种清楚的命名与分组。

## 4. 顺序、成员与模式切换

### 4.1 当前事实

VCPChat 顺序列表支持拖动、上下按钮、Alt+上下键，见 [group-slots.js](E:/VCPChat/modules/ui-system/settings/group-slots.js) 145–220 行。排列规则为：保留既有顺序中仍然属于本群的去重 ID，然后把尚未排列的已选成员追加末尾，见 225–247 行。保存再次规范化，见 [grouprenderer.js](E:/VCPChat/Groupmodules/grouprenderer.js) 919–933 行。

VCPChat 切模式只改变可见区域，保存前获取已有完整配置，并合并未激活模式的设置，见 [grouprenderer.js](E:/VCPChat/Groupmodules/grouprenderer.js) 897–953 行。成员标签保留还涉及核心规范化；不能只看到前端合并便宣称所有退群成员的风格永久保留。

Mobile 的成员切换只改 `members`，新成员默认以名字作为 Tag，退群时保留 Tag，见 [GroupSettingsView.vue](../../src/features/agent/GroupSettingsView.vue) 308–319 行。当前“顺序”没有可见的排列列表，不应要求用户通过移除再加入来修改顺序。

### 4.2 建议方案

1. 成员选择与顺序编辑分开。成员区决定“谁在群里”，顺序区决定“顺序模式下谁先说”。
2. 顺序区只显示已选成员，使用编号、头像、姓名与上下移动按钮。拖动可作为增强，不能成为唯一可操作入口，也不能直接依赖桌面 HTML Drag and Drop 行为。
3. 顺序使用成员 ID 持久化，不用姓名或当前助手列表排序当作身份。新增成员追加末尾；移除成员从当前有效序列移除；失效 ID 的规范化由统一数据边界完成。
4. 模式切换保留其他模式配置与本次草稿；保存回传完整 canonical 后再更新界面，不在 Vue 中维持一个与 Rust 配置不同的长期副本。
5. 自然随机的 Tag 和严格/自然模式仅在该模式下展示。邀请模式不展示无作用的 Tag 数值项，JEV 使用其成员风格。
6. 保存失败保留草稿与可恢复入口；切群、返回、关闭、重开不能让旧结果覆盖新群草稿。

Mobile 已有 editor epoch、pending save、canonical 更新机制，见 [GroupSettingsView.vue](../../src/features/agent/GroupSettingsView.vue) 81–85、218–306 行；[assistant.ts](../../src/core/stores/assistant.ts) 204–230 行用 canonical 的 mode/members 更新列表。重构应沿现有所有权扩展。当前页面关闭后才自动保存，失败只显示 Toast，重开会清空草稿并重读配置；新表单的返回保存应将“失败后仍能继续编辑”作为明确验收场景。

## 5. JEV 运行中的移动交互

### 5.1 发起、继续与成员插队

VCPChat 在 JEV 模式下显示“发起群聊”“继续群聊”和成员按钮：发起先随机选一名成员开场，继续直接根据已有历史裁决，成员按钮把该成员插入发言队列。见 [group-slots.js](E:/VCPChat/modules/ui-system/settings/group-slots.js) 367–428 行；调用入口见 [grouprenderer.js](E:/VCPChat/Groupmodules/grouprenderer.js) 1589–1657 行；既有邀请 IPC 根据 JEV 模式转入入队，见 [groupChatHandlers.js](E:/VCPChat/modules/ipc/groupChatHandlers.js) 201–221 行。

Mobile 的 [GroupInviteBar.vue](../../src/features/chat/components/GroupInviteBar.vue) 26、36–40、46–58 行仅面向邀请模式，群轮运行中会拒绝点击并禁用全部成员。因此不能只增加 `mode === 'jev'` 显示条件：

- 邀请模式保留现有“指定成员发言”语义。
- JEV 模式将成员操作明确标为加入队列或优先发言，运行中也由同一个后端群轮接纳，不另开群轮。
- 发起、继续、插队的可用状态以真实后端响应或快照更新，前端只能做本次点击的短期提交防重，不能凭按钮颜色推断已进入队列。
- 无成员、无话题、服务未配置、请求失败各自显示真实原因；服务尚未配置不应悄悄改变群模式。

### 5.2 运行中用户发送

Mobile 当前输入主按钮在 `isGenerating` 时执行停止，见 [InputEnhancer.vue](../../src/features/chat/InputEnhancer.vue) 565–578 行；`canSend` 与其他提交路径另有准备状态判断，见 471–483 行。JEV 如果支持用户在运行中补充消息，就必须提供清楚的触控发送入口，不能后端支持而主按钮永远只有停止。

建议 JEV 模式下将“发送新消息”与“停止群轮”分开：输入主动作允许提交新消息，群控制区保留停止动作；成员插队仍在同一群控制区。普通三模式的原行为不因 JEV 接入而无声改变。新消息是否打断当前回复、何时触发重新裁决，应由群核心定义并返回状态，UI 不自行重发或串起多个请求。

### 5.3 仲裁、排队与完成状态

VCPChat 后端快照包含 `status/running/currentAgentId/queue/manualQueue/autonomousRound/historyRevision/dirty/stopReason/stopRequested`，见 [jevGroupSessionOrchestrator.js](E:/VCPChat/Groupmodules/jevGroupSessionOrchestrator.js) 75–88 行。它也产出队列和仲裁事件。

但 VCPChat 当前前端并没有相应的完整可视队列状态： [nonStreamingEventConsumer.js](E:/VCPChat/modules/renderer/nonStreamingEventConsumer.js) 21–37 行只是消费队列/仲裁事件，静默收敛仅写 console。因此，下面的移动状态设计是本方案建议，不能表述为现有 VCPChat UI 的直接复制。

建议使用一条紧凑的群轮状态行，按实际快照展示“裁决中”“某成员发言中”“等待成员数”“停止后续待当前完成”等必要状态，结束后区分自然收敛、用户停止、自治轮数上限和决策错误。不要把这些状态写成虚假的 AI 聊天气泡，也不要只依赖容易错过的 Toast。

Mobile 已经有按会话组织的群轮 owner：`isGroupGenerating` 综合 `activeGroupTurns` 与 session active streams，见 [chatStreamStore.ts](../../src/core/stores/chatStreamStore.ts) 712–724 行；恢复回执对 `groupTurns` 对账见 1470–1494 行。应扩展这条状态通路，不在群控制组件中复制另一套 running/queue 真源。仲裁期间没有生成气泡也应保持群轮活跃、可停止；切换话题或后台恢复必须重新取得真实快照。

### 5.4 停止与取消语义：必须决定

VCPChat JEV 的“停止队列”会清空后续队列，正在进行的成员回复继续完成；若当前处于裁决阶段，可立即 abort。证据为 [jevGroupSessionOrchestrator.js](E:/VCPChat/Groupmodules/jevGroupSessionOrchestrator.js) 397–420 行。前端 Toast 明确提示“当前回复将继续完成”，见 [grouprenderer.js](E:/VCPChat/Groupmodules/grouprenderer.js) 1380–1388 行。

Mobile 当前 [GroupStopAllButton.vue](../../src/features/chat/components/GroupStopAllButton.vue) 16–21 行与输入主按钮都调用 `stopGroupTurn`；后者调用 `interruptGroupTurn`，见 [chatStreamStore.ts](../../src/core/stores/chatStreamStore.ts) 1371–1394 行。不能用同一个“停止群组发言”文案悄悄替换成另一种停止行为。

建议 JEV 首要控制明确命名为“停止后续群聊”，当前回复可继续完成；如果仍保留“立即停止所有生成”，应使用另一个明确操作并由同一后端 owner 完成终止。是否采用两个操作，以及默认按钮要表达哪一种语义，需用户决定。停止请求已发出不等于完成，状态收敛必须继续等待终态或对账。

## 6. 未知模式、帮助与升级表达

同步得到 `mode=jev` 后，当前 Mobile 编辑器不会自动回退 sequential：[GroupSettingsView.vue](../../src/features/agent/GroupSettingsView.vue) 67–75 行先展开完整配置，再仅对空 mode 设置默认。由于三种选项均不匹配，界面会出现没有选中项，未改 mode 仍可原样保存。

发消息后，[chatHistoryStore.ts](../../src/core/stores/chatHistoryStore.ts) 658–659 行针对 `mode_not_implemented` 提示改为顺序或自然随机；该文案还没有列出当前已支持的邀请模式。现有帮助只描述三模式，且顺序模式写为“按列表顺序”，见 [GroupModeHelpDialog.vue](../../src/features/agent/GroupModeHelpDialog.vue) 37–53 行。

建议升级后统一模式展示名，助手列表不再直接展示内部字符串；当前列表原样输出 `group.mode` 的位置为 [AgentList.vue](../../src/features/agent/AgentList.vue) 379–380 行。帮助说明应解释四模式、独立顺序、两种上下文窗口、JEV 的正常无回复收敛及停止语义，不靠一段笼统的“智能群聊”描述代替。

`@所有人` 目前仅为自然随机模式注入与高亮，见 [InputEnhancer.vue](../../src/features/chat/InputEnhancer.vue) 630 行。JEV 不自动继承旧自然随机的优先级与概率规则；提及、成员插队和 JEV 裁决各自以真实核心实现为准。

## 7. 移动视觉与组件边界

按项目规范采用高密度线性页面，使用现有 SlidePage、Settings 原语、页面返回栈与语义层级。首屏保持基础信息、成员数、当前模式可读；长提示词与成员风格使用逐项编辑或折叠详情，不把全部长文本铺成连续高卡片。

灰度承担主体，蓝色表达选中，红色表达错误或停止。编号、ID、状态码使用等宽字体。成员排序与模式选中用边线、2 px 侧边强调和透明度反馈，不用大幅缩放与弹跳。内容区不使用 backdrop blur。手机、平板、折叠窗口共享同一业务状态与组件树，仅按可用宽度调整布局。

当前群设置已经有较多彩色装饰与卡片嵌套，见 [GroupSettingsView.vue](../../src/features/agent/GroupSettingsView.vue) 402–570 行。此次重构可在实际改动区域收敛这些样式，不扩展成全应用视觉改版。
