# 实施裁定与进度

日期：2026-10-19。本文记录审计交付后的用户决定与施工证据；生产行为仍以代码为准。

## 用户裁定

- 不扩展或修改同步 DTO，不调整同步协议版本。群聊新参数采用手机本地值，未配置时使用默认值；同步继续承担原有聊天数据和共享字段。
- 手机群模式在尚未设置本地覆盖时继承桌面；用户在手机明确选择后独立保存，不回推覆盖桌面模式。
- 独立发言顺序、JEV 群参数、成员模型上下文窗口采用本地存储，支持 `.vcpcfg.json` 配置备份。原有自然随机标签暂沿现有共享字段，不复制第二份权威。
- 用户补充确定备份按字段恢复：未包含字段保留本机值，没有本机记录则以默认值为底。`modeSettings` 等固定结构递归合并，发言顺序数组和成员风格映射按字段整体替换，显式 `[]` / `{}` 清空；`modeOverride: null` 恢复跟随共享模式。
- JEV 支持官方 TypeSafe 和 OpenRouter。字段尽量与桌面一致，运行内核和前端遵循 Mobile 的现有所有权与交互体系。
- JEV 与群设置排版参考当前语音设置的 `SettingsCanvas` 自然画布。
- 群停止直接中断当前回复、仲裁与待发队列；语音输入也接入同一群调度，保留语音来源、朗读和取消关联。
- 本轮允许最多六个子代理并行开发，遇到产品行为选择继续讨论；不包含提交、推送和发布。

## 保留的既存问题

初审发现 legacy JS 下行输出两项群历史窗口字段，而 Mobile 严格 DTO 不接受；CDS 下行未输出这两项。该兼容风险不因新增本地参数而自动消失。本轮遵守不改 DTO 的决定，未将它作为已修复项，也不将源码判断当作真实双端同步结果。

## 当前使用入口与剩余边界

1. 「设置 → JEV 决策」启用服务，选择官方或 OpenRouter 并填写对应 Key/模型。两个服务商分别保存连接参数。
2. 群设置选择本机 JEV 模式；聊天区提供发起、继续、成员排队。顺序模式独立保存发言排列。
3. 「服务器连接 → 配置备份」导出/恢复 `.vcpcfg.json`；恢复不带回聊天消息或头像，它们继续归既有同步链。

JEV 目前保留“截断历史前拒绝自动重新生成”的边界，使用继续或明确邀请成员发言；不把持续群会话冒充单条回复重试。进程重启后不自动重放未执行的仲裁/队列。真实提供商认证、移动后台运行、语音播放、触控与平台兼容性仍需对应的实际环境证据。
