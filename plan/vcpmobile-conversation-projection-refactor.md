# 会话切换、通话与消息视窗重构计划

已批准 · 2026-11-01 · 审查基线 `46b927ce` · 实施起点 `bf1c742b` · Android 和 iOS 的共享 Vue / Rust 链路

这次重构要让两件事在代码上有明确的所有者。用户请求切换会话时，Rust 能在开始通话的同一个时刻裁决是否允许切换。用户定位一条历史消息后，在线回复、后台恢复和迟到的查询都只能修正正在观察的数据。建议按下面三个阶段实施，每个阶段单独验证。

## 一、生产代码中实际发生了什么

| 路径 | 已核实的行为和影响 |
| --- | --- |
| 开始通话和恢复 | Rust 在第一次异步等待前，以 `callId + TopicKey` 预留通话，快照已有真实 target 和 revision。Vue 却先设 `active = true`，按当前 Pinia 会话填写通话目标，忽略不匹配的恢复快照，并在会话 epoch 变化时同步调用 `end()`。仅删 watcher 会留下恢复后看不到原通话、无法控制设备的问题。[Rust 通话准入](../src-tauri/src/vcp_modules/chat/voice_service/call.rs#L283) · [Vue 通话投影](../src/features/chat/voice/voiceConversation.ts#L99) · [自动挂断入口](../src/features/chat/voice/voiceCallStore.ts#L163) |
| 选择会话 | 当前选中项、话题和每个 owner 上次打开的话题持久化在 Pinia。选择另一个 owner 会先公开 `owner + null`，再等话题列表。分享入口会先加载目标 owner 的列表，列表完成又用这批结果核对当前会话。据此可能用 B 的列表把 A 的话题清空。[会话选择](../src/core/stores/chatSessionStore.ts#L150) · [列表核对](../src/core/stores/topicListManager.ts#L279) · [分享草稿](../src/core/stores/shareStore.ts#L135) |
| 在线回复 | 单聊、普通群聊、JEV 的流式和非流式回复已有共同的持久化路径。消息提交后发 `end`，携带正文、原因、时间及可选渲染块。终态保存失败发可恢复的 `error`，真实模型错误也可以作为一条已保存消息，以 `end(finishReason=error)` 送达。这两种 error 要分别保留。[消息提交](../src-tauri/src/vcp_modules/chat/message_service.rs#L1758) · [现有气泡终态处理](../src/core/stores/chatStreamStore.ts#L1381) |
| 前台恢复 | Rust 重新连接活动请求、待恢复生成和 Android 离线完成文件。如果回复已落库、租约已释放，盘点里可以完全没有它。Vue 对先前活跃、此次缺席的 ID 先记终态标记、移出活动状态，再将当前会话重载为最新 15 条。读取失败还可能丢掉下次核对的身份。通话路径则读最新最多 500 条再合并。通知锚点和恢复即使属于同一话题，也会争写同一个数组。[Rust 重连](../src-tauri/src/vcp_modules/infra/vcp_client.rs#L3020) · [Vue 重连](../src/core/stores/chatStreamStore.ts#L1676) · [语音历史核对](../src/core/stores/chatHistoryStore.ts#L893) |
| 其他窗口写入者 | 通知先查锚点再切会话，聊天页挂载或会话变化又加载最新 5 条。搜索命中已加载消息时只滚动 DOM。键盘、重新生成的收尾、同步与重建完成也有回最新的入口。只改一处 `loadHistory`，其他入口仍能覆盖定位。[通知](../src/App.vue#L275) · [聊天页](../src/features/chat/ChatView.vue#L116) · [搜索](../src/features/globalsearch/GlobalSearchView.vue#L280) · [重新生成](../src/core/stores/chatHistoryStore.ts#L1103) · [同步后重读](../src/core/composables/useDataReload.ts#L19) |

## 二、所有权和身份

| 所有者 | 维护的数据 |
| --- | --- |
| Rust 会话准入 | 本进程已接纳的焦点，可以是欢迎页、仅选中 owner、具体 `TopicKey(ownerType, ownerId, topicId)`。焦点变更有自身版本。通话状态和设备仍归现有 voice owner；请求与群轮仍归各自 owner。 |
| Rust 历史读取与消息存储 | 已接纳的语义窗口、所属话题、稳定游标、成员范围与翻页边界；SQLite 中的正文、附件、渲染和终态。窗口有独立代次，同一话题内连续定位两条消息也能区分。 |
| Vue | 发出用户意图，消费会话、通话和消息投影；维护输入草稿、菜单、手势、滚动跟随、DOM 高亮及像素位置。可保留可丢弃的气泡渲染缓存、Aurora 帧合并、rAF 和按钮等待态。 |

设备本地“上次看哪一话题”继续作为冷启动偏好。仅当 Rust 进程尚无已接纳焦点时才提交该候选，由 Rust 验证 owner 和话题是否存活。WebView 单独重建时，先订阅并读取当前进程的焦点、通话和语义窗口，有活跃通话时恢复它的真实目标。整个进程重启时按已有偏好打开话题的最新页。像素位置不持久化。现有复合主键和话题时间索引能支持这次查询，方案无需新增数据库表、迁移或同步协议版本。[既有身份](../src-tauri/src/vcp_modules/chat/topic_types.rs#L5) · [持久化偏好](../src/core/stores/chatSessionStore.ts#L268) · [数据库索引](../src-tauri/migrations/0100_baseline_v2.sql#L249)

### 跨层接口草案

| 调用 | 输入与返回 |
| --- | --- |
| 打开聊天视图 | 输入当前文档身份、用户意图序号、目标及可选锚点。Rust 校验后一次发布已接纳的焦点和窗口标识，避免先切到 B 再发现 B 的锚点不存在。返回成功、通话阻止、目标缺失或请求已过期；数据库或 IPC 故障沿错误路径反馈。 |

## 三、阶段 1　收回通话与会话切换的裁决权

1. **统一入口。** 在聊天域内增加一个有类型的导航意图，表达欢迎页、选择 owner、打开话题、定位消息。所有入口在用户动作发生时即登记同一份页面内意图顺序，早于等待列表、通知就绪或数据库查询。Rust 标记当前文档及最新请求，读取目标后，在实际写入焦点时再次核对。慢通知 A 后手选 B，即使 B 被拒，A 也不能随后自行切换。旧 WebView 的在途命令不能覆盖新文档。文档身份可复用现有连接代际的识别方式；普通导航不触发语音文档的采集清理。
2. **同一临界区内准入。** 导航提交和 `begin_voice_conversation` 的预留经过同一把短锁，并使用真实 `VoiceCallState`，避免另存一份是否通话的布尔值。导航先查目标，锁内复核并提交焦点。拨号携带发起时看见的焦点版本和完整目标，锁内核对后才预留。拨号先赢，跨话题返回 `call_in_progress`；切换先赢，旧拨号返回已过期。A→B→A 也拒绝第一次 A 发出的迟到拨号。同一话题定位不改焦点版本。数据库、配置、权限和原生音频等待均在锁外，保留已有“挂断先于拨号”的 callId 撤销语义。
3. **投影真实通话。** 删除会话 watcher 的 `end()`，根据 Rust 版本化快照中的 `callId/target/active` 展示通话。挂断按钮发送显式命令，界面跟随对应快照和真实错误；旧通话回复不能覆盖新通话。原生清理失败与 Rust 逻辑通话结束分开反馈。后台、换页和静音沿现有采集生命周期，WebView 恢复不自动开麦。开始通话的回执绑定该次 callId。[通话结束与硬件清理](../src-tauri/src/vcp_modules/chat/voice_service/call.rs#L453) · [既有页面与采集约定](vcpmobile-voice-webview-lifecycle-refactor.md)
4. **接齐入口及其副作用。** 接入侧栏、话题列表、创建后的自动打开、返回欢迎页、通知的两种聊天目标、全局搜索、分享绑定和启动恢复。将 `setConversation/clearCurrentTopic` 等身份写入收为投影内部操作。列表按其完整 owner 核对；部分列表和读取错误没有删除含义。UI 先判断不可关闭的页面，只有当前意图成功后才关闭可关闭的覆盖层、标已读并定位；拒绝仅提示一次，保留草稿和原画面。分享已绑定、新对象已创建而跳转被拒时，分别反馈写入成功和导航受阻，可再次打开已有结果。[创建入口](../src/features/agent/AgentsCreator.vue) · [分享实际写入](../src-tauri/src/vcp_modules/infra/share_inbox.rs#L1180) · [覆盖层关闭条件](../src/core/composables/useModalHistory.ts#L63)
5. **处理真实删除。** 建议本机删除通话目标或其所属 owner 时，在写入前拒绝。删除先获准时按该目标短暂预留，禁止在 SQLite 提交期间开始指向它的通话；回滚释放预留，提交后使相应的旧导航校验失效。远端同步已经提交的删除则是数据库事实：Rust 依完整目标及 callId 清理匹配通话一次，说明“通话目标已删除”，发布新的焦点。其他话题、同名 ID、某条消息被删除或一次列表加载失败均不能结束通话。[本机删除](../src-tauri/src/vcp_modules/chat/topic_service.rs#L243) · [同步删除](../src-tauri/src/vcp_modules/sync/sync_executor/delete_executor.rs#L21)

阶段完成条件是用户所有可达的切换入口都受同一个裁决，拒绝之后没有任何通话取消调用，重建后的页面能看到并显式挂断原通话。

## 四、阶段 2　把历史窗口变成显式观察请求

在同一导航入口上接入两类观察请求：最新窗口和指定消息附近的窗口。向上翻页扩展当前窗口，点击“回到最新”显式更换窗口；保留现有普通发送从深翻处回尾和编辑重发绑定原消息的操作语义。初始通知或搜索定位缺失时提示目标已不存在，原会话和窗口继续可用。已在窗内的搜索命中、消息引用也能把当前阅读位置声明为锚点，复用已有气泡。消息引用沿用仅定位已加载消息的范围。

Rust 复用现有历史行转换器、附件与渲染缓存，以及 SQLite 的 `(timestamp, msg_id)` 排序。打开、向前分页和重新读取都返回实际的两端边界，例如各读一条额外记录判断是否还有数据。查询包括完整话题身份。到达尾端、窗口裁去较新行、用户正在读一个锚点是不同事实。保留当前 500 条内存上限。[历史查询与转换](../src-tauri/src/vcp_modules/chat/message_service.rs#L136) · [锚点读取](../src-tauri/src/vcp_modules/chat/message_service.rs#L389) · [当前窗口容量](../src/core/stores/chatHistoryStore.ts#L54)

| 事件 | 最新窗口 | 锚点或深翻窗口 |
| --- | --- | --- |
| 窗内某条回复结束或更正 | 按完整身份原位更新，不重复插入 | 同样只更新对应气泡；高度变化由 Vue 按可见消息 ID 保持位置 |
| 新回复在窗外完成 | 能接纳时按稳定顺序加入。满窗且正在跟随才允许从旧端裁剪 | 原窗口成员不被新消息挤出，提供“回到最新”。尾窗已满且用户正在读旧消息时也保住当前位置 |
| 历史分页、用户又选了另一个锚点 | 迟到结果须匹配话题、焦点版本及窗口代次 | 同话题从锚点 A 改到 B，也丢弃 A 的旧分页及滚动回调 |
| 正在观察的锚点后来被删除 | 更新或移除相应行 | 优先保留当前窗口内相邻的存活消息，提示原消息已删除。窗口已空则显示空态及“回到最新” |

Vue 依据唯一已接纳窗口投影渲染。去掉 `ChatView` 挂载时另开的最新页请求；启动预取只有在与接纳窗口相符时才可采用。键盘和输入框获得焦点只调整布局，不能把锚窗切成尾窗。初次进入锚窗直接定位目标，`ResizeObserver`、首屏自动置底和媒体迟到变高都不能再把它拉走。翻页时保留现有 DOM 锚点和平移补偿，手指和像素位置留在 Vue。[滚动所有者](../src/core/composables/useChatScroll.ts#L103) · [键盘入口](../src/features/chat/ChatView.vue#L193)

## 五、阶段 3　贯通在线终态与离线恢复

**在线。** 保留现有 Aurora 增量和提交后的 `end`，统一按完整 `MessageKey` 把持久化结果交给窗口。Rust 保留请求取消、群轮接力与 JEV、语音 TTS 各自的所有权。无论气泡是否可见，模型成功、真实错误、显式取消、等待恢复均有原来的业务含义。清理活动占位必须能对上 Rust 的事实。

**断线与重建。** 先接通现有输出，再按本次观察窗口做一次有界 SQLite 核对。热恢复提供窗口已有身份及需要核对的旧占位，Rust 校对窗口内身份并返回变化行、明确移除项和分页边界。对尾窗还要按索引枚举应接纳的新成员，覆盖整个 WebView 离线期间才开始并完成的群聊、JEV 或语音用户消息，也能识别有序区间内的回填。锚窗修正现有成员，窗外变动更新边界。新 WebView 没有任何已见 ID 时，从 Rust 保留的窗口声明建立基线。全程按页和容量限制查询；跨越容量的缺口以“有更新”呈现，不拼成一段虚假的连续历史。

**投递顺序。** 建立输出后再开始查询。在同一窗口读取期间，对已到的持久终态、删除和新增行按键合并；旧基线不能把这些键退回占位或复活。活跃文本沿现有 Aurora 快照和重接机制，不能被旧的数据库占位覆盖。冲突时对受影响键重读；窗口已变则整批作废。缓冲有上限，超限时将当前声明标为需重新核对并重新建立同窗基线。只有成功应用权威结果才移除待核对身份，查库失败可在下次重连重试。创建时间用于排序，`consumerRevision` 用于隔离投递者，`content_hash` 也不能单独区分相同正文的不同终态。这些字段都不充当数据库提交水位。[现有消费者序号](../src-tauri/src/vcp_modules/infra/vcp_client.rs#L480) · [已落库终态重读](../src-tauri/src/vcp_modules/infra/vcp_client.rs#L3785)

**隔离业务副作用。** 窗口修补只走视图投影。不得通过会再喂给 Rust TTS 的请求输出路径重放修补；也不得由新出现的渲染对象触发未读加一、消息数加一、标题总结模型请求或二次震动。真实在线提交保留其反馈，恢复时按已有权威话题统计校准。先验证基线和事件的顺序，再删掉 `chatStreamStore` 中用活动清单缺席推测终态的逻辑及多余的对账集合。保留仍承担渲染、消费者切换或控制在途操作的状态。[Rust TTS 分发](../src-tauri/src/vcp_modules/infra/vcp_client.rs#L540) · [Vue 流回调](../src/core/stores/chatHistoryStore.ts#L488) · [标题总结入口](../src/core/stores/chatHistoryStore.ts#L183)

**替换所有相关重读。** 普通回复与语音共用这条窗口核对路径，移除重连时最新 15 条的替换和语音专用最新 500 条扫描。重新生成按实际删改校对当前窗口，包括失败后已经提交的截断；同步或渲染重建可重新读取同一语义窗口以更新内容、附件或渲染块。用户明确选“回最新”仍可正常读尾页。实现收口在聊天、会话、语音及其真实调用方，不引入全应用事件总线。

## 六、实施验收与提交

| 验收目标 | 能暴露错误实现的操作及断言 |
| --- | --- |
| 通话与切换的竞争 | Rust 测试以屏障固定“拨号预留先到”和“切换先到”两种时序，包含原生初始化未结束、A→B→A、旧文档、同 ID 不同 ownerType。断言同时获准的焦点与通话目标一致；显式挂断后的新切换成功。 |
| 导航失败无副作用 | 使用真实 Pinia session/history/voice 组合，交错手选、通知及搜索；验证同话题可定位、跨话题被拒、旧通知晚到不抢焦点、抽屉及草稿保留、零隐式 end、未读未被误清。创建/分享结果可复开且不会重复写入。 |
| 重建与目标消失 | 原通话在 A，旧偏好为 B 或空，重建后恢复 A、麦克风不自启。分别验证本机删除被拒、同步删除成功、同步事务回滚、重复删除通知及同 owner 下无关话题删除。 |
| 通知锚点与终态闭环 | 真实 SQLite 提交、断开旧输出并释放租约，重连时无需伪造一条 `end`。交换“打开锚窗”和“恢复查询”完成的顺序；同窗查询中再送 live end 或删除。断言目标行、窗口成员、正文及 finishReason，检查迟到帧不改写终态。 |
| 发现离线新行与失败重试 | 整轮群聊在离线时启动并结束，含非流式成员、部分错误和首次出现的语音用户行；校验尾窗全量可达、锚窗不插窗外行。覆盖保存失败再成功、恢复查询失败再重试、相同正文不同终态和同毫秒排序。补投时 TTS、触感、未读、总结均不重复。 |

每阶段跨层实现运行 `pnpm check` 和对应定向用例，Rust 与 Vue 的 IPC 生产端和消费端在同一提交切换。整体验收运行 `cargo test --locked --lib`、`pnpm test:run`、Android arm64 Rust 编译检查及 `pnpm check:ios`。Android 有可用 Debug 设备时记录通知定位、回前台及通话切换的实机结果。Windows 上的 iOS 检查只证明工程输入，不替代 Apple 归档或实机。阶段 2 与 3 共同关闭通知竞态；只有阶段 3 的断线交错测试通过才能宣布修复。

## 七、已批准的行为选择

1. **通话目标消失。** 建议本机删除通话目标时要求先挂断；远端已提交删除时由 Rust 结束匹配的通话并说明原因。平时跨会话只拒绝切换。
2. **锚窗收到新回复。** 建议保留锚点并提示“回到最新”，即使锚点恰好处于最新一条。用户明确发普通消息或点击“回到最新”后转为尾窗。
3. **重启恢复的范围。** 建议同一 Rust 进程内恢复已接纳窗口和逻辑通话，完整进程冷启动只恢复最后的有效话题并看最新页。由此可沿用现有本机偏好及 SQLite 结构。

三项行为和三阶段范围均已批准。实施须同时满足以下条件。

- 本机删除话题、Agent 和 Group 都要在删除事务前与拨号统一仲裁，覆盖级联删除。
- 准入短锁内只比对和更新内存。输入注册、其他锁、原生调用和事件发布均在出锁后进行。
- 保留 `setConversation` 作为底层投影更新及测试构造入口，生产 UI 统一通过导航意图请求切换。
- Rust 按文档登记最新意图序号，在查库前登记，提交焦点时再核对，丢弃晚到的旧查询。
