# 03 — 触发策略与边界分析

> 状态：✅ 最终稿（第 2 轮 Q1-Q5 裁决、第 5 轮 D1/D2 确认、第 6 轮高亮目标锁定第一个 Agent）。

## 1. 核心：前置条件模型（Q4 裁决）

用户第 2 轮定义的前置条件模型（以 `theme-longpress` 为例，其余指引「以此类推」）：

```ts
interface GuideTrigger {
  requires?: string[];   // 依赖的已完成指引 id
  predicates?: { name: string; check: () => boolean }[];  // 状态条件，全部满足才触发
  settleMs?: number;     // 条件齐备后稳定期，默认 600ms 防抖动
}
```

评估机制：guideStore 通过 Vue 响应式收集 predicates 依赖（watchEffect），任何相关 store / 路由 / 页面栈 / 抽屉状态变化后重评估**所有未完成指引**；全部谓词满足且 `requires` 中的指引已完成 → 自动 `start()`（Q1 裁决：自动播放，一次性）。

## 2. 首期四场指引的触发规格

| 指引 id | requires | predicates | 说明 |
|---|---|---|---|
| `sidebar-gestures` | 无 | ①左边栏可见（手机 drawer 打开，或平板 ≥1024px 常驻）②agents ≥2 ③目标行已挂载（定位机制见 02 教学点 3+4） | 首启无 agent 时条件不满足，保持沉默；高亮目标=排位第一个 Agent |
| `theme-longpress` | `sidebar-gestures` | ①当前话题已加载 ②非 system 消息 ≥4 ③标题不匹配默认标题正则 ④左右栏均关闭 | 用户第 2 轮亲自定义的三条前置条件 + 依赖一条 |
| `plus-longpress` | 无 | ①输入框解锁（当前话题存在）②左右栏均关闭 | 「以此类推」的推演（用户确认） |
| `diary-longpress` | 无 | ①日记中心打开 ②可见日记 ≥1 条 | 日记中心是独立页面，无遮挡问题 |

> 识别标准引用：`chatHistoryStore.ts:127-142`——默认标题格式为「新话题 HH:MM:SS」或「新会话 HH:MM:SS」（HH/MM/SS 为两位数字，正则见源码），非 system 消息数 ≥4。

## 3. 逐场景回答

### 场景 A：暂未加载任何话题（聊天框锁定）

- 该状态下四场指引**都不会触发**：`theme-longpress` 缺消息环境（≥4 条），`plus-longpress` 缺输入框解锁，`sidebar-gestures` 需先打开左边栏，`diary-longpress` 需打开日记中心。
- 教学保持沉默，等待用户自然推进（打开左边栏 / 创建数据 / 加载话题）。

### 场景 B：全新 APK 首启（未填设置、无 agent、聊天框封禁）

- **模型推论：首启没有任何指引可播**（Q4 前置条件模型的自然结果，已由用户确认 D1=A，见 04 文档）。
- 最早可能触发的是 `sidebar-gestures`：用户创建出 ≥2 个 agent 并打开左边栏（agents 页签、目标行已挂载）时。
- `theme-longpress` 因依赖 `sidebar-gestures` 完成，必然在其之后；且需要 ≥4 条消息的非默认标题话题 + 干净主界面。
- 教学与「填设置」互不冲突：指引仅 1–2 步，点完末步「我知道了」即退出并记录完成态，永不再扰。

### 场景 C：触发链总览

```text
sidebar-gestures ──(完成)──> theme-longpress（等消息环境 + 干净主界面）
                 └─（独立）──> plus-longpress（等输入框解锁）
                 └─（独立）──> diary-longpress（等打开日记中心）
```

## 4. 边界清单（含 Q3/Q5 修订）

| 边界 | 处理 |
|---|---|
| 系统返回键 | **指引激活期间完全禁止**（Q5）：registerModal 的 close 返回 false（复用 syncSession canDismiss 模式），唯一退出出口 = 末步「我知道了」 |
| 用户手势 | **不检测**（Q3）：长按/右滑/拖拽全部用内建演示动画展示，步骤推进只靠卡片按钮 |
| 真实业务 | **不触发**（Q3）：演示期间黑纱拦截一切事件，无副作用 |
| 目标元素不可见/不存在 | waitFor 轮询（100ms/3s）超时 → 静默**越过**该步；整场步骤全不可解析 → finish 并记录完成态，防死循环 |
| 播放中途旋转/折叠宽度变化 | ResizeObserver + window resize 重算聚光矩形与卡片方位 |
| 软键盘弹起 | 监听 vcp-keyboard-inset 重算方位 |
| 播放中切后台再回来 | vcp-lifecycle-changed resume 时重算几何，不自动终止 |
| 多场同时满足触发条件 | pendingQueue 排队串行播放，不叠加黑纱 |
| 教学期间 PermissionGate（110 层）弹出 | gate 高于 guide(95)，属预期覆盖；v1 教学点全部避开权限步骤 |
| 教学期间收到分享 Intent/通知 | 事件由教学层拦截，指引结束后再处理 |
| 首启黑纱与 BootScreen 时序 | GuideOverlay 仅在 lifecycle READY 后挂载（与 GlobalOverlayManager 同门禁） |

## 5. 与版本门控的关系

- 上述 4 场是「交互认知类」指引：永久有效、按前置条件触发、完成一次即可。
- 未来「新功能指引」走版本门控：`introducedIn > lastSeenAppVersion` 时入队，Toast 提示「查看 vX.X 新功能指引」，不强制打断。两类指引共用同一引擎与 pendingQueue。
