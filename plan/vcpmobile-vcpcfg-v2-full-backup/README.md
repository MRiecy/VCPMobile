# VCPMobile V2 全局配置备份与恢复架构重构方案 (vcpcfg)

## 专项概述

本专项方案针对 VCP Mobile 在经历百余次提交、主功能收敛后的配置备份体系（`.vcpcfg.json`）展开深度技术重构设计。

### 核心目标与解决的关键问题

1. **突破“仅全局设置”局限，走向全局非同步数据核心持久备份**：
   - 传统 v1 与早期 v2-dev 配置仅包含连接、身份、语音及部分 UI 偏好。
   - 现将配置导出能力提升为 **“所有非同步数据配置”** 的全量持久备份，涵盖 Agent 移动端提示词/独立音色/温度参数、Group 本机模式/JEV 参数/上下文窗口、模型收藏、Tarven 规则库以及前端 Pinia 关键持久偏好。
2. **解决“空机导入”与“数据同步”时序倒挂难题（两阶段恢复机制）**：
   - 解决空机首次安装时，无 Agent/Group 实体导致配置无处附着的物理事实。
   - 确立基于 `agent_id` / `group_id` 强绑定的静默跳过与延迟恢复（Deferred/Staged Re-apply）机制。
3. **系统梳理前端 Pinia 持久化缓存**：
   - 全面审计全工程 20+ 个 Store 与数十个 localStorage 键。
   - 建立“全局偏好”、“实体绑定偏好”、“离线业务库”与“运行时易失状态”四级清晰分类边界。
4. **全新新手引导教程与首次同步后智能恢复闭环**：
   - 结合现有 Guide (Coachmark) 引擎，设计开屏引导教程，指引用户“先导配置 → 连接同步 → 恢复本体”。
   - 在数据同步首次完成并刷新时，提供智能弹窗/横幅一键恢复未应用的本地配置。
5. **版本兼容性保证**：
   - 严格遵循用户指令，**版本号继续保持 V2**（开发期平滑演进）。
   - 保持对 v1 遗留配置、早期 v2 配置的单向兼容与向前演进能力。

### 重构奠定的 7 项核心架构基石

1. **Rust 单一写事务与锁序保障**：`SettingsState` / `SettingsRepository.writer` 写锁优先，在单条 SQLite 事务中完成全局配置、助手本地列、群组本地设置与独立数据表提交；
2. **Agent 本地列与同步哈希绝对隔离**：仅更新 `mobile_system_prompt`、`use_temperature` 与 `voice_config`，SQL 写入显式保护 `config_hash` 与 `updated_at` 不被篡改，杜绝反向脏同步；
3. **Group 本地配置对等匹配与墓碑免疫**：复用并对齐 `group_local_settings` 匹配机制，存活实体合并写入，缺失实体记为 `missing`，墓碑实体静默跳过绝不复活；
4. **独立业务表完整纳入与预置防冲**：`model_favorites` 与 `tarven_rules` 作为 `standaloneData` 独立备份；Tarven 预置规则恢复时保护内核逻辑仅同步启用开关；
5. **Pinia 持久化四级分流边界**：明确通用客户端偏好、实体弱绑定偏好、独立离线业务数据与运行时易失黑名单；
6. **两阶段恢复与暂存快照免重选**：首屏预配置恢复网络与偏好并将待生效实体偏好暂存，首次 CDS 同步完成后智能提示一键应用，免除用户二次选文件；
7. **契约自动生成与向下兼容**：`ConfigBackupImportResult` 经 `ts_rs` 派生，运行 `pnpm config:generate` 自动保证前后端类型一致；物理上强制执行 1 MiB 读取硬限。
