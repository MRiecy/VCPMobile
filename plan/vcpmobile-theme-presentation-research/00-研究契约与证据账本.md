# 00. 研究契约与证据账本

## 1. 目标拆解

本专项只输出研究分析与可施工文档，不在本阶段修改业务代码。用户原始目标拆为以下可验收要求：

| ID | 明确要求 | 本专项交付 |
|---|---|---|
| R-01 | VCPMobile 支持“气泡、统一、刊物”三种模式 | 给出桌面语义映射、移动端状态与 CSS 契约 |
| R-02 | 入口位于深浅模式按钮的长按操作 | 给出短按/长按隔离、弹层、返回手势与可访问性方案 |
| R-03 | 主题设置页加入桌面端“实时预览” | 给出 dark/light 双栏局部预览数据与布局方案 |
| R-04 | 与桌面端一样，点击确认后才应用 | 冻结 draft/applied 两阶段状态和唯一提交点 |
| R-05 | 不再纵向铺开长主题列表 | 冻结横向 snap 视口和手机/平板卡片密度 |
| R-06 | 实时预览与主题选择尽量同屏 | 给出唯一纵向尺寸 owner、低高度降级和固定确认区 |
| R-07 | 考虑手机、平板和窗口变化 | 只按当前 CSS viewport 响应，不按机型/UA 分叉 |
| R-08 | 结果写成数个 Markdown，放入 `/plan` 专项目录 | 本目录 `README` + `00`—`06` |

## 3. 调研方法

本轮执行的是源码与历史证据核对，没有依赖截图猜测：

1. 读取 VCPMobile 根 `AGENTS.md`、Android UI 兼容规范和测试架构约束；
2. 追踪 VCPMobile 的 `themeStore → ThemePicker → SettingsView → ChatView → MessageRenderer/ChatBubble`；
3. 追踪 `useChatScroll`、`v-longpress`、`overlayStore/ContextMenuSheet` 的交互与滚动 owner；
4. 只读检索 VCPChat 的快捷入口、设置项、模式归一化/持久化/回滚、CSS 分支和主题选择窗口；
5. 使用 `git log -S` 定位桌面功能的历史来源，再以当前 HEAD 为最终事实；
6. 追溯 Mobile 从逐主题 CSS 到 TS 映射的转换提交、临时归档与删除记录；
7. 搜索两端现有测试，区分“代码存在”和“行为已被自动化证明”。

没有运行 VCPChat 桌面应用，也没有在 Android 真机上渲染候选布局。因此本文能证明源码结构和可实施性，不能证明视觉完成、触控手感或设备兼容已经通过。

## 5. 已证实、推断与待验证

| 结论 | 证据等级 | 说明 |
|---|---|---|
| 三种桌面模式复用同一消息 DOM | 已证实 | 当前代码以 body class 和 CSS selector 改外壳 |
| 桌面主题选择是候选预览、按钮提交 | 已证实 | `selectedTheme` 与 `applyTheme` 调用点分离 |
| Mobile 主题卡当前点击即全局生效 | 已证实 | `ThemePicker` 直接调用 `applyThemeFile` |
| Mobile 逐主题运行时源已经完全转为 TS | 已证实 | 当前树、glob、转换提交与 CSS 归档删除记录一致 |
| Mobile 可以纯前端实现三模式 | 强推断 | 所需 owner、持久化、overlay、DOM 与 CSS 均在前端；不依赖后端数据 |
| 三模式切换不会破坏全部富内容 | 待实现验证 | 架构允许，但需 fixture、流式与真机回归证明 |
| 预览和主题选择可在所有目标设备完全同屏 | 待设备验证 | 可通过响应式预算提高概率，但字体、Insets、低高度窗口需真机证据 |

## 6. 研究边界

本专项不包含：

- 修改 VCPChat 或把 Electron 的复制主题文件/整窗刷新机制移植到 Android；
- 恢复逐主题 CSS 文件、CSS raw/inline loader，或把旧 `.css` 别名提升回运行时主题源；
- 新增主题包、编辑主题变量或改变 13 个现有主题的艺术内容；
- 新增自定义气泡宽度、字体设置或桌面 `enableUserChatBubbleUi` 等额外选项；
- 将消息呈现偏好纳入跨设备同步；
- 为平板复制一套独立页面或引入桌面产品入口；
- 以 happy-dom、浏览器 viewport 或静态 CSS 检查冒充 Android WebView 真机验收。
