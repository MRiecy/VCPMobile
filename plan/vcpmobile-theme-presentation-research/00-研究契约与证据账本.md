## 3. 调研方法

本轮执行的是源码与历史证据核对，没有依赖截图猜测：

1. 读取 VCPMobile 根 `AGENTS.md`、Android UI 兼容规范和测试架构约束；
2. 追踪 VCPMobile 的 `themeStore → ThemePicker → SettingsView → ChatView → MessageRenderer/ChatBubble`；
3. 追踪 `useChatScroll`、`v-longpress`、`overlayStore/ContextMenuSheet` 的交互与滚动 owner；
4. 只读检索 VCPChat 的快捷入口、设置项、模式归一化/持久化/回滚、CSS 分支和主题选择窗口；
5. 使用 `git log -S` 定位桌面功能的历史来源，再以当前 HEAD 为最终事实；
6. 追溯 Mobile 从逐主题 CSS 到 TS 映射的转换提交、临时归档与删除记录；
7. 搜索两端现有测试，区分“代码存在”和“行为已被自动化证明”。

没有运行 VCPChat 桌面应用，也没有在 Android 真机上渲染候选布局。因此本文能证明源码结构和可实施性，不能证明视觉完成、触控手感或设备兼容已经通过。

实施完成后已补齐 host 软件证据：全量 Vitest、`pnpm check`、production build、生成物扫描与 diff check 均通过。随后在 OPPO PHZ110 上通过 USB Debug 完成手机核心旅程；该证据只覆盖这台现代 WebView 手机，不外推为平板、分屏/折叠、最低 WebView 或全部强渲染 fixture 的设备验收。

## 6. 研究边界

本专项不包含：

- 修改 VCPChat 或把 Electron 的复制主题文件/整窗刷新机制移植到 Android；
- 恢复逐主题 CSS 文件、CSS raw/inline loader，或把旧 `.css` 别名提升回运行时主题源；
- 新增主题包、编辑主题变量或改变 13 个现有主题的艺术内容；
- 新增自定义气泡/内容百分比宽度、字体设置或桌面 `enableUserChatBubbleUi` 等额外选项；
- 将消息呈现偏好纳入跨设备同步；
- 为平板复制一套独立页面或引入桌面产品入口；
- 以 happy-dom、浏览器 viewport 或静态 CSS 检查冒充 Android WebView 真机验收。
