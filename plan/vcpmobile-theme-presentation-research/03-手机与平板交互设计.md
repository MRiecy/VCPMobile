# 03. 手机与平板交互设计

## 1. 设计目标

这次不是把桌面主题窗口缩小，而是把两条高频旅程变成触控原生操作：

1. 在聊天中不离开上下文，长按深浅按钮快速切换消息呈现；
2. 在主题页横向浏览候选，一边看 dark/light 实时预览，一次确认后再影响全局。

视觉遵循高密度线性布局、灰度优先、2px Accent Bar、轻动画与内容区禁 blur。主题本身可以提供彩色壁纸和 token，但选择器的结构反馈不依赖大阴影或夸张缩放。

## 2. 顶栏长按入口

### 2.1 手势契约

| 手势 | 结果 | 不应发生 |
|---|---|---|
| 短按 | 在当前 resolved 深浅基础上切换 light/dark | 不打开呈现菜单 |
| 长按 600 ms | 轻触觉反馈并打开三模式菜单 | 不切换深浅模式 |
| 长按中移动/取消 | 取消计时 | 不打开菜单、不切深浅 |
| 菜单点遮罩/返回 | 关闭菜单 | 不改变当前模式 |
| 点模式 | 立即应用、保存、保持阅读锚点、关闭菜单 | 不重建消息列表 |

按钮无障碍名称建议为：`切换深浅模式，长按切换消息呈现`，并声明 `aria-haspopup="dialog"` 与 `aria-expanded`。长按成功可调用已有能力范围内的 `navigator.vibrate(25)`；无振动 API 时静默降级。

### 2.2 选择面板

使用紧凑 ContextMenuSheet，而不是占据 85% 屏幕的模型选择器：

```text
┌──────────────────────────────┐
│ 消息呈现                     │
├──────────────────────────────┤
│▌ 气泡                       ✓│
│  统一                         │
│  刊物                         │
└──────────────────────────────┘
```

- 三个标签保持用户指定的短名称；
- 当前项使用 2px Accent Bar + check，不能只靠颜色；
- 每项触控高度不小于 48 CSS px；
- 面板位于 `z-dialog`，通过既有 modal history 接受 Android 返回；
- 不使用 backdrop blur；遮罩为稳定半透明实色；
- 当前项再次点击只关闭面板，不重复写入或触发重排。

首次发现性不增加永久提示条。可在按钮 `aria-label` 和主题设置页的“消息呈现”说明中提供可发现入口；若后续真机反馈表明长按难以发现，再单独评估一次性提示，不在本期预埋 onboarding 状态机。

## 3. 三种消息布局

### 3.1 气泡

保持当前界面，作为零回归基线：

```text
[AI头像 名称]
[AI 气泡────────]
  10:24

             [用户头像 名称]
             [────用户气泡]
                       10:25
```

### 3.2 统一

```text
┌──────────────────────────────┐
│ [AI头像] 名称                │
│ 正文、代码、工具块……         │
├──────────────────────────────┤
│ [用户头像] 用户              │
│ 正文……                 10:25 │
├──────────────────────────────┤
│ [AI头像] 名称                │
│ 正文……                       │
└──────────────────────────────┘
```

- 消息连续面铺满聊天可用宽度；
- 头像统一放左，用户不再右对齐；
- 外层气泡完全扁平化；
- 时间为次要元信息；
- 消息间只用 1px 分隔线，不使用卡片堆叠；
- 列表表面使用主题实色/高不透明 token，无内容区毛玻璃。

### 3.3 刊物

```text
          Agent 名称
          10:24

    这是居中阅读栏中的正文。它隐藏头像，
    保留来源和时间，正文行高更舒展。

    [工具 / 日记 / 代码仍保留自身结构]

    ──────────────────────────

          用户 · 10:25
    下一段正文……
```

- 隐藏头像，不隐藏发送者和时间；
- 手机使用 `width: calc(100% - 32px)`，不再额外套大卡片；
- 宽窗口使用 `max-width: 46rem` 的居中阅读栏；
- 推荐正文行高约 `1.7`，但代码、表格、工具和日记沿用各自规则；
- 流式状态保留文字/状态标签，禁用围绕整个透明阅读栏的流光边框；
- 多个分条气泡仍保持顺序，非首段不重复头像，时间只在末段出现。

## 4. 主题设置页总体结构

### 4.1 手机竖屏

```text
┌──────────────────────────────┐
│ ‹ 主题切换                   │  Header + safe top
├──────────────────────────────┤
│ 实时预览          候选：熊熊假日│
│ ┌──────────┬──────────┐      │
│ │ 深色     │ 浅色     │      │  约 180–220px
│ │ AI 消息  │ AI 消息  │      │
│ │   用户   │   用户   │      │
│ └──────────┴──────────┘      │
│                              │
│ 主题  05 / 13                │
│ ◁ [前卡][  主卡  ][后卡] ▷   │  横向滑动，露出相邻卡
│        熊熊假日              │
│                              │
├──────────────────────────────┤
│ [ 已应用 ] / [ 确认应用 ]    │  Footer + safe bottom
└──────────────────────────────┘
```

正常高度下页面没有纵向滚动。预览首先占用可压缩高度，主题 rail 固定约 128–152px，确认区固定在底部安全区之上。

### 4.2 平板与宽窗口

```text
┌──────────────────────────────────────────────────────┐
│ ‹ 主题切换                                           │
├──────────────────────────────────────────────────────┤
│ 实时预览                                             │
│ ┌──────────────────────┬──────────────────────┐      │
│ │ 深色完整预览         │ 浅色完整预览         │      │
│ └──────────────────────┴──────────────────────┘      │
│                                                      │
│ 主题  05 / 13                                        │
│ [主题 A] [主题 B] [候选 C] [主题 D 的一部分 →]       │
├──────────────────────────────────────────────────────┤
│                                      [确认应用]      │
└──────────────────────────────────────────────────────┘
```

仍然是同一组件和同一横向 rail，只通过可用宽度增加卡片数，不改为平板专属网格，也不按设备名称分支。

## 5. 横向主题视口

### 5.1 响应式密度

建议以组件可用宽度而非 UA 决定卡宽：

| 可用宽度 | 可见密度 | 目标 |
|---|---|---|
| `<480px` | 1 个主卡 + 两侧预告 | 单手聚焦，仍提示可横滑 |
| `480–839px` | 2 个完整卡 + 下一卡预告 | 大手机、折叠/分屏、窄平板 |
| `>=840px` | 3 个完整卡 + 下一卡预告 | 平板与宽窗口 |

卡片使用 `scroll-snap-align: center`，rail 使用 `scroll-snap-type: x mandatory`、`overscroll-behavior-x: contain` 和隐藏滚动条。不要加入循环克隆、无限轮播或自动播放。

### 5.2 选择语义

- 打开主题页时，先把实际 `currentTheme` 的旧 `.css` 别名归一化为 TS module key，再把草稿定位到对应候选，而不是主题数组第一项；
- 点击卡片立即成为候选并更新实时预览；
- 横滑停止后，离视口中心最近的卡片成为候选；
- 不依赖 `scrollend`，使用 rAF 节流测量 + 80—120 ms 空闲防抖，以兼容冻结的 Chrome 87 生成目标；
- rail 上方显示 `当前序号 / 总数` 和候选名称，13 个主题不画 13 个微小圆点；
- 候选卡用 2px Accent Bar/边框和 check 表达，避免 `scale-95` 导致 snap 几何抖动；
- 触发候选只更新内存 `draftThemeKey`，`localStorage`、`currentTheme`、根 CSS 和聊天壁纸保持不变。

## 6. 实时预览

### 6.1 预览内容

每个候选同时渲染 dark 与 light pane。每个 pane 至少展示：

- 对应壁纸与稳定颜色遮罩；
- 小型 header/title；
- 一条 Agent 消息；
- 一条用户消息；
- 一个主题强调色按钮或状态条；
- `深色` / `浅色` 文本标签。

这比桌面的纯 skeleton 更贴近 Mobile 的主题消费点，但仍是轻量 mock，不挂载真实 `MessageRenderer`、Mermaid 或 WebGL。

### 6.2 预览数据绑定

候选数据直接来自已编译 TS `ThemeInfo.variables.dark/light`，只绑定到 preview pane 的局部 CSS custom properties：

```text
--preview-bg
--preview-panel
--preview-primary-text
--preview-secondary-text
--preview-agent-bubble
--preview-user-bubble
--preview-accent
--preview-border
```

壁纸 URL 从编译期可信主题变量中解析为 `/wallpaper/<basename>.webp`。不用 `v-html`，不把候选变量写入根元素，也不执行候选 `extraCss`。预览失败时回退纯色，不影响确认按钮和已应用主题。

## 7. 草稿与确认状态

主题页状态机只有四态，不引入跨页 store：

```text
CLEAN
  └─ 选择不同主题 → DIRTY
DIRTY
  ├─ 继续选择 → DIRTY（替换 draft）
  ├─ 确认 → APPLYING
  └─ 返回/关闭 → unmount，丢弃 draft
APPLYING
  ├─ 成功 → CLEAN（applied = draft）
  └─ 失败 → ERROR（全局仍是原 applied）
ERROR
  ├─ 重试 → APPLYING
  └─ 继续选择 → DIRTY
```

按钮文案：

| 状态 | 文案 | 行为 |
|---|---|---|
| CLEAN | 已应用 | disabled，不产生写入 |
| DIRTY | 确认应用 | 单次提交候选 |
| APPLYING | 正在应用… | disabled，防重复点击 |
| ERROR | 重试应用 | 保留候选，显示简短错误 |

返回不弹“是否放弃”确认框，因为候选从未影响真实界面，重新选择成本低。页面可在 rail 附近以低干扰文字说明“预览不会立即修改当前主题”。

## 8. 低高度与字体放大

布局压缩顺序冻结为：

1. 减少预览上下内边距；
2. 将预览高度从约 220px 压缩到约 150px；
3. 将主题卡高度从约 136px 压缩到约 112px；
4. 保持触控目标至少 48px、确认区和标题文本完整；
5. 仍不足时，整个主题内容区启用唯一纵向滚动，确认区可 sticky；不隐藏预览、不隐藏主题、不把文字裁成不可读状态。

字体 1.5× 时允许标题/说明换行；卡片主题名最多两行，序号不依赖绝对定位。手机横屏和分屏窄窗必须优先保证确认按钮可达，而不是强求无滚动。

## 9. 动效与性能

- 模式切换不做整列表 scale/slide；只允许颜色/opacity 的短过渡，布局重排本身不动画；
- 主题 rail 使用原生惯性滚动和 CSS snap，不实现逐帧物理引擎；
- 预览只渲染两个固定 pane，不为 13 个主题同时挂载完整预览；
- 非当前卡只显示双壁纸缩略面，不运行持续动画；
- 遵守 `prefers-reduced-motion`，关闭卡片和弹层的非必要过渡；
- 内容区与主题卡均不用 `backdrop-filter`；
- 不使用 WebGL、Canvas 或大面积持续阴影表达选中态。

## 10. 用户可见验收句

功能完成后，用户应能自然说出：

> 我短按太阳/月亮只切明暗；长按会出现气泡、统一、刊物。主题页面里左右滑就能换候选，深浅效果同时看得到，但聊天界面要等我按“确认应用”才会真的变化。
