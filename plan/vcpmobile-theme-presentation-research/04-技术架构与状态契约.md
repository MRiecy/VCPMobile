# 04. 技术架构与状态契约

## 1. 总体架构

首选架构只有一个外观 Store、一个消息组件树、一个滚动 owner 和一个主题草稿 owner：

```text
                         ┌─ light / dark / system
themeStore ──────────────┼─ applied TS theme module key
                         └─ bubble / panel / immersive
                                  │
                                  ▼
ChatView[data-presentation-mode] ──► 现有 MessageRenderer 树
          │                                  │
          └─ useChatScroll 锚定 ─────────────┘

ThemePicker local draft
  ├─ ThemeCarousel
  ├─ dark/light LivePreview（局部变量）
  ├─ confirm ───────────────► themeStore.applyThemeFile()
  └─ presentation radio ────► themeStore.setPresentationMode()
```

`ThemePicker` 拥有未提交草稿，`themeStore` 只拥有已经应用的事实。Store 不查询聊天 DOM，ChatView 不解析主题文件，预览不注入根 CSS。

## 2. 类型与命名

```ts
export const CHAT_PRESENTATION_MODES = [
  'bubble',
  'panel',
  'immersive',
] as const;

export type ChatPresentationMode =
  (typeof CHAT_PRESENTATION_MODES)[number];

export const normalizeChatPresentationMode = (
  value: unknown,
): ChatPresentationMode =>
  CHAT_PRESENTATION_MODES.includes(value as ChatPresentationMode)
    ? (value as ChatPresentationMode)
    : 'bubble';
```

`ThemeMode` 继续只表示深浅来源。禁止把新字段命名成另一个含糊的 `mode`，也禁止用中文标签作为持久化值。

## 3. 呈现模式 owner

### 3.1 Store 契约

在 `useThemeStore` 中增加：

```text
presentationMode: Ref<ChatPresentationMode>
setPresentationMode(candidate): PresentationChangeResult
```

持久化 key：`vcp-chat-presentation-mode`。

初始化顺序：

1. 读取字符串；
2. 通过唯一 normalizer 校验；
3. 非法或缺失回退 `bubble`；
4. 非法旧值可覆写为规范值，避免每次启动重复进入恢复分支；
5. `ChatView` 通过响应式 data attribute 呈现，不由 Store 操作 DOM class。

提交顺序：

1. normalize candidate；
2. 若与当前值相同，返回 `changed: false`；
3. 先尝试写本地偏好；
4. 成功后更新 ref；
5. 写入失败则保持原值，并返回错误供 UI toast；不制造“本次会话变了、重启又丢失”的隐式状态。

不增加 watcher 自动持久化，避免初始化、回退和 UI 提交形成多个写入点。

### 3.2 DOM 作用域

在 `ChatView` 根节点增加：

```vue
<div
  class="chat-view-container"
  :data-presentation-mode="themeStore.presentationMode"
>
```

CSS 统一以：

```css
.chat-view-container[data-presentation-mode="panel"] ...
.chat-view-container[data-presentation-mode="immersive"] ...
```

为作用域。不要污染 `body`，因为 Settings、Diary、RAG 等覆盖层不应继承聊天呈现规则；也不要在每个富内容块上传递 mode prop。

## 4. 长按与 click 隔离

复用全局 directive，但以显式 modifier 扩展而不是改变所有既有调用：

```vue
<button
  @click="handleThemeShortClick"
  v-longpress.suppress-click="openPresentationMenu"
>
```

`vLongpress` 的可选 `suppress-click` 契约：

- 只有计时器真正触发回调后才设置 `didLongPress`；
- 在 capture phase 消费随后的第一个 click：`preventDefault()` + `stopImmediatePropagation()`；
- touch/mouse move、cancel 或未达到阈值时不抑制正常 click；
- 若 WebView 没有派发合成 click，抑制标记在 touchend/mouseup 后的短窗口自动过期；
- contextmenu 与 touch timer 通过一次手势 token 幂等，不能打开两次；
- modifier 未使用时，现有 Topic/Message/Diary 长按语义不变。

这比 ChatView 中永久保留一个布尔 guard 更可靠：不会因某设备未派发合成 click 而吃掉用户下一次真实短按，也不会静默改变所有现有长按入口。

## 5. 模式选择 Overlay

复用 `overlayStore.openContextMenu`。对 `OverlayActionItem` 增加唯一可选字段：

```ts
selected?: boolean;
```

`ContextMenuSheet` 在 actions 中存在 `selected` 字段时：

- action 容器声明 `role="radiogroup"`；
- 每个 action 声明 `role="radio"` 和 `aria-checked`；
- selected action 使用 2px Accent Bar 和 check；
- 不依赖完整 className 串供测试；提供稳定 `data-selected`；
- selected action 的 handler 可以幂等调用 Store，随后正常关闭。

三项由同一常量生成，禁止在菜单、Store 和 CSS 各写一份不同顺序的字符串表。

## 6. 滚动锚定

### 6.1 捕获规则

在 `useChatScroll` 内复用并泛化现有消息锚点逻辑：

```ts
interface ViewportAnchor {
  stickToBottom: boolean;
  messageId?: string;
  viewportOffset?: number;
}
```

- 若 `scrollHeight - scrollTop - clientHeight < 150`，记录 `stickToBottom`；
- 否则取 DOM 顺序中第一个与 viewport 相交的 `[data-message-id]`；
- 允许 `viewportOffset` 为负，表示该消息顶部已经滚出一部分；
- 找不到消息时才回退原 `scrollTop`。

### 6.2 应用规则

由 `useChatScroll` 暴露：

```text
preserveViewportAcrossLayoutChange(change)
```

执行：捕获 → 调用 `change` → `nextTick` → 等布局帧 → 恢复。接近底部的用户继续贴底；正在读历史的用户回到同一消息的同一视觉 offset。

Store 只提交值。为同时覆盖聊天页长按入口和主题页第二入口，ChatView 对 `presentationMode` 使用 `flush: 'pre'` 的响应式 watcher：旧 DOM 尚未 patch 时捕获锚点，再通过 `preserveViewportAcrossLayoutChange` 等待 `nextTick` 与双 rAF 后恢复。不得只在某一个 click handler 周围包事务，否则另一个入口会漏掉保护。`ResizeObserver` 的 following 分支与手工恢复不能互相争夺；事务期间使用短生命周期的 layout-changing guard，恢复后立即释放并重新测量 `lastScrollHeight`。重叠事务只允许最新 generation 恢复，组件销毁会淘汰待处理事务和排帧。

## 7. 消息 DOM 与 CSS 契约

### 7.1 允许的语义标记

只给现有根节点补以下稳定 class：

| 组件 | 语义 class | 用途 |
|---|---|---|
| `MessageHeader` root | `vcp-message-header` | 对齐、重复 header、刊物元信息 |
| `ChatAvatar` root | `vcp-message-avatar` | 刊物隐藏头像 |
| `ChatBubble` root | `vcp-chat-bubble` | 拉伸、分条间距、末段时间 |
| timestamp | `vcp-message-time` | 非末段时间控制 |

不改变 message key、block key、`data-message-id` 或组件层级 owner。

### 7.2 Panel 样式边界

`panel` 只处理：

- `.messages-inner-container` 的连续稳定表面；
- `.vcp-message-item` 的全宽、padding 和相邻分隔线；
- Header 统一左对齐；
- `.vcp-chat-bubble` 拉伸；
- `.vcp-bubble-container` 外层背景/边框/圆角/阴影清零；
- 非首个分条 Header、非末个分条时间的去重；
- 外层 streaming border 关闭。

### 7.3 Immersive 样式边界

`immersive` 在 panel 扁平化基础上：

- 隐藏 `.vcp-message-avatar`；
- 让 Header、Bubble 和时间进入同一最大宽度阅读栏；
- 调整正文外层行高与段落节奏；
- 使用留白 + 细线分隔；
- 手机与平板用 `min()`/media query 改同一 max-width token。

### 7.4 强渲染保护

呈现 CSS 只能命中消息**外壳**。以下组件的背景、border、overflow、按钮和交互不得被通配清零：

- `ToolBlock` / `ToolSummaryBlock`；
- `ThoughtBlock`；
- `DiaryBlock` / DailyNote；
- `HtmlPreviewBlock`；
- `AttachmentPreview` / Viewer；
- `pre`、代码复制、KaTeX、Mermaid；
- 受控 raw HTML 和消息作用域 CSS。

特别禁止 `.vcp-message-item * { background: transparent }` 一类宽泛规则。模式规则应止于 `.vcp-bubble-container`，内部结构化表面自然继承现有主题。

### 7.5 WebView fallback

- 结构尺寸、display、overflow、分隔线必须使用 Chrome 87 基线内语法；
- `background-color: var(--vcp-panel-bg-90)` 先提供稳定结果；
- 如需 `color-mix()` 只能在后置 `@supports` 中增强；
- panel/immersive 选择器内不得出现 `backdrop-filter`；
- 不把 `content-visibility` 当作内容存在条件；
- 模式切换不永久添加 `will-change`。

## 8. 主题草稿与正式提交

### 8.1 主题源与标识边界

运行时主题源保持现状：

```ts
const themeModules = import.meta.glob(
  '../../assets/themes/*.ts',
  { eager: true },
);
```

`ThemeInfo.fileName` 当前由 glob 路径取得，语义是 `.ts` 模块 basename。主题模块中的 `meta.fileName: '*.css'`、`DEFAULT_THEME` 和 `LEGACY_THEME_MAP` 是旧版兼容信息，不是可读取的 CSS 资产。实现时提供一个唯一的 `normalizeThemeModuleKey(input)`：

1. 只接受 basename，不接受目录和 URL；
2. 先处理已知中文 legacy 名，再把兼容 `.css` 后缀转换为 `.ts`；
3. 必须命中 `themeModules` 中的现有 key 才算合法；
4. runtime current、draft、selected 与成功持久化均使用 `.ts` module key；
5. `.css` 只在启动旧值、旧事件 payload 等输入边界被接受，不建立第二份候选表。

本专项不要求批量改写 13 个模块的 `meta.fileName`；它可继续作为原 CSS 名的兼容元数据，运行时身份仍以 glob 路径导出的 TS key 为准。不得恢复逐主题 CSS、解析 CSS 文本或照搬 VCPChat 的复制 CSS 流程。开发态 Vite HMR 仍以 TS 模块为入口，继续自动重新应用**已经应用的模块**；“确认后应用”约束的是用户在 ThemePicker 中挑选候选，不禁止开发者编辑当前 TS 主题时热更新。

### 8.2 局部状态

`ThemePicker` 内部拥有：

```text
draftThemeKey
isApplying
applyError
carouselIndex
```

同页的消息呈现单选不是 theme draft 字段；它直接读取 `themeStore.presentationMode` 并调用共享 setter。这样“确认应用主题”仍是主题配色的唯一提交点，而消息呈现继续保持快捷设置语义。

派生状态：

```text
appliedThemeKey = normalizeThemeModuleKey(themeStore.currentTheme)
draftTheme = availableThemes.find(theme => theme.fileName === draftThemeKey)
isDirty = draftThemeKey !== appliedThemeKey
```

挂载时先 `fetchThemes()`，随后用归一化后的实际 `currentTheme` 初始化并滚入视口；只有该 TS 模块确实不存在时才回退默认主题。组件卸载即丢弃草稿。

如果 `onThemeUpdated` 在页面打开时改变已应用主题：

- 草稿未修改：跟随归一化后的新 `currentTheme`；
- 草稿已修改：保留用户候选，`isDirty` 按新的 applied 值重新计算；
- 不自动确认，不把外部主题写回候选。

### 8.3 主题正式提交

`applyThemeFile` 需要从“无结果的立即副作用”收敛成可判断的逻辑原子操作：

1. 把 legacy `.css` 别名或 TS 输入规范化为 `.ts` module key；
2. 在现有 TS glob 中查找并验证模块、dark/light 变量与 meta；
3. 准备目标变量和 `extraCss`；
4. 注入目标变量/extraCss；
5. 更新 `currentThemeModule/currentThemeInfo/currentTheme`，其中 `currentTheme` 使用 TS key；
6. 最后把 TS key 写入 `localStorage['vcp-theme-name']`；
7. 返回 success；失败时恢复旧模块、旧变量、旧 style 文本和旧持久化值。

主题模块是 APK 内编译期可信 TS 资产，流程不需要 Rust I/O。`initTheme`、HMR、后端事件和确认按钮继续共享这个唯一 apply owner；兼容输入只能在 owner 入口归一化，不能绕回 CSS 加载。

### 8.4 预览隔离

预览只读取由 TS 模块构造的 `ThemeInfo`，不调用 `injectVariables`。建议提供纯函数：

```ts
resolveThemeWallpaperUrl(raw: unknown): string | null
```

规则：只取 basename、去除 `url()` 与引号、只接受仓库内已支持图片扩展名、映射到 `/wallpaper/`；不接受 `http:`, `https:`, `data:`, `javascript:` 或相对上跳。即使当前主题模块可信，这个边界也能防止未来主题来源扩展时把预览变成任意 URL 加载器。

双 pane 使用局部 style object，不在候选切换时创建/删除 `<style>` 标签。预览不渲染 raw HTML，也不执行 `extraCss`。

## 9. 主题页布局 owner

`SettingsView` 对 `theme` 子页单独提供 `overflow-hidden flex min-h-0` 容器，ThemePicker 自己拥有：

- 唯一横向 rail；
- 正常高度下无纵向 scroll；
- 低高度时唯一主题页纵向 scroll；
- 底部安全区和确认 footer。
- 位于主题预览/选择/确认之后的消息呈现 radio 区。

不要用 JS 读取“手机/平板”类型。卡片数由 CSS viewport/container width 决定，窗口 resize、旋转、分屏和折叠展开自然重新排布；active index 仍是同一 `draftThemeKey`。

## 10. 并发与失败契约

| 场景 | 规定结果 |
|---|---|
| 快速重复点同一模式 | 幂等，无重复持久化、无重复锚定 |
| 切模式时正在流式 | 不取消 stream、不重建 message，布局事务后继续 |
| 切模式时正在读历史 | 恢复原消息 viewport offset |
| 非法存储模式 | 回退并修正为 bubble |
| 主题列表加载失败 | 保持现主题，展示重试；确认 disabled |
| 候选壁纸失败 | pane 回退主题纯色，其他预览仍可用 |
| 主题确认重复点击 | APPLYING gate 只允许一个提交 |
| 主题正式应用失败 | 回滚旧主题，候选与错误保留，可重试 |
| 返回未确认主题页 | 丢弃 draft，实际主题不变 |
| 系统深浅在主题页变化 | 全局 resolved 模式可变，双分支候选预览保持完整 |

## 11. 明确不新增的跨层内容

- Rust `Settings` 字段；
- `set_theme` 新用途或新 command；
- Tauri event；
- SQLite migration；
- VCPMobileSync 字段；
- Android Kotlin 插件命令；
- Router 页面；
- 第二套 MessageRenderer、ChatHistory 或 scroll state machine。

这项功能的复杂度应停留在“受控前端呈现”，不能因为桌面端使用 Electron 设置文件而把 Mobile 扩展成跨层配置工程。
