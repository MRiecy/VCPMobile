# 05. 分期施工与验收门禁

## 1. 施工原则

本功能应按独立可回归切片推进，但最终必须一次交付完整用户目标。每个阶段都复用现有 owner，不以“方便测试”为由新增生产接口。

正式改代码前：

1. 展示 `git status --short --branch`；
2. 检查是否存在用户未提交修改；
3. 因后续很可能新增测试文件，按仓库重构前存档协议先保存当前工作树；
4. 重新核对 VCPMobile 与只读 VCPChat HEAD；
5. 不修改 `/home/dudu/VCPChat`。

### 4.2 阶段验收

- 打开时聚焦实际已应用主题；
- 旧 `.css` 存储别名能定位到对应 TS 候选；候选、选中态与成功持久化统一使用 TS module key；

- 返回未确认页面不提交；
- 手机视口显示主卡和相邻预告，平板同一 rail 显示多个卡；
- 正常 portrait 不需长距离上下滚动；低高度仅有一个纵向 scroll owner；
- 1.5× 字体和四边安全区不遮挡确认按钮。
- 主题确认区之后存在与长按菜单共用枚举/Store 的气泡、统一、刊物三选项；点选立即生效，不受主题草稿确认控制。

## 6. 自动化测试矩阵

### 6.1 Store 与纯函数

| 用例 | 断言 |
|---|---|
| presentation key 缺失 | `bubble` |
| 三个合法值 | 原值恢复 |
| 非法/非字符串值 | 回退并规范持久化为 `bubble` |
| 设置当前值 | `changed: false`，不重复写 |
| localStorage 写失败 | ref 与 DOM scope 不变，返回失败 |
| legacy 中文名/`.css` 别名 | 映射到现有 TS module key，成功后持久化 TS key |
| `.ts` 当前值与等价 `.css` 旧值 | 选中态/dirty 判断视为同一主题 |
| 非法主题 module key | 不改 current/persisted/root vars |
| 成功确认 | 一次 commit，current/info/vars/extraCss/key 一致 |
| 应用异常 | 旧主题完整恢复 |
| 壁纸解析 | 接受仓库 basename；拒绝 scheme、上跳和不支持扩展 |
| 主题资产治理 | 不读取/生成逐主题 CSS，候选变量只来自 TS ThemeModule |
| 开发态 HMR | 修改已应用 TS 模块仍重载当前主题，不把 dirty draft 当成 applied |

### 6.2 Longpress 与 Overlay

使用 fake timers 覆盖：

- 599 ms 不触发，600 ms 触发一次；
- move、touchcancel、mouseleave 取消；
- 非左键 mousedown 不计时；
- `suppress-click` 只在长按成功后消费一个 click；
- 无 modifier 的既有行为保持；
- touch timer + contextmenu 不重复打开；
- selected action 有 `role=radio`、`aria-checked=true` 和语义选中 class；
- Android 返回栈只弹出当前菜单。

### 6.3 滚动事务

- near-bottom 模式切换后仍在底部；
- 顶部消息部分可见时恢复负 offset；
- anchor 消失时使用安全回退；
- mode 连续切换只由最新事务恢复；
- loading-top 与 layout-changing 不互相覆盖；
- 组件 dispose 后不残留 rAF、timer 或 observer。

### 6.4 ThemePicker 组件

- 当前 applied 主题归一化成 TS key 后初始化为 draft 并滚入候选视口；
- 卡片点击/模拟 rail 聚焦会更新 preview，不调用 `applyThemeFile`；
- dark/light pane 使用不同变量和壁纸；
- “确认应用”才调用一次正式 apply；
- applied 相同按钮 disabled；
- APPLYING 防双击；
- apply 失败显示可重试状态；
- unmount/back 不提交；
- 外部 applied 变化时，clean 草稿跟随、dirty 草稿保留；
- 第二呈现入口顺序位于实时预览/主题选择之后，与快捷入口共用三值常量和 setter；
- 不断言完整 UnoCSS class 串，不用 happy-dom 冒充真实 snap 几何。

### 6.5 消息呈现与强渲染

至少在 `bubble/panel/immersive` 三值下重复运行代表 fixture：

| 能力 | 最低断言 |
|---|---|
| 普通 Markdown | 内容与选择容器存在，无重复文本 |
| 代码高亮/复制 | code/pre 与复制入口保留 |
| KaTeX / SVG / MathML | 渲染不崩溃，关键容器存在 |
| Mermaid | 源容器和全屏入口保留 |
| raw HTML 安全边界 | 既有允许/拒绝语义不变 |
| Tool / ToolSummary | 展开、状态与操作保留 |
| Thought | 展开与流式默认态保留 |
| Diary / DailyNote | 操作与更新格式保留 |
| Attachment | 预览与 Viewer 入口保留 |
| streaming tail / AST diff | frame 收敛、无重复节点、切模式不中断 |
| message longpress | 三模式均能打开原上下文菜单 |
| multi-bubble | 顺序不变，header/time 符合模式规则 |

测试应证明模式只改变语义外壳；不能对白盒 KaTeX/Mermaid 深层 DOM 写易碎断言。

## 7. 静态与生成物门禁

改动完成后至少执行：

```text
pnpm check
pnpm test:run -- --reporter=verbose
pnpm build
git diff --check
```

并检查 production CSS/JS：

- 三种 mode 字符串没有被 Tree Shaking 丢失；
- panel/immersive 的基础结构声明实际生成；
- 内容区 mode selector 下不存在 `backdrop-filter`；
- 主题候选没有把远程 URL 或 `v-html` 引入预览；
- 没有新增第二套 MessageRenderer 或按设备 UA 的业务分支；
- 没有修改 Rust、Android 插件与 capability 注册。

本功能不触碰 Android 插件，因此不要求为了形式运行 Gradle JVM 测试；若实际施工超出计划并改动原生/生成树，则必须恢复对应 strict Gradle 和生成树门禁。

## 9. 回归停止条件

出现以下任一情况必须停止合入并修复：

- 长按同时切换了深浅模式；
- 切模式导致用户从历史位置跳到底部；
- 模式切换销毁/重建活跃 MessageRenderer；
- panel/immersive 隐藏或纯文本化强渲染块；
- 主题候选在确认前改变聊天壁纸或 root vars；
- 返回主题页后未确认候选仍被保存；
- 手机正常竖屏必须上下滚动多个屏幕才能从预览到确认；
- 内容区引入 blur 或历史消息永久合成层；
- 只凭 happy-dom/host preview 就声明手机和平板兼容完成。

## 10. Definition of Done

| 要求 | 完成证据 |
|---|---|
| 气泡/统一/刊物 | Store + DOM/CSS + 三模式 fixture + 真机截图 |
| 长按深浅按钮入口 | fake-timer/click 抑制测试 + 真机触控 |
| 主题实时预览 | dark/light 局部 preview 测试 + 真机截图 |
| 确认后才应用 | draft/confirm/back/failure 组件测试 |
| 设置页第二呈现入口 | 顺序/共享 owner/立即持久化测试 + 真机触控 |
| 横向主题视口 | 响应式源码契约 + 手机/平板滑动证据 |
| 同屏目标 | 正常 portrait 视口截图；极端低高度记录单一滚动降级 |
| 强渲染不退化 | 自动化代表 fixture + Android 关键旅程 |
| 工程门禁 | `pnpm check`、全量 Vitest、production build、diff check |
| 文档 | 对应长期 `docs/vue_docs` 与本专项状态更新 |

上述任何一项缺失时，最多标记 `IMPLEMENTED` 或 `SOFTWARE-VERIFIED`，不能标记完整完成或 `DEVICE-VERIFIED`。
