## 现有设置的语义归属

| 设置或状态 | 当前存储或所有者 | 目标归属与范围 |
|---|---|---|
| presentationMode | theme Store 和 localStorage | 聊天偏好，本设备 |
| smoothStreamingEnabled | theme Store 和 localStorage | 聊天偏好，本设备 |
| 主题文件、light/dark/system | theme Store 和 localStorage | 主题所有者，保持 |
| userName、adminUsername、adminPassword | Rust AppSettings | 身份页编辑会话提交字段 patch |
| Chat 端点模式、地址、密钥、VCPLog 连接 | Rust AppSettings | 连接页编辑会话提交字段 patch |
| 同步地址、token、fileKey | Rust AppSettings | 同一连接页编辑会话；运行行为仍归同步等功能 |
| topicSummaryModel | Rust AppSettings，Rust 总结服务读取 | 高级页中的总结配置，不迁入本地 UI 偏好 |
| agentOrder、groupOrder | Rust AppSettings | 排序所属功能继续拥有更新入口 |
| syncPrerenderEnabled | Rust AppSettings | SyncSessionView 继续拥有入口 |
| distributedEnabled 与连接参数 | Rust AppSettings | DistributedView 和后端运行时继续拥有 |
| 自动检查更新 | localStorage | 更新领域的本地偏好 |
| 上次检查时间、跳过版本 | useAutoUpdate 的 localStorage 记录 | 留在自动更新生命周期，不作为普通偏好 |
| 头像 | assistant/avatar 既有链路 | 不加入身份表单事务或配置备份 |
| 已连接、下载中、原生授权 | 对应运行时 | 不复制为 Settings 中的布尔值 |

“聊天偏好”是用户信息分类，不代表所有聊天相关字段都迁到同一个 Store。以 Rust 读取的总结模型为例，页面可以调整位置，配置权威仍留 Rust。

## 存储兼容基线

| key | 当前表示与缺省行为 | 迁移要求 |
|---|---|---|
| vcp-chat-presentation-mode | bubble / panel / immersive；无效值归 bubble | P1 原 key、原字符串，继续修复已识别的无效值 |
| vcp-smooth-streaming-enabled | true / false 字符串；缺省 false | P1 原 key；保留读取归一化与写失败处理 |
| vcp-theme-name | 主题 TS 模块名，兼容既有旧名映射 | 仍归 theme，不改 |
| vcp-theme-mode | light / dark / system；当前无偏好使用 light | 保留 index.html 首帧读取与 theme 初始化配合 |
| vcp_auto_update_check | off 表示关闭，其他情况开启；写入 on/off | P4 保留原表示和缺省开启 |
| vcp_last_update_check | 成功检查时间，决定冷却 | 留原自动更新生命周期 |
| vcp_update_skipped_version | 用户跳过的版本 | 留原自动更新生命周期 |
| SQLite settings / global | Rust Settings 的 JSON | 保持顶层字段和现有 patch 协议 |

聊天偏好写入当前先持久化成功，再更新 ref；不能迁为先改 ref、依赖深层 watch 尝试落盘。主题文件应用还包含 DOM 回滚，不应用通用布尔偏好的机制替换。

## 配置提交的现有保护

1. settings Store 的 enqueueOperation 串行处理 fetchSettings 和 updateSettings。
2. Rust update_settings 在锁内读取当前配置、合并顶层字段、反序列化校验并保存。
3. internal_write_settings 在事务提交后更新缓存，再按实际变化协调运行时。
4. 运行时协调有 generation 和锁，旧请求不能在新配置之后提交过期副作用。
5. 读取具备迁移和损坏原文备份恢复；恢复通知不应因页面拆分重复触发。

Rust 当前合并是顶层替换。把配置改成嵌套领域 JSON 后仍发送局部子对象，会覆盖同域兄弟字段。本专项通过页面字段投影建立领域边界，不改变物理存储形态。

## 需要闭合的真实问题

| 发现 | 源码依据 | 证据范围 |
|---|---|---|
| 返回未等待到可靠保存结果 | SettingsView 的 saveSettings 捕获异常返回 false，goBack 不检查该值仍退出 | 源码确认控制流 |
| 子页返回栈可能提前注销 | registerModal 回调启动 goBack；useModalHistory 只判断同步 false | 源码确认协议不匹配 |
| 全量草稿可能回写外部新值 | 保存后 baseline 替换为完整响应，旧草稿未对未编辑字段重基 | 源码推断，实施时执行并发场景复现 |
| 依赖保存的动作不能等待事件完成 | 连接测试、表情库重建、导出使用 emit(save-request) | 源码确认调用关系；具体竞态需执行验证 |
| 关闭设置不等于卸载 | FeatureOverlays 首开闩锁和 SlidePage 的 v-show | 源码确认生命周期 |
| 自动更新开关缺少可靠写入闭环 | UpdateSection 先改 ref，再直接 setItem | 源码确认写入顺序 |

外部配置写入是真实存在的：AgentList 更新排序、SyncSessionView 更新预渲染、DistributedView 更新连接、导入更新白名单字段。配置队列可以防止请求乱序，但不能自动修复页面主动发送的过期字段。

## 页面与返回生命周期

- [FeatureOverlays.vue](../../src/components/FeatureOverlays.vue) 首次打开后保留 SettingsView。
- [SlidePage.vue](../../src/components/ui/SlidePage.vue) 使用 v-show；隐藏不会执行 SettingsView 的卸载清理。
- [useModalHistory.ts](../../src/core/composables/useModalHistory.ts) 的关闭回调是同步 boolean 或 void，false 表示此次不关闭。
- [guideStore.ts](../../src/features/guide/stores/guideStore.ts) 和 [GuideCenterSection.vue](../../src/features/guide/components/GuideCenterSection.vue) 存在关闭设置或 popToRoot 的外部收尾。

因此，导航需要区分正常用户离开和外部强制隐藏。前者可以等待保存，后者只能清理和使迟到回调失效，不能在 watcher 或卸载时假装获得了可等待的保存机会。

## 原有消费链必须保留的细节

- ChatView 同时使用主题明暗和聊天呈现；迁移呈现字段不代表删除主题依赖。
- MessageRenderer 的 Mermaid 明暗仍使用主题；平滑动效另有流式、AST、后台、页面可见性、减少动态效果等实际条件。
- ToolBlock 当前没有报告示例里的 isStreaming prop；MessageRenderer 传 defaultExpanded。新增折叠策略需要独立处理人工选择与块身份，本次不改。
- chatHistoryStore、chatStreamStore、长按菜单等具有不同震动时机。本次不增加开关或改变触发行为。
- 备份白名单包含身份、核心连接、同步连接和分布式连接；排除头像、本地偏好、排序等。保持 .vcpcfg、版本字段和解析入口。

## 范围排除

本专项不整理所有功能的 Store，不拆 Rust 配置数据库，不改变后端运行时协调，不重写原生权限或平台能力模型，不迁移退役浮动助手，不新增搜索、偏好同步或重置全部偏好。原方案暂缓的触感和折叠已被用户后续明确纳入实施，具体语义见 06。

Agent/GroupSettingsView 与 TarvenSettings 的业务编辑流程不并入本专项页面目录；它们是独立业务入口。必要修改只限真实共享控件调用的适配。
