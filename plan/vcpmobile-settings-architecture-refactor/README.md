# VCPMobile 设置架构重构方案

本专项将设置系统整理为“领域拥有设置、设置中心组织入口、公共基础提供可靠机制”的结构。目标是让新增设置的修改集中在所属领域、设置界面和真实消费者，同时保持既有主题、聊天、连接、同步与原生能力的行为边界。

用户已认可上述架构方向。本目录进一步提出目录落点、接口契约、迁移顺序和验收办法；本次交付是方案，尚未实施生产代码重构。后续实现以生产代码和用户最新决定为准，文档和测试不反向定义产品行为。

## 设计决定

1. 聊天呈现模式和平滑流式归聊天领域，主题资源、明暗模式和 CSS 应用继续归主题。
2. 设置中心只组织页面，不成为配置总仓库，也不要求业务模块依赖设置页面。
3. 保留现有 Rust 配置快照、前端操作队列、后端事务与运行时协调；领域化先落实到接口和草稿边界。
4. 使用显式、类型化的薄页面目录。普通控件复用现有原语，复杂页面继续使用正常 Vue 组件。
5. 区分即时偏好、编辑草稿、正式配置、运行状态和操作结果；保存成功不等于连接或任务完成。
6. 页面保存只提交本页实际编辑的字段；异步响应不能覆盖保存期间的新输入。
7. 返回流程复用现有同步否决机制，等待保存完成后再退出；不另建全局页面栈。
8. 保留现有存储 key、格式、默认值与备份白名单；不为目录重组顺便迁移数据格式。
9. 公共持久化工具保持窄边界，通过聊天和自动检查更新两个实际使用场景提炼，不建立万能设置引擎。
10. 本专项不新增回复震动开关、工具折叠开关、设置搜索或偏好同步；这些只作为后续接入范例。

## 范围和工作区

- 用户指定工作区：E:/VCPMobile；本次新增文件全部位于本专项目录。
- 源码审计基线：Git HEAD 238ce3c4，开始编制时工作树干净。
- 重构主要位于 Vue 层。Rust 配置层是需要保持的依赖，不预设修改其 DTO、表结构或 IPC。
- 保留 Android 正式链路及 iOS 实验边界；不新增桌面产品分支，不建设 iOS 实机测试体系。
- 不修改 VCPToolBox、VChat、CI、版本、签名或发布流程；不执行提交、push 或发布。
- AGENTS.md 中的旧 G: 路径不作为本次写入目标；用户本次明确指定 E:/VCPMobile/plan。

## 实施完成标准

- 设置页和聊天快捷入口使用同一个聊天偏好所有者；主题模块不再承载聊天偏好。
- SettingsView 不持有完整 AppSettings 草稿，不理解任何具体配置字段。
- 页面目录描述导航和组件，不描述字段、持久化、权限或业务动作。
- 保存失败保留草稿；在途保存与外部设置变更不产生无意覆盖。
- 导出、连接测试、依赖配置的修复操作具有明确的可等待顺序。
- 原有 key、默认值、主题首帧、备份范围和运行时状态所有权保持连续。
- 自动检查更新的 UI 与消费端使用同一个偏好入口，OTA 状态仍由 Rust 拥有。
- 静态检查、行为验证、构建和设备观察分别记录证据，不互相替代。

下一次进入实施时从 P0 开始，不需要重新设计整套架构。若发现源码已变化，只调整受影响的契约和迁移步骤，并记录原因。
