# 设置架构分阶段迁移计划

迁移按“独立领域所有者 → 修正编辑与提交 → 拆页面装配 → 验证第二领域复用 → 收口”推进。每个阶段以可运行的真实调用链为交付单位，不靠旧接口转发和双份状态维持表面兼容。

## P0 实施基线

输入：本专项方案和实施时的生产工作树。

步骤：

1. 检查 Git 状态，记录 HEAD，读取本次修改路径适用的 AGENTS.md，保留无关修改。
2. 核对 00 中的调用方、字段、key、备份范围以及返回和隐藏入口；只更新已经变化的部分。
3. 确认当前主题、聊天渲染、Rust 配置与更新相关代码没有同时进行的冲突编辑；发现并行工作时划清实际路径。
4. 核对已有测试描述与生产代码，挑出可继续使用的行为场景。源码字符串断言只说明结构约束。
5. 决定本阶段必要的可恢复点。干净 HEAD 或已有任务恢复点足够；不创建空提交，不重复 save，不因编制方案自动提交。

产物：明确的实施基线和实际任务路径。可在本目录新增阶段结果文件记录事实，不提前创建空结果账本。

退出条件：所有实际修改均可归入当前阶段，未混入新产品开关或平台发布工作。P0 本身不要求新增测试脚本。

## P1 聊天偏好独立

目的：让现有两个聊天偏好离开主题所有者，建立第一条完整纵向链路。

### 实施步骤

1. 新建 chat/preferences/model.ts，迁移呈现模式类型、三种选项、归一化规则；默认值保持 bubble 和 false。
2. 新建 storage.ts 和 Composition API store.ts，接收两个原 key、同步读取、修复行为和 setter。两个 setter 的结果语义先保持一致。
3. 同一次改动替换 ChatView、MessageRenderer、presentationMenu 的对应消费；保留这些文件真正需要的主题明暗依赖。
4. 新建 ChatPreferencesPage.vue，迁入呈现与平滑动效 UI，沿用设置原语和现有错误反馈。
5. SettingsView 的 rendering 入口指向新页面，标题改为聊天偏好；保留原内部 ID。
6. ThemePicker 移除聊天偏好部分及 section=theme/rendering 双职责入口；主题预览和确认应用保持原语义。
7. theme.ts 移除已迁出的状态、key、类型和 setter，不留转发导出。
8. 迁移对应测试的真实依赖；主题测试继续检验主题，聊天偏好测试使用新的所有者。

### 退出条件

- 旧 key 恢复与既有默认值连续；写失败保持原值。
- 设置页与长按菜单修改同一偏好，聊天实际渲染读取新所有者。

- ThemePicker 和 theme Store 不再拥有聊天偏好；主题首帧与应用回滚保持。
- 运行 pnpm check 和受影响的行为测试。若修改影响打包依赖，再运行 pnpm build。

恢复范围：本阶段生产路径。保留 key 使代码恢复不依赖反向数据迁移；任何会抛弃工作树修改的 Git 操作仍须按根规则另行取得明确同意。

## P2 字段编辑会话与可等待提交

目的：先修正真实保存边界，随后页面拆分只移动已明确的所有权。

### 实施步骤

1. 建立 fieldSets.ts，定义身份、连接、总结三个窄字段集合。SettingsView 暂时负责装配这三个会话，移除完整 AppSettings 默认草稿。
2. 建立 useSettingsEditSession，完整实现 02 的 ready、dirty、pending、editRevision、重基、单飞保存与 dispose。
3. 进入队列前捕获 patch；保持 SettingsStore 唯一快照和 Rust 顶层 patch。不扩展写入命令。
4. 身份、连接和总结区块改为窄输入和明确的编辑事件，所有用户编辑经 edit；移除直接修改整个 settings prop 的写法。
5. 去掉依赖顺序上的 save-request 事件：连接测试、表情库重建和导出等待明确提交结果。
6. 导出使用成功结果快照；导入使用原白名单解析和确认，冻结编辑并排空已请求保存后再应用，按被替换字段接受当前正式快照。
7. 总结模型的 watch、blur、选择回调合并到同一会话，保留现有提交时机，阻止程序重基触发用户保存。
8. 现有 SettingsView 的返回立即接入同步 veto 和可等待 prepareLeave；保存失败不得关闭，连续返回不得提前出栈。P2 同时按访问创建会话，成功离开或强制隐藏时 dispose，并建立最小访问标识、局部覆盖层清理与迟到结果检查。
9. 修正“配置同步成功、变更已生效”的过度成功文案，保持通知只描述配置提交。

### 为什么仍暂留 SettingsView 装配

这一阶段不同时搬动全部页面和布局。三种会话按字段隔离，仅为当前编辑页访问建立一个实例，SettingsView 暂时是其挂载点。P3 再逐页移动会话，避免在结构迁移中重写并发算法。常驻外壳不会使会话跨已结束的访问复用。

这不是永久兼容层，也不建立一份新状态去同步旧全量草稿。旧全量草稿和无明确消费方的 diffSettingsPatch 在实际最后引用移除时删除；若测试仍引用，仅因测试不能保留生产死接口。

| 修改 | src/features/settings/components/UserProfileSection.vue、VcpCoreSettingsSection.vue、SyncSettingsSection.vue、TopicSummarySection.vue、ConfigBackupSection.vue |
| 必要精确修改 | src/core/stores/settings.ts 的入队捕获和成功文案 |

### 退出条件

- 首次加载失败不能把默认草稿提交为正式配置。
- 保存中继续编辑、改回旧值、再次保存、外部字段更新均按 02 处理。
- 保存失败保留草稿，返回保留页面和 modal；重试可恢复。
- 保存前置失败时，依赖动作未启动；导出使用确定快照。
- 导入仅覆盖确认范围，其他未提交字段保留。
- 导入不会被旧保存循环的后续批次覆盖；强制隐藏立即释放会话和本页弹面，迟到结果不影响新访问。
- 设置之外的排序、预渲染、分布式配置仍沿原入口工作。
- 运行 pnpm check 及 P2 相关行为测试，必要的缺陷复现结果留在阶段记录。

若实际实现需要修改 useModalHistory，应先确认现有同步 false 是否已足够；本方案默认不修改其全局协议。

## P3 页面目录与导航壳

目的：把 P2 已建立的会话移入对应页面，使 SettingsView 不再理解配置字段。

### 实施步骤

1. 建立 contracts.ts 和 catalog.ts，保留七个既有 ID；组件在模块级稳定懒加载。
2. 提取身份、连接、高级三个页面，把对应会话与局部动作一同移动；原装配点立即移除，不保留父子双会话。
3. 模型选择器归 AdvancedSettingsPage；身份页头像选择、裁剪和清理保持原所有者。
4. 目录直接装配现有 AboutSection；关于页背景保留在设置壳的独立常驻宿主，以可见性控制活动状态，保持既有挂载后 idle 编译和沉浸呈现。
5. 建立 useSettingsNavigation，接管局部当前页、访问序号、单飞离开和退出动画清理。把 P2 返回修复原样接入。
6. SettingsView 只留下公共头部、分类、错误与加载态、有限 frame 布局和页面装配，删除字段默认值、全量加载、保存分支和 READ_ONLY_SUBPAGES。
7. 将 P2 已成立的隐藏、外部 popToRoot 和迟到身份处理迁入导航与页面；验证快速重新打开时语义保持。子页 modal 提供真实 surface。
8. 保持首次打开懒加载、主题和关于页 idle 预热。列表、主题、关于页分别只有一个明确的纵向滚动所有者。
9. 完善 SettingsSwitch 的触控和可访问语义，核对所有调用方，删除已被原语替代的外层交互包装。

| 新增 | src/features/settings/catalog.ts、contracts.ts、useSettingsNavigation.ts |
| 新增 | src/features/settings/pages/ 下身份、连接、高级三个目标页面 |
| 修改 | src/features/settings/SettingsView.vue、ThemePicker.vue、components/AboutSection.vue |

“按需精确接入”不是预先要求修改共享层。若现有 transition 和关闭入口已能满足协议，保持原文件。

### 退出条件

- SettingsView 无具体 AppSettings 字段、默认值和编辑会话。
- catalog 无偏好值、保存函数、字段 schema 或平台门禁。
- 同一返回意图只执行一次离开；失败可再次返回；模型选择等内层弹面优先。
- 隐藏后无子页 modal 残留，旧 Promise 和旧动画回调不影响新访问。
- 主题返回丢弃未应用预览；聊天返回无额外写入；关于页不可见时不运行背景循环。
- 窄窗口、键盘、较大字号下设置仍可操作，无额外滚动容器吞掉内容。
- 运行 pnpm check、相关组件与导航测试；运行 pnpm build 检查懒加载装配。

## P4 自动更新偏好与公共 IO

目的：用第二个真实领域检验公共机制，同时修正重复偏好来源。

### 实施步骤

1. 在现有 update Store 增加清晰分离的本地 autoCheckEnabled 和 setAutoCheckEnabled，不写入 Rust UpdateStatus。
2. 保留 vcp_auto_update_check、on/off 编码、缺省开启规则，写成功后发布新值，失败返回旧值。
3. UpdateSection 和 useAutoUpdate 改用同一入口，删除组件自己的偏好 ref 和重复 key。
4. 从聊天 storage.ts 提取真正重复的本地读写异常处理至 core/preferences/localPreference.ts；聊天解码和 key 留原领域。
5. 保留 useAutoUpdate 的时间戳、跳过版本、Android 条件、READY 后延迟、冷却和每会话检查规则。
6. 不因开关变化新增“立即检查”行为，不改 Rust OTA、下载、安装或平台说明。

退出条件：UI 与自动检查读取同一偏好；失败不会显示未保存的新值；iOS 不启动 APK 更新链。运行 pnpm check 和针对上述变化的更新测试。

本阶段只整理一个现有偏好，不成立新的 updater 偏好总框架，也不读取或修改 CI/Release workflow。

## F1 用户追加的聊天开关

用户于 2026-10-18 授权在架构重构后接入两个开关。消息震动由一个默认开启的偏好控制发送与回复结束，保持既有时机和强度，不影响长按触感；流式工具折叠默认关闭，开启时仅改变未被用户手动操作的工具块默认状态。

实现依赖新的聊天偏好所有者和真实聊天消费链。人工展开状态随当前消息块实例保留，不进入全局设置持久化；工具身份需要跨流式与终态 hash 表示保持连续，同时避免把大段工具正文复制到 VNode key。实际实现与验证见 06。
