# 设置重构验证与风险清单

验证围绕可能推翻设计判断的真实行为展开。下列场景是实施阶段的验证计划，尚未执行；它们不因写入文档就成为已通过证据。

## 证据边界

| 证据 | 能说明什么 | 不能替代什么 |
|---|---|---|
| 生产调用链审计 | 所有者、调用时机、字段和资源路径 | 异步时序实际执行 |
| Vue 行为测试 | 当前运行环境中的状态、组件和可控时序 | Android/iOS 原生运行表现 |
| pnpm check | TypeScript 与 host Rust 静态检查 | Apple/Android 目标编译、设备交互 |
| pnpm build | Vue 生产构建、模块装配 | 真机加载速度、触控和 GPU 表现 |
| 具名 Android Debug 设备 | 该设备、该窗口与版本上的观察 | 所有机型或 iOS |
| 既有 iOS 阶段性 Apple 构建 | 对应输入的编译和链接 | 未取得的实际 UI 运行证据 |

本轮仅文档交付，验证文件内容、源码引用、内部链接和工作树范围即可，不因编写计划运行产品构建或操作设备。

## P1 聊天偏好

| 场景 | 需要观察的结果 |
|---|---|
| 未打开设置直接进入聊天 | 呈现和动效已恢复，不依赖 ThemePicker 挂载 |
| 三种旧呈现值、缺失值、无效值 | 按当前归一化恢复，无意外默认值变化 |
| 平滑动效 true/false、缺失与异常原文 | 保持原恢复和修复语义 |
| 存储拒绝写入 | 返回失败，渲染与控件仍显示旧值，可重试 |
| 同值 setter | 无多余写入，无额外反馈和渲染扰动 |
| 设置页修改后打开快捷菜单，反向再修改 | 选中项与真实聊天呈现一致，只有一个所有者 |
| 切换排版时正在阅读历史 | 保持原有阅读锚点，不强制滚到底 |
| 平滑开启但页面后台或减少动态效果启用 | 实际动效仍遵循原条件，偏好本身不被改写 |
| 主题选择、预览、应用失败 | 局部预览不改全局，原主题回滚仍有效 |

优先迁移 ThemePresentationStore、ThemePicker、MessagePresentationRenderer、PresentationControls 中仍验证真实行为的用例。不能为了保留旧 import 或旧组件结构而留下已无生产消费者的接口。

## P2 编辑和异步动作

使用可控 Promise、真实会话实现和真实 Store 提交边界构造顺序，不只断言 patch 构造函数。

| 场景 | 必须成立 |
|---|---|
| 首次加载失败后尝试保存 | 不以默认字段覆盖正式配置 |
| 只编辑身份字段，外部修改排序 | 发出的 patch 不包含排序，正式新排序保留 |
| 本页未编辑字段被其他入口修改 | 草稿跟随新值，下次保存不回写旧值 |
| 提交 A 时继续输入 B | A 的响应不覆盖 B；B 留作 dirty 或由后续显式保存提交 |
| 原值 0，提交 1，在途又改回 0 | pending 与 editRevision 保留最后的 0，不能因暂时不 dirty 而丢失 |
| 保存中再次点击保存 | 后次保存意图被合并处理，不能只等待旧批次 |
| 某批失败 | 草稿保留，错误可见，不无限重试，不继续依赖动作 |
| 离开时已有在途保存 | 冻结新输入，等待并补存已有新草稿；无 dirty 才退出 |
| 外部较新操作已更新 Store，较旧页面 Promise 才恢复 | 页面按当前正式快照结算，不把旧响应写回 Store |
| 页面释放后保存返回 | 共享 Store 接纳实际结果，旧页面不更新或导航 |
| 等待保存时设置被隐藏，随后重新打开 | P2 就使旧访问失效，旧保存不能关闭或冻结新访问 |
| 两入口主动写同字段 | 按既有提交顺序生效，不宣称自动冲突合并 |

对依赖操作分别验证：

- 保存失败时，不调用 test_vcp_connection、regenerate_emoticon_library 或文件导出。
- 导出内容来自确定的成功快照，保持原白名单；不是仍会变化的草稿引用。
- 保存排队期间不能修改已捕获的 patch 值。
- 导入确认前取消不写设置；成功仅替换验证后的字段。
- 导入所含字段覆盖当前同字段草稿，未包含的 dirty 字段保留。
- 导入发生时已经存在 saveRequested 的下一批保存：先排空保存，再导入，不能形成 save1 → import → save2 的反向覆盖。
- 导入等待只结算已请求保存，不额外提交原本未请求的其他 dirty 字段；等待失败不继续导入。
- 原生文件选择迟到、取消和临时文件释放继续沿现有所有者执行。
- 端点预览仍由 Rust preview_chat_endpoint 生成，不在 Vue 重新拼写 URL 规则。
- 总结模型的用户编辑能够保存，程序重基不触发循环写入。

现有 SettingsPatch.test.ts 的差异函数与源码扫描不足以证明这些时序，应补执行型用例。现有 useConfigBackup.test.ts 的白名单和编码验证继续有价值，但不能替代导出等待保存的行为验证。

## P3 导航和页面生命周期

| 场景 | 必须成立 |
|---|---|
| 头部返回、硬件返回、Escape | 进入同一离开流程，不提前注销子页 modal |
| 保存失败后再次返回 | 页面和 history entry 仍在，可再次保存或重试 |
| 连续返回多次 | 只有一个离开过程，不穿透关闭整个设置 |
| 模型选择器或确认框在上层 | 优先处理真实栈顶弹面 |
| 主题草稿未应用就返回 | 不保存、不新增确认对话框 |
| 聊天偏好返回 | 不再重复保存或回滚已经成功的即时修改 |
| 外部 closeSettings 或 popToRoot | 撤销子页 modal，active=false，迟到结果不重新导航 |
| 隐藏时仍在选择头像或显示裁剪、模型选择 | 立即清理本页弹面和访问身份，迟到 picker 不在隐藏页打开覆盖层 |
| 保存或退场期间快速重开设置 | 旧访问序号和旧 after-leave 不清理新页面 |
| 异步页面尚未加载就返回 | 取消该次访问，迟到组件不重新显示 |
| 加载失败后重试 | 保持可返回，不能调用上一页残留的 beforeLeave |
| 关于页隐藏但宿主仍挂载 | 背景循环停止，退场视觉和资源清理符合约定 |
| 关于页内容退出后再次进入 | 内容可以重新挂载，独立背景宿主保持，既有 idle 编译不被当作单纯 chunk 预载 |
| 反复打开关闭 | 无重复注册、timer、observer 或原生操作泄漏 |

导航测试应包含实际 useModalHistory 的同步否决行为，不能用一个无条件等待 Promise 的 mock 掩盖协议差异。

移动端观察关注：单一滚动容器、键盘遮挡、字体放大、触控目标、语义开关、焦点返回和关于页退出。无设备时记录待验证，不以 Vite 预览宣称通过。

## P4 更新偏好

- 读取原 on/off 和缺失值，保持缺省开启。
- UI 修改后，useAutoUpdate 读取同一所有者。
- 存储失败保留旧值，不启动额外检查。
- 保留 Android 限定、READY 后既有延迟、24 小时冷却及每会话检查逻辑。
- iOS 仍显示原更新说明，不因读取本地偏好调用 APK 初始化。
- 上次检查和跳过版本仍属于原生命周期，备份范围不扩大。
- UpdateStatus 继续反映 Rust 状态，本地偏好变化不伪造下载、安装或可用状态。

已有 UpdateStore 和 UpdateSection 测试分别覆盖状态与界面的一部分，新增验证应针对本阶段真实变化。源码扫描式 UpdateGovernance 不等于执行过自动检查生命周期。

## 检查入口

每个涉及前端、跨层或核心逻辑的实施阶段完成后运行：

~~~powershell
pnpm check
~~~

选择相关测试路径执行；下面是当前已有资产，可按实际迁移后的路径更新命令：

~~~powershell
pnpm exec vitest run src/tests/unit/components/settings src/tests/unit/settings
pnpm exec vitest run src/tests/unit/chat/MessagePresentationRenderer.test.ts src/tests/unit/components/ui/PresentationControls.test.ts
pnpm exec vitest run src/tests/unit/update
~~~

页面装配和最终收口运行：

~~~powershell
pnpm build
~~~

不要把这些命令机械地在每次小修改后全部重复执行。静态检查失败先修复；行为测试按新变化或未解决疑点扩展。若实现实际触及 Rust，则依据具体模块补充相关 Rust 检查，不为纯 Vue 偏好迁移强制跑无关集成测试。

Android 设备日常操作仅使用 pnpm android:debug:*，只操作 com.vcp.avatar.debug。iOS 维持现有源码审计和按需阶段性 Apple 构建；此专项不建设新的实机验证体系或自动发布流程。

## 主要风险与处置

| 风险 | 预防与处置 |
|---|---|
| 为统一结构改变存储格式 | 保留 key 和顶层 patch；若新需求确实要求迁移，单独记录格式与失败恢复 |
| 页面拆分产生第二份已提交配置 | 唯一 Store 快照；页面只有字段草稿，不互相同步镜像 |
| 把业务副作用搬到页面 watch | 继续由 Rust 或既有功能所有者协调，页面只提交意图 |
| 单飞保存丢掉后一次意图 | saveRequested 合并、pending revision 和退出冻结输入 |
| 异步返回导致 history 提前出栈 | 同步 return false，成功后单一注销路径 |
| 常驻组件被误当已卸载 | isOpen/active 清理和访问身份失效，动画结束后释放子页 |
| 通用控件出现嵌套按钮 | 迁移 SettingsSwitch 时检查真实父级包装和所有调用方 |
| 懒加载目录变成 eager 依赖入口 | 稳定异步组件，业务不反向导入 catalog，不在注册时初始化功能 |
| 导入导出默默扩范围 | 保留原白名单、文件版本与解析所有者 |
| 测试反向规定产品 | 用生产调用链核对失败原因，替换失效结构断言，不保留死路径 |

## 恢复与交付纪律

本方案避免格式迁移，因此大部分恢复只涉及代码；这不授权覆盖工作树。恢复前检查状态、展示精确目标和影响，按根规则取得破坏性操作同意。默认优先通过可审查的修复消除问题。

已有干净 HEAD 或任务恢复点足够，不为每阶段创建重复 checkpoint。未经用户授权不提交、不 push、不发布。

交付结果分别报告：实际实现范围、静态检查、行为测试、生产构建、设备或平台构建证据、剩余限制。不能把“文件已移动”写成“架构迁移已完成”。
