结构按业务所有权和页面装配分开组织。下列目录已随本次重构建立；阶段编号表示主要归属，最终实施验证见 06。

主题 UI 暂时保留原路径，不为目录对称搬动主题资源体系。新增聊天设置界面放在聊天领域，设置中心只装配它。身份、连接等现有跨功能配置表单暂留 settings/pages，数据权威仍由已有 SettingsStore 和 Rust 持有。

## 模块责任

| 模块 | 拥有的内容 | 不拥有的内容 |
|---|---|---|
| chat/preferences/model | 聊天偏好合法值、默认值、显示选项、读取归一化 | 页面导航、存储实例、网络请求 |
| chat/preferences/storage | 原有 key 和编码、同步恢复、写入结果 | 全局 Vue 状态、主题、后端配置 |
| chat/preferences/store | 每个 Pinia 实例中的唯一聊天偏好和 setter | 设置页开关生命周期、运行时权限、消息块人工展开状态 |
| core/preferences/localPreference | 有失败结果的读写机制 | 字段总表、跨域事务、自动同步、全局 watch |
| core/stores/settings | 已提交的 Rust 快照、请求串行化、恢复提示 | 页面草稿、表单校验文案、连接完成状态 |
| editing/useSettingsEditSession | 本次页面字段投影、用户编辑、保存批次、重基 | 持久化第二份配置、全局导航、实际服务连接 |
| SettingsView 和 useSettingsNavigation | 当前子页、公共外壳、返回协议、加载错误、离开访问身份；壳保留关于页背景宿主 | 具体配置字段、表情库重建、主题应用 |
| catalog | 页面 ID、标题、说明、懒加载组件和有限展示类型 | 偏好值、权限表、字段 schema、业务回调 |
| 页面组件 | 领域区块装配、页面草稿、用户动作和局部状态 | 第二份已提交配置、跨页面服务生命周期 |
| SettingsSwitch 等原语 | 触控、可访问语义、展示和用户意图事件 | localStorage、Pinia、invoke、Toast |
| update Store | 现有 Rust OTA 状态镜像；独立的自动检查本地偏好 | 将本地偏好写入 UpdateStatus、冷却记录或版本跳过历史 |

## 依赖关系

~~~mermaid
flowchart TD
    Shell["SettingsView 与局部导航"] --> Catalog["薄页面目录"]
    Catalog --> Pages["各功能提供的设置页面"]
    Pages --> Chat["聊天偏好 owner"]
    Pages --> Theme["主题 owner"]
    Pages --> Edit["页面编辑会话"]
    Pages --> Update["更新 owner"]
    ChatUI["聊天页与快捷菜单"] --> Chat
    Edit --> Repo["唯一 SettingsStore"]
    Repo --> Rust["现有 Rust 配置与运行时协调"]
    Chat --> Local["窄本地持久化工具"]
    Update --> Local
~~~

业务消费者可以直接调用其所有者，不需要穿过 catalog、SettingsView 或设置组件。catalog 允许引入页面组件；领域 Store 不反向导入 catalog。公共工具不能引用 features。

同一个设置的多入口共享所有者，不共享页面草稿。页面草稿有意独立：它代表尚未提交的输入，不能被其他页面当作已生效值。

## 页面目录与布局

保留现有内部页面 ID，避免纯重命名扩大影响。rendering 的用户标题改为“聊天偏好”；内部 ID 继续是 rendering，不建立 chat/rendering 双别名。

| ID | 标题 | 目标组件 | 展示类型 | 返回契约 |
|---|---|---|---|---|
| identity | 用户身份 | IdentitySettingsPage | list | 保存本页字段，失败停留 |
| connection | 服务器连接 | ConnectionSettingsPage | list | 保存本页字段，失败停留 |
| theme | 主题切换 | ThemePicker | viewport | 丢弃未应用预览，不新增确认 |
| rendering | 聊天偏好 | chat/settings/ChatPreferencesPage | list | 即时偏好，返回不再保存 |
| advanced | 高级功能 | AdvancedSettingsPage | list | 结算已有总结配置修改；维护动作独立 |
| guide | 帮助与指引 | 现有 GuideCenterSection | list | 沿现有引导入口，处理外部关闭 |
| about | 关于 | 现有 AboutSection | immersive | 独立头部与返回，壳停用背景循环 |

三种展示类型只回应现有差异：

- list：设置壳拥有唯一纵向滚动容器、常规内边距和安全区，页面提供内容。
- viewport：壳提供 min-height 为零的可用区域，主题页拥有自己的滚动和布局；壳不再加第二层纵向滚动。
- immersive：关于页拥有头部、内容和滚动，覆盖公共头部；仍使用现有语义层级和页面范围。

窄屏、平板、折叠窗口共享组件和状态，按可用宽度响应。不因平台身份复制页面。

## 页面字段投影

fieldSets.ts 使用显式字段数组和 Pick 类型，不通过 AppSettings 的任意字符串索引扩展页面权限。

| 页面投影 | 字段 |
|---|---|
| IdentityFields | userName、adminUsername、adminPassword |
| ConnectionFields | vcpServerUrl、chatEndpointMode、vcpApiKey、vcpLogUrl、vcpLogKey、syncServerUrl、syncHttpUrl、syncToken、fileKey |
| SummaryFields | topicSummaryModel |

agentOrder、groupOrder、syncPrerenderEnabled、distributed 字段、currentThemeMode 和退役助手字段均不进入这些普通页面草稿。

备份的导入白名单大于 ConnectionFields，这是操作语义，不应靠扩大连接页草稿解决。导入沿验证后的全局 patch 提交；当前页只重基自己的字段，其他消费者由 SettingsStore 的正式快照获得变化。

## 生命周期归属

聊天偏好在 Store 创建时同步恢复；不能等到打开设置页才初始化。主题启动仍由现有 appLifecycle 和主题所有者负责；不在 catalog 顶层调用任何 useStore 或 invoke。

页面的异步组件在模块级建立稳定引用，渲染时不反复创建 defineAsyncComponent。延续现有主题和关于页的 idle chunk 预热，但预热只加载代码或已有缓存，不提前启动页面动作。

设置壳继续常驻。当前子页的实例与草稿只属于一次页面访问；退出动画结束后释放。隐藏时立即撤销子页 modal 和交互，作废迟到导航，再保留退场视觉直到动画完成。

关于页背景保留在 SettingsView 的独立常驻宿主中，AboutSection 只承担内容。这是既有视觉资源的保活边界，不受子页内容退出卸载影响；无需新增仅转发内容的 AboutSettingsPage。

WebGLFluidBackground 在宿主挂载后进行既有 idle 编译，单纯预载关于页 chunk 不能替代 GPU 预热。只有设置可见且关于页活动时运行背景循环；隐藏时停用循环并保留必要的退场画面。壳可以管理这类展示资源，但不因此拥有任何业务配置。

## 共享控件

SettingsSwitch 应提供原生 button 的 switch 语义、aria-checked、可访问名称和足够触控范围，保留受控 modelValue 与 update:modelValue 接口。禁用或处理中状态阻止重复意图，控件不自行保存。

完善原语时核对所有实际使用者，包括当前 ThemePicker 为补足语义而添加的外层 button，避免迁移后产生 button 嵌套。线性分组、灰度主体和克制反馈保持项目规范，不新增内容区毛玻璃。

## 有意不建立的结构

不建立全应用 Preferences 巨型对象、不引入自动注册插件系统、不根据文件名扫描注册页面、不生成全量表单 DSL、不复制全局返回栈、不增加统一平台功能门禁。

搜索、跨设备同步、批量重置和偏好导入具有各自产品语义。真正需要时再增加目标条目 ID 或导出接口；本次不预留空壳机制。
