# P4.4 本机知识授权与 `vref` 合同

> 状态：`CONTRACT-FROZEN / CODE-PENDING`
>
> 冻结基线：VCPMobile `cab034257d3b`，2026-08-14
>
> 本文是 P4.4 的施工 ADR。实现完成并通过本文件的回归门以前，`localLoopback.vref` capability 必须保持
> `false`；`vcpPlugin` 的 `vref`、远端 `file://` 和伪造 `vref_files` 继续在 Runtime 前拒绝。

## 1. 产品裁决

P4.4 只解决一件事：用户把受控文件明确授权为**本机知识**后，`VCPMobileCLI action=run` 可以通过
`vref:N` 离线选出最多 N 个文件，并把这些文件的 attempt 私有副本交给该次 Bash Job。

首期不做以下事情：

- 不给 Agent 增加 `import/list/grant/revoke/read_knowledge` action；
- 不让 Agent、Shell 或 manifest 自行取得 SAF 权限；
- 不复用 SkillBridge、RAG 灵视中心、LightMemo、消息附件 UI 或新的 prompt 注入；
- 不用关键词搜索冒充向量召回；
- 不实现远端 artifact transport，也不把 VCPToolBox 主机的 `file://` 当成本机文件；
- 不引入第二个 embedding owner、向量 daemon、ANN、Python 或 PRoot 内模型。

知识授权只存在于 VCP CLI 同一 SlidePage 的“本地知识”页签。一次导入采用：

```text
原生文件选择器
  → owner-owned 有界 staging
  → inspect token + hash + generation
  → 用户阅读边界并明确确认
  → atomic commit，同时授予 local_vref
```

“导入确认”本身就是显式 `local_vref` grant，不再制造第二个授权开关。撤权等于从未来召回中立即移除并
请求删除；若文件已被一个尚未完成 Runtime admission 的 durable selection 持有，则等该 hold 释放后再删除
canonical object。已经完成 admission 的 Job 拥有自己的 disposable copy，撤权不会伪装成可以收回已交给
运行中进程的字节。

## 2. 唯一 owner 与存储边界

新增一个 app-managed `KnowledgeCatalogOwner`，拥有 catalog generation、导入事务、授权、删除、chunk 和
attempt hold。它与 Skill catalog、消息 attachment CAS、同步、Runtime ledger 分离，但复用现有 SHA-256、
`O_NOFOLLOW`、临时文件、`fsync + rename` 和 operation replay 模式。

知识使用独立的 App 私有 CAS：

```text
<app-private>/vcp-cli/knowledge/
  staging/<opaque-token>
  objects/<sha256>
```

不复用消息附件的物理对象。原因是消息附件当前没有在线物理 GC，且附件、知识与未物化 attempt 的引用
所有权不同；共享对象会使“撤权并删除”无法可靠兑现。独立 CAS 允许应用级删除，但不承诺闪存取证级安全
擦除。host 绝对路径、SAF URI 和 staging token 均不得进入 WebView、模型消息、ToolResult、argv 或 env。

SQLite migration `0009` 固定以下本机表；它们不进入 Sync DTO：

| 表 | owner / 用途 |
|---|---|
| `local_knowledge_meta` | 单行 schema、catalog generation 与账面配额 |
| `local_knowledge_sources` | source ID、受控显示名/MIME、size/hash、index 状态、grant/revoke 时间 |
| `local_knowledge_chunks` | source + ordinal、UTF-8 bounded text、content hash；source 删除时级联 |
| `local_knowledge_import_candidates` | opaque token、候选 digest、过期时间与内部 staging identity |
| `local_knowledge_operations` | inspect/commit/discard/revoke 的 operation digest 与 replay 结果 |
| `local_knowledge_attempt_holds` | turn attempt + operation + source；保护 admission 前仍需复制的 canonical object |

catalog 只有一个全局 `local_vref` scope。首期不增加 agent/group/topic 三级 ACL；这既符合上游“用户选择的
知识库”语义，也避免把 speaker Agent 的私人授权错误带入 Group。将来若确有多 catalog/ACL 需求，必须通过
新 schema 明确迁移，不能靠 source 名称猜作用域。

## 3. 导入与索引合同

### 3.1 首批格式

首批只接收实际内容为 UTF-8（允许 UTF-8 BOM）、不含 NUL 的纯文本、Markdown 与常见代码/配置文件。
扩展名和 provider MIME 只用于显示与初筛，最终以 bounded byte scan 为准。PDF、DOCX、XLSX、PPTX 暂不
开放；现有通用 extractor 会在部分路径先构造大字符串，不能直接充当知识导入的内存、压缩炸弹、取消和
deadline 边界。

Android 现有 picker 增加可选 `maxBytes`，逐块按**实际读取字节**停止；provider 报告 size 为 0、未知或
伪小时也不能越过上限。超限、流错误、取消、低存储或进程死亡必须删除残片，不能创建 candidate/grant。
该参数是现有 picker 的窄扩展，不新增另一套文件选择器。

### 3.2 冻结配额

| 项目 | 首期硬上限 |
|---|---:|
| 单个源文件 | 32 MiB |
| active knowledge source | 64 个 |
| knowledge CAS | 512 MiB，不做静默 LRU |
| pending candidate | 16 个、总计 128 MiB、24 小时过期 |
| 单文件可索引 UTF-8 | 1 MiB；其余原文件保留但显示 `index_text_truncated` |
| chunk | 最多 4 KiB UTF-8、512 B overlap、优先在换行边界切分 |
| 单文件 chunk | 最多 300；全 catalog 最多 19,200 |
| query | 最后一条真实 user 与其前最近 assistant 各 16 KiB，先走秘密/系统块过滤 |
| embedding selection | 复用唯一 permit，最多 60 秒，并服从 outer cancellation/deadline |
| `vref:N` | `1..=50`；0、51、溢出与非 `run` action 均拒绝 |

配额超限必须在确认前显示 used/limit 并拒绝，不自动淘汰已授权源。派生向量仍可使用现有 20,000 行 LRU；
chunk 文本与 source 授权不是缓存，不能因向量淘汰而丢失。模型代际变化只使派生向量失效并按需重建。

## 4. 召回语义

`vref` 继续是 `run` 的 meta 字段，不进入 Bash command/argv。查询只从该 turn 冻结的原始 request messages
构建，不能误用后续插入的 `VCP_TOOL_PAYLOAD role=user`：

1. 取最后一条真实 user 和它之前最近的一条 assistant；
2. 分别清洗、截到 16 KiB并嵌入；缺少 assistant 时只用 user；
3. 两者都存在时计算 `normalize(0.7 * user + 0.3 * assistant)`；
4. 用现有 `LocalEmbeddingOwner`、同一模型/mmap/permit 批量取得 chunk 向量；
5. 每个 source 只保留最高分 chunk，再按 `score DESC, source_sha256 ASC, source_id ASC` 稳定排序；
6. 按 source SHA 去重后取 N 个文件。

本地模型不同，所以冻结的是 0.7/0.3、最近消息、按文件去重和稳定 Top-N 结构，不声称分数或命中文件与
VCPToolBox 逐字相同。

错误分层：

- 没有任何 active grant、索引 schema/模型损坏、catalog generation 漂移、selected CAS hash/路径异常：
  在 Bash 前 fail closed；
- catalog 有有效授权但确实没有可用 chunk：持久化 `resolved=0` 与稳定原因，创建空的 attempt vref 目录后
  继续 Bash，保持上游“空数组仍执行工具”的产品语义；
- 不允许回退 FTS5、LightMemo、`river=last:N` 或关键词检索冒充 vref。

## 5. Durable selection 与 attempt copy

`LocalCliStepRecord` 在现有 `river_projection` 旁增加独立 `vref_projection`。二者由一个内部
`AttemptProjectionBundleV2` 送入 Runtime，但对外的 `VCP_RIVER_CONTEXT_FILE` 内容保持 V1 字节合同，
避免把 vref schema 混进现有 River 文件。

vref canonical JSON 使用 `vcp.mobile.vref-projection.v1`，至少固定：requested/resolved、model ID、user 与
assistant query SHA、0.7/0.3 权重、catalog generation、每个 source 的 rank/logical ref/display name/MIME/
size/SHA/guest relative path、omissions。它不含原始 query、host path、SAF URI 或 grant token。

执行顺序：

```text
closed batch claim
  → selection
  → 同一事务持久化 canonical vref projection + source holds
  → Runtime 重新检查 generation/grant/hash
  → attempt-private copy
  → admission 线性化点
  → 释放 canonical holds
  → ProcessHost
```

恢复时若 projection 已存在，只复用相同 operation ID 与这些 canonical bytes，不重新搜索。撤权或 catalog
变化在 admission 前获胜时，删除未启动副本并稳定失败，ProcessHost start counter 必须为 0；admission 先
获胜时，Job 生命周期接管，撤权只影响未来调用。

Runtime 在 `<projectionRoot>/<attempt-stem>/vref/` 写入副本，文件名为稳定 rank + hash + 受控 basename。
每 64 KiB 复制块检查 cancellation/deadline，使用 opened-fd size/hash、`O_NOFOLLOW`、临时文件、fsync、
rename；失败删除整个 attempt vref 目录。Kotlin 对目录、manifest、全部 child 做 NOFOLLOW、hash/size、无
额外文件/嵌套目录/特殊文件校验，然后仅 bind 该 attempt 目录：

```text
VCP_VREF_DIR=/run/vcp-vref
```

rootfs 必须可复现地包含空目标目录 `/run/vcp-vref`。canonical knowledge CAS 永不 bind；PRoot fake-root 下
guest 可改写或删除自己的 disposable copy，host 启动后不回读。start failure、终态、eviction 与进程重启
orphan GC 都清理副本，运行中不能提前删除。

## 6. `river + vref` 合并预算

两个 meta 可同时出现，选择和 omission 必须分别持久化。首期冻结：

| 维度 | River | vref | 合并 |
|---|---:|---:|---:|
| 文件数 | 保持现有最多 16 | 最多 50 | 最多 66 |
| 单文件 | 保持现有最多 64 MiB | 最多 32 MiB | 各自子预算不变 |
| 字节 | 保持现有最多 256 MiB | 最多 256 MiB | 最多 512 MiB |

先保持 River 已冻结的选择结果，再按 vref relevance 顺序填充 vref 子预算与合并预算；不为 vref 挤掉当前
会话显式附件。每个被省略的 vref source 都写稳定 omission code。Runtime admission 要求复制后仍至少保留
256 MiB 可用空间，即启动前 free space 不少于 `本次尚需复制字节 + 256 MiB`。

River 继续逐文件 bind；vref 使用一次目录 bind，因此 66 个逻辑文件不会变成 66 个新增 PRoot argv bind。

## 7. UI 与 manifest

同一 CLI SlidePage 增加第四个“本地知识”页签，复用 `vcpCliStore`、现有页面返回栈和确认对话框，不新建
overlay/store。列表采用高密度线性布局、2 px 状态条和 monospace hash；不使用 AttachmentViewer、
attachmentStore、`convertFileSrc` 或卡片式预览。

UI commands 固定为：

- `get_vcp_mobile_cli_knowledge_catalog`
- `inspect_vcp_mobile_cli_knowledge_import`（内部拉起 native picker）
- `commit_vcp_mobile_cli_knowledge_import`
- `discard_vcp_mobile_cli_knowledge_import`
- `revoke_vcp_mobile_cli_knowledge_grant`

确认文案必须说明：文件会复制到 App 私有知识库；只供 localLoopback vref；命中文件还会复制给目标 CLI
Job；命令 stdout/stderr 或模型续轮可能把其中内容发给当前模型服务；它不是聊天附件、同步数据或提示词；
Agent 不能选择 catalog 外文件。

最后一个 Runtime/Kotlin 门通过后，才把 local capability 改为 `vref=true` 并更新唯一 canonical manifest：

- 明示 `vref` 只用于 `run`，范围 `1..50`；
- 明示 `$VCP_VREF_DIR`、空命中、预算与本机授权边界；
- 给出真实 `run + vref:3` 示例；
- action 集仍只有既有 run/poll/cancel/list 与一等 Skill actions，不增加知识管理 action；
- `vcpPlugin` 继续拒绝 vref/远端 `file://`。

ToolResult 复用现有稳定 ToolBlock，显示 requested/resolved、logical ref、hash、guest path、omissions；不新增
前端“召回结果状态机”。

## 8. 分期与硬验收

1. **P4.4a catalog substrate**：`0009`、独立 CAS、bounded picker、inspect/commit/revoke、UI；capability=false。
2. **P4.4b index + durable selection**：deterministic chunk、0.7/0.3 query、file dedupe、projection/hold/recovery；capability=false。
3. **P4.4c Runtime + Android**：copy、整目录验证/bind、rootfs、GC；全部门通过后翻 local capability与 manifest。

必须覆盖：

- Rust L1/L2：`vref=0/51/overflow`、非 run、UTF-8 chunk、权重 golden、文件去重/tie-break；inspect/commit
  replay、candidate/generation TOCTOU、导入不经确认不授权、撤权四个竞态、0/1/50 hit 恢复不重选；
- 文件/CAS：provider size 伪报、途中超限、流错误、symlink/special/parent swap、hash/size 漂移、配额与
  low-storage，均无半文件/半授权；
- Kotlin L3：错误 stem、额外 child、nested dir、symlink/special/hash 错误拒绝；无 vref 时无 bind/env；
- Vue L4/L5：同一页签、generation fence、二次确认、撤权失败回滚、无 host path；唯一 manifest 没有知识
  action，vref 只在 run meta；
- exact-once：selection/copy 中 cancel 或 deadline 均无 Job/ProcessHost start/残目录；crash 只重放 durable
  selection；guest 改写副本后 canonical hash 不变；
- Android L7/L8：API 26/36 飞行模式召回、最大投影、连续 50 次查询、App PSS/温升、低存储、Doze/cancel、
  terminal/start-failure/orphan GC 与 guest 写攻击。

Host/JVM/静态测试只能关闭代码合同，不能替代上述产品设备门。P4.3 尚未完成的 App PSS、冷热召回与
低存储证据必须和 P4.4 一起列为发布前门禁，不能因 P4.4 capability 打开而改写为已验收。
