## 1. 阻断性回归：PRoot 子进程 `RLIMIT_AS` 过小

- **现象**：P5 手动终端打开即 `Shell 已退出 · code 134`，PTY 输出
  `bionic/linker/linker_cfi.cpp:158: MapShadow CHECK 'p != MAP_FAILED' failed`；Agent Job `run` 同样崩溃。
- **根因**：最后两个提交给 PRoot 子进程设 `RLIMIT_AS = 512 MiB`
  （`CliPtyHost.kt` 的 `PTY_ADDRESS_SPACE_KIB`、`CliProcessHost.kt` 的 `PROCESS_ADDRESS_SPACE_KIB`）。
  bionic 动态链接器 exec 主机 PRoot PIE 时要保留约 2 GiB 的 CFI shadow（`MAP_NORESERVE`，不占物理内存），
  512 MiB 下该 mmap 必然失败。P5 的「代码完成」此前从未在真机跑通过。
- **实测阈值**：`/system/bin/echo` 在 512 MiB / 1 GiB / 2 GiB 下均崩，约 2.1 GiB 以上正常。
- **修复**：两处常量 `512L * 1024L` → `4L * 1024L * 1024L`（4 GiB），附 CFI shadow 注释；README P5 行同步。
  提交 `22a8191`。
- **复验**：PTY 出现 `localhost:/workspace#` 且 `pwd` → `/workspace`；Job `run` `state=completed / exit_code 0`
  （`source=local_loopback`，`uname` 为 `aarch64 GNU/Linux`）。

## 4. VCPToolBox 源码核证（仓库 `/home/dudu/VCPToolBox-main`）

`[[VCPToolUse=Forbidden]]` 是 VCPToolBox 的**请求级全局禁执行控制面**，非用户开关、非 VCPToolBox 自行注入：

| 位置 | 行为 |
|---|---|
| `modules/chatCompletionHandler.js:42` | 定义 `VCP_TOOL_USE_FORBIDDEN_PLACEHOLDER` |
| `modules/chatCompletionHandler.js:187-209` | 在开头连续顶层 system 消息里找并**剥掉**标记（首非 system 即 break） |
| `modules/chatCompletionHandler.js:854` | `vcpToolUseForbidden = consume(...)` |
| `modules/handlers/streamHandler.js:441` | `toolCalls = vcpToolUseForbidden ? [] : ToolCallParser.parse(...)` |
| `modules/handlers/nonStreamHandler.js:318` | 非流式同款 |

关键结论：标记一旦存在，**该轮所有已注册插件都被跳过**（全局禁执行），不是只跳过 `VCPMobileCLI`。
中央 loop 分两层——Parser 通用文本解析（不查注册表）、Executor 按工具名查注册表；Forbidden 关的是 Parser。
