# 08. 分期实施路线图与验收门禁

## 1. 路线原则

本路线以“iPhone/iPad 实验性未签名附属产物”为首个可交付目标，不以 Android 功能逐项复刻或正式 Apple 分发为目标。实施时必须遵守五条边界：

1. Vue/Pinia、Rust 业务 owner 和现有生命周期 generation/cancellation 机制继续作为唯一事实源；
2. Swift 只实现平台适配、权限、文件桥接与原生事件，不创建第二套 Chat、Sync、Distributed 状态机；
3. 平台支持度、当前实现度、用户授权和运行资格必须是独立事实，禁止非 Android fallback 继续伪成功；
4. 每一阶段都按证据等级退出，Linux 静态检查、GitHub macOS 编译、Simulator、实验产物和社区真机报告不得互相替代；
5. 不支持 macOS/Catalyst/桌面端；iOS CI 失败不得阻断 Android 正式 Release。

在任何产品代码施工前，还需遵守仓库的重构存档协议：先确认工作区既有修改的 owner 和范围；若将新增模块目录、拆分大文件或修改跨模块调用链，先建立可恢复存档。存档不等于替用户提交，未经授权不得 commit 或 push。

## 2. 总体路线

```text
Phase 0  决策冻结（本轮已完成）
   ↓
Phase 1  平台中立能力契约 + GitHub macOS/Simulator 尖峰
   ↓
Phase 2  前台核心 + iPhone/iPad WebKit/UI
   ↓
Phase 3  P0 附件（文档/文本/图片）
   ↓
Phase 4  iOS 26 尽力后台 + 前台常亮回退
   ↓
Phase 5  未签名 artifact 附加到 Android GitHub Release
```

Phase 0–5 是一条线性 P0 主线；附件和 iOS 26 continued processing 都不是可书面延期的 P1。社区真机与性能数据在主线之外并行收集，不阻塞 Phase 5，也不得被写成项目已验证。系统通知、语音、视频解析、incoming share、APNs、iOS updater、传感器和正式签名不进入这条路线。

## 4. Phase 1：平台中立能力层与 macOS 构建尖峰

Phase 1A 可在现有环境开始设计和测试；Phase 1B 由 GitHub Actions macOS runner 完成，不要求 distribution 证书、付费 Team 或真机。二者都通过才可进入 MVP 施工。

### Phase 1A：收紧共享契约

- 引入 typed `PlatformCapabilities`，拆分 support、implementation、authorization 和 runtime policy/state/eligibility；
- 建立 `MobilePlatform`/facade 边界，Vue 不直接通过 UA 猜测命令；
- 把非 Android 的权限、硬件、通知、文件删除、剪贴板等伪成功改为 fail-closed 的结构化结果；
- 在现有 Rust Chat、Sync、Distributed、lifecycle owner 内补 task admission/cancel/join/settle 与回执，不复制状态机；
- iOS updater capability 固定 disabled，自动检查、下载、通知、安装和 Store/TestFlight route 均不挂载；
- 为 Android 现有语义补回归契约，避免平台抽象破坏生产目标。

### Phase 1B：最小 Apple 工程尖峰

- 在固定 GitHub macOS runner 上安装/验证完整 Xcode、CocoaPods 和 Rust Apple targets；
- 执行 `pnpm tauri ios init`，审查生成树后再决定哪些文件纳入版本控制；
- 建立最小 Swift 插件骨架，证明同步 command、异步 command、错误和事件四种通路；
- 验证 SQLite、网络、Rust TLS、Tauri plugin 集合和现有依赖能为 Apple target 编译与链接；
- 显式设置 deployment target、Bundle ID、Info.plist、Background Processing 与 capabilities；不生成麦克风/通知/Share/APNs/Catalyst target；
- 未实现命令要么不进入 iOS capability/授权，要么仅在旧调用迁移期由 compatibility handler 返回 `unavailable_by_platform`；不复用开发 fallback。

### 退出门禁

- [ ] macOS 分别完成 device `aarch64-apple-ios` 与 runner 对应 simulator target（Apple Silicon 通常为 `aarch64-apple-ios-sim`）的 locked check；最终 target 以当期 Tauri/Xcode 工具输出冻结；
- [ ] 无 distribution 签名的 Simulator Debug build 成功；code-sign-disabled device `.app` 完成编译/链接，具体命令按冻结的 Tauri/Xcode 版本记录；
- [ ] iPhone 与 iPad Simulator 至少各启动一次，并完成 Rust↔Swift↔Vue smoke；
- [ ] 生命周期、网络和错误事件不会重复注册或丢失 owner；
- [ ] Android 的 `pnpm check`、前端测试、Rust 测试和插件契约测试通过；
- [ ] 41 条命令在 iOS capability 表中无“未知默认成功”；
- [ ] macOS job 不读取任何 Apple signing secret，且失败不阻断 Android CI/Release。

### 失败退出条件

若关键依赖无法支持 Apple target、必须大规模 fork Tauri/核心依赖，或最小 command/event 通路不能稳定建立，应暂停并重新评估技术路线，不得直接扩展 Swift 功能面。

### 此时允许的声明

“Apple unsigned Debug 工程可构建并完成 Simulator 桥接 smoke。”仍不得声明真机兼容、后台可靠或可直接安装。

## 5. Phase 2：前台核心 MVP

### 目标用户旅程

1. 首次启动完成真实 capability discovery 与用途解释；不批量请求可选权限，也不复活 Android PermissionGate；
2. 配置服务器，进入核心 Chat/Diary/Settings；
3. 前台发起、流式接收和取消会话；生成期间 screen-keeper 引用计数正确，Phase 4 前切后台返回明确 interrupted；
4. 前台执行 Sync，切后台后安全收口，返回时按本地 generation/设置决定是否重建客户端 session；
5. 附件入口在 Phase 3 完成前明确 disabled，不落入 HTML/mock 假成功；
6. 正常冷启、热启、短暂 inactive、旋转和分屏不产生重复 owner。

### 关键施工

- Swift 提供聚合 scene snapshot + monotonic sequence，并与 Rust lifecycle epoch 对账；MVP 不启用多窗口 Scene；
- 前台 screen-keeper 与 Rust attempt 建立 exact-once acquire/release；短收尾 token 与 Rust drain outcome 建立回执；
- 动态 CSS safe-area 与 `visualViewport`/原生键盘候选分别进入现有 Insets owner；先由 Simulator 固定优先级和回退，社区设备证据只触发后续校正；
- 先在 Tauri/Wry spike 证明是否存在原生返回手势，再与应用横滑抽屉仲裁；无论结果如何都取消全屏误触入口；
- 设置输入与核心触控命中达到已冻结的可访问性标准；
- 同时治理 viewport meta 与全局 `touch-action` 的禁缩放影响；若保留限制，limitations 必须说明可访问性尚未获真机验证；viewer 自定义 pinch 只做局部声明；
- modal/sheet 补焦点进入与恢复、背景 inert、键盘关闭闭环；装饰 WebGL 在 hidden/reduced-motion 时停 rAF，并处理 context loss/restore；
- Chat 在既有 attempt owner 内补 lifecycle cancel/join/settle；服务端无 cursor/helper cache，断开后明确终止；
- Sync 保留现有 epoch/generation/cancel/join 结构；
- Distributed 首期不注册；
- 文件路径全部限定为 app container 或经授权后复制的 staging。

### 退出门禁

- [ ] 核心旅程在 iPhone/iPad Simulator 通过自动化或可复现 smoke；
- [ ] iPhone/iPad Simulator 覆盖布局、modal focus、键盘、foreground screen awake 与生命周期终态；
- [ ] 无 continued task 时切后台给出明确 `interrupted/foreground_required`，不出现永远 pending；
- [ ] 所有 `X` 能力在普通 UI 中无误导入口；
- [ ] Android 生产关键旅程无回归。

### 此时允许的声明

“iOS 前台核心已通过固定 Simulator smoke。”必须同时列出未支持能力；不得写成设备验证、Beta、正式 Release 或“全面兼容 iOS”。

## 6. Phase 3：P0 文件与图片附件

只实现已冻结的附件闭环：

| 能力 | 实现边界 | 主要门禁 |
|---|---|---|
| Document Picker + staging | Swift 处理 security-scoped URL 并流式复制；Rust 重新验证 | 超限、取消、重复导入、ticket 清理、canonical containment |
| Office/PDF/text | 复用 Rust `zip`/`pdf_oxide`/`encoding_rs`/`chardetng` extractor | DOCX/XLSX/PPTX/PDF 固定 fixture、BOM/编码、50 MiB/输出字符硬上限 |
| 图片选择 | PHPicker/Files，不预申请整个照片库 read/write | provider staging、MIME/魔数、取消、方向 |
| 图片转换 | 小图复用已有 fallback；≥5 MiB 级/HEIC 用 ImageIO/CoreGraphics 写 staging | 像素/字节上限、无整图双份 Base64、失败清理 |
| 缩略图 | 必要时使用 QLThumbnailGenerator，结果进入 cache | 可重建、cache 清理、原件 owner 不变 |

明确不在本阶段：相机、PhotoKit 保存、outgoing/incoming share、录音/音频、视频抽帧、系统通知、background URLSession、传感器。

### 退出门禁

- [ ] 每项能力都有 capability、授权拒绝、撤销授权和平台限制测试；
- [ ] 所有临时文件都有 owner、大小上限、清理时点和 canonical containment；
- [ ] 文档/文本/图片的 MIME、扩展名、魔数和服务端 Content-Type 一致；
- [ ] Info.plist/PrivacyInfo 与实际代码路径一致；
- [ ] Apple compile + iPhone/iPad Simulator fixture/staging smoke 通过；
- [ ] 性能保持 `NOT-EVALUATED`，但既有大小/字符/路径硬上限没有被放宽。

### 此时允许的声明

“文档/文本/图片附件已通过 Apple compile、fixture 与 Simulator staging smoke。”不得外推真实第三方 Files provider、真机内存或视频/音频能力。

## 7. Phase 4：iOS 26 尽力后台生成

服务端不改造，本阶段只延续同一个客户端 Rust SSE attempt：

- `if #available(iOS 26.0, *)` 时提交 `BGContinuedProcessingTask`；即时 admission 失败返回 `continued_task_rejected/foreground_required`；
- task accepted 后，Swift 只持有 task token/Progress/cancel handler，Rust 继续拥有 request/attempt/DB terminal；
- iOS <26、重签导致最终 Bundle ID/task identifier 配置不匹配或系统拒绝时，要求用户保持 Chat 主界面，生成期间 `UIApplication.isIdleTimerDisabled=true`；
- expiration、系统取消、用户取消、网络断开和 terminal 经同一 compare-and-complete owner exact-once 收口；
- `max_output_tokens` 只可表达输出预算上限。有可信 token 时显示“已接收 N / 上限 M”，无可信计数时使用 indeterminate + 字符/字节/chunk 活动；terminal commit 后才 completed；
- Sync/Distributed 不借用 Chat continued task；服务端无 cursor，task 失效后不自动恢复；
- 不实现 APNs、Share Extension、silent push、BGAppRefresh 轮询或伪 audio/location background mode。

### 退出门禁

- [ ] availability guard 覆盖 iOS <26 / 26+，没有调用新 API 导致旧系统启动失败；
- [ ] admission accepted/rejected、system/user cancel、expiration、foreground race 和重复回调均有契约测试；
- [ ] screen-keeper 只在前台 active generation 持有，所有 terminal/取消/异常路径释放；
- [ ] Progress 无定时器伪造；budget usage 不标“完成百分比”；
- [ ] Simulator 证明桥接路径；真实调度时长仍标记 `COMMUNITY-DEVICE-UNVERIFIED`；
- [ ] 不再沿用 Android FGS/helper/WakeLock 术语向用户承诺，UI 明示“系统尽力/可能中止”。

### 此时允许的声明

“iOS/iPadOS 26 continued-processing 路径已通过编译和 Simulator 契约；旧系统/系统拒绝时前台常亮回退。”不得写“后台可靠”“强保活保证”或“真机已验证”。

## 8. Phase 5：实验性未签名附属产物

- Android GitHub Release `published` 后启动独立 macOS job；
- 从同一 tag/commit 生成 code-sign-disabled device `.app` 和 Simulator smoke；
- 产出 `.app.zip`（可选经结构验证的 `.unsigned.ipa`）、SHA-256、artifact manifest 和 limitations；
- manifest 记录实际 code-sign 检查、`distributionSigned=false`、Xcode/runtime/target、Bundle ID、minimum system、capabilities 和实际测试层级；
- limitations 明示需用户自签、免费 profile 通常 7 天、无第三方工具支持、无自动更新、无项目真机/性能保证、后台可能终止；
- 资产附加到现有 Android GitHub Release，不创建 App Store/TestFlight CTA；
- iOS job 失败可见但不阻断 Android job，不删除或修改签名 APK。

### 最终产物门禁

- [ ] 所有 P0 缺陷关闭或 P0 能力从本 artifact 完全下架；P0 不允许只写风险延期，只有 P1 可裁决延期；
- [ ] Phase 1–4 的 Apple compile/Simulator/契约门禁通过；
- [ ] Release UI 不展示 Root、通知监听、OEM 权限、语音、系统通知、Share Extension 或 APK/iOS 更新入口；
- [ ] unsigned artifact、hash、manifest、limitations 与 tag/commit 一致，且 CI 未读取签名 secret；
- [ ] Android Release 与现有 CI/CD 未被 iOS 分支破坏；
- [ ] 发布说明明确前台/后台、附件、自签、无更新与未验证边界。

社区设备证据和性能数据不在最终门禁内。允许的状态是 `EXPERIMENTAL-UNSIGNED-ARTIFACT-PUBLISHED`，不使用 `BETA`、`RELEASED`、`DEVICE-VERIFIED` 或 `APP-REVIEW-APPROVED`。

## 10. 回滚与停止规则

任一阶段出现以下情况，应停在当前 evidence state，不得用产品文案掩盖：

- 必须使用私有 API、越狱能力或不真实 background mode 才能满足核心承诺；
- 不接受 12 条 `X` 的不可用语义；
- 产品重新要求“后台持续生成必达”，而非已经接受的 iOS 26 尽力续跑 + 前台回退；
- 无可用 GitHub macOS/Xcode runner，却要求声明 Apple binary 已编译；
- 平台抽象要求复制 Chat/Sync/Distributed owner；
- iOS 改造持续破坏 Android arm64 生产路径且没有可隔离修复。

没有 Apple Team、项目真机或性能报告本身不是停止条件。停止时将结论保持为 `RESEARCHED`、`MACOS-CI-BUILD-PENDING` 或对应阶段，等待工具链或范围发生真实变化。

## 11. 完成定义

本专项最终完成不以“存在 `gen/apple`”为标准，而以以下闭环为标准：

```text
产品承诺
  = capability 真值
  = Vue 可见状态
  = Rust 单一 owner 行为
  = Swift 公开 API 行为
  = CI/Simulator/实验产物证据
  = Info.plist/PrivacyInfo/artifact limitations 声明
```

任何一项不一致，都只能降级能力或证据等级，不能把缺口留给 fallback 假成功。社区真机与性能证据是明确的已接受缺口，不得暗改为“已通过”。
