## Phase 1：平台身份与共享契约

2026-10-08 的初次实施见 [阶段子规划](./phase-1/00-阶段子规划.md) 和 [验收与 Phase 2 交接](./phase-1/07-验收与Phase2交接.md)。其中四字段能力表与启动查询已在本轮被同步平台身份和局部 Vue 分支替代；以下是当前继续维护的契约，不要求恢复历史结构。

目标：

- 通过统一入口消费原生平台身份，普通交互差异使用共享 Vue 运行时分支，不建立逐项能力总表；
- 启动编排、说明入口和实际操作分别消费所需状态，不以整表加载作为 READY 前提；
- cfg 拆为 Android/iOS/host-test；
- iOS 返回 adapter 的真实结果，host 数据留在开发分支；
- Tauri 的 Android/iOS 命令授权按实际前端消费者配置；内部 Rust 接口不为形式对称公开；
- Android 专属机制保留其真实实现；完整设备工具在 P3-4/P3-5 接入 iOS，缺失字段如实返回；
- 将附件 data/cache/staging 目录语义平台化；
- 把 lifecycle DTO 升级为 phase + native sequence + snapshot。

完成条件：

- Android 消费者仍连接原有实现与数据目录；
- 平台分支、实际 Tauri 授权、Rust/TS DTO 和 UI 消费一致；
- 每条返回结果都对应实际状态/副作用或明确错误；
- `pnpm check` 与针对字段、取消、路径的必要检查通过。

下一阶段输入是确定的 DTO、命令映射、目录接口和状态所有者。

## Phase 3：前台核心、权限、通知与设备工具

生命周期策略：

## Phase 5：SSE 后台专项、常亮与其他后台任务

任务与依赖：

| 任务 | 具体实现与依赖 | 完成条件 |
|---|---|---|
| P5-1 SSE 持续接收方案 | 优先核对用户提出的静音音频、continued task 等候选的具体 API/系统条件、资源成本、中断和清理；依赖 Phase 2 lifecycle 与 P3-1 实际 SSE 链 | 给出有来源的条件比较及采用理由，分别说明连续接收/断线恢复/结果落盘；未覆盖的连续接收情形明确未关闭，不能以“尽力后台”替代新要求 |
| P5-2 attempt 与单次终态 | 依赖 P3-1；把选定运行资源接到同一 Rust attempt、取消原因、settle receipt、进度与持久化路径 | 正常、用户取消、system end、transport error 和迟到回调只提交一次 terminal；结果归属可追踪，重启按已持久化事实对账 |
| P5-3 continued adapter | 依赖 P5-2；当前 minimum 26.0，按实际 SDK 接入 request/handler/activation/expiration/completion 与 Bundle ID task 前缀，更高版本 API 仍做 availability | 注册、提交、激活和失败路径完整；真实累计进度与未知总量映射明确；无任务时的处理与 P5-1 最终方案一致，不抢先取消其他有效保活路径 |
| P5-4 前台常亮与其他后台策略 | 依赖 P5-2；接 idle timer 的任务持有/释放，明确 Sync、Log/Info、Distributed、维护的后台收尾和前台恢复 | 常亮在完成/取消/离开后释放；其他任务按各自尽力策略 stop/join/flush；前台回退清楚可见，不宣称已经满足严格 SSE 目标 |

continued-task 路径保留以下实现要点，最终 SSE 继续/收尾条件按 P5-1 的实际选择回填：

- iOS/iPadOS 26.0 基线下的 request/handler/expiration/completion 接入，更高版本 API 的 availability；
- attemptId 与 taskId 绑定，提交拒绝时采用前台常亮；
- Rust 真实累计字符/字节/可选 token → Swift Progress 与系统标题；
- continued-task 路径由其真实激活状态决定继续或收尾；其他候选资源采用各自条件，其他连接/维护循环按领域关闭；
- 正常完成、用户取消、system end 和 transport error 共享单次 terminal。

完成条件：

- 04 中最终采用路径的状态表和每种分支都有对应生产实现，候选方案与已实现分栏记录；
- 注册/提交/激活顺序明确，迟到 handler 按 generation 归属；
- Progress 已知/未知总量分支有具体映射，真实事件驱动计数；
- 取消、expiration、终态竞争有可复现事件序列；
- runtime Bundle ID 与 plist 任务前缀一致。
- SSE 高优先目标仍有未解决的技术条件时，如实保留未关闭项并向用户说明；源码正确、host 检查或 Apple 构建都不被写成持续后台运行的保证。
