### 当前结构与后续接入方式

```text
Vue / Pinia
  ├─ plugin-os 同步身份 → isAndroid / isIOS 局部分支
  └─ 现有 Feature / Store / Composable → Tauri IPC
       ├─ Rust domain owners：Chat / Sync / Persistence / Files / Distributed
       └─ 实际原生操作
            ├─ Android Kotlin + JNI/Channel
            └─ iOS Swift + C FFI/Channel
```

必须维持的 owner 不变量：

- Chat attempt、Sync session、数据库、附件 CAS 和 Distributed client 仍由 Rust 唯一拥有；
- Swift 只报告 app phase/network/权限事实，呈现 picker/share/system UI，并持有 Apple task token；
- SSE、同步队列、重试与恢复继续归现有 Rust owner；
- Vue 用同步平台身份表达差异，用领域返回值呈现真实结果；不复制页面树、平台策略表或每按钮适配器；
- 获批准、已接入、用户授权及即时条件是不同事实，按实际消费者分别处理，不要求每项都填写统一状态表；研究记录集中在 00。

### Swift 插件的完整注册链

```text
build.rs .ios_path("ios")
  → tauri-plugin/build/mobile.rs → Swift Package 静态库
  → ios_plugin_binding!(init_plugin_vcp_mobile)
  → register_ios_plugin(init_plugin_vcp_mobile)
  → VcpMobileState.plugin_handle
  → run_mobile_plugin[_async](命令名, DTO)
  → Swift @objc selector → Invoke.resolve/reject / Channel.send
```

自有插件的 `ios/Package.swift`、Swift product 和 Rust binding 已建立；`tauri-plugin-opener 2.5.4` 保留为上游参照。2026-10-07 研究读取的构建实现为 `tauri-plugin 2.6.3` 与 `tauri-utils 2.9.3`；当前锁定为 `2.7.1` / `2.10.1`，工程输入须以当前版本为准。Swift package product、库名与 Rust binding 符号的实际 Apple 链接待 G1 核验。

历史研究从 `tauri 2.11.5` 的 `PluginManager.invoke` 追到 IPC queue 与 ObjC selector；当前自有 Swift 的 `registerNativeEvents` 已显式进入主队列。后续 UIKit、复制/解码与 DTO 实施继续按各自线程和接口要求处理；当前框架为 Tauri 2.12.1，旧版本源码引用不表示本轮获得了新的编译结果。

Swift 在 `registerNativeEvents` 保存 Channel，回放当前生命周期快照，再发送生命周期与网络变化。Rust 生命周期仍归约到现有 transition epoch。通知点击由 Swift 暂存，并通过 WKWebView 的 `vcp-notification-pending` 事件提示 Vue 取走。Phase 3 新增通知授权、发送、待处理点击、剪贴板及设备/传感器 selectors，由相应消费者调用。`getNativeCapabilities` 已删除，平台身份独立于事件注册和设备查询。

桥接取消仍有实际依赖约束：Tauri 2.12.1 的异步 oneshot 与同步 mpsc 回调都对 send 使用 `unwrap()`。事件注册继续保留一个有界在途槽位；通知异步命令与传感器/Distributed 的阻塞原生调用由 blocking worker 持有 receiver 至最终响应，外层取消不会撤销已执行的系统操作。`#[command(async)]` 本身只离开 IPC/UI 线程，不等同 blocking 池；各调用沿真实等待边界审查。已无能力查询槽位。

### cfg 与错误语义

稳定结构应显式拆成：

```rust
#[cfg(target_os = "android")]
// Android production

#[cfg(target_os = "ios")]
// iOS adapter

#[cfg(not(any(target_os = "android", target_os = "ios")))]
// host test/development scaffold
```

当前通知、剪贴板、设备/传感器 iOS 分支已有实际 Swift 操作；分享、原生媒体及后台资源尚未接通的分支继续返回 `not_implemented:`，Android 独有机制仍返回真实不可用。预期不可执行入口由 Vue 说明并返回，不以防绕过为理由逐命令增加另一层功能门禁，也不要求建立通用错误状态机。

已执行操作按其消费者需要区分权限拒绝、取消、条件暂不可用与失败。成功结果携带真实路径或操作结果；固定容量/电量等 host 数据留在开发分支，iOS 不借用这些值。共同权限引导和设备工具按实际字段接入，不用空值或零值冒充成功。

### 数据与网络边界

- SQLite 建议继续放 `app_config_dir/app_data_dir` 内；附件 CAS 用 `app_data_dir`，瞬时 picker/security-scoped 副本和大文件上传用 `app_cache_dir`；
- 外部 security-scoped URL 不进入长期数据库；Swift 在授权窗口内复制到 staging，再由 Rust hash/CAS；
- Rust HTTP/WebSocket 在 transport owner 执行 scheme、证书和受信 LAN policy；WebKit/URL Loading 路径配置对应 ATS 项；
- LAN 使用说明、拒绝后的可恢复错误与设置返回重试纳入功能实现；
- `127.0.0.1` 高速上传沿现有 token、长度与 CAS 链审查，补前端 abort 和过期回调处理，见 05。

### 最小改造顺序

1. 使用已接入的同步平台身份，完成本轮入口、自动任务与监听分支的简化及验证；
2. 保留已有 cfg、路径、Channel 和共享 owner，取得 G1 工程编译诊断；
3. 闭合 Chat/SQLite/Settings/Sync 前台业务及原生附件链；
4. 按最新审批接共同权限、分享/通知、相机/相册和网络遥测/Distributed，实际任务在相应阶段展开；
5. 研究 SSE 后台持续接收方案，闭合 attempt/task identity、进度、终态和其余尽力后台；
6. 在 G2 汇总集成、构建与用户自签产物。

每项按源码推演、实现与缺陷回扫推进；Apple 构建仅在 G1 插件接入、G2 首版集成/打包验收时通过 GitHub Actions 手动执行。检查细目见 07。
