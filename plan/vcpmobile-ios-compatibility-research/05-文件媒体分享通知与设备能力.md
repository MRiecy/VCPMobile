# 05. 文件、媒体、分享、通知与设备能力

## 1. 总体原则

iOS 原生层的职责不是接管附件业务，而是把系统资源安全地交给现有 Rust owner：

```text
Apple Document Picker / PHPicker / ImageIO
  -> bounded staging file + factual metadata
  -> Rust validate path/type/size/hash
  -> existing attachment CAS + DB commit
  -> cleanup ticket
```

任何 Swift 路径都不应绕过 Rust 的路径、大小、hash、所有权和清理边界。

附件是首个实验产物的 P0，但“附件”必须拆成两层：**iOS 原生层只负责获取、security-scoped URL、staging、缩略图和必要媒体预处理；DOCX/XLSX/PPTX/PDF/文本的解析继续由现有 Rust extractor 完成。** 当前 Android 文件选择本身是 Kotlin SAF，并非 Google 通用编码器；现有 `chardetng`/`encoding_rs` 是 Rust/Mozilla 系编码检测与转换库，Android `MediaCodec` 只参与音频/媒体路径，不是 Office/PDF 通用解析器。

## 2. 数据目录重构

当前附件根目录通过 `document_dir()` 后 `pop()` 推导，带有 Android 路径结构假设。iOS 施工前应按数据性质明确目录：

| 数据 | 推荐容器 | 备份/清理语义 |
|---|---|---|
| SQLite、用户设置、聊天/日记正文 | app support/data | 持久、迁移、受保护；是否备份需产品决策 |
| 附件 CAS 原件 | app data 或明确 documents | 持久；按用户数据策略备份 |
| 可重建缩略图/预渲染 | caches | 不备份，可被清理，必须可重建 |
| picker/camera 临时导入 | temporary/staging | 有 ticket、超时和异常清理 |
| Share Extension 交接 | 当前不创建 | incoming share 不在实验产物范围；未来另立项时才引入 App Group |
| background URLSession 文件 | 当前不创建 | 首期附件由前台 picker/staging 完成 |

必须设计 Android 既有路径到跨平台目录的迁移，不能在 iOS 上简单改变函数后让 Android 数据失联。

## 3. Files 与 security-scoped URL

[attachmentStore.ts](../../src/core/stores/attachmentStore.ts) 的 Android 分支调用原生 picker，非 Android 才使用 HTML `<input>` fallback；后者只是候选路径，不等于完整 iOS 文件系统集成。对于系统 Files provider，iOS 使用 `UIDocumentPickerViewController`。参见 [Apple Document Picker](https://developer.apple.com/documentation/uikit/uidocumentpickerviewcontroller)。

推荐流程：

1. 用户显式发起 picker；
2. Swift 获得 URL 后在授权窗口内协调访问；
3. 检查文件是否为 regular file、大小上限、UTType 和可读性；
4. 流式复制到本 App staging，避免长期持有 provider URL；
5. 返回 `ticket/path/name/size/declared_type`；
6. Rust 重新 canonicalize、探测真实 MIME、计算 hash、注册附件；
7. 成功或失败都按 ticket 清理。

不要：

- 把外部 security-scoped URL 当永久内部路径存库；
- 在 Swift 一次性读完整大文件再 Base64 穿过 IPC；
- 只相信扩展名/UTType；
- 为方便测试扩大 asset protocol scope。

### 3.1 现有 Rust 解析器是主路径

[file_extractor.rs](../../src-tauri/src/vcp_modules/infra/file_extractor.rs) 已按扩展名处理 DOCX、XLSX、PPTX、PDF 和文本；[Cargo.toml](../../src-tauri/Cargo.toml) 已引入 `zip`、`pdf_oxide`、`encoding_rs`、`chardetng`、`memmap2`。因此 iOS 不需要寻找一个“Apple 版 Google 通用文档编码器”，也不应把解析重写进 Swift：

1. Swift 把 provider URL 流式复制到 app staging；
2. Rust 执行既有路径/大小/类型/编码检查和 Office/PDF/text extraction；
3. 解析结果继续进入现有附件 CAS/DB owner；
4. Apple compile/link 证明依赖可构建，fixture 测试证明解析结果不回归；性能状态仍标记 `NOT-EVALUATED`。

原生 Apple API 补的是媒体和预览，而不是文档正文解析：`CGImageSource`/ImageIO 用于图像解码与缩放，`QLThumbnailGenerator` 用于系统缩略图，`AVAssetImageGenerator` 是未来视频抽帧候选，`PHPickerViewController` 用于用户选择照片。它们不能替代 Rust Office/PDF extractor。

## 4. 相机与照片（首期仅图片附件导入，其他默认延期）

### 4.1 相机输入

相机拍摄不是首个实验产物 P0；首期可隐藏 camera shortcut，只保留 Files/PHPicker 图片导入。未来若确需拍照，HTML `<input capture="environment">` 可作低成本候选，稳定路径则使用 Swift/AVFoundation 或系统 camera UI，并保持输出进入 staging。

未来启用时才必须覆盖：

- `NSCameraUsageDescription`；
- first ask、denied、restricted、Settings 恢复；
- HEIC/JPEG、方向、色彩空间和 Live Photo 是否接受；
- 超大原图的缩放/编码预算；
- 用户取消不视为 error toast；
- Simulator 只能验证权限/UI 流，真实质量只能由社区真机报告补充。

参见 [Requesting Authorization to Capture and Save Media](https://developer.apple.com/documentation/avfoundation/requesting-authorization-to-capture-and-save-media)。

### 4.2 照片选择与照片库访问

照片能力至少拆成四条，不能共用一个 `limited/denied` 状态。首期只选“用户选择照片”用于附件；拍照、保存和直接管理图库均延期：

| 能力 | 系统路径 | 授权事实 |
|---|---|---|
| 拍照 | 相机/AVFoundation 或系统 camera UI | camera authorization 独立 |
| 用户选择照片 | `PHPickerViewController` 候选 | 系统私密选择通常不要求 App 先取得整个照片库 read/write 权限；返回项仍需 staging/大小/MIME 验证 |
| 只保存到相册 | PhotoKit add-only | 记录 requested access level 与该 level 的 authorization status；不能无条件套用 `limited` |
| 直接浏览/管理照片库 | PhotoKit read/write | 只有产品确需时请求；此时才处理 limited library 范围与选择变化 |

参见 [PhotoKit privacy guidance](https://developer.apple.com/documentation/photokit/delivering-an-enhanced-privacy-experience-in-your-photos-app)。

### 4.3 保存照片

`save_image_to_gallery`/`save_image_from_path` 可用 PhotoKit 做 add-only 实现：

- 使用最小照片写入权限和用途说明；
- 分别记录 add-only access level 与其 `notDetermined/authorized/denied/restricted` 等实际状态；若另有 read/write 能力，再单独处理 limited library；
- 先验证 sandbox path、UTType、文件大小和实际图像解码；
- 返回真实 local identifier/结果，不伪造 Android URI；
- 保存失败不删除原始附件。

参见 [PHPhotoLibrary](https://developer.apple.com/documentation/photos/phphotolibrary)。

## 5. Outgoing Share 与 Incoming Share（当前均不进入首期）

两者是不同产品能力，不能共用“分享”一个勾选框。冻结决策是首个实验产物均不实现；以下只保留未来若另立项时的技术边界。

### 5.1 Outgoing Share

从 VCPMobile 分享文本、图片或文件可使用 `UIActivityViewController`：

- iPhone 模态呈现；
- iPad 必须提供正确 popover source；
- 大文件用 file URL/item provider，不先转 Base64；
- completion 只表示系统 sheet 结束，不一定表示目标 App 成功处理；
- capability 只能在后续版本中独立实现，首期 UI 隐藏。

参见 [UIActivityViewController](https://developer.apple.com/documentation/uikit/uiactivityviewcontroller)。

### 5.2 Incoming Share

从其他 App 分享到 VCPMobile 需要独立 Share Extension，不是普通插件 command：

```text
Share Extension process
  -> validate input count/type/size
  -> copy to App Group staging
  -> atomically write immutable manifest/ticket
  -> complete extension request; do not assume it can open host App
Host App
  -> claim ticket once on its next normal/approved activation
  -> Rust validate/hash/CAS/DB
  -> mark consumed + cleanup
```

Apple 的 extension 生命周期边界只允许 Today widget 请求系统打开 containing App；Share Extension 不能靠 `openURL` 强拉主 App。首期交接必须允许“分享已暂存，主 App 下次正常打开后导入”，不得使用 responder-chain 等非公开绕行。若产品要求分享后立即进入主 App，需要另行核验当期公开的系统入口，不能把它作为既定能力。参见 [Understand How an App Extension Works](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/ExtensionOverview.html)。

所需新增面：

- 第二个 Bundle ID；
- Extension target；
- host/extension 一致的 App Group entitlement；
- 独立 provisioning profile；
- 激活规则、超时、内存预算；
- 多文件/大文件、冷启动/热启动、重复投递测试；
- ticket generation、claim owner 和过期清理。

Extension 不应启动 Rust Chat 核心、写主 SQLite、连接 VCP server 或持有长期状态。参见 [Apple Share Extension](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/Share.html)。

冻结结论：incoming share 不进入当前 iOS 产品范围，不创建 Extension、App Group、第二 Bundle ID 或 provisioning 依赖。

## 6. 录音、语音识别与音频附件

当前 Android 版本的录音/语音链本身不可用；Web recorder 虽会探测 MP4 等容器，附件与 Whisper 上传仍固定 `.webm`，不能把它当作可复用资产。

冻结结论：

- iOS 隐藏录音、语音附件与语音识别入口；
- 不初始化 `MediaRecorder`，不引入 AVAudioRecorder，不请求麦克风权限；
- Info.plist 不添加 `NSMicrophoneUsageDescription`；
- 不为 iOS 修复 `.webm`/`audio/mp4` 不一致，也不把音频测试列为 iOS 门禁；
- 若以后全平台重新启用语音，必须作为独立功能重建真实 MIME/扩展名/魔数、服务端接收格式和取消清理契约。

## 7. 图片、视频与文档处理

### 图片与附件预算

当前不是一个统一的“5 MB 图片上限”，而是多条不同路径：

- 附件 import 的 WebView IPC 小文件路径约束为 `<2 MiB`，更大文件另走本地 XHR/受控路径；
- 非 GIF 图片附件还有约 10 MiB 的前端约束；
- Rust 多模态图片转换的非 Android 整文件 Base64 fallback 使用 5 MiB 级预算，它不代表整个附件导入链；
- HEIC 等格式的候选转换仍应输出受控 staging，由 Rust 管理，而不是放宽某一条 Base64 IPC 上限。

首期实现保持三条预算独立：小于现有 fallback 上限的图片可继续走 Rust 路径；达到/超过 5 MiB 级多模态 fallback 上限或需要 HEIC/方向处理时，Swift 用 [CGImageSource/ImageIO](https://developer.apple.com/documentation/imageio/cgimagesource) + CoreGraphics 解码、按像素/字节上限缩放并写入 staging，再交 Rust。缩略图可用 [QLThumbnailGenerator](https://developer.apple.com/documentation/quicklookthumbnailing/qlthumbnailgenerator)。不得把 MB/MiB 或一条 fallback 外推为全链上限，也不得为了“大图能过”取消现有硬上限。

### 视频

当前视频抽帧只有 Android 实现，非 Android 分支明确 unsupported。首期冻结为 `unsupported_by_product_scope`：可按普通文件附件发送，但不做视觉抽帧/多模态视频解析；相关入口必须解释限制。未来若需求恢复，使用 [AVAssetImageGenerator](https://developer.apple.com/documentation/avfoundation/avassetimagegenerator) 输出受控 staging，并分别限制帧数、像素和总字节，不能在内存中构造整批 Base64。

### Office/PDF/文本

Rust file extractor 静态看来是复用候选；当前边界包括 50 MiB 级输入文件上限与一千万输出字符上限。P0 要求 Apple compile/link、既有真实 DOCX/XLSX/PDF/PPTX fixture 和编码 fixture 通过；不新增 iOS memory benchmark/soak 门禁。运行时性能与 jetsam 写作 `PERFORMANCE-NOT-EVALUATED`，社区故障报告触发修复，不能因为底层是 Rust 就写“无压力”或“已优化完成”。

## 8. 通知能力分层

| 能力 | iOS 结论 | 说明 |
|---|---|---|
| App 内 Toast/通知中心 | 复用 | Vue/Pinia 现有能力 |
| 本 App local notification | 首期不实现 | 不请求 UserNotifications 权限；保留 App 内 Toast/通知中心 |
| remote notification/APNs | 不在当前范围 | 服务端不改造，且当前无正式签名/推送资产 |
| notification click/deep link | 首期不实现 | 不保留伪 pending notification；未来启用时交现有路由 owner |
| Android ongoing download notification | 不等价 | iOS updater 不存在；continued task 的系统 Progress 属于 BackgroundTasks 契约，不另做自定义 ActivityKit Live Activity |
| 监听其他 App 通知 | 不支持 | iOS 无 NotificationListenerService 等价 |
| 读取系统通知历史 | 不支持 | `get_pending_notification` 只能表示本 App 待处理 response |

首期 iOS 不触发系统通知授权。能力查询必须区分 `supported_by_platform` 与 `unsupported_by_product_scope`，不能以空操作成功代替。

## 9. 屏幕常亮、电池、网络和热状态

### 屏幕常亮

`UIApplication.isIdleTimerDisabled` 可近似实现屏幕常亮，但必须：

- 继续由现有引用计数/owner 控制；
- 只在前台生成期间启用；App inactive/background 时收回，即使 continued task 仍在运行也不宣称屏幕常亮；
- 异常退出或最后 owner 释放时恢复；
- UI 明确把它描述为“前台等待时防自动锁屏”，不是后台 CPU/网络保活。

参见 [UIApplication.isIdleTimerDisabled](https://developer.apple.com/documentation/uikit/uiapplication/isidletimerdisabled)。

### Battery

可获得有限的电量和充电状态，并可观察 Low Power Mode；普通 App 没有当前 Android DTO 中“电池温度 25°C”的公开等价。温度字段必须 nullable/unsupported，不能以固定值填充。

### Thermal

`ProcessInfo.thermalState` 返回 nominal/fair/serious/critical 等系统热压力，用于降载，不是 CPU 摄氏温度。DTO 和 UI 必须改名。参见 [ProcessInfo Thermal State](https://developer.apple.com/documentation/foundation/processinfo)。

### Network

`NWPathMonitor` 可提供连接路径、接口、昂贵/受限状态；它不保证 VCP endpoint 可达，也不保证稳定获得本机 IP 或链路速度。

## 10. 传感器与 Distributed 工具（首期不实现）

首个实验产物不为传感器、完整设备遥测或 Distributed 工具请求额外权限。下表只保留 capability fail-closed 的平台事实，不能据此自动注册工具：

| 当前工具/数据 | iOS 候选 | 产品结论 |
|---|---|---|
| Location | Core Location | 只在用户明确用途下请求；后台另行审核 |
| Motion | Core Motion | 前台候选，按设备 capability |
| Barometer | Core Motion/altimeter | 设备可能无硬件，nullable |
| Ambient light | 无普通 Android TYPE_LIGHT 等价 | MVP 不支持 |
| CPU temperature | 无公开等价 | 用 thermal state 替代并改名 |
| GPU renderer/load | Metal device name 部分可取 | 不声称 GPU load；字段重定义 |
| Root/Shell | 无 | 永不广告 |
| Clipboard | UIKit/Tauri 官方插件候选 | 只在用户操作中读写；未实现不广告 |
| System local notification | UserNotifications | 首期产品范围外；只保留 Vue Toast/通知中心 |

Distributed registry 必须消费同一 `PlatformCapabilities`：

- 平台不支持：不注册；
- 设备无硬件：不注册或标 unavailable；
- 用户未授权：不注册，或只注册显式请求授权的安全动作；
- 当前后台：整个 Distributed session offline；
- 所有结果返回真实时间、来源和可用性，不返回演示数据。

参见 [Core Motion](https://developer.apple.com/documentation/coremotion/)。

## 11. 剪贴板与隐私体验

当前非 Android **native/Distributed clipboard command** 读返回 placeholder、写入无操作成功；普通 Vue 交互中另有多处直接使用 `navigator.clipboard`，两者不能混为“整个前端剪贴板不可用”。iOS 必须对两条路径分别选真实实现与 feature-detect：

- 用户点击“复制”时写入剪贴板；
- 用户明确点击“粘贴”时读取；
- 或使用经过审计的 Tauri 官方 clipboard 插件；
- 不在后台/启动时自动读取；
- 不实现时返回 unavailable，不能返回假内容。

## 12. 已冻结的能力清单

[08-分期实施路线图与验收门禁](./08-分期实施路线图与验收门禁.md) 是实施顺序真源；本节给出文件/媒体侧的最终范围。

### 首个实验产物 P0

- Files Document Picker + security-scoped URL + bounded staging；
- DOCX/XLSX/PPTX/PDF/文本继续走 Rust extractor 与既有 fixture；
- 图片附件：PHPicker/Files 输入，小图复用既有 fallback，大图/HEIC 用 ImageIO/CoreGraphics staging；
- screen awake：只在前台生成期间启用；
- 所有未实现或平台不支持能力 fail-closed，不返回 mock 数据。

### 当前明确砍掉或延期

- 砍掉：录音、语音识别、音频附件专用处理、系统 local notification、APNs、incoming Share Extension、iOS 更新链；
- 延期：相机拍摄、PhotoKit 保存、outgoing share、视频抽帧、background URLSession、location/motion/barometer、完整设备遥测、Distributed、clipboard/haptics 增强；
- 项目不为上述延期项承诺版本，也不让它们阻塞首个未签名产物。

### 永不对等

- Root、Root manager；
- 跨 App 通知监听；
- Android Wake/Wi-Fi Lock；
- OEM auto-start/battery whitelist；
- 程序化退后台；
- APK/IPA 自安装更新；GitHub 未签名产物只能由用户在应用外自行重签安装。
