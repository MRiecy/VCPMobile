# 02. 平台能力与 41 条命令兼容矩阵

## 1. 分类口径

本表覆盖 [插件 build.rs](../../src-tauri/plugins/vcp-mobile/build.rs) 中全部 41 条公开命令，并与 Rust `invoke_handler` 和 `permissions/all.toml` 交叉核对。分类保持**当前命令的产品语义**；不能把 APK updater 命令改名解释成通用文件传输后再声称兼容。

| 级别 | 定义 | 产品动作 |
|---|---|---|
| `R` | 现有 Rust 逻辑或已引入的跨平台插件路径基本可复用 | 移出错误 cfg/复用既有 facade，验证 Apple target 与容器路径 |
| `S` | 需要 Swift，Apple 公开 API 可实现接近原语义 | 实现、补权限、补跨语言契约测试 |
| `L` | 只能实现部分目标，字段、生命周期或用户承诺必须改变 | 先改契约，再实现；UI 显示限制 |
| `X` | 当前命令语义在 iOS sandbox/公开 API 中无安全等价 | 正常能力面不授权、不展示；迁移期若旧调用仍可达，则临时 compatibility handler 返回结构化 `unsupported` |

“可实现”不等于“已实现”，所有 `R/S/L` 都仍是理论结论。

计数闭合：

- `R`：#16、#20、#24、#25，共 4；
- `S`：#1、#2、#17、#21–#23，共 6；
- `L`：#3–#6、#8–#9、#14、#18–#19、#29–#35、#39–#41，共 19；
- `X`：#7、#10–#13、#15、#26–#28、#36–#38，共 12；
- 总计：`4 + 6 + 19 + 12 = 41`。

Apple 在 iOS/iPadOS 26 增加了用户发起长任务的 continued-processing API，但系统仍可拒绝、取消或因资源压力终止；它只能支撑“尽力继续”，不能重新包装成持续 SSE 保证。更早版本回退为前台运行。参见 [Performing long-running tasks](https://developer.apple.com/documentation/backgroundtasks/performing-long-running-tasks-on-ios-and-ipados/) 和 [BGContinuedProcessingTask](https://developer.apple.com/documentation/backgroundtasks/bgcontinuedprocessingtask)。

## 3. 41 条之外的隐藏原生面

公开命令表不是完整平台边界，以下调用同样必须纳入 iOS 设计：

| 隐藏面 | 当前事实 | iOS 动作 |
|---|---|---|
| `set_keepalive_mode` | 主应用单独注册，仍映射 ForegroundGuardian | 纳入 iOS 26 continued/前台常亮 logical lease，返回实际模式 |
| lifecycle event | Rust 已监听 iOS，只有 Kotlin sender | Swift 发同名事件，Rust epoch 不变 |
| network event | Rust 监听 `vcp-mobile://vcp-network-status-changed` | Swift `NWPathMonitor` 发事实，Rust reconnect owner 不变 |
| keyboard Insets | Android Kotlin 注入 `vcp-keyboard-inset` | 复用同一前端 owner，增加 iOS source 或实测 viewport source |
| clipboard | Distributed 直接调用 native bridge，非 Android 返回 placeholder/no-op | 采用真实 Swift/官方插件或不广告 capability |
| local notification | 非 Android 空操作成功 | 首期不实现；iOS capability 返回产品范围外且 UI 隐藏 |
| media processing | 文档解析主要在 Rust；图片小文件有 fallback；音频/视频 Android 化 | 文档复用 Rust；大图由 ImageIO staging；音频禁用、视频延期 |
| updater | 非 Android 仍下载并打开 APK | iOS 禁用检查、下载、通知和安装全链路 |
| restart/exit | 非 Android `process::exit(0)` | iOS 返回 unavailable，不提供自重启/退出 |
| floating overlay | 命令已注销但有遗留 UI 调用 | 不为 iOS 复活；平台隐藏并作为独立现存缺陷处理 |

## 4. 功能级产品矩阵

| 功能族 | iOS MVP 建议 | 说明 |
|---|---|---|
| 核心 Chat/Diary/Settings | 支持 | 复用 Vue/Rust/SQLite，需 Apple target 与 WebKit 验证 |
| 前台 Sync | 支持 | 进入后台时收口，恢复后按 generation 继续 |
| 前台 Distributed | 默认延期 | 未来启用时只广告真实工具；不承诺后台运行 |
| 文档/文本/图片附件 | P0 支持 | Document Picker/security-scoped URL 进入 staging；Rust 解析文档；大图用 ImageIO/CoreGraphics |
| 相机/相册写入/外部分享 | 默认延期 | 与附件导入分开，确有需求再逐项增加 |
| 语音录音 | 不支持 | 当前 Android 路径也不可用；iOS 隐藏且不请求麦克风权限 |
| 视频提取 | 延期 | 当前非 Android 明确 unsupported；后续可评估 `AVAssetImageGenerator` |
| 系统 local notification | 首期不支持 | 保留现有 App 内 Toast/通知中心；不申请系统通知权限 |
| incoming share | 首期不支持 | 不创建 Share Extension/App Group/第二签名目标 |
| 后台文件传输 | 二期 | 新建平台中立 transfer owner；background URLSession 不复用 APK progress 通知命令 |
| 后台 Chat 持续生成 | iOS 26+ 尽力续跑 | `BGContinuedProcessingTask` 被系统接纳时延续同一 Rust SSE；其他情况前台常亮等待；服务端不改 |
| Root/跨 App 通知/OEM 自启动 | 永不对等 | iOS UI 隐藏 |
| APK/IPA OTA | 禁用 | 未签名产物只在 GitHub Release 供用户手动自签，应用内无更新链 |
| PWA | 不在本专项 | 需独立 IPC/存储/后台/安装设计 |

## 5. Capability DTO 建议

不要用一组 `bool` 继续承载权限、平台能力和运行状态。建议统一返回事实型结果：

```json
{
  "platform": "ios",
  "capabilities": {
    "chatForeground": {
      "support": "supported",
      "implementation": "not_implemented",
      "authorization": "not_applicable",
      "runtime": { "policy": "foreground_only", "state": "active", "eligibleNow": true }
    },
    "chatBackground": {
      "support": "degraded",
      "implementation": "not_implemented",
      "authorization": "not_applicable",
      "runtime": { "policy": "system_managed", "state": "background", "eligibleNow": true },
      "minimumOSForContinuedProcessing": "26.0",
      "activeMode": "continued_processing",
      "fallbackMode": "foreground_screen_awake",
      "reasonCode": "IOS_SYSTEM_MAY_SUSPEND_OR_TERMINATE"
    },
    "photoLibraryWrite": {
      "support": "supported",
      "implementation": "not_implemented",
      "authorization": "not_determined",
      "runtime": { "policy": "unrestricted", "state": "active", "eligibleNow": false }
    },
    "notificationListener": {
      "support": "unavailable_by_platform",
      "implementation": "not_implemented",
      "authorization": "not_applicable",
      "runtime": { "policy": "unrestricted", "state": "active", "eligibleNow": false },
      "reasonCode": "IOS_NO_CROSS_APP_NOTIFICATION_ACCESS"
    }
  }
}
```

建议至少分离四组事实：

- `support`：平台是否存在安全实现；
- `implementation`：当前仓库尚未施工、部分施工或已实现；
- `authorization`：用户授权状态；
- `runtime.policy/state/eligibleNow`：能力运行策略、当前前后台/网络条件和此刻是否可执行。

这样可避免把“平台有 API 但尚未施工”“平台不支持”“用户拒绝”“当前离线”混成同一个 `false`。`eligibleNow` 必须按系统版本和本次 task admission 动态计算；示例中的 `true` 只是“iOS 26+ 且本次已接纳”的快照。编译、Simulator、社区真机和产物证据仍属于独立 evidence state，不能塞进 capability DTO。

## 6. 命令命名迁移

现有 Android 命名不应一次性破坏调用方，可采用兼容迁移：

1. 新增平台中立 facade，例如 `request_permission`、`get_platform_capabilities`；
2. Android 旧调用暂时映射到新 owner，标记 deprecated；
3. Vue 全部改走 typed facade，不再直接基于 UA 选 command；
4. 稳定一个版本后再删除旧命令及僵尸 permission；
5. 每次调整同步更新 Rust handler、`build.rs`、permissions、guest-js、Kotlin/Swift selector tests。

当前 [guest-js/index.ts](../../src-tauri/plugins/vcp-mobile/guest-js/index.ts) 只封装部分命令，其他前端直接 `invoke`。iOS 施工前应统一 typed facade，不能假设现有 guest-js 已完整覆盖 41 条。

## 7. 产品硬边界

若产品不接受 12 条 `X` 的不可用结论，项目应停止“iOS 等价迁移”而不是寻找私有 API 或继续返回伪成功。对 `X` 的稳定态是从 iOS capability 中移除；只有旧前端仍可能调用的迁移窗口，才保留最小授权并由 compatibility handler 返回结构化错误。未正式上架不改变 iOS sandbox、公开 API 与后台调度事实。
