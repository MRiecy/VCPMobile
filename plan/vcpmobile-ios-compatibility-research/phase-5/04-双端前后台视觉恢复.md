# 双端前后台视觉恢复

日期：2026-10-17。用户确认 Android/iOS 同时采用原生旧画面快照遮罩；不做主题底色同步，不以设备验证作为实现前置条件。本轮沿用此前“检查、测试与构建延后”的决定。

## 目标与所有权

回到前台时先呈现离开时的实际画面，覆盖网页重新提交图层的空档，待当前文档布局与原生绘制均就绪后揭幕。壁纸、主题、消息气泡由真实快照保留，不用推测颜色代替。

- Android `NativeWebViewResume` 持有 PixelCopy 结果和兄弟遮罩，监听实际主 Activity；业务 `LifecycleBridge` 不改用途。
- iOS `NativeWebViewResume` 由 `NativeWebKit` 持有，绑定实际 WKWebView/Scene，持有 UIKit 快照和兄弟遮罩；不替换 Wry 的 navigation delegate。
- Vue `useWebViewResume` 只确认当前文档可展示；ChatView 发送当前会话首屏消费完成信号，App 提供现有启动状态与实际壁纸 URL。
- Rust `plugins/vcp-mobile/src/webview.rs` 只转交两个短期命令，不持有图片、业务终态或新的后台任务。

SSE、同步、通知、bootstrap 和持久化继续归各自既有 owner。视觉恢复不重新发送生成请求，不保持后台 WebView 强制可见，不新增常亮或音频租约。

## 握手

1. 每次文档初始化建立 `window.__vcpWebViewResume = { documentId, readyToken: null }`，先监听 `vcp-webview-resume`，再调用 `connect_webview_resume({ documentId })`。返回当前待处理 token 或 null，覆盖事件早于页面监听安装的情况。
2. 原生在真正后台后的回前台流程建立新 token，通过同名 DOM 事件发送 `{ token }`。UUID 只用来比较身份，不比较大小；前端不会用迟到的 connect 返回覆盖已接到的新事件。
3. 前端等待实际可展示状态、当前会话首屏、Vue 布局和壁纸解码；不等待流式正文停止变化，也不等待所有分页历史或所有后台任务。
4. 前端设置 `readyToken`，调用 `complete_webview_resume({ documentId, token })`。命令返回只表示已交给原生，未表示画面已显示。
5. 原生核对文档标识和 token，再等待平台绘制。揭幕前再次核对身份、就绪标识、前台状态和当前几何，防止旧回调移除新遮罩。
6. 成功揭幕后通过同一个事件发送 `{ token, finished: true }`，前端只清除匹配的当前 token，避免正常键盘或窗口变化继续为已结束的恢复解码壁纸、发送命令。

权限页和启动错误页本身是可展示结果，不强制等待 `READY`。壁纸加载失败按现有页面降级显示，不把失败变成永久遮罩。

## 平台绘制边界

Android minSdk 26 使用窗口 PixelCopy 保存已合成的 WebView 区域，避免软件 `View.draw(Canvas)` 丢失硬件内容。`postVisualStateCallback` 之后仍等待后续绘制；API 29+ 使用帧提交回调，旧版本使用绘制回调与后续帧调度。它不是固定毫秒数的揭幕计时器。

API 29+ 的帧提交监听必须在该次绘制开始前登记，再请求 WebView 绘制；不能放到 `OnDrawListener` 内才登记。AOSP `ViewRootImpl.performDraw` 先收集 commit callbacks，后续 `draw` 才派发 `OnDraw`，否则静态页面可能没有下一帧来消费迟登记的回调。

iOS 在 Scene 即将失活时用 `snapshotView(afterScreenUpdates: false)` 留下已渲染画面；只有实际进入后台才保留到复归。前台的 `takeSnapshot` 使用非空小区域及显式 `afterScreenUpdates = true`，临时结果立即释放。WebKit 的该路径先等待页面呈现更新，再经 CA post-commit 进行截图；应用不调用私有 API。

真实 WebView 始终留在窗口中正常绘制，遮罩放在其原生兄弟层级，不进入 DOM 或被截图的 WebView 子树。正常揭幕直接移除遮罩，不叠加主题颜色或额外淡出动画。

## 异常与资源

- 暂时失焦但未进入后台，不触发完整遮罩恢复。
- 快速切换、显式重试、页面重载及几何变化按本轮身份作废旧回调。
- 截图未到、失败或已经过期时不制造空白截图；未取得可用快照时退回框架原有显示。
- 原生等待超过 5 秒只提供“界面仍在恢复”的操作面；重试显示换 token，显式重新加载调用既有 WebView reload，不把超时当作绘制成功。
- 一次只保留一份旧画面。iOS 同一上下文只持有一个在途小截图；重载、真实后台或 Scene 更换会撤销旧操作的逻辑权限，系统迟到回调不能清除新上下文的操作。Android PixelCopy 写入期间不得回收目标 Bitmap，已展示 Bitmap 只释放引用，避免 RenderThread 尚在引用时立即 recycle。
- 原生销毁、Scene 脱离和内存压力都有清理边界；不写磁盘快照，不建设截图缓存池。
- 整个 App 进程被杀后按既有冷启动路径处理，本方案不承诺跨进程保存原画面。
