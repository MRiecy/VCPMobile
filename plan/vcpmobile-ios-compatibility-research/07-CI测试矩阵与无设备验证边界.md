# 07. CI、测试矩阵与无设备验证边界

## 1. 当前事实

现有 Android **软件与契约层**测试资产较完整，但权威设备证据仍是 pending，且完全没有 Apple 执行面：

- [ci.yml](../../.github/workflows/ci.yml) 只有 `ubuntu-latest` job；
- CI 生成 Android tree，执行 Gradle/Robolectric 和 Rust/Vitest；
- [release.yml](../../.github/workflows/release.yml) 只有 Ubuntu + NDK + Android keystore + APK；
- [package.json](../../package.json) 没有 iOS build/test/release script；
- 没有 Swift XCTest、XCUITest、Simulator、Apple target 或未签名 iOS artifact 资产；
- 当前主机没有 Xcode/Swift/CocoaPods/Apple Rust targets。

因此本轮只能标记 `STATIC-AUDITED` 和 `DEPENDENCY-GRAPH-RESOLVED`。

## 2. 验证层级

| 层级 | 环境 | 必须产物 | 可关闭风险 |
|---|---|---|---|
| I0 静态治理 | Linux | 源码/配置/命令矩阵报告 | 缺文件、错误 cfg、假 fallback、UI 泄漏 |
| I1 Host tests | Linux | Vitest/Rust tests/build | 状态机、DTO、生成物语法、协议契约 |
| I2 Apple compile | macOS + Xcode | Rust Apple target、Swift Package、Xcode build | 编译、链接、binding、generated tree |
| I3 Simulator | iPhone/iPad runtime | 启动 artifact、截图、XCTest/XCUITest | 基础 IPC、布局、键盘/safe area、路由 |
| I4 Community device | 用户自签的具名 iPhone/iPad | 自愿设备报告、日志、截图、build SHA | 只关闭该设备上的权限、后台、LAN、媒体与手势问题 |
| I5 Experimental artifact | GitHub macOS + Android Release | unsigned `.app`/自签输入、SHA-256、manifest | 同源码完整 device artifact 可编译、可追溯发布 |

任何测试名称都应包含层级，避免把 host/simulator 报告误写成 device evidence。

与 [00-证据等级](./00-研究契约与证据账本.md#3-证据等级) 的映射是：`E0 → I0`，`E1 → I0/I1`，`E2 → I2`，`E3 → I3`，`E4 → I4`，`E5 → I5`。I5 只证明实验资产附加成功，不证明可直接安装、签名、真机行为或正式分发。

## 3. 无 Mac/设备时可以做什么

### 可以完成

- `PlatformCapabilities` DTO、平台矩阵与 UI 可见性单测；
- `android/ios/host_test` cfg 组合的纯 Rust 单元测试；
- 禁止 iOS 使用固定 `true`、Mock 传感器、空 `Ok(())` 的静态契约；
- Chat lifecycle epoch、continued-task admission/cancel/expiration、foreground fallback、partial/final/terminal 状态测试；
- Sync/Distributed cancel+join、无迟到 commit、无双 owner 测试；
- server 不可恢复时的 `interrupted`/显式重试契约；
- 文件 staging、path containment、hash、size/MIME 预算测试；
- DOCX/XLSX/PPTX/PDF/text fixture 与图片 staging 契约；
- Android/iOS command 与 permission manifest 的文本契约；
- Info.plist/entitlement/PrivacyInfo 的静态 schema/内容测试；
- iOS UI 不出现 Android Root、OEM 电池、listener、APK updater；
- 现有 Android CI 软件回归，保证跨平台施工不破坏已覆盖的合同；L6/L7、截图、触控和多设备 WebView 仍需 Android 设备，不能称“无设备全量回归”。

### 不能完成

- `tauri ios init/build`；
- Swift selector/binding 的真实编译；
- WKWebView CSS、Canvas、MediaRecorder、Clipboard 行为；
- Apple SDK 下 SQLite、reqwest、tokio、pdf/zip 等依赖链接；
- Local Network prompt、ATS 真机行为；
- 真实 Files provider/PHPicker 与第三方键盘；
- suspend、continued-task 实际调度、jetsam；
- 用户自签工具、profile entitlement 与安装续签行为。

语音、APNs、Share Extension、系统通知和正式签名不属于首期，因而不是“待完成测试”。iOS 性能/长稳也不设项目门禁，统一记录为 `PERFORMANCE-NOT-EVALUATED`。

## 4. Linux 静态门禁设计

在不生成 iOS 工程之前，可以先增加下列治理测试：

### 4.1 平台能力 fail-closed

- 每个 capability 必须有独立 support、implementation、authorization 与 runtime policy/state/eligibility；
- `unavailable_by_platform` 不得转成 `true`；
- host test mock 必须带 `source=host_test`；
- iOS registry 不得包含 Root、listener、autostart、helper、move-to-back；旧 wake-lock 调用只能映射为真实 continued/foreground logical lease 并返回实际模式；
- 未授权的 location/motion 不上报；
- `get_cpu_thermal_status` 不再声称摄氏 CPU 温度。

### 4.2 跨语言命令契约

对于每个 Rust native call：

- Android Kotlin 有 selector，或 Android capability 显式 unsupported；
- iOS Swift 有 selector，或 iOS capability 显式 unsupported；
- method name、argument label、DTO 字段与 optionality 一致；
- handler、`build.rs`、permissions、typed JS facade 一致；
- 删除命令后 autogenerated permission 无残留。

当前 guest-js 只封装部分命令，新增 iOS 前应先统一 typed facade，再冻结快照。

### 4.3 前端治理

- 禁止以 UA 作为权限/平台能力真源；
- iOS 不挂载 Android PermissionGate、BatteryOptimizationGuide、Root、APK installer；
- capability 改变不复制 Pinia owner；
- safe-area 只从根变量消费；
- 语义 z-index 与 no-blur 宪法继续生效；
- 强渲染 fixture 在 Android/iOS build target 都存在。

### 4.4 后台/协议

- lifecycle transition 乱序；
- iOS 26 continued task admission/expiration/cancel 与 foreground race；
- iOS <26 或 admission rejected 时 screen-keeper 引用计数与 `foreground_required`；
- cancel receipt 幂等；
- partial terminal 不重复写库；
- user-stopped generation 不被 resume；
- Sync/Distributed child join 完成后才清 owner；
- 无真实 token usage 时 Progress 保持 indeterminate；budget usage 不标成完成率；terminal 后才 completed。

## 5. macOS 编译 CI

应新增独立 macOS job，不能把它塞进现有 Android job。第一版建议固定 runner 与 Xcode 版本，避免 `macos-latest` 漂移。

候选步骤：

1. checkout clean commit；
2. 安装固定 Node/pnpm/Rust；
3. 添加 `aarch64-apple-ios`、`aarch64-apple-ios-sim`，按 runner 架构补 simulator target；
4. 安装/验证 CocoaPods 与 SwiftPM；
5. 运行前端 typecheck/test/build；
6. 执行 `pnpm tauri ios init --ci`，以当前 CLI help 为准冻结参数；
7. 检查 generated Apple/plugin permission tree 漂移；
8. Apple target Cargo check；
9. Swift XCTest；
10. Xcode iPhone/iPad Simulator build + smoke；
11. code-sign-disabled Apple device `.app` compile/link；
12. 校验 iOS 26 availability guard、Info.plist/task identifier 与 P0 capability；
13. 跑 Rust document fixtures、Swift staging tests 与关键 Vitest；
14. 上传 build log、derived metadata 和 CI artifact，不接触任何签名 secret。

供应链基线还应包括：第三方 Actions 固定完整 SHA、pnpm frozen lockfile、Cargo `--locked`、CocoaPods lockfile 与 SwiftPM `Package.resolved` 的 owner、固定 Xcode/runtime 版本，以及 macOS job 的最小 `permissions`/`concurrency`。所有 iOS job 都不接触 certificate、provisioning、App Store Connect 或 APNs secrets。

生成树只能选择一种 owner：要么 clean `ios init` 可重建且所有项目定制由受控 patch/config 施加；要么把经审查的 Apple project 纳入版本控制并做 drift check。首期只有主 App target，不生成 Share Extension、Catalyst 或 macOS target。

退出条件：clean checkout 可重复生成和编译，不依赖开发者本机缓存。

## 6. Simulator 自动化

### 6.1 建议最小矩阵

实验 artifact job 覆盖最低支持 runtime 和含 iOS 26 continued-processing API 的固定 runtime；PR CI 为控制成本可只跑一个代表 runtime/设备。runner image 上没有冻结 runtime 时应明确 fail 或有期限地更新基线，不能静默换成 `latest`。

| 设备形态 | 窗口/方向 | 核心场景 |
|---|---|---|
| 小/标准 iPhone | portrait + landscape | 启动、Chat、键盘、viewer、safe area |
| 带 cutout 的现代 iPhone | portrait + landscape | 四边 inset、边缘手势、弹层 |
| iPad | portrait + landscape | single/dual pane、sheet presentation |
| iPad 分屏 | compact/regular 切换 | 状态不丢、抽屉不重复、键盘 |

不要把几十个设备型号塞入 CI；按形态选代表，Release 前再扩展。

### 6.2 Simulator 可测旅程

- cold start → bootstrap → READY；
- Rust/Swift 同步与异步 command round-trip；
- scene active/background/foreground event；iOS 26 continued-task handler/admission fixture 与旧系统 foreground fallback；
- CSS safe area、基础 software keyboard；
- Chat text send、stream fixture、真实 activity/progress、cancel/expiration/interrupted；
- Diary CRUD、数据库 restart；
- DOCX/XLSX/PPTX/PDF/text fixture、Files/PHPicker UI 与图片 staging 预筛；不外推真实 iCloud/第三方 provider 或 security-scoped 互操作；
- permission denied UI（能模拟的部分）；
- modal/sidebar/router 关闭顺序；
- Markdown/KaTeX/Mermaid/raw HTML fixture；
- iPad width transition；
- Accessibility Inspector/可访问树与 focus 的基础审计；真实 VoiceOver 旅程留给具名设备。

### 6.3 Simulator 不能替代

- 真实 iCloud/第三方 Files provider 与 PHPicker；
- Local Network privacy；
- 物理边缘手势与第三方键盘；
- Low Power Mode、热压力、jetsam；
- continued task 的实际 admission、资源终止时机与最终重签 entitlement。

相机、语音、APNs、传感器与 Share Extension 已退出首期，Simulator 不测试这些路径。

## 7. 社区真机报告矩阵（非发布门禁）

项目没有 iPhone/iPad，真机测试成本由愿意使用实验产物的用户/社区分摊。没有报告不阻止 CI 产物；收到报告也只证明对应设备/build，不升级为正式兼容认证。

优先征集四类事实：

| 类别 | 建议旅程 |
|---|---|
| iOS <26 的 iPhone | 自签安装、启动/配置、前台生成+屏幕常亮、键盘、文档/图片附件、LAN |
| iOS 26+ 的 iPhone | 上述旅程 + continued task admission、锁屏/切后台、系统取消/expiration |
| iPadOS <26 的 iPad | portrait/landscape、窗口宽度、sheet、键盘、Files provider |
| iPadOS 26+ 的 iPad | 上述旅程 + continued task、分屏/旋转期间的能力回退 |

报告模板：

```text
release tag + unsigned artifact SHA-256 + commit
device model + OS build
resulting Bundle ID（不要附证书、profile 或账号秘密）
installation/re-sign tool name + version（自愿）
network topology + permission state
test case + expected/actual
screenshots/sanitized logs + timestamp
```

最有价值的运行事实是：Local Network allow/deny；security-scoped Files provider；safe area/第三方键盘/边缘手势；continued task 的 admission/cancel/expiration；断网后的 terminal；大文档/图片失败。电量、内存、thermal、jetsam 和 soak 可随故障报告附带，但项目不设采样方案、阈值或性能验收结论。

## 8. 实验产物 CI 与 GitHub Release

新增独立 `ios-experimental` macOS job/workflow：

- 触发于与 Android 相同的 GitHub Release `published` 事件，并校验 tag/commit 映射；
- 固定 GitHub macOS image、Xcode/runtime、Node/pnpm/Rust 与 Apple targets；
- 运行 I0/I1、code-sign-disabled device build、iPhone/iPad Simulator smoke；
- 检查 architectures、Info.plist、requested capabilities、PrivacyInfo、实际 code-sign 状态、`distributionSigned=false` 与不存在 signing secret；
- 打包 `.app.zip`/经验证的自签输入、SHA-256、artifact manifest 和 limitations；
- 使用最小 `contents: write` 权限把资产附加到现有 GitHub Release；
- iOS 失败必须可见并保留日志，但不得让 Android job 失败、删除 Android APK 或回滚 Release；
- 不上传 TestFlight/App Store Connect，不使用 certificate/profile/API key。

canonical 序列：

```text
IOS-STATIC-PASSED
  -> IOS-MACOS-COMPILED
  -> IOS-SIMULATOR-SMOKE-PASSED
  -> IOS-UNSIGNED-ARTIFACT-PACKAGED
  -> IOS-EXPERIMENTAL-ASSET-ATTACHED
```

任一步失败即停在该步并保留 `IOS-EXPERIMENTAL-FAILED(reason)`；Android Release 仍可完成。asset attached 不代表用户已签名或设备已验证。

## 9. 证据状态机

```text
RESEARCHED
STATIC-AUDITED
DEPENDENCY-GRAPH-RESOLVED
MACOS-COMPILED
SIMULATOR-VERIFIED
EXPERIMENTAL-UNSIGNED-ARTIFACT-PUBLISHED
COMMUNITY-DEVICE-REPORTED(scope)   # 可选、并行，不是前置
```

永久并列状态：`COMMUNITY-DEVICE-UNVERIFIED`、`PERFORMANCE-NOT-EVALUATED`、`FORMAL-DISTRIBUTION-OUT-OF-SCOPE`。`*-PENDING` 只表示尚未取得下一层证据，不是成功状态。每个成功状态必须附 commit、环境和证据链接；产品 capability 另用 support、implementation、authorization 与 runtime policy/state/eligibility，不能拿 CI 状态替代运行时事实。

## 10. Android 回归保护

iOS 施工不得降低现有 Android 门禁：

- `pnpm check`；
- Vitest；
- Rust workspace tests/integration/clippy；
- `tauri android init --ci` generated drift；
- Kotlin/Robolectric strict dependency verification；
- Android arm64 Release 签名与版本治理。

跨平台改造应先扩展 owner，再接 iOS adapter；不能为了 Apple build 把 Android 原生能力改成最低公分母。

## 11. 当前阶段的验证命令

本轮文档交付只需要：

- Markdown 链接/结构检查；
- 41 条矩阵计数检查；
- `git diff --check`；
- 工作区状态核对；
- 不运行 iOS 构建，不把 `cargo tree` 解释为 compile。

由于没有修改产品代码，本轮不以工作区既有或并发产品改动触发无关全量构建。
