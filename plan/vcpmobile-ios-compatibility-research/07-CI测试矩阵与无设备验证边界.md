# 07. 日常源码审计与阶段性 GitHub Actions 验收

> 2026-10-09 修订：保留既定 Windows 日常源码审计与手动 GitHub Actions 验收方式，补入已批准的权限、通知、设备工具、分享/媒体和 SSE 后台专项；本轮不触发构建。

> 2026-10-16，用户同意开发中按需手动执行 Apple 构建。下文记载当时拟定的分期验收范围。现行操作见 [iOS 构建说明](../../docs/IOS_BUILD.md)。

## 固定工作方式

项目现在及后续均不建设 iOS 实机测试体系。施工采用“源码审计推进实现 → 阶段性 GitHub Actions 构建 → 诊断回到源码闭环”的固定流程。日常验收以调用链、目标分支和资源生命周期为单位；GitHub Actions 集中检查编译、链接与产物。

| 工作节奏 | 输入与动作 | 交付记录 |
|---|---|---|
| 每批实现 | 生产源码、锁定依赖、Swift/API 声明、模板；沿受影响路径逐层展开 | cfg、类型、符号、线程、状态与缺陷闭环 |
| 本地辅助检查 | Windows 现有工具；按改动运行 `pnpm check` 与能够回应实际不确定性的领域用例 | 具体输入与诊断，随源码问题一起处理 |
| 阶段验收 | 手动触发 GitHub Actions macOS runner，使用固定工程输入 | Rust/Swift 编译、链接、配置与 bundle 检查结果 |
| 交付打包 | 阶段验收产生的 device archive，按 06 检查包结构 | `.app.zip`、条件性 `.unsigned.ipa`、manifest、SHA-256 |

iPhone/iPad、系统回调和文件授权等情形纳入下文源码路径矩阵。模拟器只保留为 GitHub Actions 阶段验收中的按需诊断选项，默认验收走 device 构建与产物检查。

### 编译器处理阶段对应的审查

将每个结论落实到编译器处理的具体规则和应用状态迁移：

1. **选择输入**：以 `aarch64-apple-ios` 展开依赖与 features，另核对 Android/host 受影响分支；区分 build script 的 host 和库的 target。启用 Simulator 诊断时再展开对应 target；
2. **名字与类型**：列出 cfg 后存活的模块、导入、宏注册、trait bounds、DTO 和 Swift selector；
3. **所有权与并发**：检查 future/回调生存期、Send/Sync、主队列、锁与取消；
4. **原生代码**：记录 C/汇编输入、ABI、SDK include、deployment target、静态库和 framework；
5. **链接与装配**：从 FFI 声明追到符号定义，核对 SwiftPM product、Rust archive、资源/plist；
6. **行为路径**：对正常、拒绝、取消、迟到与重复回调逐条演算到终态。

01 已完成 SQLite/zstd/ring 的目标 feature 与构建分支分析。实施时可复用下列只读命令继续展开目标图：

```powershell
cargo tree --locked --offline --manifest-path src-tauri/Cargo.toml --target aarch64-apple-ios -e features
```

离线源缺失时按锁文件取得对应包，再进入具体源码。遇到未决项写清文件、符号、条件和下一步查阅来源。Apple 工程、Swift adapter 和脚本依据锁定模板同步施工，构建输入在阶段验收时集中执行。

### 日常遍历与缺陷闭环

1. **建立覆盖清单**：从当前插件命令、app commands、启动入口、native callbacks、配置与构建脚本枚举受影响入口，02 作为导航。每项列出调用者、所需授权、平台实现和结果消费方，不以旧命令数量限制新增任务。
2. **双向追踪**：从入口追到依赖实现、系统 API 与资源释放，再从返回值/事件追回最终消费者。跨进程、跨线程、跨语言处逐字段检查；宏、代码生成与 FFI 展开到实际定义。
3. **演算分支**：每条链覆盖正常、空值、边界值、授权拒绝、超时、取消、重复/乱序/迟到回调、部分写入与恢复；按可达事件顺序检查状态和资源所有者。
4. **修复并回扫**：记录触发条件、根因和改动位置；修复后沿调用者、被调用者及共享 owner 扩展检查同类缺陷。锁文件、DTO、cfg 或生命周期变化时重新审计相关依赖路径。
5. **形成阶段结论**：记录已覆盖入口、目标条件、闭环问题和具体剩余项。单项改动审计受影响路径，阶段收束时复核完整入口清单；以“哪些路径和问题已经查清”描述完成度。

涉及跨层或核心逻辑的实现继续执行仓库要求的 `pnpm check`。可在 Windows 执行的解析检查和领域回归按真实问题选择，不把同一张文档表复制成源码断言充当新增证据；Apple 特有分支按锁定语言规则、接口声明及依赖实现逐项推导。

## 当时的阶段验收设计

方案将原生插件接入与首版集成打包分开记录，同一提交的原生问题可以按需提前诊断。

| 验收点 | 合并检查的施工范围 | 默认执行 |
|---|---|---|
| G1：插件与生命周期接通 | Phase 1–2 的配置、cfg/ACL、DTO、Swift 注册、Channel 和生命周期 | device debug archive；集中检查编译、符号、链接和资源装配 |
| G2：首版功能集成与打包 | Phase 3–5 的核心、共同权限/通知/Distributed、文件媒体/双向分享/WebKit，以及 SSE 专项实际实现和其他后台策略，连同 Phase 6 打包脚本 | device release archive；扩展及声明结构检查、用户自签资产、manifest 与 SHA-256 |

当时为 G1 规划 arm64 device debug archive，为 G2 规划独立的 release archive。讨论过 Simulator 专项取证，此记录没有相应运行结果。

### 框架升级的审查范围

计划升级 Xcode/Tauri 时单独比较：

- 生成全新 Apple 工程；
- Scene manifest/delegate、单窗口启动、active/inactive/background；
- Tauri/tao 对新 SDK 的启动代码与 availability；
- 生成模板、SwiftPM 依赖和 Android Gradle/AGP/Kotlin 差异。

连字符插件名的生成代码须按锁定模板核对 Swift product、导出符号和 Rust binding；采用小范围修正还是框架升级，由具体差异决定。

## 日常源码路径矩阵

以下是逐条施工、审计和回扫的清单；每项从生产入口追踪到最终状态或资源释放：

| 路径 | 必须查清的实现关系 |
|---|---|
| 启动到 READY | 同步平台身份、初始化先后、错误传播、服务 owner 与重复启动；不加载静态能力总表 |
| Swift/IPC/Channel | 注册符号、selector、DTO 键、队列、快照回放、接收方生存期与迟到响应 |
| SQLite/Settings/Diary | 目录、schema/迁移、事务、提交点、重开读取、取消中的写入归属 |
| Chat | attempt identity、SSE 消费、成功/取消/transport error、旧回调与唯一 terminal |
| 手动 Sync | session/generation、start/stop/join、child drain、部分传输与状态恢复 |
| 布局与返回 | iPhone/iPad 窗口宽度输入、单位换算、safe area、键盘重复补偿、overlay/page LIFO |
| 附件三入口 | HTML IPC、loopback、Files/PHPicker 各自到 CAS；scope、路径、hash、取消和 staging 清理 |
| 图片与渲染 | 方向、MIME、ImageIO 输出、像素/副本/并发预算、DOM/样式/事件消费 |
| 平台交互与权限 | 更新/Root/语音的说明动作、共同权限引导、设置返回刷新；Rust cfg 与实际 Tauri 授权和消费者一致 |
| 系统通知 | 本 App 发送/前台展示、真实授权结果、冷启动及运行期点击响应、同一导航 owner 去重 |
| 设备/网络与 Distributed | 实际采样来源、逐工具授权、缺失字段、单项不可用、client stop/join、前台重连与结果聚合 |
| 相机/相册与双向分享 | 拍摄编码、PhotoKit 写入、share 取消；Extension 到主 App 的交接、cold/warm start、ticket 与临时文件清理 |
| SSE 后台专项 | 候选方式适用条件、资源消耗、中断边界；同一连接的持续接收、断线恢复和落盘分别记录 |
| 原生后台任务 | availability、request/handler/expiration、真实进度、任务归属、常亮释放与终态竞争 |

Mermaid/KaTeX/raw HTML/Canvas、图片方向和大图边界沿现有 fixtures 核对输入、处理过程与实际消费方。通知、设备/传感器与 Distributed 的 P3 源码链及本地验证另见 [阶段记录](./phase-3/README.md)，不能替代 Apple 编译或原生运行；P4 分享/相机/原生媒体和 P5 后台专项仍待实施。语音实现、视频抽帧、Android CLI 与尚未批准的 APNs 服务端仍按 09 保留边界。

### 系统交互的源码演算

| 对象 | 核对的声明与实现 | 演算的输入和收尾 |
|---|---|---|
| continued task | request/handler、进度映射、expiration、单次 completion | 拒绝、接受、迟到激活、取消/expiration/成功竞争；归约到同一 terminal |
| LAN | 用途说明、Rust transport、拒绝恢复、endpoint probe | 允许/拒绝、连接超时、断线和前后台切换；错误与重试由现有 owner 消费 |
| File Provider | scope 配对、回调临时路径、复制/取消、staging | 空结果、临时文件失效、部分复制、超限、取消；逐项核对文件与 scope 释放 |
| 权限与通知 | 原生授权查询/请求、用户通知响应、设置返回刷新 | 未询问、拒绝、有限状态；取消不误报失败，冷启动与运行期同一响应不重复导航 |
| 分享扩展 | 扩展 target、共享容器或其他交接输入、ticket、各 Bundle ID/profile | 主 App 未运行、已运行、重复交接、导入失败、扩展取消；签名条件与所选路径对应 |
| 设备工具 | 采样 API、字段可得范围、用户授权和 session 归属 | 某工具/字段缺失、设备无传感器、授权撤回和切后台；其余工具仍按真实结果运行 |
| SSE 保活候选 | continued task 与用户提出的静音音频等候选的具体 API/系统条件 | 资源争用、系统中断、网络变化、连接结束与清理；不从 API 名称或编译通过推导持续运行保证 |
| 用户签名 | 签名工具源码、包结构、最终 ID、profile/entitlement 配套 | ID 改写、嵌套代码、资源封印、包输入与签名参数；产物结构在 G2 检查 |

将外部事件作为显式输入，枚举可达状态迁移和回调次序，检查业务不变量、资源预算及终态。查阅到的调度/API 条件写入对应分支；审计结论登记覆盖范围与具体问题。

## 当时拟审查的产物

方案要求将构建提交、工具版本、架构、签名状态、扩展和隐私声明与实际 device archive 对应。归档清单与用户当前可下载的内容见 [iOS 构建说明](../../docs/IOS_BUILD.md)。

## Android 回归与执行约定

- Android CI/Release 独立运行，iOS job 返回自身的真实失败诊断；
- 新 workflow 按仓库规则固定 actions，检查其实际脚本、输入、权限和触发方式；
- 源码审计清单优先复用现有文档和领域测试；按需诊断脚本只覆盖所选问题及有限输出；
- 构建 job 使用 `contents: read`、timeout 与 concurrency cancellation，发布资产另设授权步骤；
- G1 debug 构建采用 iOS 专属配置保留诊断符号，Android profile 延续原配置；
- 跨层实现后按项目要求运行 `pnpm check`，额外测试针对取消、归属、路径和实际行为差异。

## 结果记录

每批源码审计使用简短记录：

- 入口/消费者与版本：命令、路径、符号及锁定依赖；
- 目标条件：cfg/features、availability、线程、授权、事件次序；
- 覆盖与发现：已展开的分支、触发条件、根因和受影响路径；
- 修复闭环：改动位置、回扫范围、结论和具体剩余项；
- 本地检查：已执行的命令、输入和结果。

阶段验收另记 G1/G2、commit、GitHub Actions run、构建输入、诊断与产物 hash。只在手动选择 Simulator 诊断时补充该次运行记录。

源码审计完成后按 08 推进下一项施工；阶段构建失败则将具体诊断回填到相应路径，修复并集中复验。产物交付以 G2 的实际 archive 和包检查结果收束。
