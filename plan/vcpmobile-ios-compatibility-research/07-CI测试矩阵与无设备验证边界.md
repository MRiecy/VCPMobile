# 07. CI、测试矩阵与无设备验证边界

## 1. 当前事实

现有 Android **软件与契约层**测试资产较完整，但权威设备证据仍是 pending，且完全没有 Apple 执行面：

- [ci.yml](../../.github/workflows/ci.yml) 只有 `ubuntu-latest` job；
- CI 生成 Android tree，执行 Gradle/Robolectric 和 Rust/Vitest；
- [release.yml](../../.github/workflows/release.yml) 只有 Ubuntu + NDK + Android keystore + APK；
- [package.json](../../package.json) 没有 iOS build/test/release script；
- 没有 Swift XCTest、XCUITest、Simulator、Apple target 或 TestFlight 资产；
- 当前主机没有 Xcode/Swift/CocoaPods/Apple Rust targets。

因此本轮只能标记 `STATIC-AUDITED` 和 `DEPENDENCY-GRAPH-RESOLVED`。

## 2. 验证层级

| 层级 | 环境 | 必须产物 | 可关闭风险 |
|---|---|---|---|
| I0 静态治理 | Linux | 源码/配置/命令矩阵报告 | 缺文件、错误 cfg、假 fallback、UI 泄漏 |
| I1 Host tests | Linux | Vitest/Rust tests/build | 状态机、DTO、生成物语法、协议契约 |
| I2 Apple compile | macOS + Xcode | Rust Apple target、Swift Package、Xcode build | 编译、链接、binding、generated tree |
| I3 Simulator | iPhone/iPad runtime | 启动 artifact、截图、XCTest/XCUITest | 基础 IPC、布局、键盘/safe area、路由 |
| I4 Device | 具名 iPhone/iPad | 设备报告、日志、截图、build SHA | 权限、后台、LAN、媒体、手势、内存 |
| I5 Distribution | 签名/TestFlight/App Review | archive/IPA、签名报告、审核结果 | provisioning、分发、隐私、审核 |

任何测试名称都应包含层级，避免把 host/simulator 报告误写成 device evidence。

与 [00-证据等级](./00-研究契约与证据账本.md#3-证据等级) 的映射是：`E0 → I0`，`E1 → I0/I1`，`E2 → I2`，`E3 → I3`，`E4 → I4`，`E5 → I5`。I5 内仍必须细分上传、处理、内部 Beta、外部 Beta、App Review 和发布，不能用一个 slash 状态跳级。

## 3. 无 Mac/设备时可以做什么

### 可以完成

- `PlatformCapabilities` DTO、平台矩阵与 UI 可见性单测；
- `android/ios/host_test` cfg 组合的纯 Rust 单元测试；
- 禁止 iOS 使用固定 `true`、Mock 传感器、空 `Ok(())` 的静态契约；
- Chat lifecycle epoch、background cancel、partial/final/terminal 状态测试；
- Sync/Distributed cancel+join、无迟到 commit、无双 owner 测试；
- server request ID、idempotency、resume cursor 与 replay 契约；
- 文件 staging、path containment、hash、size/MIME 预算测试；
- audio MIME → extension 映射；
- Android/iOS command 与 permission manifest 的文本契约；
- Info.plist/entitlement/PrivacyInfo 的静态 schema/内容测试；
- iOS UI 不出现 Android Root、OEM 电池、listener、APK updater；
- 现有 Android CI 软件回归，保证跨平台施工不破坏已覆盖的合同；L6/L7、截图、触控和多设备 WebView 仍需 Android 设备，不能称“无设备全量回归”。

### 不能完成

- `tauri ios init/build`；
- Swift selector/binding 的真实编译；
- WKWebView CSS、Canvas、MediaRecorder、Clipboard 行为；
- Apple SDK 下 SQLite、reqwest、tokio、pdf/zip 等依赖链接；
- Local Network prompt、ATS 真机行为；
- camera/microphone/photo/Files provider；
- suspend、jetsam、APNs、Share Extension；
- signing、TestFlight、App Review。

## 4. Linux 静态门禁设计

在不生成 iOS 工程之前，可以先增加下列治理测试：

### 4.1 平台能力 fail-closed

- 每个 capability 必须有独立 support、implementation、authorization 与 runtime policy/state/eligibility；
- `unavailable_by_platform` 不得转成 `true`；
- host test mock 必须带 `source=host_test`；
- iOS registry 不得包含 Root、listener、autostart、helper、wake lock、move-to-back；
- 未授权的 location/motion 不上报；
- `get_cpu_thermal_status` 不再声称摄氏 CPU 温度。

### 4.2 跨语言命令契约

对于每个 Rust native call：

- Android Kotlin 有 selector，或 Android capability 显式 unsupported；
- iOS Swift 有 selector，或 iOS capability 显式 unsupported；
- method name、argument label、DTO 字段与 optionality 一致；
- handler、`build.rs`、permissions、typed JS facade 一致；
- 删除命令后 autogenerated permission 无残留。

当前 guest-js 只封装部分命令，新增 iOS 前应先统一 typed facade，再冻结快照。

### 4.3 前端治理

- 禁止以 UA 作为权限/平台能力真源；
- iOS 不挂载 Android PermissionGate、BatteryOptimizationGuide、Root、APK installer；
- capability 改变不复制 Pinia owner；
- safe-area 只从根变量消费；
- 语义 z-index 与 no-blur 宪法继续生效；
- 强渲染 fixture 在 Android/iOS build target 都存在。

### 4.4 后台/协议

- lifecycle transition 乱序；
- background expiration 与 resume race；
- cancel receipt 幂等；
- partial terminal 不重复写库；
- user-stopped generation 不被 resume；
- Sync/Distributed child join 完成后才清 owner；
- server replay 不重复消息或工具执行。

## 5. macOS 编译 CI

应新增独立 macOS job，不能把它塞进现有 Android job。第一版建议固定 runner 与 Xcode 版本，避免 `macos-latest` 漂移。

候选步骤：

1. checkout clean commit；
2. 安装固定 Node/pnpm/Rust；
3. 添加 `aarch64-apple-ios`、`aarch64-apple-ios-sim`，按 runner 架构补 simulator target；
4. 安装/验证 CocoaPods 与 SwiftPM；
5. 运行前端 typecheck/test/build；
6. 执行 `pnpm tauri ios init --ci`，以当前 CLI help 为准冻结参数；
7. 检查 generated Apple/plugin permission tree 漂移；
8. Apple target Cargo check；
9. Swift XCTest；
10. Xcode Simulator build；
11. 上传 build log、derived metadata，不上传签名 secret；
12. PR job不做 distribution signing。

供应链基线还应包括：第三方 Actions 固定完整 SHA、pnpm frozen lockfile、Cargo `--locked`、CocoaPods lockfile 与 SwiftPM `Package.resolved` 的 owner、固定 Xcode/runtime 版本，以及 macOS job 的最小 `permissions`/`concurrency`。PR job 不接触 distribution、App Store Connect 或 APNs secrets。

生成树只能选择一种 owner：要么 clean `ios init` 可重建且所有项目定制由受控 patch/config 施加；要么把经审查的 Apple project 纳入版本控制并做 drift check。Share Extension 等新 target 不能只靠开发者本机手改未受管 generated project，clean regeneration 必须能保留或重放它。

退出条件：clean checkout 可重复生成和编译，不依赖开发者本机缓存。

## 6. Simulator 自动化

### 6.1 建议最小矩阵

Release 门禁覆盖最低系统版本和当前主版本各一组；PR CI 为控制成本可只跑一个固定的当前 runtime/代表设备，最低+当前矩阵转到 scheduled 或 release candidate job。runner image 上没有对应 runtime 时应明确 skip/fail 策略，不能静默换成 `latest`。

| 设备形态 | 窗口/方向 | 核心场景 |
|---|---|---|
| 小/标准 iPhone | portrait + landscape | 启动、Chat、键盘、viewer、safe area |
| 带 cutout 的现代 iPhone | portrait + landscape | 四边 inset、边缘手势、弹层 |
| iPad | portrait + landscape | single/dual pane、sheet presentation |
| iPad 分屏 | compact/regular 切换 | 状态不丢、抽屉不重复、键盘 |

不要把几十个设备型号塞入 CI；按形态选代表，Release 前再扩展。

### 6.2 Simulator 可测旅程

- cold start → bootstrap → READY；
- Rust/Swift 同步与异步 command round-trip；
- scene active/background/foreground event；
- CSS safe area、基础 software keyboard；
- Chat text send、stream fixture、interrupt/recovery；
- Diary CRUD、数据库 restart；
- fixture/provider UI 与 staging 预筛；不外推真实 iCloud/第三方 provider 或 security-scoped 互操作；
- permission denied UI（能模拟的部分）；
- modal/sidebar/router 关闭顺序；
- Markdown/KaTeX/Mermaid/raw HTML fixture；
- iPad width transition；
- Accessibility Inspector/可访问树与 focus 的基础审计；真实 VoiceOver 旅程留给具名设备。

### 6.3 Simulator 不能替代

- 真实相机、麦克风格式与音频 route；
- Local Network privacy；
- APNs/device token；
- 物理边缘手势与第三方键盘；
- Core Motion/定位/气压计真实性；
- Low Power Mode、热压力、jetsam；
- Share Extension 与第三方 App 的真实互操作。

## 7. 真机验收矩阵

设备尚未确定，下表是 release 前最小类别，不是当前已具备资产：

| 类别 | 最少证据 |
|---|---|
| 最低支持 iOS 的 iPhone | cold/warm start、Chat、键盘、生命周期、内存；LAN 仅在 manifest 选中时 |
| 当前 iOS 的现代 iPhone | cutout、性能；相机、MediaRecorder、系统 local notification 仅在选中时 |
| 最低支持 iPadOS 的 iPad | D5 纳入 iPad 时验证 portrait/landscape、split view、sheet；Files 仅在选中时 |
| 当前 iPadOS 的 iPad | D5 纳入时验证当前窗口宽度、外接键盘/触控板；多 Scene 只有获批时才测 |

Phase 2 工程 Beta 的最低门禁是一台具名受支持 iPhone，加上 D5 若纳入 iPad 时的一台具名 iPad；它不等于 release 矩阵。Phase 5B/5C 再覆盖最低与当前系统/设备形态。同一物理设备只有在其 OS/形态确实同时满足两行时才能合并证据；不能用一个当前系统设备代替最低版本。每个 Beta 只测试其 manifest 选中的可选能力。

每个 build 记录：

```text
commit/tag
IPA SHA-256 + xcarchive identity/manifest metadata（若归档为稳定 zip，再记录该 zip SHA-256）
Bundle ID + version + build number
device model + OS build
installation channel
network topology
permission state
test case + expected/actual
screenshots/logs
reviewer + timestamp
```

### 真机必须覆盖（核心项 + 该 build manifest 选中的能力）

- Local Network allow/deny/Settings 恢复；
- HTTP/WS 与 HTTPS/WSS、IPv6-only、Wi-Fi/蜂窝/VPN/热点；
- 刘海/Home Indicator/横屏四边 safe area；
- 中文/英文/第三方/iPad 浮动键盘；
- 系统边缘手势、文本选择、长按、pinch/pan；
- camera/photo/Files/security-scoped URL；
- MediaRecorder MIME、蓝牙、来电/锁屏；
- foreground → background → suspend → terminate → relaunch；
- Chat/Sync/Distributed generation 与 DB 一致性；
- APNs/notification click（若启用）；
- Share Extension（若启用）；
- 大文本、附件、图片、视频、预渲染、SQLite memory pressure；
- Low Power Mode、thermal state、reduce motion、VoiceOver。

## 8. TestFlight 与 Release 门禁

建议独立受保护 workflow：

- 只接受已通过同 commit iOS CI 的 tag；
- 校验 package/Tauri/Cargo marketing version；
- 校验 `CFBundleVersion` 单调递增；
- 恢复最小签名 secrets；
- app-store-connect export；
- 检查 codesign、provisioning、entitlements、architectures、Info.plist、PrivacyInfo；
- 上传 TestFlight；
- 清理 keychain/profile/private key；
- 不公开上传 IPA；
- 归档签名报告和 App Store Connect build ID。

分发序列必须逐级保存，不允许把斜杠写法当成一个状态：

```text
UPLOAD-CANDIDATE
  -> TESTFLIGHT-UPLOADED
  -> TESTFLIGHT-PROCESSED
  -> INTERNAL-BETA-DEVICE-VERIFIED
  -> EXTERNAL-BETA-VERIFIED       # 仅在本版本需要外部 Beta 时
  -> APP-REVIEW-APPROVED
  -> RELEASED
```

首次上传只依赖 `UPLOAD-CANDIDATE`，不依赖未来的 processed/beta 状态。`DEVICE-VERIFIED(scope)` 也可以先由 development-signed 真机 build 获得，但不能冒充 TestFlight 分发证据。

## 9. 建议状态机

技术证据使用固定状态：

```text
RESEARCHED
STATIC-AUDITED
DEPENDENCY-GRAPH-RESOLVED
MACOS-COMPILED
SIMULATOR-VERIFIED
DEVICE-VERIFIED
```

分发则使用第 8 节的独立状态序列。`*-PENDING` 只表示尚未取得下一层证据，不是成功状态。每个成功状态必须附 commit、环境和证据链接；不能只写“iOS tests passed”。产品 capability 另用 support、implementation、authorization 与 runtime policy/state/eligibility，不能拿 CI/分发状态替代运行时事实。

## 10. Android 回归保护

iOS 施工不得降低现有 Android 门禁：

- `pnpm check`；
- Vitest；
- Rust workspace tests/integration/clippy；
- `tauri android init --ci` generated drift；
- Kotlin/Robolectric strict dependency verification；
- Android arm64 Release 签名与版本治理。

跨平台改造应先扩展 owner，再接 iOS adapter；不能为了 Apple build 把 Android 原生能力改成最低公分母。

## 11. 当前阶段的验证命令

本轮文档交付只需要：

- Markdown 链接/结构检查；
- 41 条矩阵计数检查；
- `git diff --check`；
- 工作区状态核对；
- 不运行 iOS 构建，不把 `cargo tree` 解释为 compile。

由于没有修改产品代码，本轮不以既有 `SlidePage` 工作区状态触发无关全量构建。
