## 本轮工程参数

| 用途 | 实际约束 |
|---|---|
| 原生文件取得 | 512 MiB；流式复制缓冲 64 KiB；配置取得/解析 1 MiB |
| WebView 内存产物 | Rust 附件/临时导出单次 8 MiB；长文本粘贴保留 2 MiB UTF-8 上限 |
| 列表图 | 长边 512、512² 像素、编码 1 MiB |
| 全屏显示 | 长边至多 2048、4,194,304 像素、编码 8 MiB；消费期结束释放工作图 |
| 头像工作图 | 长边 2048、4,194,304 像素、编码 20 MiB；裁剪结束或替换释放 |
| 模型图片 | 长边 2048、4,194,304 像素、单图编码 4 MiB、质量 0.82；整次请求图片 data URL 累计 16 MiB，超限返回明确错误 |
| 拍照 | 选设备支持的至多 12 MP 最大尺寸；没有该档位时选最小支持档且不超过 24 MP；编码文件 32 MiB |
| 文本预览 | 128 KiB 有界读取，返回截断状态和实际解码名称，不截坏 UTF-8/UTF-16 字符 |
| 远程图形查看 | 下载 32 MiB；SVG 文本 8 MiB，宿主解析后生成受限 PNG；原件与显示副本分别持有 |
| Canvas/SVG 导出 | 长边 2048、2048² 像素、编码 8 MiB；全应用像素任务活动数 1，iframe 先获队列授权再分配 |
| Mermaid | 渲染活动数 1；缓存按估算字符串字节计量 4 MiB，单项 512 KiB；每次 DOM 挂载重映射 SVG ID/引用 |
| 接收分享 | 16 项、文件总量 512 MiB、文本 1 MiB UTF-8；iOS App Group 暂存总量 1 GiB，保留 64 MiB 空间；Android 继续保留 provider 单文件 30 秒/总 60 秒及 64 MiB 空间预算 |
| Android 对外打开/分享 | 系统无可靠读取完成回调，FileProvider 持独立副本；单份 512 MiB、总量 1 GiB，24 小时后在下次操作时定向清理；结果表示面板已打开 |

像素预算不等于进程峰值：2048² RGBA 约 16 MiB，编码文件、ArrayBuffer、`Array.from` 数字数组和 JSON 序列化仍有同时存在的副本。8 MiB 输入的数字数组可达约 64 MiB 数量级，具体表示由 JS 引擎决定；SVG 字符串与 codec/系统内部内存另计。上述上限约束应用持有资源，不承诺约束任意 HTML 脚本或系统 codec 的全部分配。

## 复审关闭的问题

- 分享 manifest 的有效 SHA-256 与已导入附件一起参与启动 GC，覆盖 CAS 提交后、分享记录回填前进程终止的恢复窗口。
- 已发送记录先于原件校验处理；丢失 IPC 响应后重试返回原消息，不因收件文件已清理而重新导入。
- 旧清理重新读取当前槽位，不能删除新分享；获取中断通过文件 lease/Android 当前 owner 判定为失败，新分享取消也不恢复旧分享。
- 草稿响应按 revision 单调接收，分享的发送锁仅覆盖消息提交，不占用整个 AI 流式回复。
- PhotoKit 副本创建与启动清理在同一文件队列定序；相机覆盖“按快门后立即取消”及最终 capture 错误路径。
- 同一图表多处显示使用独立 SVG ID；iframe 的 Blob 只在所属 document 读取，并经过 source/nonce 与队列授权交接。

### 取得与导入

- `pick_file` 仅在 `multiple=true` 且 mode 为 `file`/`gallery` 时发送 `maxFiles=16`；未开启时仍返回单个 `PickedFile`，头像、配置、拍照及 CLI 技能包导入无需更改消费者。批次即使只有一个成功项也返回 `{ files, errors }`。
- Android 的 `ACTION_OPEN_DOCUMENT` 开启 `EXTRA_ALLOW_MULTIPLE`，读取去重的 `ClipData` URI 并以 `data` 作单项回退，沿同一个文件 worker 串行复制。[Android 多选结果说明](https://developer.android.com/guide/components/intents-common)
- iOS Files 开启 `allowsMultipleSelection`，逐项 scope/协调读取；PHPicker 采用 ordered selection，选择后关闭面板，串行加载 provider，在其回调返回前复制借用 URL。原生 owner 保留至真正终态，关闭面板不代表取消复制。[PHPicker 配置](https://developer.apple.com/documentation/photosui/phpickerconfiguration-swift.struct)
- 每批最多 16 项；成功暂存文件与当前复制的总量受同一 512 MiB 预算约束，失败半成品立即删除，不消耗后续项的可用额度。无法在系统 UI 限数的选择器若返回更多文件，前 16 项继续处理，额外项明确列入失败摘要，不静默丢弃。
- 原生成功项交接后，Store 为全部待导入项创建独立 ID，按结果顺序逐个校验支持类型并登记 CAS。一项获取、格式或登记失败不阻断其他项；每项结束即释放自身 staging/thumbnail，已提交 CAS 资源不由该清理入口删除。

### 取消和反馈

取得阶段删除占位、清空、切换会话或 Store 销毁使整个批次失效，原生清理尚未交付的成功副本与当前半成品；迟到的成功响应由 Store 逐项释放。登记阶段可删除排队项或正在登记的单项，其余项继续；清空、切换会话和销毁取消全部尚在途项，不再注册后续项，也不重新插回迟到结果。系统取消不弹失败通知。

导入卡显示文件名、批次序号及当前项进度；未知大小显示已复制字节。图片导入卡临时加宽且实际渲染根同步宽度，删除按钮仍位于卡片右上角；暂存层统一呈现进度，避免与基础附件层叠加。失败按“全部失败”或“部分失败”汇总，保留已导入数量与逐项原因到通知历史。
