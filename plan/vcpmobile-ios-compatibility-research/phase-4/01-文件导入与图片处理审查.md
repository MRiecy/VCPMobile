## 1. 用户完成的四条流程

| 用户操作 | 目标流程 | 结果 |
|---|---|---|
| 选择文件或照片作为附件 | 打开 Files/PHPicker → 取得应用副本 → 核验并登记 CAS → 显示附件卡片 | 原件持久保存，可取消进行中的导入；进度按复制、登记、派生处理阶段显示 |
| 更换用户、Agent 或群头像 | 选择照片 → 生成适合裁剪的工作图 → 用户裁剪确认 → 保存头像 | 取消保留原头像；裁剪结束释放工作图 |
| 查看图片、发送给模型 | 根据 CAS 原件分别取得显示图和模型输入图 | 列表清晰、全屏可查看细节；模型输入符合本次请求的格式、尺寸和字节预算 |
| 拍照或保存到相册 | 拍照进入附件导入；保存操作把所选原件或图形输出交给 Photos | 授权在操作时请求；完成提示对应真实拍摄/写入结果 |

文件/照片从系统取得后进入同一个 Rust 附件领域。相册保存可以单独完成，不要求先成为聊天附件。显示图、头像工作图、模型输入图和保存原件各有明确用途，互不替代。

## 2. 职责、接口与文件状态

### 2.1 三层职责

| 层 | 持有内容 | 对外结果 |
|---|---|---|
| Vue | 当前页面/会话意图、附件卡片、裁剪交互、活动请求句柄与 generation | 发起操作、请求取消，消费属于当前操作的进度和最终结果 |
| Rust 文件领域 | 导入身份、传输/登记取消状态、受控目录、hash、CAS 和数据库提交 | 发布已登记附件；决定提交边界；向图像服务提出具体用途的派生请求 |
| Swift | picker/presenter、security scope、provider Progress、复制任务、图像对象、相机与 Photos 操作 | 应用内完整文件、真实图像元数据及系统操作终态 |

同一导入的 `operationId` 贯穿 UI、传输、原生回调和登记；Vue 的 generation 用于确认结果仍属于当前页面意图。领域身份与页面代际分工明确。进度通过带 ID 的事件传递，最终结果通过一次 invoke 响应返回。

### 2.2 接口草案

以下字段表达交接语义，具体命令名称与 DTO 拆分在对应实施片段确定。

| 操作 | 输入 | 输出与终态 |
|---|---|---|
| 选择并取得文件 | operationId、用途（附件/头像/配置）、选择模式、Rust 解析的 staging 目标、取得阶段预算 | `completed` 携带应用内 path、名称、实际 MIME、字节数、可选 hash；或 `cancelled` / 带失败阶段的错误 |
| 接收 WebView 内存字节 | operationId、元数据、用途（仅限 Canvas 导出/长文本粘贴/头像裁剪等内存产物）及字节预算 | 有界接收后的 staging 文件；内存附件继续登记，临时导出交消费方持有；外部文件严禁走此通道 |
| 登记附件 | operationId、完整 staging 文件、可选预览元数据 | CAS hash、正式路径、真实类型/大小及派生信息；结果表明主记录已经提交 |
| 生成图像派生 | operationId、应用内源路径、用途、目标像素/编码字节预算、输出格式要求 | 派生 path、MIME、像素尺寸、字节数；释放由具体消费方负责 |
| 保存到 Photos | operationId、可读取文件及其所有权、文件名/MIME | 系统写入完成结果与 asset 标识；取消/拒绝/写入失败各自结束 |

文件大小以实际读取计数为准；类型和编码与内容一致。图片尺寸先从元数据取得，尚未准备好预览时 UI 显示处理中。错误由当前页面统一展示，取消正常收尾；不为本专题新增通用错误平台。

### 2.3 目录与所有权

CAS 原件由 Rust 在 Application Support 持久管理；未提交导入使用 cache `uploads`；显示/模型派生使用可重建缓存；头像工作图和纯保存操作使用各自短期暂存。路径由 Rust 统一解析后传入 Swift，输出后缀由实际编码确定。

派生缓存键包含原件 hash、用途与变换参数，清理后按需重建。缓存文件的路径和有效期由领域入口交给消费者，不把 `asset://` 地址持久化为跨平台资源身份。Share Extension 的待交接 Inbox 属于 P4-4 的持久交接区，与本专题的临时目录分开。

## 3. P4-1：Files 与 PHPicker

### 3.1 Files 推荐路径

主队列呈现 `UIDocumentPickerViewController(forOpeningContentTypes:…, asCopy:false)`。2026-10-17 用户追加文件附件多选；配置和 CLI 单文件导入仍为单选。获得结果后在独立文件队列逐项取得 security-scoped access，通过 `NSFileCoordinator` 协调读取，将外部文档流式复制到本次 operation 的 staging 文件。成功取得的 scope 用 `defer` 配对释放；失败、取消、超限和空间不足执行同一释放路径。[Document Picker 官方说明](https://developer.apple.com/documentation/uikit/uidocumentpickerviewcontroller)

复制以实际累计字节执行上限，provider 声明大小用于进度提示；未知总量显示已复制字节。关闭写入句柄后发布完整 staging 路径，Rust 从该文件重算 hash 并登记。完成这次取得即结束外部访问；本流程无需长期 bookmark。文件复制和 provider 下载可能分别占用应用与系统存储，磁盘预算说明应包含这两类副本的归属。

### 3.2 PHPicker 推荐路径

采用 UIKit `PHPickerViewController`，以用途区分附件与头像。2026-10-17 用户追加相册附件多选，头像保持单选。用户完成系统选择后即可取得所选内容，不请求整库读取授权。[Apple 隐私说明](https://developer.apple.com/documentation/photokit/delivering-an-enhanced-privacy-experience-in-your-photos-app)

用 `NSItemProvider.loadFileRepresentation` 获取文件表示，避免 `loadObject(UIImage.self)` 把整幅原图提前物化。provider completion 返回时临时文件会被系统删除，因此**必须在该回调返回前完成应用副本的建立**；不能把 URL 丢进另一个异步任务后立即返回。保存其 `Progress`，取消时通知 provider，并让迟到 completion 清理本次文件、不进入登记。[Apple 文件表示生命周期](https://developer.apple.com/documentation/foundation/nsitemprovider/loadfilerepresentation(fortypeidentifier:completionhandler:))

建议获取当前文件表示，HEIC/方向/主图交给自身 ImageIO 处理，不依赖选择器隐式转 JPEG。这里“原件”指 picker 提供的当前表示，不承诺 Photos 未编辑的底片或完整 Live Photo。只导入静态图片部分；Live Photo 视频配对资源不自动纳入。

### 3.3 原生导入与内存产物落盘的取消与提交

双端均全面采用系统原生文件选择器（iOS 为 `UIDocumentPickerViewController` / `PHPickerViewController`，Android 为 SAF / 原生插件 `pick_file`），彻底移除前端 HTML `<input type="file">` 选文件入口及大文件 XHR / 高速 TCP 上传通道。外部文件一律由原生层流式拷贝到 staging 目录后直接做路径交接；WebView 字节传输**仅服务于前端内存生成的业务产物**（Canvas 导出 Blob、裁剪后头像、长文本转 txt、录音数据）。两种来源以同一导入身份交接到 Rust CAS 登记入口。Swift/Kotlin 仅持有原生操作对应的 picker、provider Progress、scope、复制任务与临时文件。

| 时点 | 取消的实际作用 | 完成/清理要求 |
|---|---|---|
| picker 尚未选择 | 主队列关闭所属 picker | 返回一次取消；不得误关闭其他系统弹窗 |
| provider 下载/复制 | 调用 Progress.cancel；复制块边界检查取消 | scope、句柄及本次临时文件释放；迟到回调只清理 |
| WebView 内存产物 IPC 传输 | 在落盘前观察到取消信号 | 丢弃未落盘字节，清理部分写入的临时文件；卡片标记取消 |
| Rust 哈希、CAS 放置之前 | 在读取块和放置前观察取消 | 删除本次未提交 staging；不修改其他同 hash 文件 |
| CAS 主记录已经提交 | 保留已经生效的登记结果 | 淘汰过期 generation 的卡片或会话回填；未引用附件由文件领域回收 |
| PhotoKit 写入已经提交 | 无法把关闭页面当作撤销系统写入 | 等待真实 completion 后报告结果并释放本次副本 |

UIKit 系统选择器/权限弹窗可能引起 `inactive`，不能据此自动取消导入；按实际用户取消、页面会话失效或明确操作期限处理。真正退后台时按资源可继续程度记录结果，不承诺持续复制；与 Phase 5 后台能力分离。

原生桥接保留 receiver 到最终响应；取消请求发给实际 operation。Swift 停止资源活动后仍完成一次 resolve/reject，Rust 接收并按提交点处理结果。前端失联时原生 owner 独立收尾，清理不依赖 Vue `finally`。

picker 返回协议明确区分 `cancelled` 与失败。内存产物 IPC 的传输错误与超时均使当前等待结束一次；迟到结果由 operationId/generation 判定归属。冷启动回收上次意外退出的临时文件，在允许新导入前完成；持久 Share Inbox 不参与该清理。

## 4. P4-2：同一 ImageIO 服务的各类消费者

### 4.1 原件与派生分离

CAS 保存用户所选文件的完整内容，供重新处理、保存和导出。列表/全屏显示、头像裁剪和模型输入分别按用途生成派生；改变显示尺寸或发送策略只重建对应派生，CAS hash 与原件保持稳定。

Swift 图像服务接应用内源路径和具体用途，返回受控输出路径、实际 MIME、字节数及像素尺寸，源文件保持只读。模型临时图由 Rust 在读取结束后释放；显示缓存由 viewer/列表持有使用期，并在空闲时按缓存预算淘汰；头像工作图归本次裁剪操作。图像处理属于 Rust 内部调用时无需前端 ACL。

| 消费者 | 输出与尺寸依据 | 生命周期 |
|---|---|---|
| 附件列表 | 按卡片实际显示尺寸与显示密度取目标像素，限制总像素；候选长边封顶 512px | 登记后生成并缓存；未准备完成时显示占位，退出列表不影响原件 |
| 全屏查看 | 根据当前窗口、显示密度与缩放需求生成显示图，受单图预算约束；更高清请求按当前查看意图重新生成 | viewer 持有正在显示的派生；关闭释放占用，磁盘缓存可保留至淘汰 |
| 头像裁剪 | 工作图覆盖裁剪区显示像素与允许放大范围，最终头像按产品显示需求输出带透明度的 PNG | 选择后生成工作副本，确认/取消/替换/卸载均释放；最终头像独立保存 |
| 模型输入 | 根据目标服务接受的格式、尺寸/字节限制和本次图片数量确定编码；必要时有界缩小或调整质量 | 在模型请求预处理阶段生成，Rust 读取并构建 payload 后释放临时图；覆盖全部来源的 CAS 图片 |
| 保存/导出 | 默认读取原件；Canvas/Mermaid 保存用户请求的完整图形输出 | 持有原件只读引用或专用导出副本直到系统完成，独立于显示图缓存 |

上述尺寸由各消费场景论证。512px 是列表首轮候选，不约束全屏查看、头像或模型输入；模型尺寸不在这里预设统一长边。缺少服务端上限时需要明确的应用侧默认预算和超限处理，见第 7 节。

### 4.2 解码、方向与编码

1. `CGImageSourceCreateWithURL`，源选项禁用不必要的解码缓存；先读类型、主图索引、宽高、方向、帧数，执行溢出安全的像素核算。HEIF 使用 `CGImageSourceGetPrimaryImageIndex`，不能假设所有容器第 0 帧都是主图。[Apple 主图索引](https://developer.apple.com/documentation/imageio/cgimagesourcegetprimaryimageindex(_:))
2. `CGImageSourceCreateThumbnailAtIndex` 明确指定 max pixel、创建缩略图和 transform，做一次有界下采样与方向归一化；避免先创建原尺寸 `UIImage` 再缩小。transform 默认关闭，需显式打开。[Apple transform](https://developer.apple.com/documentation/imageio/kcgimagesourcecreatethumbnailwithtransform)、[Apple 图像内存实践](https://devstreaming-cdn.apple.com/videos/wwdc/2018/219mybpx95zm9x/219/219_image_and_graphics_best_practices.pdf)
3. 输出 JPEG/PNG 并校验 destination finalize 结果，文件名/MIME/真实容器一致。可用编码格式由 `CGImageDestinationCopyTypeIdentifiers` 查询；不能因系统能解码 WebP 就硬编码能编码 WebP。[Apple 编码格式查询](https://developer.apple.com/documentation/imageio/cgimagedestinationcopytypeidentifiers())
4. 在离开原生图像队列前释放 CGImage、source、临时缓冲；不要在这些对象仍存活时让 WebView 再解码同一大副本。完成后 Rust 再构建 base64；不从 Swift 跨桥传大 `Data`/JSON 数组。
5. 主图格式不支持、元数据异常、像素越界和输出超限返回具体失败，结束本次派生并释放输出。CAS 原件保留；导入、显示与模型发送分别反馈各自结果。

派生结果携带真实 MIME，Rust 根据已核验的编码决定后缀。预览、缓存和清理方消费同一派生记录；原件的格式与派生格式分别保留。主记录提交成功后，派生失败允许独立重试，并向当前需要该派生的消费者返回具体结果。

### 4.3 按用途建立像素、字节与并发预算

预算在三处生效：取得文件时约束实际输入字节与磁盘副本；派生时约束目标像素、编码文件和活动任务；发送时约束整次请求的累计编码内容。源图尺寸用于校验和估算解码风险，不能直接当作 ImageIO 必须分配的像素缓冲尺寸。

例如 3840×2160 的 RGBA 单帧约 31.6 MiB，两个同尺寸缓冲约 63.3 MiB；还要计入编码输出、base64、JSON 和 WebView 显示。ImageIO 的缩略解码可减少应用持有的像素，但 codec/系统内部开销无法仅由目标尺寸精确推出。静态预算分别列出可计算的应用缓冲、库内部不确定项和同时存在的任务，不宣称得到精确进程峰值。

首轮工程建议为串行图像解码、固定大小流式复制缓冲、每个派生的编码字节上限以及请求级累计检查。列表、全屏、头像、模型输入、Mermaid/Canvas 导出分别填入用途参数；Canvas 在分配前按长边与总像素缩放，编码后再检查字节数，纯导出走临时文件交接。

**实现取值见实施记录：**原生取得、列表、全屏、头像、模型和导出分别设置字节/像素预算。4K、大图及多附件的像素缓冲、编码和传输副本分别核算，不能由一个“图片最大值”代替。

## 5. 相机：AVCapturePhotoOutput 最小取景页

采用 `AVCaptureSession + AVCapturePhotoOutput`，从当前 active format 的 `supportedMaxPhotoDimensions` 选择拍摄上限，取得编码文件表示，避免自行构造原尺寸 UIImage。原生页只包含取景、快门、取消和镜头切换；配置、拍摄和停止由串行 capture 队列负责，最终 capture delegate 回调裁定成功或失败。

Apple 明确 `maxPhotoDimensions` 必须选设备当前格式支持的值，返回尺寸不超过选定上限。[最大拍照尺寸](https://developer.apple.com/documentation/avfoundation/avcapturephotooutput/maxphotodimensions)。`fileDataRepresentation()` 返回编码文件 `Data`，预算需包含该缓冲和拍摄内部资源。[编码文件表示](https://developer.apple.com/documentation/avfoundation/avcapturephoto/filedatarepresentation())

相机授权在用户点击时请求，配置 `NSCameraUsageDescription`。拍照功能只获取静态照片，完成后进入 staging→CAS 管线；保存相册由独立用户操作发起。方向、镜像和真实编码一起归一化，取消、拒绝、无硬件、会话中断与正常拍摄各自收尾。iPad 呈现绑定主 Scene 的有效控制器。

## 6. 保存相册：add-only 与真实完成

附件查看、Mermaid 图表和富消息图片查看共同进入保存流程。用户点击保存后，先准备本次可读取的文件，再请求 add-only 授权并提交 PhotoKit；页面保留处理中状态，完成或失败由该次保存结果更新。

| 图片来源 | 文件准备 | 释放方式 |
|---|---|---|
| CAS 附件 | 取得原件的只读引用，核验格式与可读取性 | Photos 完成后释放引用；原件继续归 CAS |
| 远程图片 | 有界下载到本次导出暂存，核验实际内容与大小 | 写入结束或准备失败后删除本次副本 |
| Mermaid/Canvas | 分配前按像素预算生成输出，`toBlob` 编码后检查字节数，再有界传输到导出暂存 | 系统 completion 后删除副本；页面取消可停止尚未提交的准备工作 |
| WebView Blob / data URL | Blob 在所属 document 读取；data URL 先执行编码字节检查，作为有限小图输入 | 传输完成后释放 WebView 临时对象，系统完成后释放文件 |

opaque iframe 的 Blob 在创建它的 document 中序列化，经带 source/nonce 校验的图片桥交接，详见 [WebKit 专题](./03-WebKit缓存与交互审查.md)。传输用途为“临时导出”，文件完成后直接交保存操作持有；只有用户选择“添加为附件”才进入 CAS 登记。保存的内容使用原件或用户请求的图形编码输出，显示派生只承担查看。

使用 `PHPhotoLibrary.authorizationStatus(for:.addOnly)` / requestAuthorization，添加 `NSPhotoLibraryAddUsageDescription`。不为保存一张图片申请 read-write，不为创建应用相册扩大授权。权限拒绝不阻止聊天或文件选择。[Apple add-only](https://developer.apple.com/documentation/photos/phaccesslevel/addonly)、[用途描述规则](https://developer.apple.com/documentation/bundleresources/information-property-list/nsphotolibraryusagedescription)

使用 `performChanges` 内 `PHAssetCreationRequest.addResource(with:.photo,fileURL:options:)`，直到 completion 成功才提示保存成功。PhotoKit 延后读取文件，因此调用 `addResource` 后立即删除文件是错误的；保留本次副本至最终 completion。CAS 原件永不作为“调用完成必须删除”的临时文件。设置 `shouldMoveFile=false` 或另建受控副本，避免 Photos 接管/移动原 CAS。[Apple 资源导入语义](https://developer.apple.com/documentation/photos/phassetcreationrequest/addresource(with:fileurl:options:))

保存结果携带实际文件名、MIME、字节数和 Photos asset 标识。`localIdentifier` 按系统资产身份表达；页面根据完成结果提示“已保存到相册”。拒绝授权时保留原图和当前页面，提供实际可用的系统设置恢复动作。

## 7. 已采用的图片语义与参数归属

相机采用第 5 节的 AVCapture 路线。图片保留原件，模型输入使用静态主图，透明度用 PNG，HDR 派生采用 SDR 色彩转换；不取得 Live Photo 视频配对资源。

工程参数按用途一次收敛：列表与全屏清晰度、头像裁剪放大范围、模型格式与默认预算、输入文件和源像素范围、缓存/导出占用。特别需要确定模型接口没有提供图像限制时的应用侧默认值，以及超过请求总量时是降低派生质量还是要求用户减少附件。涉及可见质量与操作行为的选择在实施前说明；内部缓冲尺寸和资源释放方式由具体方案负责。

文件选择、原生复制、ImageIO 转换和 PhotoKit 写入均按上述职责实施，接口参数只服务真实消费者。录音/语音与视频抽帧保持既定范围；音视频普通文件的导入不代表已具备对应的模型处理能力。
