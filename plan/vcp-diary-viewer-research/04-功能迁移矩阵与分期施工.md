# 04｜功能迁移矩阵与分期施工

> 目标：把研究结论转换为可排期、可验收、可停损的施工路线。  
> 首个可发布范围：完成 P0 后交付“浏览 + 普通搜索 + 受保护的整文件编辑”。  
> 原则：先打通可靠纵切，再恢复管理能力；不以桌面功能数量作为移动端完成度。

## 1. 功能迁移裁决

| 桌面能力 | 真实语义 | 移动端裁决 | 首版表达 | 阶段 |
|---|---|---|---|---|
| 打开独立 Memo 窗口 | 进入远端 memo 管理器 | 保留入口，重做容器 | 右侧栏“日记中心”进入一个懒加载 SlidePage | P1 |
| 文件夹分类 | 顶层目录列表，无统计 | 保留 | 顶栏当前文件夹；点击打开选择层 | P1 |
| 日记/知识库/思维簇分组 | 基于名称的消费端分类 | 谨慎保留 | 仅作分组标题，不升级为领域类型 | P1 |
| `MusicDiary` 过滤 | 桌面硬编码隐藏 | 待实服确认 | P0 确认产品意图后再决定；未知时不静默丢数据 | P0 |
| 隐藏、折叠、拖拽排序 | 本机 `memo.config.json` 偏好 | 后置 | 首版沿用服务端顺序/轻量分组 | P3 |
| 卡片网格 | 一文件一卡、显示摘要 | 改造 | 高密度线性行、1px 分隔、结构化文件名增强 | P1 |
| 结构化文件名解析 | 从文件名提取日期、时间、标题 | 保留且允许失败 | 解析成功显示友好标题；失败显示原文件名 | P1 |
| 整文件读取 | 获取不透明 UTF-8 正文 | 保留 | 连续滚动 Markdown 阅读页 | P1 |
| Markdown 预览 | `marked` 直入 `innerHTML` | 重写 | feature-local 严格净化后进入主 DOM | P1 |
| 当前文件夹搜索 | 返回文件摘要 | 保留 | 默认当前文件夹范围，显示明确 scope | P2 |
| 全局普通搜索 | 返回跨目录文件摘要 | 保留 | 用户显式切换“全部文件夹” | P2 |
| 搜索命中定位 | 桌面仅定位到文件 | 不虚构 | 打开文件后可本地高亮文本，不承诺服务端 offset | P2 |
| LightMemo 语义检索 | Bearer Human Tool 调用 | 后置 | 与普通搜索分开呈现、分开错误和取消生命周期 | P4 |
| 整文件编辑 | blind full overwrite | 保留但重做一致性 | 显式编辑态、dirty guard、baseline hash、读回核验 | P2 |
| 标题输入 | 桌面看似可改但保存不 rename | 删除假入口 | 首版标题只读；rename 有真实 API 后另做 | 不进入首版 |
| 新建 DailyNote | Human Tool create | 后置 | 单独表单和 Bearer 契约，不伪装成空文件保存 | P3 |
| 单项/批量删除 | 可能部分成功 | 后置 | 明确选择态、逐项结果和不可撤销确认 | P3 |
| 批量移动 | 可能部分成功、重名不覆盖 | 后置 | 返回 moved/errors 明细，不显示笼统“全部成功” | P3 |
| 删除文件夹 | 只允许空目录 | 后置 | 仅在空目录事实确认后提供 | P3 |
| 多文档工作台 | 拉取多篇全文并拼接 | 暂不移植 | 先验证真实工作流价值和内存预算 | P4 评估 |
| 联想发现 | 返回相关 memo | 改造后置 | 先做相关 memo 线性列表 | P4 |
| Canvas 力导向图 | 持续 RAF 的桌面可视化 | 不移植首版 | 只有任务数据证明必要时再独立设计 | 不排期 |
| 桌面毛玻璃/大卡片/厚阴影 | 氛围视觉 | 不移植 | 实色表面、细线、透明度/Accent Bar 反馈 | 全阶段 |
| 本地全文缓存/离线写队列 | 桌面不存在 | 不新增 | 内存保留当前正文与草稿；断网不排队写 | 全阶段 |

## 2. 施工阶段

### P0｜部署契约冻结

P0 不是“先写接口再联调”，而是消除会改变架构或产品含义的未知事实。

必须完成：

1. 用实际部署验证 `/folders`、`/folder/:folder`、`/note/:folder/:file`、`/search` 的成功和错误响应；
2. 采集脱敏的普通、结构化、非结构化、Unicode、超长文件名样本；
3. 统计目录数、单目录文件数、正文 UTF-8 bytes 的 P50/P95/max；
4. 验证 URL 是否带反向代理 path prefix，以及 `vcpServerUrl` 的真实配置形态；
5. 验证 401/403、404、429、5xx、畸形 JSON、连接超时和响应超限；
6. 探测 ETag、revision、`If-Match` 或等价条件写能力；
7. 验证 admin raw-save 后文件读取和 KnowledgeBase/RAG 索引的一致性与生效延迟；
8. 确认 `MusicDiary` 隐藏、文件夹分类、创建默认 folder/fileName 的产品规则；
9. 确认 DailyNote tool 对换行、引号、反斜杠和 Unicode 的参数转义；
10. 形成不含正文秘密和凭据的 fixture 与契约断言。

P0 退出条件：05 文档中的开放项被标为“已验证”或有明确的保守默认；任何写入未知都不能靠 UI 文案掩盖。

### P1｜只读纵切

交付一条完整、可在真机验证的读链路：

~~~text
右侧栏入口
  → DiaryCenter 懒加载
  → 配置/认证门
  → 文件夹选择
  → 文件线性列表
  → 整文件阅读
  → 返回与刷新
~~~

施工内容：

- Rust typed service、受限 HTTP client、URL 与路径段校验；
- folders/list/get commands 与 DTO；
- 一个 `useDiaryStore`，为 folders/list/document 建立 generation 提交门；
- `DiaryCenterView`、选择层、列表和 reader；
- 严格 Markdown sanitizer profile；
- loading、refreshing、empty、auth、timeout、not-found、oversize 状态；
- 结构化文件名解析纯函数与 fallback；
- Android 返回键、选择文本、深色主题和动态 viewport 验证。

P1 不包含：编辑器、新建、删除、移动、语义检索、工作台、图谱。

### P2｜普通搜索与受保护编辑

这是首个完整可发布版本的收口阶段。

搜索：

- 当前文件夹/全部文件夹两种显式 scope；
- 250–300ms 输入 debounce；
- Rust 侧取消旧搜索，前端 generation + requestId 双门；
- 返回 `limited` 时明确提示；
- 结果仍按“文件”导航，不伪造条目层；
- 打开正文后可做安全的纯文本命中标记。

编辑：

- 阅读页显式进入单栏编辑态；
- 初始化 `{key, content, contentHash}` baseline；
- dirty 离开确认、保存多击合并、保存中返回保护；
- 保存使用不可变 snapshot；
- Rust 串行 mutation、保存前复读 hash、POST、读回验证；
- conflict、save uncertain、force overwrite 各有独立动作与二次确认；
- 任何失败保留草稿，不自动重试写入；
- P0 未证明索引一致性时，写入功能不得进入发布验收。

### P3｜文件管理与创建

只有 P1/P2 的遥测、用户反馈和服务契约稳定后进入：

- DailyNote 创建；
- 单项/批量移动；
- 单项/批量删除；
- 删除空文件夹；
- 本地隐藏、折叠和顺序偏好；
- 从聊天 `DiaryBlock` 深链到日记中心。

管理操作必须使用独立 mutation operation ID、逐项结果和 partial-success UI。删除后的 tombstone/epoch 必须阻止迟到 list/get 让对象“复活”。

### P4｜关系能力实验

候选能力：LightMemo 语义检索、相关 memo 线性列表、多文档工作集。每项都先用真实任务验证：

- 是否比普通搜索提高找回率或缩短完成时间；
- 是否需要额外 Bearer 权限提示；
- 最坏请求耗时、响应大小和取消效果；
- 是否能在低端 Android 设备保持稳定；
- 是否引入用户理解不了的第二套导航。

Canvas 图谱不作为 P4 的默认终点。关系数据若有价值，先证明线性结果不够用。

## 3. 预计代码落点

以下是施工边界，不是要求一次创建全部文件：

| 层 | 新增/修改 | 责任 |
|---|---|---|
| Rust domain | `src-tauri/src/vcp_modules/chat/diary_service.rs` | HTTP、DTO、错误、hash、并发与 command handler |
| Rust module facade | `chat/mod.rs`、`vcp_modules/mod.rs` | 声明与最小 re-export |
| Tauri root | `src-tauri/src/lib.rs` | manage state、注册普通 commands |
| Feature root | `src/features/diary/DiaryCenterView.vue` | 单一全局页与内部视图编排 |
| Feature state | `src/features/diary/diaryStore.ts` | 唯一业务状态、generation、draft |
| Feature contract | `src/features/diary/types.ts` | DTO 与 view model |
| Feature security | `src/features/diary/diaryMarkdown.ts` | feature-local Markdown 净化 |
| Feature UI | `src/features/diary/components/*` | folder/list/reader/editor |
| Overlay wiring | `overlay.ts`、`FeatureOverlays.vue` | 一个 `diaryCenter` page type、懒加载 |
| Entry | `RightSidebar.vue` | 替换一个“待开发”入口 |

不修改 Router、SQLite schema、Sync V2、Android 插件、全局层级数字和 VCPChat。

## 4. 存档与提交边界

正式施工将新增模块目录/文件并修改 `mod.rs`、`lib.rs`，触发项目“重构前强制存档协议”。第一行代码之前必须：

1. 展示 `git status --short --branch`；
2. 区分用户已有修改、研究文档和本功能施工范围；
3. 由用户确认 checkpoint 的纳入范围；
4. 完成可恢复的本地 commit 后再改模块声明；
5. 不 push，除非用户另行要求。

当前已知工作区存在用户自己的删除/移动痕迹，不能把 `git add .` 当作无需审查的机械步骤。

推荐以阶段为提交边界：

- `save: checkpoint before diary center modules`
- `feat(diary): add bounded read-only diary service`
- `feat(diary): add mobile diary browser`
- `feat(diary): add guarded search and editing`
- `test(diary): cover contracts races and sanitization`

实际提交信息服从项目当时约定；上述文本只是边界示例。

## 5. 测试映射

### L1｜Rust 纯逻辑

- base URL 规范化与反向代理前缀；
- 路径段拒绝/编码；
- response byte budget 与 checked-add；
- NoteSummary schema 归一化；
- 结构化文件名解析/fallback；
- content hash、baseline conflict、save outcome 分类；
- stable error code 映射；
- owner/epoch 清理只能由当前 owner 完成。

### L2｜Rust 集成

使用 mock HTTP server 覆盖：

- Basic Auth 正确发送且不进入输出；
- redirect same-origin/cross-origin 策略；
- folders/list/get/search 正常响应；
- 无/伪造 `Content-Length` 的超大 body；
- 慢响应、断流、畸形 JSON、401/404/429/5xx；
- 新搜索取消旧搜索；
- baseline 一致、冲突、force、POST 超时后的 read-back；
- 写后读一致但索引不一致的独立失败门。

fixture 必须是仓库内相对路径并脱敏，不得包含生产凭据或真实私密日记。

### L4｜Vue Store 与组件

- A→B→A 文件夹/文档迟到 success、error、finally；
- refresh 保留旧数据，成功后原子替换；
- 搜索 scope、debounce、取消和 `limited`；
- 任意文件名/空摘要/坏时间戳 fallback；
- empty、auth、timeout、oversize、not-found；
- dirty back、saving back、保存多击、conflict 与 uncertain；
- 文件名、摘要、错误使用文本节点；
- Markdown 中 script、事件属性、危险 URL、SVG/data document 被阻断；
- reader 可选择文本，交互目标可聚焦并有可读标签。

### L5｜跨层契约

- Rust command 注册名与 TypeScript invoke 名一致；
- DTO 字段和 error code 快照一致；
- 普通 Tauri command 不误入 Android 插件 permissions；
- `diaryCenter` overlay type、懒加载入口和关闭路径一致。

### L7/L8｜真机与性能

代表性旅程：

1. 未配置管理员凭据 → 设置引导 → 返回重试；
2. 切换文件夹 → 打开长文 → 搜索 → 打开结果；
3. 编辑 → 后台/前台 → 冲突 → 保留草稿 → 明确覆盖或取消；
4. 弱网中刷新/搜索/保存，确认没有旧请求覆盖和假成功；
5. 低端 Android 上快速滚动长列表和长文，观察内存、长任务和合成层。

窗口化列表不是先验要求。先记录真实列表规模和滚动 profile；只有渲染量造成可复现瓶颈时，复用项目已有 `@vueuse/core/useVirtualList`。

## 6. 每阶段验证命令

实现阶段至少运行：

~~~text
pnpm check
pnpm test:run
cargo test --locked --lib
~~~

若新增 Rust integration target，再运行对应 `cargo test --locked --test ...`。文档或纯前端施工不以构建 APK 作为验证手段；真机 E2E 在 P1/P2 验收门单独执行。

## 7. Release 1 验收清单

### 功能

- [ ] 能从右侧栏进入并完整退出日记中心；
- [ ] 能浏览所有未被产品规则明确排除的文件夹与 memo；
- [ ] 结构化和任意文件名均可打开；
- [ ] 普通搜索 scope、结果上限和错误明确；
- [ ] 正文可选择、可滚动、可安全渲染；
- [ ] 编辑前后目标 key 不漂移，冲突不覆盖，失败不丢草稿；
- [ ] 远端写入和索引一致性均通过 P0 规定的验收。

### 可靠性与安全

- [ ] Basic 凭据从未进入 Vue、日志或错误 body；
- [ ] 响应大小、超时、redirect、路径段全部 fail closed；
- [ ] 迟到 success/error/finally 不能覆盖新意图；
- [ ] 外部正文、摘要、文件名、服务端错误无法注入主 DOM；
- [ ] 保存超时不会自动重试或显示假成功；
- [ ] 没有离线 mutation queue。

### UI/UX 与性能

- [ ] 360dp 宽度无横向溢出，触控目标不小于 48dp；
- [ ] 内容区无 backdrop blur、大阴影或持续 Canvas 动画；
- [ ] 返回键顺序为 editor/reader → diary root → 原页面；
- [ ] 键盘弹出时保存/取消动作可达；
- [ ] 深浅主题下正文与关键控件满足对比度要求；
- [ ] 真机 profile 未发现由本功能引入的持续合成层尖峰或可复现长任务；
- [ ] 未经测量不新增虚拟列表或 Markdown 重型插件。

## 8. 停损规则

出现以下任一情况，停止扩大范围，回到 P0/对应阶段修复：

- 实际部署响应与 DTO 不一致；
- 无法证明 admin raw-save 后索引一致；
- 保存只能提供 blind overwrite，且产品拒绝明确冲突风险；
- 正文上限在目标设备造成不可接受的内存峰值；
- Basic Auth 只能经前端暴露才能调用；
- 搜索无法取消并持续占用服务端有限并发槽；
- 任何视图需要复制全局导航、同步或缓存状态才能工作。

首版宁可保持可靠的只读纵切，也不以不安全写入换取功能表上的“已完成”。
