# 04｜功能迁移矩阵与分期施工

> 目标：把研究结论转换为可排期、可验收、可停损的施工路线。  
> 当前发布完成定义：浏览、普通/语义搜索、编辑、重命名、创建、移动、删除、批量与本机隐藏文件夹管理全部交付。
> 原则：仍按纵切阶段施工，但 P1—P3 共同组成当前里程碑；仅工作台与联想发现后置。

## 1. 功能迁移裁决

| 桌面能力 | 真实语义 | 移动端裁决 | 首版表达 | 阶段 |
|---|---|---|---|---|
| 打开独立 Memo 窗口 | 进入远端 memo 管理器 | 保留入口，重做容器 | 右侧栏“日记中心”进入一个懒加载 SlidePage | P1 |
| 文件夹分类 | 顶层目录列表，无统计 | 保留 | 顶栏当前文件夹；点击打开选择层 | P1 |
| 日记/知识库/思维簇分组 | 长期稳定的名称分类 | 保留 | 线性分组标题，不升级为权限类型 | P1 |
| `MusicDiary` 过滤 | 桌面硬过滤；LightMemo 默认排除搜索 | 不复制消费端硬编码 | 本机隐藏默认空；语义结果服从 LightMemo | P1/P3 |
| 隐藏、折叠、拖拽排序 | 桌面本机 UI 偏好 | 保留但与服务端排除解耦 | 文件夹管理态；对服务端返回集合做附加发现性过滤 | P3 |
| 卡片网格 | 一文件一卡、显示摘要 | 改造 | 高密度线性行、1px 分隔、结构化文件名增强 | P1 |
| 结构化文件名解析 | 从文件名提取日期、时间、标题 | 保留且允许失败 | 解析成功显示友好标题；失败显示原文件名 | P1 |
| 整文件读取 | 获取不透明 UTF-8 正文 | 保留 | 连续滚动 Markdown 阅读页 | P1 |
| Markdown/raw HTML 预览 | `marked` 直入 `innerHTML` | 保留可信语义 | `marked.parse` 后直接 `v-html`/`innerHTML`，最多复用轻量过滤 | P1 |
| 当前文件夹搜索 | 返回文件摘要 | 保留 | 默认当前文件夹范围，显示明确 scope | P2 |
| 全局普通搜索 | 返回跨目录文件摘要 | 保留 | 用户显式切换“全部文件夹” | P2 |
| 搜索命中定位 | 桌面仅定位到文件 | 不虚构 | 打开文件后可本地高亮文本，不承诺服务端 offset | P2 |
| LightMemo 语义检索 | Bearer Human Tool 调用 | 当前核心 | 显式提交，与普通搜索分开错误、scope 和取消生命周期 | P3 |
| 整文件编辑 | blind full overwrite | 保留但重做一致性 | 显式编辑态、dirty guard、baseline hash、读回核验 | P2 |
| 文件名重命名 | 用户已验证的桌面能力 | 当前核心 | 明确重命名层；无原子端点时用可恢复 transaction | P2 |
| 新建 DailyNote | Human Tool create；`fileName` 是生成文件名的可选后缀 | 当前核心 | 全屏 Composer + 官方 Tool ESCAPE，打开响应返回的实际文件 | P3 |
| 单项/批量删除 | 可能部分成功 | 当前核心 | 明确选择态、逐项结果和不可撤销确认 | P3 |
| 批量移动 | 可能部分成功、重名不覆盖 | 当前核心 | 返回 moved/errors 明细，不显示笼统“全部成功” | P3 |
| 删除文件夹 | 只允许空目录 | 当前核心 | 文件夹管理态，服务端再次裁决 | P3 |
| 多文档工作台 | 拉取多篇全文并拼接 | 后置 | 先验证真实工作流价值和内存预算 | P4 评估 |
| 联想发现 | 返回相关 memo | 后置 | 未来先做相关 memo 线性列表 | P4 |
| Canvas 力导向图 | 持续 RAF 的桌面可视化 | 不移植首版 | 只有任务数据证明必要时再独立设计 | 不排期 |
| 桌面毛玻璃/大卡片/厚阴影 | 氛围视觉 | 不移植 | 实色表面、细线、透明度/Accent Bar 反馈 | 全阶段 |
| 本地全文缓存/离线写队列 | 桌面不存在 | 不新增 | 内存保留当前正文与草稿；断网不排队写 | 全阶段 |

## 2. 施工阶段

### P0｜最新上游契约固化

P0 的源码问题已在 2026-08-12 复核最新 VCPToolBox `351dadc7` 后完成：

1. `/admin_api/dailynotes` 的 folders/list/get/search/save/move/delete/folder-delete 契约已确认；
2. 400/401/403/404/429/499/500/503/504 响应路径已确认；
3. 服务端没有 ETag、revision、`If-Match` 或原子 rename endpoint；
4. 管理 mutation 进入 KnowledgeBaseManager 外部 FIFO，并异步调度 SQLite/Rust 索引；HTTP 不等待索引完成；
5. `lastModified` 为 `mtime.toISOString()`；单文件 GET 无服务端上限；
6. 正文已知平均数 KiB、数百字节至数十 KiB，单目录数百至数千文件；
7. 文件夹分类规则长期稳定；服务端语义排除是基线，本机隐藏是默认空且不硬编码 `MusicDiary` 的附加过滤；
8. Agent 与 folder 相互独立，公共日记本可由多个 Agent 和用户共同写入；
9. Human Tool 已有 `「始ESCAPE」...「末ESCAPE」` 和工具块字面量转义协议；
10. 日记正文按可信 HTML 处理，并由 Diary feature 自己完成 Markdown 到 HTML 的渲染。

开工前仍需做部署联调 fixture，但它不再是架构探索：验证成功/错误 JSON、反代 path prefix、真实重命名请求、索引追平延迟，以及结构化/Unicode/HTML 文件样本。fixture 必须脱敏且不含凭据。

### P1｜浏览纵切

交付一条完整、可在真机验证的读链路：

~~~text
右侧栏入口
  → DiaryCenter 懒加载
  → 配置/认证门
  → 文件夹选择
  → 文件线性列表
  → 整文件阅读
  → 返回与刷新
~~~

施工内容：

- Rust typed service、受限 HTTP client、URL 与路径段校验；
- folders/list/get commands 与 DTO；
- 一个 `useDiaryStore`，为 folders/list/document 建立 generation 提交门；
- `DiaryCenterView`、选择层、`useVirtualList` 文件列表和 reader；
- `marked.parse → v-html/innerHTML` 的可信正文渲染；
- loading、refreshing、empty、auth、timeout、not-found、oversize 状态；
- 结构化文件名解析纯函数与 fallback；
- Android 返回键、选择文本、深色主题和动态 viewport 验证。

P1 不包含 mutation；这些在同一当前里程碑的 P2/P3 紧接交付。

### P2｜普通搜索、受保护编辑与重命名

搜索：

- 当前文件夹/全部文件夹两种显式 scope；
- 250–300ms 输入 debounce；
- Rust 侧取消旧搜索，前端 generation + requestId 双门；
- 返回 `limited` 时明确提示；
- 结果仍按“文件”导航，不伪造条目层；
- 打开正文后可做安全的纯文本命中标记。

编辑：

- 阅读页显式进入单栏编辑态；
- 初始化 `{key, content, contentHash}` baseline；
- dirty 离开确认、保存多击合并、保存中返回保护；
- 保存使用不可变 snapshot；
- Rust 串行 mutation、保存前复读 hash、POST、读回验证；
- conflict、save uncertain、force overwrite 各有独立动作与二次确认；
- 任何失败保留草稿，不自动重试写入；
- 保存成功后标记语义结果 stale；索引由服务端异步追平，不把 HTTP 成功误写成“索引已完成”。

重命名：

- 以用户桌面实测作为功能验收事实；
- 先采集运行态请求，若存在专用端点则按 fixture 实现；
- 最新上游没有原子 rename 时，执行“写新文件 → 读回 hash → 删除旧文件”；
- 已知目标重名先拒绝；无条件端点时明确保留“探测 → POST”的跨客户端 TOCTOU，不宣称零覆盖窗口；源删除失败返回“新旧并存”的 partial outcome；
- 成功后原子迁移 current key、baseline、列表项和返回位置。

### P3｜管理、创建与 LightMemo 语义搜索

P3 属于当前发布里程碑，不再后置：

- DailyNote 创建；
- 单项/批量移动；
- 单项/批量删除；
- 删除空文件夹；
- 本机隐藏、恢复、折叠和顺序偏好；`hiddenFolders` 默认空；
- 当聊天 `DiaryBlock` 明确给出 `folder + fileName` 时深链到日记中心；不按 Agent 名称猜 folder；
- LightMemo 语义搜索：Bearer、显式提交、folder/all scope、独立取消与错误态；all scope 仍服从服务端 `EXCLUDED_FOLDERS`；
- 把语义 chunk 按 `folder + fileName` 折叠为文件结果，并处理索引最终一致提示。

Mobile 不调用 `/admin_api/plugins` 镜像排除项；该接口返回全插件配置文本，既过宽也不是有效语义范围的专用契约。当前由 LightMemo 服务端先过滤，本机 `hiddenFolders` 只对返回结果追加过滤。若以后需要在请求前标识服务端排除目录，必须先有去敏、目的明确的服务端只读 DTO。

DailyNote 创建必须使用官方 Tool ESCAPE 协议，不再用固定 1 秒延时猜测完成。管理操作使用独立 mutation operation ID、逐项结果和 partial-success UI；删除后的 tombstone/epoch 阻止迟到 list/get 让对象“复活”。P1—P3 全部通过才算当前版本完成。

### P4｜明确后置的关系与工作台能力

候选能力仅剩相关 memo/联想发现、Canvas 图谱与多文档工作台。每项先用真实任务验证：

- 是否比普通搜索提高找回率或缩短完成时间；
- 最坏请求耗时、响应大小和取消效果；
- 是否能在低端 Android 设备保持稳定；
- 是否引入用户理解不了的第二套导航。

Canvas 图谱不作为 P4 的默认终点。关系数据若有价值，先证明线性结果不够用。

## 4. 存档与提交边界

正式施工将新增模块目录/文件并修改 `mod.rs`、`lib.rs`，触发项目“重构前强制存档协议”。第一行代码之前必须：

1. 展示 `git status --short --branch`；
2. 区分用户已有修改、研究文档和本功能施工范围；
3. 由用户确认 checkpoint 的纳入范围；
4. 完成可恢复的本地 commit 后再改模块声明；
5. 不 push，除非用户另行要求。

当前已知工作区存在用户自己的删除/移动痕迹，不能把 `git add .` 当作无需审查的机械步骤。

推荐以阶段为提交边界：

- `save: checkpoint before diary center modules`
- `feat(diary): add bounded read-only diary service`
- `feat(diary): add mobile diary browser`
- `feat(diary): add guarded editing and rename`
- `feat(diary): add management create and semantic search`
- `test(diary): cover contracts races trusted html and mutations`

实际提交信息服从项目当时约定；上述文本只是边界示例。

## 5. 测试映射

### L1｜Rust 纯逻辑

- base URL 规范化与反向代理前缀；
- 路径段拒绝/编码；
- response byte budget 与 checked-add；
- NoteSummary schema 归一化；
- 结构化文件名解析/fallback；
- content hash、baseline conflict、save outcome 分类；
- rename transaction、目标重名与 source-retained outcome；
- Tool ESCAPE 编码与 LightMemo 结果归一化；
- stable error code 映射；
- owner/epoch 清理只能由当前 owner 完成。

### L2｜Rust 集成

使用 mock HTTP server 覆盖：

- Basic Auth 正确发送且不进入输出；
- redirect same-origin/cross-origin 策略；
- folders/list/get/search/save/move/delete 正常与 partial 响应；
- 无/伪造 `Content-Length` 的超大 body；
- 慢响应、断流、畸形 JSON、400/401/403/404/429/499/500/503/504；
- 普通/LightMemo 新搜索分别取消同类旧搜索；
- baseline 一致、冲突、force、POST 超时后的 read-back；
- rename 专用端点 fixture 或兼容 transaction 的完整/部分成功；
- Tool ESCAPE 的正文 marker 字面量、DailyNote/LightMemo 插件错误；
- 文件 HTTP 成功后语义索引短暂落后的最终一致状态。

fixture 必须是仓库内相对路径并脱敏，不得包含生产凭据或真实私密日记。

### L4｜Vue Store 与组件

- A→B→A 文件夹/文档迟到 success、error、finally；
- refresh 保留旧数据，成功后原子替换；
- 普通/语义搜索 scope、debounce/显式提交、取消、`limited` 与索引追平提示；
- 任意文件名/空摘要/坏时间戳 fallback；
- empty、auth、timeout、oversize、not-found；
- dirty back、saving back、保存多击、conflict 与 uncertain；
- 重命名重名、成功、新旧并存；创建与管理 partial success；
- 管理 API 目录集合、本机隐藏/恢复/折叠/顺序偏好，以及语义排除范围不串线；
- 数千文件虚拟列表、稳定 key 和滚动恢复；
- raw HTML 在正文容器原样保留；文件名、摘要、语义元信息和错误使用文本节点；
- reader 可选择文本，交互目标可聚焦并有可读标签。

### L5｜跨层契约

- Rust command 注册名与 TypeScript invoke 名一致；
- DTO 字段和 error code 快照一致；
- 普通 Tauri command 不误入 Android 插件 permissions；
- `diaryCenter` overlay type、懒加载入口和关闭路径一致。

### L7/L8｜真机与性能

代表性旅程：

1. 未配置管理员凭据 → 设置引导 → 返回重试；
2. 切换含数千文件的文件夹 → 快速滚动 → 普通搜索 → 打开结果；
3. 编辑 → 后台/前台 → 冲突 → 保留草稿 → 明确覆盖或取消；
4. 重命名 → 重名拒绝 → 模拟删除源失败并确认新旧并存提示；
5. 创建 → 移动/删除部分成功 → 本机隐藏/恢复后语义排除范围不变；
6. LightMemo 语义检索 → 取消 → 保存后短暂索引追平 → 重试；
7. 弱网中刷新/搜索/保存，确认没有旧请求覆盖和假成功；
8. 低端 Android 上观察虚拟列表、长文和可信 HTML 的内存、长任务和合成层。

窗口化是当前规模下的既定能力：复用项目已有 `@vueuse/core/useVirtualList`，不新增依赖。正文仍连续渲染，不窗口化。

## 8. 停损规则

出现以下任一情况，停止扩大范围，回到 P0/对应阶段修复：

- 实际部署响应与 DTO 不一致；
- VCPToolBox mutation 未进入已确认的最终一致索引队列，或部署行为与最新上游明显漂移；
- 保存只能提供 blind overwrite，且产品拒绝明确冲突风险；
- 正文上限在目标设备造成不可接受的内存峰值；
- Basic Auth 只能经前端暴露才能调用；
- 搜索无法取消并持续占用服务端有限并发槽；
- 任何视图需要复制全局导航、同步或缓存状态才能工作。
