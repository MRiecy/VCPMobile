# 02｜移动端产品与 UI/UX 方案

> 产品定义：VCPMemo 在手机上的可靠记忆文件中心，而不是缩小版桌面工作台，也不是小说阅读器。  
> 审美基线：高密度线性布局、灰度优先、彩色只表达状态、内容区域零毛玻璃。

## 1. 设计目标

当前完整版本要让用户以明确、可恢复的操作完成：

- 找到某个记忆文件；
- 舒适阅读完整内容；
- 进入编辑、可靠保存或识别冲突；
- 重命名、新建、移动、删除与批量整理；
- 在普通搜索与 LightMemo 语义搜索之间明确切换；
- 从任何子状态用系统返回键逐级退出，不丢草稿。

体验优先级：

1. **正确与可恢复**：不误开、不误覆盖、不因迟到请求跳页；
2. **可发现**：搜索范围、编辑、刷新和错误恢复都用明确文案；
3. **高密度**：一屏看到足够多的文件，不用大卡片装饰；
4. **移动直觉**：单栏、底部易达动作、键盘与物理返回优先；
5. **性能克制**：无内容 blur、无持续动画、无无证据依赖。

## 2. 信息架构

### 2.1 数据层与页面层分开

数据层只有：

~~~text
Folder
└─ Memo file
   └─ Opaque full content
~~~

页面状态可以有：

~~~text
DiaryCenterView（唯一全局 SlidePage）
├─ 文件列表态
│  ├─ 文件夹选择 Sheet
│  ├─ 普通 / LightMemo 语义搜索态
│  └─ 批量选择与文件夹管理态
├─ 整文件阅读态
├─ 整文件编辑态
│  └─ 预览子态
└─ DailyNote 新建态
~~~

页面状态多于数据层级不代表服务端多出“条目”。这条边界必须在组件命名、类型和埋点中保持一致：使用 `note/file/document`，不要使用未经证实的 `entry`。

### 2.2 入口

当前主入口放在右抽屉底部两个“待开发”槽之一，命名“日记中心”，图标建议使用简洁的 `BookOpenText` 或 `NotebookText`。

不在首版加入：

- 主聊天顶栏常驻图标：当前 360dp 顶栏已经拥挤；
- Agent 卡片按名称猜日记本：Agent 与 folder 相互独立，“公共”等日记本可由多个 Agent 与用户共同写入；
- 新 Vue Router 路由：当前产品以 Overlay/SlidePage 为主。

当前 `DiaryBlock.file_name` 只是 DailyNote 请求后缀，无法唯一定位服务端最终文件；P3 因而不显示“查看所在文件”。未来只有工具结果能可靠返回并关联唯一 `folder + file` 时再增加该入口。

## 3. 核心页面

### 3.1 日记中心 / 文件列表

~~~text
┌──────────── safe top ────────────┐
│ 日记中心                 搜索  刷新  × │
├──────────────────────────────────┤
│ 当前文件夹  Nova 的知识          ▾ │
│ 普通搜索输入框（搜索态才展开）       │
├──────────────────────────────────┤
│▌TXT  六一晨间的温柔拥抱             │
│     今天和用户讨论了……              │
│     2026-06-01 06:21 · 08-12 21:34 │
├──────────────────────────────────┤
│ MD   日记提示词哲学                 │
│      对 DailyNote 的协议边界……       │
│      2026-05-28 18:43               │
├──────────────────────────────────┤
│ 普通文件名.txt                      │
│ 无法解析时间也必须正常显示             │
└──────────── safe bottom ──────────┘
~~~

规则：

- 一行对应一个完整文件，不对应文件内条目；
- 默认沿用服务端修改时间倒序；
- 标题一行、摘要最多两行、元信息一行；
- 格式、时间、原始文件名等技术信息使用 monospace；
- 结构化文件名解析成功时显示可读标题与时间，失败时显示原名；
- 搜索结果额外显示来源文件夹；
- `preview` 为空或“文件过大”时给明确占位，不伪造摘要；
- 不展示目录文件数、最近摘要、Agent 头像或 Tags，除非未来接口直接提供。

### 3.2 文件夹选择层

~~~text
┌──────────── 文件夹 ─────────────┐
│ [筛选文件夹…………………]              │
│ 日记 / 知识库                    │
│▌Nova 的知识                     │
│  Sakura                         │
│  已整理                          │
│ 思维簇                           │
│  项目设计簇                       │
└──────────── safe bottom ─────────┘
~~~

规则：

- 采用底部 Sheet，最大高度约 72vh，内部独立滚动；
- 文件夹使用纯线性行，选中态是 2px 左侧 Accent Bar；
- 名称以“簇”结尾的长期稳定规则用于“思维簇”分组；其他目录进入“日记 / 知识库”；
- 普通文件夹列表以管理 API 返回集合为底，再应用用户主动设置的本机隐藏偏好；偏好默认空，不硬编码过滤 `MusicDiary`；
- 点击文件夹立即关闭 Sheet，并保留旧列表直到新列表成功原子替换；
- 文件夹很多时提供本地名称过滤；
- 当前版本提供显式“管理文件夹”模式完成隐藏、恢复、折叠/排序与删除空文件夹，不混入普通选择态；隐藏是本机发现性过滤，不是权限或服务端配置写入。

现有全局 BottomSheet 的历史栈和安全区行为可借鉴，但其 2rem 圆角、厚阴影、scale 反馈不适用于本功能。首版应使用克制的 feature-local 视觉，或先小范围泛化共享原语。

### 3.3 普通与语义搜索

搜索入口展开后显示明确范围，而不是复刻桌面“一个图标循环三态”：

~~~text
[普通] [语义]  [本文件夹] [全部]  搜索记忆内容…………
~~~

规则：

- 普通搜索 250–300ms debounce；空查询回到当前文件夹列表；
- 新查询使旧查询失去提交权；
- “本文件夹 / 全部”使用文字段控，范围永远可见；
- 结果达到服务端限制时显示“结果已截断”，读取 `limited` 而非假装完整；
- 搜索结果只保证定位文件；正文高亮在打开文件后本地完成；
- 从结果打开文件再返回时，恢复 query、scope 与滚动位置；
- LightMemo 语义检索属于当前核心功能，使用 Bearer API Key 和显式“开始语义检索”按钮，不随输入 debounce 自动调用；
- 语义模式显式展示 folder/all scope、上游默认 `k=5`、检索中/取消/失败/索引可能追平中的状态；客户端对 k 设硬上限 50；
- “全部”只表示 LightMemo 当前服务端配置允许搜索的全部日记本；排除范围由服务端 `EXCLUDED_FOLDERS` 先行裁决。本机隐藏不据此初始化，但会继续从已返回结果中滤掉用户隐藏的 folder；“取消隐藏”只能恢复本机附加过滤，不能把服务端已排除目录带回语义结果；
- 语义结果按 `folder + fileName` 归一化到文件行，同文件多个 chunk 合并摘要；不能把 chunk 当成可独立编辑的文件内条目；
- 普通与语义请求分别持有 request owner，切换模式会取消旧请求但保留查询文字。

### 3.4 阅读态

~~~text
┌──────────── safe top ────────────┐
│ ‹  六一晨间的温柔拥抱          ⋯ │
│ TXT · Nova 的知识 · 2026-06-01   │
├──────────────────────────────────┤
│                                  │
│ Markdown 正文                     │
│ 连续滚动、可选择复制                │
│ 表格和代码仅局部横向滚动             │
│                                  │
├──────────────────────────────────┤
│                            编辑   │
└──────────── safe bottom ──────────┘
~~~

规则：

- 默认只读，显式点击“编辑”才进入 textarea；
- 日记正文按可信内容处理，Markdown 内 raw HTML 原样保留，使用 `marked.parse` 后的 HTML 直接渲染；
- 顶栏始终可见，不做中央点按呼出、3 秒隐藏或左右点击区；
- 连续滚动，不做分页、仿真翻页、音量键翻页；
- 正文容器添加 `select-text vcp-scrollable no-swipe`，兼容根级 `select-none` 和侧栏手势；
- 文件名在阅读态默认只读，`⋯ → 重命名` 打开明确的文件名输入层；不把正文标题和文件名混为一谈；
- 删除、移动、重命名等管理操作放在 `⋯`；联想能力后置；
- 平板仅增加内容最大宽度和左右留白，不切回桌面双栏；
- 网络刷新失败时保留已有正文，并显示非阻断错误。

### 3.5 编辑态

~~~text
┌──────────── safe top ────────────┐
│ ×  编辑日记                       │
│ Nova 的知识 / 原始文件名.txt       │
├──────────────────────────────────┤
│ 单栏 Markdown textarea             │
│                                  │
│                                  │
├──────────────────────────────────┤
│ 保存状态       阅读预览       保存 │
└──────────── keyboard / safe bottom┘
~~~

规则：

- 单栏原文编辑；预览是显式切换，不左右分栏；
- 编辑器底栏随键盘 Insets 上移；
- 保存按钮至少 48dp 触控区，保存中禁用重复提交；
- dirty、saving、saved、error、conflict 必须是可见状态，不能只靠 Toast；
- 保存成功留在编辑态，并更新 baseline；
- 保存失败或冲突保留完整草稿；
- dirty 状态关闭、系统返回、切文件或删除前必须确认；
- saving 期间页面不可关闭；返回键由 ModalHistory close gate 拒绝；
- 冲突默认不覆盖，提供“复制草稿”“加载远端”“明确强制覆盖”；
- 首版不做富文本工具栏、自动格式化或每键全量预览。

### 3.6 重命名与管理态

重命名是当前核心能力，但 UI 不把文件名输入框常驻在编辑器里：

~~~text
重命名文件
[2026-08-12-19_30_00-新的标题.txt        ]
保留扩展名 · 目标已存在时禁止覆盖
                              取消  重命名
~~~

- 默认选中主文件名、保留原 `.txt`/`.md` 扩展名；
- 新名称为空、包含 `/`、`\`、`.`/`..` 路径语义或目标重名时就地报错；
- operation 期间固定源 key 与目标 key，不跟随当前页面漂移；
- 若服务端没有原子 rename，Mobile 以“写新文件 → 校验 → 删除旧文件”执行；删除旧文件失败时明确显示“已复制为新名称，原文件仍保留”，绝不宣称完全成功；
- 兼容 transaction 的“目标不存在”检查仍有跨客户端 TOCTOU；在捕获到专用原子端点前，技术说明和验收不得把它宣传成强原子重命名；
- 成功后原子替换当前 `NoteKey`、baseline、列表项与返回目标。

批量管理由长按文件行或顶栏“管理”进入：顶部显示已选数量，底部只放“移动”“删除”；返回键先退出选择态。移动/删除逐项展示 partial success，失败项保持选中，成功项立即从列表移除并由 tombstone 阻止迟到请求复活。

新建使用全屏 Composer，字段为日期、署名、folder、可选“文件名后缀”、Tag 和 Content。该后缀映射到 DailyNote 的 `fileName`，服务端仍会生成日期/时刻前缀并在碰撞时原子分配 `(n)`；UI 不把它假装成完整目标文件名。提交走 DailyNote Human Tool 的 ESCAPE 字段协议；成功响应中的实际 `folder + fileName` 用于打开新文件，不使用固定延时猜测落盘完成。

## 4. 返回键与覆盖层优先级

Android 物理返回和边缘返回必须遵守同一顺序：

1. 当前确认 Dialog；
2. 当前文件夹/更多操作 Sheet；
3. 保存中的编辑态：拒绝关闭；
4. dirty 编辑态：打开离开确认；
5. clean 编辑态：退回阅读态；
6. 阅读态：退回之前的文件/搜索列表；
7. 批量选择态：先退出选择；
8. 普通/语义搜索态：取消请求并回当前文件夹列表；
9. 日记中心根页：关闭并回聊天。

实现上复用 `useModalHistory` 的 LIFO 和可返回 `false` 的 close gate，不在日记 Store 内另造一套浏览器 history。

## 5. 视觉规格

### 5.1 布局与密度

| 元素 | 建议 |
|---|---|
| 页面水平边距 | 手机 16px；宽屏 20–24px |
| 顶栏内容高度 | 48–52px，加 `--vcp-safe-top` |
| 文件行 | 固定 84px；1px 下分隔线，供 `useVirtualList` 稳定测量 |
| 标题 | 15–16px / 600，一行省略 |
| 摘要 | 13–14px / 1.45，两行省略 |
| 元信息 | 11–12px monospace |
| 阅读正文 | 16px / 1.65，用户系统字号仍应生效 |
| 段间距 | 0.75–1em |
| 阅读最大宽 | 720px，居中 |
| 触控热区 | 至少 48×48dp |
| 选中/当前项 | 2px 左 Accent Bar + 轻微背景色 |

48dp 触控区来自 [Android Accessibility 官方建议](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views)。正文与背景至少达到 WCAG AA 的 4.5:1，参见 [W3C SC 1.4.3](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html)。

### 5.2 色彩

复用现有主题变量：

- `--primary-bg`
- `--secondary-bg`
- `--primary-text`
- `--secondary-text`
- `--highlight-text`
- `--border-color`
- `--danger-color`
- `--success-color`

状态色只用于：

- 蓝：当前文件夹、搜索范围、可执行主操作；
- 黄：未保存或提醒；
- 红：错误、冲突、删除；
- 绿：短暂的保存成功。

不能只靠颜色表达状态；必须同时有文字、图标或结构。

### 5.3 明确禁止

- 滚动容器、列表行、阅读正文、编辑器上的 `backdrop-filter`；
- 15–30px 大圆角卡片海；
- 厚重投影和辉光；
- hover 上浮、active 大幅缩放、弹跳；
- 全局 `transition: all`；
- 每一行逐项入场动画；
- Canvas 常驻 RAF；
- 为“显得高级”人为增加延迟。

允许的动效只作用于 `transform`/ `opacity`：

- 页面进退沿用 SlidePage；
- Sheet 180–260ms；
- 状态文字 120–180ms 淡入；
- `prefers-reduced-motion` 下关闭非必要动画。

## 6. 页面状态矩阵

| 场景 | 必须覆盖的状态 | 交互要求 |
|---|---|---|
| 进入日记中心 | 初始化、缺少 URL、缺少 admin 凭据、认证失败、服务器不可达 | 给“前往设置”或“重试”，不进入启动死锁 |
| 文件夹 | loading、正常、为空、过滤无结果、切换失败 | 切换失败保留旧选择和旧内容 |
| 文件列表 | 首载、刷新、正常、空、失败、超大响应 | 刷新不先清空；失败可重试 |
| 搜索 | 空查询、debounce、请求中、结果、截断、无结果、失败、陈旧结果 | 陈旧 success/error/finally 均不得提交 |
| 语义搜索 | 未配置 API Key、等待显式提交、检索中、取消、结果、索引追平、失败 | 不随输入自动调用，chunk 归一为文件 |
| 文档 | loading、正常、读取失败、超大、远端删除、stale | 旧文档不可被新请求迟到覆盖 |
| 编辑 | clean、dirty、saving、saved、error、conflict、结果不确定 | 草稿始终优先保留 |
| 重命名 | 校验、目标重名、执行中、成功、新旧并存的部分成功 | 固定 source/target，绝不覆盖已有目标 |
| 管理 | 单选/多选、移动、删除、partial success、本机隐藏/恢复、折叠/排序、空文件夹删除 | 成功项退出，失败项保留并可重试 |
| 创建 | 编辑、校验、提交、索引排队、成功、失败 | 使用 Tool ESCAPE，不用固定延时刷新 |
| 生命周期 | 退后台、回前台、进程被杀 | dirty 时不自动刷新；MVP 明示杀进程不保证草稿恢复 |
| 离线 | 无网络、有当前内存正文 | 可读已加载内容并标“可能过期”，不可离线排队写 |

## 7. 加载与空态

- 首次文件列表可使用 5–7 行静态骨架；
- 刷新已有列表时只在顶栏显示细进度，不用整页骨架覆盖；
- 骨架不做大面积 shimmer，最多低频透明度变化；
- 空文件夹文案为“这个文件夹还没有 memo 文件”，不显示“加载失败”；
- 缺少配置与认证失败分开；
- 超大正文显示大小边界和建议在桌面处理，不截断后假装完整；
- 正文以外的错误、文件名、folder 和搜索元信息只走文本绑定；可信 HTML 决策不扩展到接口元数据。

## 8. 搜索、阅读与性能边界

当前版本直接承担已由规模证明必要的列表窗口化，但不提前支付其余复杂度：

- 文件列表虚拟化：已知单目录存在数百至数千文件，直接复用 `@vueuse/core/useVirtualList`，固定 84px 行高并保留适量 overscan；
- 正文虚拟化：会破坏选区、锚点、高亮和滚动恢复，不采用；
- KaTeX/Mermaid/高亮全量预处理：按真实内容比例和 profile 决定；
- 文件内目录：只有真实 fixture 证明稳定标题/条目语法后才做；
- 独立阅读主题、字体包和字号设置：首版跟随现有主题与系统字号。

## 9. 后续能力的移动表达

| 桌面能力 | 后续移动表达 |
|---|---|
| 工作台 | 独立页面，引用线性列表 + 整合编辑；默认保留原文 |
| 联想发现 | 先做“相关 memo”线性列表 |
| Canvas 图谱 | 不直接移植；只有线性结果无法满足真实任务时重新设计 |

## 10. UX 验收场景

1. 用户在右抽屉打开日记中心，无配置时能一键去设置；
2. 用户切 A→B 文件夹，即使 A 最后返回也只看到 B；
3. 任意文件名和空 preview 均能打开；
4. 搜索结果打开后返回，query、范围和滚动位置仍在；
5. 阅读正文可原生长按选择复制，横向代码滚动不会打开侧栏；
6. 编辑后按系统返回出现未保存确认；
7. 保存冲突时不覆盖、不清空草稿；
