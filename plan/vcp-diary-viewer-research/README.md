# VCPMemo 日记中心移动端移植研究

> 状态：`IMPLEMENTATION-READY AFTER P0`  
> 调研日期：2026-08-12  
> 施工 SSOT：本目录的 `01`—`06` 文档；旧版《排版与交互研究报告》仅作视觉研究附件

## 结论

本次研究已把桌面 VCPMemo 的真实实现、当前 VCPToolBox 服务端路由和 VCPMobile 基础设施对齐。推荐方案不是缩小桌面窗口，而是保留领域能力、重做移动端表达：

```text
右抽屉“日记中心”
  → 当前文件夹 + 高密度 memo 文件列表
  → 整文件阅读
  → 显式进入整文件编辑
```

需要牢记的五条结论：

1. 真实数据模型是“文件夹 → memo 文件 → 整文件内容”，不存在已证实的“日期文件内多条日记”领域层。
2. 日记管理 API 使用管理员 Basic Auth；DailyNote/LightMemo 工具调用才使用 Bearer VCP API Key，两套凭据不能混用。
3. 网络、凭据、限流、响应体上限和保存冲突检查由 Rust 负责；Vue 只持有页面状态和编辑草稿。
4. 首个完整版本聚焦可靠浏览、普通搜索和受保护的整文件编辑；工作台、批量管理、语义检索和联想图谱后置。
5. 移动端使用线性列表、实色表面、细分隔线和 2px Accent Bar；不移植内容区域毛玻璃、大卡片、厚阴影、持续 Canvas 动画或人为等待。

## 开工条件

P0 契约冻结完成前，可以做只读页面骨架和纯逻辑测试，但不得把写入行为宣布为完成。至少需要从实际部署采集并脱敏保存：

- `/folders`、`/folder/:folder`、`/note/:folder/:file`、`/search` 的成功与错误响应；
- 保存前后正文及索引可检索性；
- 认证失败、404、超时、超大正文和畸形 JSON；
- 真实目录数、单目录文件数、正文 P50/P95/max，以及旧/新/非结构化文件名样本；
- 服务端是否支持 ETag、revision、`If-Match` 或其他原子条件写。

若服务端没有原子条件写，移动端只能提供“保存前复读 + hash 冲突拦截”的 best-effort 防护；它不能被描述成真正 CAS。
