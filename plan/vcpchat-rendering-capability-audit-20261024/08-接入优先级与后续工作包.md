# 接入优先级与后续工作包

本文件是 2026-10-24 审计后的建议，不是实施授权或排期承诺。工作包按目标行为、现有 owner 与验证问题划分；不以桌面提交数量、文件数量或库是否流行为优先级。

## 1. 建议先处理的顺序

1. **先保证相同消息在移动端表达正确。** CSS 作用域、工具结果定界与 HIDDEN 读取、JEV 卡片、Markdown 结构元数据属于现有内容的可读性/语义完整性；HIDDEN 还关联后续上下文。
2. **再完善大内容和交互的生命周期。** 工具详情按需挂载、媒体清理、按钮失败恢复及明确的 HTML 状态延续边界，直接服务于已存在功能。
3. **最后单独接入新的资产/运行时能力。** Pele、v 图表引用、Pixi/动画岛、上下文 checkpoint，各有不同数据和资源所有者，不能打成一个“渲染引擎升级”大包。

不建议为了追齐桌面，将移动 Rust AST/TailFrame 换回 JS 全量管线；不增加桌面业务分支，不照搬 Electron 多窗口或鼠标交互，也不以禁用富内容解决兼容问题。

## 2. 第一批：现有内容正确性

| 工作包 | 具体目标 | 当前 owner / 建议改动边界 | 验收关注点 | 优先理由 |
|---|---|---|---|---|
| A1 CSS 作用域 | 保留根后代选择器、`:is/:where` 内逗号、嵌套条件规则和 keyframes 结构 | 现有 messageStyles / useMessageStyleInjector 与 HTML 样式提取；采用真正 CSS 语法解析，不新增第二份消息样式状态 | 两条同类名消息不串色；body 后代不丢；media 生效；动画规则完整；代码/工具数据中的 style 不被抽走 | 04 已直接执行当前转换函数取得错误输出，影响既有静态/响应式富 HTML |
| A2 工具结果语义域 | 完整结果内嵌标记保持为数据，真正外层结束后才恢复其它协议 | Rust content_parser 与 StreamBlockParser 共同修正；同步检查正文编译、尾部封印、终态和历史编译 | 结果中含嵌套结果、think、TOOL_REQUEST、反引号、角色分隔；任意 chunk 切分后的终态语义一致 | 桌面已有嵌套区间/数据域优先级，移动两个解析入口仍有首结束匹配差异 |
| A3 JEV 工具呈现 | 没有传统 tool_name 的合法 JEV 自然语言请求具有准确标题与正文，不显示 Processing... 或误报 | 当前工具解析结构与 ToolBlock，保留原始消息；不关联 JEV 群聊调度实现 | 传统字段、JEV 显式名称/能力描述、混合字段、坏标记、流式半字段 | 与当前服务端/桌面消息协议直接相接，改动目标清晰 |
| A4 Markdown 结构 | 任务列表、`ol start`、表格列对齐；按需要接受 graph/flowchart 图表别名 | Rust parser → MarkdownNode/DTO → astRenderer / astExecutor / 快照缓存身份；别名走既有 Mermaid owner | 同一输入在活动尾部、稳定块、终态、重读历史保留结构；任务 checkbox 只读还是可编辑需保持产品明确 | 存在具体字段丢失/未启用选项，不能只补 CSS 或改 ToolBlock 的 Marked 配置 |
| A5 HIDDEN 跨端读取 | 识别桌面已排除的结果，在显示与后续上下文中保留其语义 | 当前工具结果解析、历史读取与 context_assembler；先核实同步文本中的标记保持情况 | 桌面隐藏后同步到移动，再发送一条消息，排除内容是否仍进入请求；恢复后是否重新可用 | 移动当前助手历史投影只剥离 voice-guidance，未见 HIDDEN 过滤，不能把已有折叠开关当作覆盖 |

A1/A2/A4/A5 涉及核心或跨层，应在实施时运行 `pnpm check`；AST 形状改变要核对当前 render-cache 身份/编译器版本和持久缓存再生成，不允许靠旧 HTML 缓存掩盖新旧结果不一致。验证语料见 03、04、05、06，不为“支持表”逐格生成镜像断言。

任务列表和图表别名是行为选择；列表起点、表格对齐和 CSS 结构则首先是保留输入语义。不要把所有项目都用一个全局富文本开关控制。

## 3. 第二批：已存在能力的运行质量

### B1 工具按需挂载与呈现收敛

桌面“折叠”“详情 DOM 挂载”“从未来上下文隐藏”是三种行为。先核移动 ToolBlock 当前实际挂载与展开状态 owner，再决定是否借鉴桌面的折叠时释放重型详情、展开时装配。保留用户本次手动展开选择，避免终态 hash 变化重置它。

五种桌面呈现样式可作为素材，移动默认采用高密度线性结构，不需要先加入五个配置项。验收应使用大结果、多图/音视频/HTML 预览、反复折叠、流式到终态、切话题；检查实例数和资源释放，不只看 CSS 高度变小。

### B2 按钮与媒体生命周期

AI 按钮复用现有 `historyStore.sendMessage`，失败后反馈与可重试状态应有明确结果来源。不要复制第二个发送状态机，不能把本地表单按钮、系统工具按钮和“发送下一步”按钮混成一类。

音视频附件内联播放属于独立产品增量；原生文件打开已有。若接入内联播放，应同时明确只有一个播放器还是多个可并发、离屏/后台是否继续播放、消息删除时如何停止、远程资源错误如何反馈。raw HTML 媒体与附件播放器各有入口，不能只验证其中一个。

### B3 长历史布局与 HTML 会话连续性

先取得具体问题的 Android Debug 观察，再决定是否需要消息实测高度缓存、读写批处理或更细的可见性 owner。Pretext 估算不能替代含工具/图表/图片的真实高度，桌面字体、宽度和配额不照抄。

HTML 预览切换全屏/代码/主题可能重建 iframe。应按产品需要明确哪些切换值得保持计时器、输入或游戏进度；消息内 DOM 保留不代表 iframe 状态保留，更不代表话题卸载后任意 JS 状态可恢复。只为真实消费者增加保持机制。

## 4. 第三批：独立新增功能专题

| 工作包 | 可以复用的基础 | 需先解决的关键问题 | 不应误解为 |
|---|---|---|---|
| C1 Pele 图表后端 | 现有 Mermaid placeholder、全屏 Viewer、SVG/PNG 导出与主题 owner | 语法兼容与数学/图标 resolver；中文布局；同步计算预算；若要求流式需最新 revision 合并与最近成功图策略 | 桌面已实现 token 级图表增量，或 Pele 可替换整个消息 AST |
| C2 vcp-chart 引用 | 已有 HTML 隔离文档、消息生命周期、同步/CAS 基础 | chartId 对应资产如何到手机；数据源边界；离线行为；移动基线缺 moveBefore 时如何保持实例；只读/可编辑范围 | 新增一个 fence renderer 就等于完整 Chart 工作台迁移 |
| C3 raw 动画岛/Pixi | HTML preview 受控脚本能力、图片/Canvas 导出窄桥 | raw 输入怎样成为执行岛；何时启动；引擎按需加载；实例预算；隐藏暂停；销毁；内联/全屏同实例语义 | 只引入 Pixi 库或删掉 sanitizer 即兼容完成 |
| C4 完整工具结果隐藏/恢复操作 | A5 读取兼容、现有消息编辑/保存/同步与上下文组装 owner | 从移动发起隐藏/恢复时，持久化、hash、同步与两端后续上下文都要闭合 | 本地折叠偏好，或删除工具结果正文 |
| C5 上下文 checkpoint 呈现 | 移动已有总结能力、消息仓储和同步 DTO | contextCompaction 元数据是否跨端保留；哪个 owner 决定上下文起点；卡片与摘要字段契约 | 只把新消息套进现有 SummaryBlock 就已实现桌面压缩 |
| C6 气泡朗读/审批预览 | 原生 TTS/通话 owner；已有批准、拒绝和理由 | 单条朗读与通话隔离、文本投影；审批参数/diff摘要由真实事件提供 | 新建另一套语音引擎，或移动没有审批 |

C2/C3 不能复用桌面主 DOM 的真实 window/document 执行环境；现有移动 iframe 可以承载脚本和视觉，不需要转成纯文本。使用实际原生执行条件处理差异，仍遵循共享 Vue、Rust 业务 owner、平台资源收口。

## 5. 三个审视角度的综合判断

这是对本次六个并行审计结果的综合分析，未假称另运行了三位 Magi 代理，也未启动核心实现阶段。

| 角度 | 支持的方向 | 需要约束的扩大化 |
|---|---|---|
| Melchior：系统、类型与资源 | 同步修两个 Rust 解析入口；AST 保留字段；帧身份/缓存身份明确；实例/observer/timer 归已有 owner | 仅因“增量”就声称全链 O(Δ)；仅靠 100k 字符限制宣称布局有界；复制 Electron bridge |
| Balthasar：移动交互 | 高密度工具呈现、合理默认折叠、触屏图表查看、失败可重试、保留有价值输入状态 | 桌面彩虹扫光/持续流光、大卡片、内容毛玻璃、鼠标滚轮控件硬迁移 |
| Casper：工程与交付 | A 批先取得内容正确性收益；重型运行时单独专题；每包一个可观察目标 | 全部打包重写渲染器；提前建设无消费方状态框架；为截图相似复制业务状态 |

## 6. 后续验证的真实完成条件

每项实现按实际不确定性组合证据：

| 证据层 | 能回答的问题 | 不能代替 |
|---|---|---|
| 当前源码及固定 SHA diff | 当前入口/字段/所有者、何时增加或移除 | 设备效果与性能 |
| 直接生产函数/解析器样例 | 输入怎样变成 AST/CSS/HTML、chunk 边界是否改变语义 | 浏览器布局、GPU、原生权限 |
| `pnpm check` 与有针对性的现有测试 | 类型、静态规则、所覆盖的行为 | 手机滚动、触控、长时间资源表现 |
| 具名 Android Debug 旅程 | WebView 117+、窄屏/分屏、返回、图片/图表交互、后台恢复与资源观察 | 其它设备和 iOS |
| iOS 源码审计及阶段 G1/G2 | 共享前端/原生分支、Apple 编译/链接/打包 | iOS 真机性能；本项目不新增 iOS 实机测试体系 |

本次没有生产代码变化，不要求用全套构建给文档结论背书。后续任何核心/跨层实现仍按仓库规则运行 `pnpm check`，失败先解决静态错误。

## 7. 本轮建议结论

最先值得进入实施讨论的是 **A1 CSS 语义、A2 工具结果数据域、A3 JEV 呈现、A4 Markdown 结构、A5 HIDDEN 读取兼容**。Pele、v 图表和动画岛都有明确增量价值，但分别需要图表语法、资产访问和脚本生命周期方案。现有移动流式底座继续作为这些能力的承载层。
