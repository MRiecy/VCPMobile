## 2. 当前生产链的责任分布

### 2.1 桌面：同一内容运行时，分开处理稳定区、尾部和终态

```text
生产端 StreamCoordinator / 消息事实
  → 每个 Surface 的 createStreamProjection
  → operation ID 校验、初始化前缓冲、累计全文
  → 直接 dirty 合帧 / 可选平滑队列
  → 30 fps 渲染循环
      ├─ 新稳定源码范围 → full-render 预处理 → Marked → 只追加稳定 DOM
      └─ 未稳定 tail → stream-fast 预处理 / 协议封印 → Marked → morphdom
  → 生产端规范终稿
  → 停止旧帧、完整渲染一次、富内容后处理、清退流态
```

- `createStreamProjection()` 每个实例持有自己的 runtime、Map、队列与定时器。`streamProjectionRuntime.js` 用 `streamOperationId::messageId` 映射运行态，避免同 ID 的旧操作直接覆盖新操作。它是 UI 投影 owner，不拥有 durable history 的提交权。[桌面 runtime](E:/VCPChat/modules/renderer/streamProjectionRuntime.js:5)、[投影工厂](E:/VCPChat/modules/renderer/streamManager.js:17)
- `appendStreamChunk` 在进入预缓冲之前检查 operation identity；初始化未完成时最多保留最新 1,000 个 chunks，超出会丢旧 chunk。初始化完成后累计完整文本，并决定进入平滑队列还是直接标记 dirty。[接收与预缓冲](E:/VCPChat/modules/renderer/streamManager.js:2338)
- 普通/非平滑模式也不会每个网络 chunk 立刻重绘；由共同 rAF 循环以 30 fps 合帧。可选平滑模式以 `queuedChars` 计算自适应消费量，工具结果或超大块可以跳过逐字队列，避免工具源码慢慢漏出。[dirty 合帧](E:/VCPChat/modules/renderer/streamManager.js:1955)、[30 fps](E:/VCPChat/modules/renderer/streamManager.js:2151)、[突发块分流](E:/VCPChat/modules/renderer/streamManager.js:2409)
- 渲染开始重新核对当前会话签名；不属于当前视图的流不写 DOM。当前流节点丢失会触发单实例 DOM 补建；切回会话时从已有稳定块 HTML 记录恢复，不重新解析其源码。[视图与恢复](E:/VCPChat/modules/renderer/streamManager.js:1607)、[稳定块恢复](E:/VCPChat/modules/renderer/streamManager.js:583)

### 2.2 移动：Rust 定义内容和补丁，Vue 只执行已接纳的帧

```text
Rust 统一正文 / 请求输出 owner
  → StreamBlockParser：扫描闭合语义块、留住开放 tail
  → AuroraBuffer：stableAppend + TailTextOp + TailFrame
  → Tauri 交付成功后提交本次发送水位
  → chatStreamStore：流身份 / 帧游标 / baseCount / hash 校验与 rAF 归约
  → MessageRenderer
      ├─ 稳定 Rich Blocks / AST 结果
      └─ useMessageTailRenderer → AstExecutor / 局部 DOM engine
  → durable end 的完整正文与 blocks 原子接管
```

- `TailFrame` 带 `streamId / epoch / revision / frameSeq / reset / snapshot / mutations`；`AuroraUpdate` 区分 `delta` 与 `snapshot`，稳定块增量带 `baseCount`，文本追加带 `previousHash`。这比桌面纯视图 operation identity 多了 IPC 补丁的基线约束，但两者解决的问题不完全相同。[移动协议](E:/VCPMobile/src-tauri/src/vcp_modules/chat/aurora_pipeline.rs:35)
- `prepare_delta_update` 先构造待发送数据及 delivery commit，`commit_delivery` 才推进已发送水位并清空已交付 mutations。构造一次 payload 不等于消费者已经收到。[准备增量](E:/VCPMobile/src-tauri/src/vcp_modules/chat/aurora_pipeline.rs:517)、[提交交付水位](E:/VCPMobile/src-tauri/src/vcp_modules/chat/aurora_pipeline.rs:648)
- 前端先认领整个事件的 stream identity 和 TailFrame 游标，再合并 `chunk/blocks/tail`；拒绝迟到帧时不会留下“AST 被拒绝但文字仍被重复追加”的半更新。[事件接纳](E:/VCPMobile/src/core/stores/chatStreamStore.ts:1084)
- Store 接收水位与 DOM 实际应用水位分离。组件重挂、epoch 变化、快照缺失、执行器失败都沿现有恢复入口处理，不能仅以 Store 接收成功认定 DOM 已应用。[DOM 水位与恢复](E:/VCPMobile/src/features/chat/composables/useMessageTailRenderer.ts:25)

## 3. 内容流水线：哪些内容现在被明确当作独立语义域

桌面完整路径的顺序已经显式集中到 `contentPipeline.js`。它不是新的通用 AST 编译器，而是对既有处理器的顺序编排。完整渲染大体为：

1. assistant 回填注释剥离、表情 URL 规范化。
2. 保护完整思维链；扫描时先遮蔽工具结果，使工具返回里的 `<think>`、围栏和协议示例不会开启外层语义。
3. 保护工具结果，直到 Markdown 解析之后才恢复其专用 HTML。
4. 保护工具请求，并只在该域内处理 `「始」/「末」` 字段语法。
5. Mermaid 占位转换、代码域保护、Flowlock 转换、去缩进、桌面推送占位、特殊块转换。
6. HTML 封装、通用内容处理、相邻粗体边界规范化、恢复代码域。
7. Marked 解析后恢复 LaTeX 和工具结果专用渲染。

证据：[流水线入口](E:/VCPChat/modules/renderer/contentPipeline.js:158)、[思维链保护](E:/VCPChat/modules/renderer/contentPipeline.js:207)、[工具结果保护](E:/VCPChat/modules/renderer/contentPipeline.js:327)、[完整运行顺序](E:/VCPChat/modules/renderer/contentPipeline.js:458)、[Markdown 后恢复](E:/VCPChat/modules/messageRenderer.js:2016)。

`stream-fast` 则只做较轻处理，不把完整管线逐帧套回 tail。协议识别和封印仍由 `parseStreamTailMarkdown` 补充：完整工具结果先封存；再选择最早的未闭合工具块/思维链作为封印边界；最后处理未闭合代码围栏。工具结果内部的 `DESKTOP_PUSH`、`TOOL_REQUEST`、`<think>`、代码围栏都只是返回数据。[流尾入口](E:/VCPChat/modules/messageRenderer.js:2181)

### 4.1 稳定不代表完整 Markdown 文档语义已永久确定

桌面保留一个普通段落作为余量，移动则在空行处沉淀段落。这些都是应用级流式策略，不是任意 Markdown 未来输入都不可改变前文语义的证明。跨段列表、引用定义、HTML、特殊块边界需要分别核验。两端终态的完整渲染接管是必要阶段，不应为了让 streaming hash 与 final hash 相同而永久保留错误中间结构。

移动根约束本来就允许流中与终态分块/hash 不一致；代码也确实如此：有完整结果才 `replaceRenderProjection`，解析失败继续保留已经显示的尾部，不把“流结束”与“展示必须清空”绑定。[移动终态处理](E:/VCPMobile/src/core/stores/chatStreamStore.ts:1292)、[失败时继续显示 tail](E:/VCPMobile/src/features/chat/MessageRenderer.vue:159)

### 4.2 “增量”必须具体说明发生在哪一层

**桌面：**稳定块追加可避免重复重建已经固化的 DOM；但每帧仍取累计可见源码、处理消息 CSS、扫描稳定边界并解析整个 tail。代码行虽然有稳定 DOM key 和单次高亮，`parseStreamTailMarkdown` 每帧仍会 `split('\n').map(...)` 全部尾部代码行。不能把它称为全文 token parser 的 O(Δ) 实现。[可见文本/CSS](E:/VCPChat/modules/renderer/streamManager.js:1640)、[代码行字符串重建](E:/VCPChat/modules/messageRenderer.js:2254)

**移动：**稳定块增量、文本差量和 `PatchCode/PatchRawHtml` 减少 IPC 和前端重复工作；普通 Markdown tail 超过 65,536 bytes 会退出 AST 推测，先用 plain text，防止无换行巨段反复 AST 解析。代码围栏、协议封印、HtmlDoc、Thought 与 RawHtml 有不同快速路径，不能仅看这个上限就说“所有 64 KB 以上富内容都不支持”。[上限与路由](E:/VCPMobile/src-tauri/src/vcp_modules/chat/aurora_pipeline.rs:15)

尤其要保留一个限定：**移动 RawHtml 的 html5ever 仍每帧全量 parse 当前 tail。** 它随后只序列化新冻结节点和当前活跃子树，所以优势主要在传输与前端 DOM 稳定性，而不是原生 parser 从输入追加到输出全链 O(Δ)。代码也仍有尾部字符串构造/拷贝；不应把“高亮状态增量”扩大为无全量工作。[html5ever 全量 fragment parse](E:/VCPMobile/src-tauri/src/vcp_modules/chat/aurora_pipeline.rs:272)、[代码快路径](E:/VCPMobile/src-tauri/src/vcp_modules/chat/aurora_pipeline.rs:219)

## 5. 动画孤岛与冻结：桌面能力丰富，但应拆开吸收

### 5.1 流中视觉呈现与脚本真正执行是两件事

桌面裸 HTML 岛的稳定块调用 `renderPostProcessedHtml` 时明确传 `processScripts: false`；切回重建稳定块同样不执行脚本。终态完整内容默认 `processScripts: true`，避免脚本先绑定到即将删除的稳定块，终态又重复执行。[稳定块禁脚本](E:/VCPChat/modules/renderer/streamManager.js:532)、[恢复禁脚本](E:/VCPChat/modules/renderer/streamManager.js:605)、[终态脚本门](E:/VCPChat/modules/messageRenderer.js:3758)

`animation.js` 会排除 `pre/code/HTML preview/流式代码块` 内的脚本；允许裸 HTML 岛脚本在宿主内执行，并为常用 document 查询、rAF、timer、Pixi 注入局部包装。[代码域排除](E:/VCPChat/modules/renderer/animation.js:292)、[注入包装](E:/VCPChat/modules/renderer/animation.js:505)

这是一套运行时适配器，不是能够隔离所有主动执行能力的安全沙箱。它依赖部分字符串替换、IIFE 的局部变量遮蔽和被追踪实例。迁移时可复用“显示阶段/执行阶段分离”“实例归内容 owner”“移除前清理”的原则；不能用该包装替代移动当前受控富 HTML/预览的执行边界。具体 HTML、媒体与主动内容能力由专项其他章节继续展开。

### 5.2 消息级可见性调度

桌面 `createVisibilityOptimizer` 基于 chat container 的 `IntersectionObserver`，热区提前 200 px；暂停/恢复批量延迟 50 ms，脚本后的补扫描延迟 150 ms。它会管理：

- CSS/WAAPI 动画与晚出现的 `animationstart`，包括伪元素动画；
- Anime.js、Three.js、Pixi 的已登记实例；
- 受包装器管理的 rAF、timeout、interval；
- video/audio 的播放状态；
- SVG SMIL；
- GIF/WebP、Canvas 的可见性。

证据：[配置与 observer](E:/VCPChat/modules/renderer/visibilityOptimizer.js:65)、[消息动态元素登记](E:/VCPChat/modules/renderer/visibilityOptimizer.js:160)、[暂停实现](E:/VCPChat/modules/renderer/visibilityOptimizer.js:583)、[恢复实现](E:/VCPChat/modules/renderer/visibilityOptimizer.js:705)。

需要区分“暂停”“隐藏”“销毁”：视频是调用 `pause()`；GIF/WebP 是 `visibility: hidden`；Pixi 离开热区只停 ticker，保留启动配额；这些行为不能统一宣传为已经停止所有解码/GPU/JS 工作。没有设备测量就不推断电量收益。

2026-09-12 的 Pixi 接入带来更具体的资源预算：每个当前聊天根最多三个已启动气泡；首次历史加载的有效上限为一个；只淘汰热区外最老实例，不强行销毁热区内实例。这个预算可以借鉴“资源类型专门计数 + owner 释放”的思路，但数字本身是桌面策略，不能直接作为手机规格。[Pixi 配额](E:/VCPChat/modules/renderer/visibilityOptimizer.js:449)

移动当前已经有全应用后台渲染暂停、流式文字动效清退、`prefers-reduced-motion`/后台状态抑制，以及 `content-visibility:auto`。本次没有在移动消息主链找到覆盖桌面全部上述资源类型的统一每消息可见性运行时。两者不是简单的“移动完全没有冻结”。[应用暂停](E:/VCPMobile/src/core/composables/useAppLifecycle.ts:56)、[消息动效准入](E:/VCPMobile/src/features/chat/MessageRenderer.vue:99)、[本机 content-visibility](E:/VCPMobile/src/features/chat/MessageRenderer.vue:1157)

### 5.3 流式动画不是新增语法能力

桌面代码完成行可播放彩色扫光，持续 2,400 ms，最多三行并发；普通块可用可配置动画预设和时长；平滑队列又是另一层体验控制。它们不是解析正确性的一部分。[代码扫光与限额](E:/VCPChat/modules/renderer/streamManager.js:1501)、[块动画](E:/VCPChat/modules/renderer/streamManager.js:1838)

移动已经有 AST append 驱动的文本渐显及块 reveal，且结构 mutation 会先清理临时动画片段，避免临时 span 干扰 DOM 基线。[移动执行帧动效](E:/VCPMobile/src/core/utils/astExecutor.ts:1149) 因项目要求内敛、技术精确、灰度优先，不建议为对齐桌面而引入 2.4 秒彩虹扫光、大幅 slide 或更多动效设置。

## 6. Pretext 与长历史：新改进是调度和高度所有权

Pretext 在桌面早于本轮新增窗口：`dda4801c / d87c3e4d` 为 2026-04-02 接入，后续依赖和适配持续更新。它对纯文本执行 `prepare + layout` 估算高度，缓存 text/width/lineHeight；真正的消息布局仍由浏览器 DOM 决定。[Pretext bridge](E:/VCPChat/modules/renderer/pretext-bridge.js:95)

当前 `scheduleMessagePretextEstimate` 主动跳过工具协议、图片、表格、媒体、Canvas、SVG、iframe、style/script、代码围栏等结构内容。它只 warm 纯文本估算，不把结构化消息伪装成纯文本高度。`visibilityOptimizer` 则读取真实 `offsetHeight`，写入 `containIntrinsicSize`。[结构化内容跳过](E:/VCPChat/modules/messageRenderer.js:4368)、[真实高度](E:/VCPChat/modules/renderer/visibilityOptimizer.js:333)

值得关注的 10 月新改进有两个：

1. **批量测量先读后写。** 10 月 2 日 `38842628` 将历史多消息高度登记汇入一帧；10 月 3 日 `4e82b2c3 / a903a038 / 78e92eb5` 补上取消、generation、owner 与重入登记。`flushHeightMemory` 先收集全批次读值，再写样式，避免每条消息“读 layout → 写 style → 下一条再读”引发重复同步布局。[批量高度实现](E:/VCPChat/modules/renderer/visibilityOptimizer.js:359)
2. **Pretext 的 idle 队列按窗口合并。** `b70a3be7`（2026-10-07）把每消息一个 idle callback 合并为每窗口一个队列；按 idle deadline 分片，同节点重渲染覆盖旧 job；消息清理删除未执行 job。[Pretext 队列](E:/VCPChat/modules/messageRenderer.js:4396)

移动已有浏览器原生 `content-visibility:auto; contain-intrinsic-size:auto 100px`。可评估的方向是需要时加入移动自己的实测高度/批处理所有权，不是直接移植桌面 Segoe UI、Consolas、80% 气泡宽度、880/560 px 等估算常量。宽度、字体、折叠块、图片解码和手机滚动锚点才是需要设备证据的问题。Pretext 也不能解决 Markdown 解析、图表绘制或 WebGL 实例清理。

## 7. 并发、恢复与清理：已有保障和不能过度承诺的部分

### 7.1 桌面已经明确的保障

- 消息 stream identity 在预缓冲之前检查；surface 有独立运行态；当前视图签名变化会失效缓存。[接纳身份](E:/VCPChat/modules/renderer/streamManager.js:2338)、[视图签名](E:/VCPChat/modules/renderer/streamManager.js:1607)
- 终态使用每消息 token 防止重复并发投影。入口先删除该消息的帧任务；等初始化/DOM 恢复退出后，用生产端 `fullResponse` 优先接管，不按字符串长度猜权威内容；没有可用终稿才回退 renderer 累计文本。[终态入口](E:/VCPChat/modules/renderer/streamManager.js:2443)、[终态 token](E:/VCPChat/modules/renderer/streamManager.js:2677)
- 内容后处理有内容节点 revision，异步附件/Mermaid 恢复后核对 revision、连接状态和可选 render session；写新 HTML 之前先释放预览、动画、媒体、大工具结果等旧资源。[后处理 revision 与 cleanup](E:/VCPChat/modules/messageRenderer.js:3656)
- 消息卸载取消观察、动态扫描、timer、rAF 队列并释放 Three/Pixi/WAAPI；surface dispose 取消全部已登记帧/timeout，并等待已追踪异步操作退出。[可见性卸载](E:/VCPChat/modules/renderer/visibilityOptimizer.js:1045)、[投影 dispose](E:/VCPChat/modules/renderer/streamManager.js:2728)

### 7.2 桌面仍需按真实范围解释的限制

1. **预缓冲数量有上限，不等于所有内存都有上限。** 普通活动流仍累计完整文本，稳定记录保留 source 与 HTML，平滑队列也持有待显示片段。代码没有使整条巨大消息变成恒定内存；“1,000 chunks 上限”只描述初始化前那个数组。
2. **morphdom 失败回退用同一份已经封印的 raw HTML 重建 tail。** 这避免工具请求等待回执期间永远空白，但会失去该 tail 子树的局部 DOM 身份；它是可用性兜底，不是 diff 成功。[失败同帧重建](E:/VCPChat/modules/renderer/streamManager.js:1863)
3. **稳定块完整性仍是策略。** HTML 岛扫描有 128 层/256 KiB 限制；正常块沉淀不会证明所有恶意或畸形未来输入安全。可信 role 结束行跳过前方词法结构是明确的协议假设，不能扩展为通用安全隔离。[限制常量](E:/VCPChat/modules/renderer/streamManager.js:51)、[可信结束行](E:/VCPChat/modules/renderer/streamManager.js:1041)
4. **脚本包装与资源清理依赖被追踪接口。** 不能凭 IIFE、字符串替换、`isConnected` 和若干 API wrappers 声称任意脚本、所有第三方实例、所有外部监听都可撤销。内联脚本仍在宿主环境插入执行。[执行点](E:/VCPChat/modules/renderer/animation.js:520)
5. **稳定块异步后处理不是每个都并入同一个全局 await 链。** 稳定块追加只给 enrichment Promise 安装 `.catch()`，其失效主要依靠后处理内部 revision/isConnected；不能把 `dispose()` 等待 `pendingAsyncOperations` 表述为等待任意第三方异步全部完成。[稳定 enrichment](E:/VCPChat/modules/renderer/streamManager.js:532)
6. **终态路径内部有多次 await，当前视图判定是在前段捕获的。** renderer 内部连接/revision 防线能拒绝部分旧结果，但本文没有运行导航/补建/终态交错序列，因此不认定所有交错竞态都已闭合，也不将源码疑点写成已经复现的串话题 Bug。[终态 await 与判定](E:/VCPChat/modules/renderer/streamManager.js:2494)

### 7.3 移动现有保障应保留

- 组件 sandbox 重挂会清理 registry、重建 AST 快照并认领当前帧，避免补丁二次应用；同一 stream/epoch 才比较 frameSeq。[sandbox 重挂](E:/VCPMobile/src/features/chat/composables/useMessageTailRenderer.ts:177)
- 帧执行在首个 mutation 失败时停下并返回已执行个数/原因，然后请求恢复快照；连续恢复失败可以关闭 AST diff、继续现有 tail 展示。该帧并不进行事务式 DOM 回滚，所以快照恢复而非“所有 mutation 原子成功”才是准确保证。[执行失败语义](E:/VCPMobile/src/core/utils/astExecutor.ts:1162)、[恢复/降级](E:/VCPMobile/src/features/chat/composables/useMessageTailRenderer.ts:73)
- RawHtml patch 核对冻结数量和实际 childNodes，失配交给恢复入口；不是无限相信后端补丁。[冻结 frontier 校验](E:/VCPMobile/src/core/utils/astExecutor.ts:733)
- `durable end` 先清理 rAF 更新，覆盖正文，完整 blocks 接管后再移除活动流；终态编译失败保留已经显示内容。[终态 owner](E:/VCPMobile/src/core/stores/chatStreamStore.ts:1292)
- 消息 owner 随整条消息存活，气泡拆分不重置尾部恢复；unmount 清 registry/Thought tail，消息自身 abort 重后处理。[卸载](E:/VCPMobile/src/features/chat/composables/useMessageTailRenderer.ts:262)、[消息重处理取消](E:/VCPMobile/src/features/chat/MessageRenderer.vue:949)

## 9. 建议的后续收敛顺序

### A. 优先核对协议正确性，不替换架构

1. 围绕真实工具返回示例，统一核对完整解析与流解析的工具结果嵌套配对、代码域/思维链/角色标记优先级。桌面 9 月 30 日的行为有明确生产价值；移动需从 Rust parser 的 owner 处实现。
2. 核实 CRLF 与空白空行进入移动正文的实际路径。若未统一规范化，修正文段沉淀扫描的规则与增量续扫窗口；不要仅为了测试加入一层重复文本副本。
3. 对可信 `END_ROLE_DIVIDE_USER` 封口，先说明该行由谁产生、工具载荷能否包含字面同名行、终态如何解释畸形未闭合域，再决定是否需要。不能把“强制推进稳定区”当通用修复。

### B. 按实测决定性能工作

1. 长历史、工具折叠、图片解码、代码/HTML 巨尾分别观察耗时；native parse、IPC bytes、JS DOM、layout/paint 分开记账。
2. 需要缓存高度时，复用移动已有消息/滚动 owner，采用批量先读后写、取消和 generation；不默认引入桌面估算字体和宽度常量。
3. 新增 Pixi/其他动态富内容之前，先有消息级 owner、热区预算、背景暂停、重入与卸载路径；资源数字由手机/平板证据决定。

### C. 保留移动现有优势与边界

- 保留 Rust AST + TailFrame + Vue DOM executor，不引入平行的 Marked/morphdom 全尾主链。
- 保留 `streamId/epoch/frameSeq`、交付水位、恢复快照和失败保留内容；不以全量重渲染掩盖补丁身份错误。
- 保留 Thought 外壳、受控 HTML、移动自己的平滑偏好和 reduced-motion；不照搬宿主 script 执行、彩虹扫光和桌面屏幕布局。
- 图表在活动 tail 连续绘制属于独立图表生命周期改造。应与既有 Pele 专项合并判断，不能包装成“追平桌面 MoonAST”。
