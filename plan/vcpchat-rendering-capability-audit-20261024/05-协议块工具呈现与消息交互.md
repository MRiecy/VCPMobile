## 3. 工具请求：常规字段与 JEV

### 3.1 输入形式

```text
<<<[TOOL_REQUEST]>>>
tool_name:「始」ExampleTool「末」
command:「始」ReadFile「末」
path:「始」src/example.ts「末」
<<<[END_TOOL_REQUEST]>>>

<<<[TOOL_REQUEST]>>>
JEV:「始」请用 'ExampleTool' 完成 {联网搜索}，然后整理结果。「末」
<<<[END_TOOL_REQUEST]>>>
```

桌面 `readToolRequestField()` 按字段声明扫描并越过完整前序载荷，避免在参数正文中误取伪字段；起始/结束标记不依赖独占一行，但会排除代码域和工具结果域。普通字段支持 `「始」/「末」`、`{始}/{末}` 与 ESCAPE 对。`tool_name` 也保留 XML 兼容。见 [toolRequestScanner.js:18](E:/VCPChat/modules/renderer/toolRequestScanner.js:18)、[127](E:/VCPChat/modules/renderer/toolRequestScanner.js:127)、[364](E:/VCPChat/modules/renderer/toolRequestScanner.js:364) 和 [messageRenderer.js:1273](E:/VCPChat/modules/messageRenderer.js:1273)。

移动端已有独立的字段边界扫描；不能说它仍用简单正则截断所有请求参数。`find_tool_request_end()` 跳过字段内部的结束标记，`extract_tool_name_value()` 支持字段/XML，标记模式还包括 `exp`。不同之处在于请求外壳需行首、且无 JEV 元数据分支。见 [content_parser.rs:343](E:/VCPMobile/src-tauri/src/vcp_modules/chat/content_parser.rs:343)、[1022](E:/VCPMobile/src-tauri/src/vcp_modules/chat/content_parser.rs:1022)、[1050](E:/VCPMobile/src-tauri/src/vcp_modules/chat/content_parser.rs:1050)。

### 3.2 JEV 显示身份

桌面 `parseJevToolUse()` 只做呈现：原始 JEV 文本保留，不把自然语言翻译为旧工具参数。显示名优先级为单引号/反引号/中文引号内显式名称，其次 `{能力}`；没有这些形式但存在非空 JEV 字段，也构成合法 JEVToolUse，标题可以没有名称。见 [jevToolUse.js:21](E:/VCPChat/modules/renderer/jevToolUse.js:21)。普通 tool_name 路径与 JEV 路径并存，DailyNote 专用展示优先；实际选择见 [messageRenderer.js:1212](E:/VCPChat/modules/messageRenderer.js:1212)、[1254](E:/VCPChat/modules/messageRenderer.js:1254)。

移动端 `ContentBlock::ToolUse` 只携带 `tool_name/content/is_complete`，解析无工具名时固定返回 `Processing...`；终态同样调用这条分支。因此一个完整、合法、只有 JEV 字段的桌面工具请求，会在移动显示普通工具卡和这个回退名称，而不是 JEV 身份。见 [content_parser.rs:748](E:/VCPMobile/src-tauri/src/vcp_modules/chat/content_parser.rs:748)、[1064](E:/VCPMobile/src-tauri/src/vcp_modules/chat/content_parser.rs:1064)、[ToolBlock.vue:149](E:/VCPMobile/src/features/chat/blocks/ToolBlock.vue:149)。这不是数据丢失，但会把已完成请求显示得像仍在解析。

桌面另有畸形字段提示：未识别 tool_name 或字段标记损坏时说明问题；JEV 本身可替代 tool_name 身份，不因其缺失报错。见 [toolRequestMarkers.js:37](E:/VCPChat/modules/renderer/toolRequestMarkers.js:37)。移动缺少对应提示。若移植，应表达“请求文本解析结果”，不能把前端推断包装成服务端真实执行结果。

### 3.3 流式到终态

桌面未闭合请求进入 sealed 文本尾部，不执行参数中的 HTML；闭合后生成工具卡，详情按需挂载。工具字段正文输出处统一转义一次，避免 `&#039;` 字面量和 `<pre>` 换行干扰后文。见 [messageRenderer.js:2220](E:/VCPChat/modules/messageRenderer.js:2220)、[1292](E:/VCPChat/modules/messageRenderer.js:1292)、[125](E:/VCPChat/modules/messageRenderer.js:125)。移动流式块与终态解析共用字段提取和 DailyNote 判断，未闭合特殊块的终态容错则降为普通 Markdown。见 [stream_block_parser.rs:788](E:/VCPMobile/src-tauri/src/vcp_modules/chat/stream_block_parser.rs:788)、[content_parser.rs:720](E:/VCPMobile/src-tauri/src/vcp_modules/chat/content_parser.rs:720)。

## 4. 工具结果：完整数据域、内容样式和上下文隐藏

### 4.1 数据域与嵌套标记是首要兼容项

```text
[[VCP调用结果信息汇总:
- 工具名称: ExampleTool
- 执行状态: success
- 返回内容: 工具读取到的一段源码如下：
[[VCP调用结果信息汇总:
这里是源码中的字面量
VCP调用结果结束]]
这行仍是外层工具结果
VCP调用结果结束]]
```

桌面对起始标记加深度、结束标记减深度，深度回零才闭合最外层结果；未闭合结果占有当前流尾。结果中的 TOOL_REQUEST、DESKTOP_PUSH、think、围栏和结束符均不应重新取得外层协议身份；代码域计算使用结果区的等长遮蔽文本。见 [toolResultRegions.js:25](E:/VCPChat/modules/renderer/toolResultRegions.js:25)、[65](E:/VCPChat/modules/renderer/toolResultRegions.js:65)、[134](E:/VCPChat/modules/renderer/toolResultRegions.js:134)。完整流水线在 Markdown parse 前保护结果，parse 后恢复其独立渲染，见 [contentPipeline.js:471](E:/VCPChat/modules/renderer/contentPipeline.js:471)、[499](E:/VCPChat/modules/renderer/contentPipeline.js:499)。注意流水线表面先保护 Thought，但其扫描同样排除结果区，不能仅凭调用顺序认定 Thought 高于工具数据域。

移动终态入口只先识别 VoiceGuidance，再进入按源顺序扫描的 `MASTER_START`；工具结果闭合使用 `TOOL_RESULT_END.find(search_area)`，流式使用 `find_at(search_area, scan_from)`，两者没有嵌套深度。上述内嵌标记例子会被首个行首结束符提前定界。见 [content_parser.rs:536](E:/VCPMobile/src-tauri/src/vcp_modules/chat/content_parser.rs:536)、[571](E:/VCPMobile/src-tauri/src/vcp_modules/chat/content_parser.rs:571)、[687](E:/VCPMobile/src-tauri/src/vcp_modules/chat/content_parser.rs:687) 和 [stream_block_parser.rs:699](E:/VCPMobile/src-tauri/src/vcp_modules/chat/stream_block_parser.rs:699)。这是源码可确定的定界规则差异；本次未执行设备样本，不能进一步声称所有 UI 错位或后续业务副作用已复现。

若实施，应首先以“工具返回源码含有同名协议常量”“工具返回 Markdown 围栏跨过协议标记”“增量分片落在内层结束符前后”为真实不确定性，核对增量和终态共同的数据域，而不只是增加一个 UI 特判。普通消息中的引用/代码示例仍需保持原有字面量语义。

### 4.2 详情渲染并非两端完全相同

桌面仅将指定 Markdown 字段交给安全 Markdown；图片 URL 有专门入口，其余字段做转义和链接化，footer 是转义的 `<pre>`。危险/完整 raw HTML 不走消息正文的主动渲染管线。超过 50,000 字符的 Markdown 字段先取 80 行，点击再展开全部；这是字符阈值，源码注释“50KB”不能当作精确字节保证。见 [messageRenderer.js:468](E:/VCPChat/modules/messageRenderer.js:468)、[2374](E:/VCPChat/modules/messageRenderer.js:2374)、[2387](E:/VCPChat/modules/messageRenderer.js:2387)、[2435](E:/VCPChat/modules/messageRenderer.js:2435)。

移动 `ToolBlock` 对全部普通详情值和 footer 执行 `marked.parse → withCodeBlockClass → filterTrustedRichHtml`；图片支持 HTTP URL 和 base64 data URI；有逐字段复制、全屏查看、复制全部。见 [ToolBlock.vue:21](E:/VCPMobile/src/features/chat/blocks/ToolBlock.vue:21)、[126](E:/VCPMobile/src/features/chat/blocks/ToolBlock.vue:126)、[182](E:/VCPMobile/src/features/chat/blocks/ToolBlock.vue:182)、[215](E:/VCPMobile/src/features/chat/blocks/ToolBlock.vue:215)。因此“移动工具结果没有 Markdown/图片/详情”是错误判断；真正差异是域边界、字段策略、体积和生命周期。

桌面折叠的详情不参与活动 DOM，展开才加载，收起清理图片、媒体、预览及完整内容引用。移动 `v-show="isExpanded"` 仅隐藏现有节点，全部字段仍遍历/解析；缓存最多 50 条并非按字节有界。见 [messageRenderer.js:125](E:/VCPChat/modules/messageRenderer.js:125)、[ToolBlock.vue:18](E:/VCPMobile/src/features/chat/blocks/ToolBlock.vue:18)、[175](E:/VCPMobile/src/features/chat/blocks/ToolBlock.vue:175)。长输出和 base64 场景值得优先取得移动性能样本，避免一味增加折叠布局却不减少渲染工作。

### 4.3 `[HIDDEN]` 是上下文控制，不是折叠

```text
[[VCP调用结果信息汇总: [HIDDEN]
- 工具名称: ExampleTool
- 执行状态: success
- 返回内容: 仍保留在历史中的完整内容
VCP调用结果结束]]
```

桌面还识别 `<!--HIDDEN-->`、`(HIDDEN)` 及若干“注入上下文: 隐藏”元数据形式。点击眼睛按钮修改原文标记并保存历史，重新渲染显示“已隐藏”；恢复时移除标记。流式/思考中禁止变更。定位使用结果序号和原文 hash，不靠工具名称猜测实例。见 [toolResultRegions.js:160](E:/VCPChat/modules/renderer/toolResultRegions.js:160)、[messageRenderer.js:2347](E:/VCPChat/modules/messageRenderer.js:2347)、[2501](E:/VCPChat/modules/messageRenderer.js:2501)、[2530](E:/VCPChat/modules/messageRenderer.js:2530)。

上下文剔除实际接在单聊组装和主进程请求路径： [singleChatRequestOrchestrator.js:185](E:/VCPChat/modules/chat/singleChatRequestOrchestrator.js:185)、[chatHandlers.js:1234](E:/VCPChat/modules/ipc/chatHandlers.js:1234)。它既节省后续上下文，又保留历史内容；不是“看不见就不发送”的 UI 推断。

移动生产代码未发现上述隐藏标记的消费路径，`context_assembler` 对 assistant 历史只剥离 voice-guidance，然后继续加入正文，见 [context_assembler.rs:166](E:/VCPMobile/src-tauri/src/vcp_modules/chat/context_assembler.rs:166)。因此桌面隐藏结果同步到移动后，**按当前组装路径不会获得桌面的排除语义**。即使暂不提供隐藏按钮，也应先决定历史协议的读取/上下文兼容；只给卡片加隐藏徽章不足以闭环。

## 5. 工具呈现器与折叠策略

桌面新增 `createToolPresentation()` 在原协议节点上装饰，不改工具执行模型。全局 `appearanceProfile.toolPresentation` 默认 `legacy`、`toolExpansion` 默认 `attention`；只有 `data-ui-mode="next"` 才启用其他布局。会话 Agent/Group 可以覆盖；群成员个人设置不替代会话 owner。见 [appSettingsManager.js:288](E:/VCPChat/modules/utils/appSettingsManager.js:288)、[toolPresentation.js:119](E:/VCPChat/modules/renderer/toolPresentation.js:119)、[150](E:/VCPChat/modules/renderer/toolPresentation.js:150)。

| 模式 | 真实行为与边界 |
| --- | --- |
| `legacy` | 保留原有卡片；新呈现器恢复原 header，不套用新布局规则 |
| `compact` | 每个请求/结果/摘要成为紧凑行，可展开；请求与结果仍独立 |
| `grouped` | 连续工具节点归组；正文、真实角色分界和其他组件截断分组 |
| `inline` | 紧邻且同名的请求/结果视觉配对；连续读取/搜索归“查阅”、命令归“终端” |
| `process` | 仅终态、至少两条调用、首尾工具同父节点时，将两者间过程含中间正文收为一行，最终回答留外面 |

## 6. Thought、Diary、摘要和语音指导

### 6.1 Thought：基础能力已具备，域语义需核对

## 8. 通知、审批与系统错误

### 8.1 审批增强属于通知投影

桌面 `tool_approval_request` 可显示文件路径、AI 理由、`changePreview` 和按 ProjectForge 命令推导的具体影响，支持 diff、更多行提示及“审计”弹窗；批准/拒绝附最多 1000 字理由。已处理项移除操作控件，显示已允许/拒绝/过期，再切为 resolved 归档。见 [notificationRenderer.js:583](E:/VCPChat/modules/notificationRenderer.js:583)、[848](E:/VCPChat/modules/notificationRenderer.js:848)、[887](E:/VCPChat/modules/notificationRenderer.js:887)、[1038](E:/VCPChat/modules/notificationRenderer.js:1038)。自动批准规则也在通知业务路径中，不属于渲染兼容范围。

### 8.2 通知正文折叠

桌面 `collapseFloatingNotifications` 与 `collapsePanelNotifications` 分别控制浮动通知和面板通知，只有设置严格为 true 才生效，缺失默认关；当前实例通过 `notificationExpanded` 覆盖，`collapseExempt` 可豁免。折叠后的右键菜单提供“展开通知”。见 [filterManager.js:649](E:/VCPChat/modules/filterManager.js:649)、[notificationRenderer.js:13](E:/VCPChat/modules/notificationRenderer.js:13)、[29](E:/VCPChat/modules/notificationRenderer.js:29)。移动通知正文当前直接展示，不存在同等默认折叠控制；若需要应采用明确触控展开，不照搬右键入口。

### 8.3 系统错误不是 Markdown 新语法

桌面 system 消息采用单行 notice 布局，`notice='error'` 选择错误图标和样式；失败请求只生成一条消息还涉及请求归约，不是单纯改 CSS。见 [domBuilder.js:153](E:/VCPChat/modules/renderer/domBuilder.js:153)、[mainChatSurfaceAdapter.js:92](E:/VCPChat/modules/renderer/mainChatSurfaceAdapter.js:92)。移动本次未发现同名 `notice` 消息契约，但这不足以判定其错误反馈缺失；移动已有通知、流状态和失败处理。若统一错误呈现，应从各自实际失败 owner 审计一次终态和重复反馈，不能要求照搬桌面 DOM 模型。

## 10. 建议次序与后续验证问题

1. **P1：工具结果数据域。** 先核对嵌套标记、源码字面量、围栏和半截分片，统一流式/终态的定界认识；这比样式追平更直接影响内容完整性。
2. **P1：JEV 请求识别。** 保留原文，补显示身份和名称优先级；支持纯自然语言 JEV；不把它转成旧工具调用，也不与 JEV 群调度混用。
3. **P1：`[HIDDEN]` 读取与上下文语义。** 对桌面历史做到显示与后续上下文行为可解释；是否新增移动操作按钮再独立决定。需要核对单聊、群聊、重新生成、语音会话等真实上下文入口。
4. **P1/P2：长工具详情。** 用多字段长文本、超长单行 JSON、base64 图片和反复展开/收起样本测量解析、DOM、内存和滚动成本。候选为按需挂载和明确展开全部，而非仅改变 `display`。
5. **P2：高密度呈现。** 可优先取紧凑请求/结果摘要、失败/待确认展开；保留手动展开状态及原始块身份。调用数只表明可见请求记录，不宣称真实完成数。
6. **P2：审批结构化预览与通知折叠。** 复用已有 notification owner 和 approve/reject/reason 回传，补可审阅详情；不顺带建设自动批准规则。
7. **按需求另议：气泡朗读、转发、分支、侧栏提问、Flowlock 执行、桌面画布。** 这些都有独立业务所有者、生命周期与产品边界，不能以“整理渲染新增”直接获得实现授权。
