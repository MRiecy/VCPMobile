# 04. 消息强渲染能力保护契约

## 1. 目的

消息气泡不是普通文本列表，而是 VCPMobile 的核心工作台。性能与兼容工程必须证明“同一内容仍能完整表达和交互”，不能用删能力、隐藏块或纯文本替换来换取指标。

本文件是专项施工的硬门禁。若某个候选与本契约冲突，候选自动否决，无需再比较性能数字。

## 2. 必须保留的能力面

| 能力 | 当前主要实现 | 不可退化条件 |
|---|---|---|
| Markdown 结构 | Rust AST/blocks + `astRenderer` | 标题、列表、引用、表格、链接、分隔线等语义完整 |
| 代码与高亮 | 后端 `highlighted_html` + code block | 语言、换行、横向滚动、复制与高亮完整 |
| KaTeX | 占位符 + 动态 `import('katex')` | inline/display 公式、MathML/字体、错误隔离完整 |
| Mermaid | 动态 import、缓存、全屏 viewer | 当前产物支持的图类型、SVG、缩放/全屏、错误提示完整 |
| raw/trusted HTML | `filterTrustedRichHtml` + `v-html` | 视觉结构、SVG/MathML和允许交互完整；现有主动内容防护不得削弱 |
| HTML Preview | 独立 `HtmlPreviewBlock` | 完整预览、流式状态、全屏与安全边界完整 |
| Tool/Thought/Summary | 专用 Vue block | 展开态、流式态、结果与错误语义完整 |
| Diary/DailyNote | `DiaryBlock` 及更新语义 | 创建/更新块、替换目标和交互完整 |
| 附件 | `AttachmentPreview` 与 Viewer | 图片/文件、打开、下载/分享与错误完整 |
| 多气泡结构 | `messageBubbles` | 一条消息内角色/分段关系不被拍平 |
| 流式增量 | 30 Hz 合帧、AST mutation、snapshot fallback | 不丢字、不重复、不乱序，最终 blocks 与后端一致 |
| 后台恢复 | hidden WebView 快照收敛 | 回前台单帧追平，不回放无界 mutation |
| 消息历史 | 分页、500 条数据窗口 | 数据不静默丢失，scroll anchor 和当前会话 owner 正确 |

## 3. 渲染不变量

### R-01：最终语义一致

相同后端 final blocks 输入，优化前后应得到相同的可见文本、块类型、层级、链接目标、代码、公式源、Mermaid 源、附件和工具状态。允许 DOM 因懒加载 wrapper 或无障碍改进产生非语义差异，不允许内容消失或换成摘要。

### R-02：流式收敛一致

无论增量 mutation 如何分帧，终态必须与后端最终 blocks 一致。取消、断网、后台冻结、snapshot reset、组件卸载重挂和同消息重新生成都必须收敛到当前 generation，旧异步任务不得覆盖新内容。

### R-03：能力不按设备关闭

旧 WebView 可以缺少 blur、mask 流光、`color-mix` 和 `content-visibility` 加速，但不能因此关闭公式、图表、HTML、代码或专用块。若目标引擎无法执行项目的核心 JS 语法，应通过明确支持政策或构建 target 处理，不能运行一个功能残缺分支。

### R-04：异步资源必须离线可得

代码分包后的 KaTeX、Mermaid、Block 和字体仍必须打入 APK，在无网络环境首次打开即可加载。异步失败不得低于当前基线：必须有局部错误或可诊断状态，不能变成永久空白；若候选改变 loader 生命周期，再为该 loader 设计显式重试，不把当前尚不存在的重试能力伪装成基线。

### R-05：安全边界不倒退

当前 `filterTrustedRichHtml` 会保留富 HTML，同时过滤直接进入宿主能力的主动内容入口；HtmlPreview 有独立边界。性能项目不得跳过过滤来减少耗时，也不得借性能名义扩大 active content。反过来，任何未来安全策略调整也应单独评审，不能静默把丰富内容全量纯文本化。

### R-06：状态与交互可恢复

离屏卸载或懒挂载不得破坏 Tool/Thought 展开态、Diary 操作态、Mermaid 全屏入口、附件 viewer、文本选择、当前焦点、scroll anchor 和可访问名称。若某类状态无法可靠保存，该组件暂不进入窗口化。

## 4. 允许与禁止的优化

| 允许 | 条件 | 禁止 |
|---|---|---|
| 动态 import 稀有 Block | APK 离线可用，首次出现可加载 | 永久不注册该 Block |
| KaTeX/Mermaid/CSS 按需加载 | 资源 ready 后完整绘制，失败不低于当前错误状态；新 loader 应可重试 | 在旧机上改成源代码/纯文本 |
| 同帧合并重复 render 请求 | 终态强制 flush，generation 校验 | 任意降低内容更新频率来隐藏卡顿 |
| feature hint 跳过无关 DOM 扫描 | hint 只能证明“不包含该能力” | 靠正则猜测并漏掉合法内容 |
| 缓存与增量 LRU | key 包含内容版本，失效正确 | 缓存串用导致旧 HTML |
| 离屏 DOM 窗口化 | 数据、尺寸、状态、锚点可恢复 | 删除历史消息或只保留摘要 |
| 视口优先调度 | 滚入前提升优先级，最终全部完成 | 永久不渲染离屏强内容 |
| 装饰 fallback | 结构、语义、对比度不变 | 用 display:none 隐藏不兼容块 |
| skeleton/占位 | 高度稳定且有完成/错误状态 | 提前报 READY 后长期空白 |

特别禁止以下“伪优化”：

- 关闭 AST diff、KaTeX、Mermaid、代码高亮或 raw HTML；
- 把 Tool/Thought/Diary 变为不可交互文本；
- 只测空欢迎页并据此宣布首屏达标；
- 把复杂消息延迟到用户滚动后，却没有完成保证和错误状态；
- 通过缩短历史数据窗口、丢附件或降图片质量掩盖内存问题；
- 用现代机平均值抵消旧机失败。

## 5. 标准强渲染 fixture

建议新增一个可版本化的五消息数据集 `StrongRenderingFixtureV1`，由固定 final blocks 和固定流式帧序列组成；能力可跨五条消息分布，合计至少包含：

1. 中文与英文段落、emoji、链接、引用和多级列表；
2. 宽 Markdown 表格与超长不换行 token；
3. Rust/TypeScript/JSON 代码块、行内代码和复制；
4. inline/display KaTeX、矩阵、错误 LaTeX；
5. Mermaid flowchart、sequence、class/ER、含中文标签的图；另由构建清单或参数化契约测试保证当前可分包加载的其他图类型没有被 tree-shake/漏打包，设备 fixture 选代表类型而非制造一条超级消息；
6. SVG、MathML、允许的 trusted raw HTML 与被防护的主动内容样本；
7. Tool use/result、Thought、Tool summary；
8. Diary create/update；
9. 图片与普通附件；
10. 一条消息多 bubble；
11. 流式未闭合 Markdown/HTML、reset snapshot、取消与最终 blocks；
12. 后台 2 秒后恢复、组件卸载重挂、cache hit/miss。

不建议对整个生成 DOM 做逐字节快照：KaTeX/Mermaid 可能产生动态 ID，OEM 字体也影响截图。应使用多层 oracle。

## 6. 等价性验收

### 6.1 语义 oracle

- 每个输入 block 对应的渲染组件类型和数量；
- 可见文本、代码、公式源、Mermaid 源和链接属性；
- active-content guard 的危险属性被移除，允许结构保留；
- final blocks 与流式终态的规范化结构一致；
- 所有异步资源 Promise 最终 settled，无遗留占位符。

### 6.2 交互 oracle

- Tool/Thought 展开、Diary 操作、代码复制；
- Mermaid 全屏、缩放、关闭；
- 附件打开与返回；
- 链接策略、文本选择和长按；
- 键盘打开时输入框与最后一条消息仍可见；
- 上翻分页前后 scroll anchor 不跳。

### 6.3 视觉 oracle

- 手机、平板 portrait/landscape 的截图；
- 普通主题和至少一个高对比主题；
- 允许字体抗锯齿与动态 Mermaid ID 差异；
- 不允许裁切、重叠、透明文字、表格/代码撑破 shell、公式未着色、图表空白。

### 6.4 性能 oracle

- 普通消息不应加载 KaTeX/Mermaid JS；
- 公式/图表首次加载不能出现 >门禁阈值的长期主线程阻塞；
- 稳定块更新次数、DOM 查询次数和 renderer long task 相比基线不增加；
- 100+ 富消息滚动后 layer count、RSS 和帧时间回到稳定范围；
- 性能改善必须在正确性门禁全部通过后才计入。

## 7. 异步 owner 与缓存约束

KaTeX/Mermaid/图片/异步 Block 的结果提交前必须能证明结果仍属于当前组件与内容版本。推荐的语义身份为：

```text
messageId + block revision + mounted element owner
```

旧任务完成时，如果元素已被 Vue 替换、消息已切换、block hash 已变化或组件已卸载，结果只可丢弃，不能写回新 DOM。当前 Mermaid 已检查 element containment，并有 cache/in-flight 去重；优先用组件局部 revision token 扩展这一所有权。只有竞态测试证明仍会跨会话串写时，才加入 conversation epoch，而不是预先冻结四字段框架或建立另一套全局 renderer。

HTML cache 当前达到 500 项后整表清空。若 trace 发现周期性重算，可改为同容量增量 LRU：每次命中刷新顺序，超限只淘汰最旧 key；`clearMessageCache` 与全量清理语义保持不变。没有 trace 证据时不优先施工。

## 8. 性能工程完成定义

只有同时满足以下条件，才能说“在不牺牲强渲染的前提下完成优化”：

- 三类启动 fixture 和三类目标设备的正确性全通过；
- 强渲染语义、交互和视觉 oracle 全通过；
- median 与 p95 改善超过基线噪声，且 RSS、长帧、错误率无退化；
- 旧 WebView 只失去可选装饰，不失去 L0—L2 能力；
- 无永久 feature flag、无设备 UA 分叉、无未归属的异步任务；
- 失败候选已完整回滚，文档记录证据而不是保留半套路径。
