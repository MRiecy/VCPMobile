## 2. 对附件假设的修正

`v-memo` 失效只表示需要重新计算相应 VNode，不等于一定清空 DOM；真正需要对齐的是展示粒度、身份和输出。终态全量更新权威数据，与复用相同的展示对象并不冲突；识别变化时仍按终态重新展示。

不能直接用 `node.hash` 作为内容相等的证明。Rust u64 进入 JS number 后可能丢精度，同文重复段落也需要独立身份。当前实现按气泡、节点类型/hash和出现次序选取上一轮候选，随后递归比较所有非 hash 字段。碰撞或字段变化不复用，不搜索整个候选桶，避免引入平方匹配。展示块不携带旧传输块 hash，使用既有消息内 WeakMap 缓存 HTML；只保留上一轮投影引用，不复制正文或维护全局身份表。

生产流式稳定段与全量普通 Markdown 使用相同的 `parse_markdown_to_ast` 入口，正常等价节点的 hash 可以匹配；引用链接等全局上下文导致 AST 变化时，放弃复用是正确行为。活动 tail 仍由自己的执行器收尾，不迁移其 DOM 到稳定区域。

原始 HTML 容器可能表示为「开标签节点 + Markdown 节点 + 闭标签节点」。为保持此语义，任意深度包含原始 HTML 的来源块不做此次拆分；含原始片段的 HTML 输出继续整体审核。动态 `wrapper_class`、自定义节点 `kind` 补齐属性转义；异常标题级别继续沿用原审核路径，没有增加新的语法纠错规则。

附件中的 95%、60%、90%+、小于 2 ms 和像素级零跳动均不是本轮实测结论。缓存命中仍需浏览器解析 HTML；纯 AST 轻路径也仍有最终 DOM 插入。方案 5 未实施，不能宣称视口绝对静止。
