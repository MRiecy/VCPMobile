# 04 · 移动端共享架构与施工计划

> 本篇回答「01 日志中心」与「02 任务调度中心」**怎么落到 VCPMobile 现有架构里**，
> 给出统一的代码落位、集成点清单与分期计划。前置阅读：01、02 篇。

---

## 1. 统一架构模式（沿用日记中心已验证的三层）

```
Vue 组件（features/<domain>/*.vue）
  → Pinia store（features/<domain>/*Store.ts，Composition API 风格）
  → Tauri invoke（@tauri-apps/api/core）
  → Rust command（vcp_modules/<domain>/，Result<T, String>，禁 unwrap）
  → reqwest → VCPToolBox admin_api（Basic Auth: admin_username/admin_password）
```

两个新功能都是「纯远程控制台」：本地无持久化、无原生能力依赖，
**不需要触碰 tauri-plugin-vcp-mobile 插件**，也不涉及权限声明四重注册。

### 新增模块落位

| 层 | 日志中心 | 任务调度中心 |
| --- | --- | --- |
| Rust | `vcp_modules/logcenter/{mod,log_service}.rs` | `vcp_modules/taskcenter/{mod,task_service}.rs` |
| 前端 | `features/logcenter/{LogCenterView.vue, logCenterStore.ts, components/…}` | `features/taskcenter/{TaskCenterView.vue, TaskEditorView.vue, taskCenterStore.ts, components/…}` |
| 文档 | `docs/vue_docs/features/logcenter/` | `docs/vue_docs/features/taskcenter/` |

### 建议抽取的共享件

1. **`vcp_modules/infra/admin_api_client.rs`（最小面共享件）**：
   目前 `diary_service.rs` 自建 reqwest client + Basic Auth + URL 规范化；
   日志中心与任务中心是第三、四个使用者。抽一个最小 helper
   （构造 client / 拼 admin_api URL / basic_auth / 超时与响应大小上限四件事），
   **仅供 logcenter、taskcenter 两个新模块使用；diary 模块本期不迁移**，
   避免无收益回归风险（见 05 篇 Casper 裁决）。
2. **前端 `components/ui/StatStrip.vue` + `StatusBadge.vue`（可选）**：
   日志统计条、任务统计行、未来插件中心仪表盘（03 篇灵感 2）共用同一套
   「Monospace 大数字 + 灰色小标签」与「状态徽章」语言。

## 2. 集成点清单（每个新页面都要走的 6 步）

1. **overlay store**（`src/core/stores/overlay.ts`）：
   `OverlayPageType` 增加 `'logCenter' | 'taskCenter'`；
   新增 `isLogCenterOpen` / `isTaskCenterOpen` computed 与 open/close 包装。
2. **RightSidebar**（`src/components/layout/RightSidebar.vue`）：
   `moreTools` 数组追加两项：
   - 日志中心 — 图标 `ScrollText`（lucide），`overlayStore.openLogCenter()`；
   - 任务调度 — 图标 `CalendarClock`（lucide），`overlayStore.openTaskCenter()`。
   **注意布局**：popover 当前 `grid-cols-2`，条目从 3 → 5 后建议改 `grid-cols-3`
   或压缩按钮内边距，需在真机验证触控高度 ≥44px。
3. **FeatureOverlays**（`src/components/FeatureOverlays.vue`）：
   `defineAsyncComponent` 懒加载 + `createFirstOpenLatch` 首开挂载。
4. **治理测试同步**（`src/tests/unit/governance/PerformanceGovernance.test.ts`）：
   latch 清单加入 `isLogCenterOpen` / `isTaskCenterOpen`。
5. **契约测试**：DiaryContracts 风格的源码契约测试为新页面各加一份
   （入口存在性、latch、侧边栏 aria-label）。
6. **Rust 注册**：`lib.rs` invoke_handler + `vcp_modules/mod.rs` 导出；
   `pnpm check` 双端静态检查。

## 3. 工程纪律检查单（两个功能共用）

- [ ] Rust command handler 全部 `Result<T, String>`，无 `unwrap/expect`；
- [ ] 所有网络 IO 异步（tokio），connect/total 超时显式设置；
- [ ] 响应体大小上限（日志 4MB JSON / 任务配置 2MB JSON），防 OOM；
- [ ] 前端渲染远程文本一律转义，禁 `v-html`（日志高亮用节点拆分方案）；
- [ ] 轮询全部生命周期感知（页面关闭停、`vcp-lifecycle-changed` 退后台停）；
- [ ] UI 宪法：无毛玻璃、无大圆角、无缩放弹跳动画；状态反馈用 2px accent bar；
- [ ] Monospace 用于时间戳/ID/计数/偏移量等技术值；
- [ ] 宽屏（≥768px / ≥1280px）按 `ANDROID_UI_COMPATIBILITY.md` 响应式验证；
- [ ] 修改 `mod.rs`/`lib.rs` 模块声明前先 `git add . && git commit -m "save"`；
- [ ] 完成后 `pnpm check` + `pnpm test:run` 全绿。

## 4. 分期计划

两个功能相互独立、可并行施工、可独立发布。建议顺序：

### S1：日志中心（先做，难度低、反馈快）

理由：协议最简单（2 个端点只读为主）、AdminPanel-Vue 有现成 Vue 3 蓝本、
能最先沉淀「admin_api Rust 代理 + 轮询 store + 虚拟滚动列表」三件套范式，
为 S2 铺路。

交付物：01 篇 §7 施工清单全部。

### S2：任务调度中心（后做，UI 比重大；内部再拆两批）

理由：端点多（10+）、表单复杂、有编辑器子页与分段视图，
是本次 UI/UX 设计的主战场。S1 的共享件（admin client、StatStrip、轮询范式）
直接复用。

- **S2a（只读 + 操作批）**：任务列表、启用拨钮（PATCH）、强制触发、执行历史、
  全局开关、503 空态。无编辑器，可快速上线形成价值闭环；
- **S2b（编辑批）**：任务编辑器（新建/编辑/删除）、占位符 chips、
  randomN 控件化、异步委托追踪 Tab。

交付物：02 篇 §8 施工清单（按 a/b 批拆分）+ 开放问题 O-1~O-4 的结论记录。

### S3（后续迭代，非本期）：插件中心灵感落地

03 篇灵感清单按价值排序逐项评估；优先候选：异常第三态、统计横幅、
分组计数（可复用 S1/S2 沉淀的组件）。

## 5. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| admin 凭据未配置 | 两个功能整页不可用 | 统一空态组件：检测 `adminUsername/adminPassword` 缺失 → 引导跳全局设置 |
| TaskAssistant 插件未加载（503） | 任务中心不可用 | 结构化错误码 + 专用空态「插件未加载」 |
| trigger 端点长耗时（同步等 Agent，上限 180s） | 移动端弱网下体验差 | Rust 侧 trigger 单独放宽超时；前端 pending 态 + 可后台等待（Toast 异步通知结果） |
| 日志轮询耗电 | 后台常驻流量 | 页面级轮询（关闭即停）+ 前后台暂停 + 失败退避 |
| 日记服务抽取共享 client 时回归 | 影响既有功能 | 抽取单独 commit，先跑日记相关测试再合入 |
