# 01 · VCP 日志中心 —— 上游契约与移植方案

> 目标：将桌面端「VCP 日志中心」移植到 VCPMobile 右边栏「更多」工具盘，
> 并借移植机会修复桌面端已知的性能与交互短板。
> 上游参考有两个实现：**VCPChat/Logmodules**（Electron 子窗口，原生 JS）与
> **VCPToolBox-main/AdminPanel-Vue 的 ServerLogViewer**（Vue 3 + 组合式函数，更新更优）。
> **移植应以 AdminPanel-Vue 版为主要蓝本**，VCPChat 版仅作功能对照。

---

## 1. 功能总览

日志中心是 VCPToolBox 服务器日志（`DebugLog/ServerLog.txt`）的远程查看器：

| 功能点 | VCPChat 桌面版 | AdminPanel-Vue 版 | 移动端取舍 |
| --- | --- | --- | --- |
| 全量加载（尾部最多 2MB） | ✅ | ✅ | 保留 |
| 增量轮询（字节 offset 协议） | ✅ 1.8s | ✅ 3s | 保留，生命周期感知（见 §5） |
| 日志轮转检测（inode / needFullReload） | ✅ | ✅ | 保留（后端协议自带） |
| 行数限制 | 50–20000，默认 500 | 100–100000，默认 5000 | 保留，默认 500，上限建议 5000 |
| 文本筛选（子串，高亮） | ✅ | ✅（`<mark>` + DOMPurify） | 保留 |
| 预筛选 chips（IP/TOOL/RAG/POST/PLUGIN/ERROR） | ✅ | ❌ | 可选（P1） |
| 正/倒序切换 | ✅ | ✅ | 保留 |
| 级别着色（ERROR/WARN/INFO/DEBUG） | ✅ | ✅ | 保留，灰度优先 + 状态色 |
| 复制可见日志 | ✅ | ✅ | 保留 |
| 清空 | 清空**服务器文件**（危险） | 仅清空**本地显示** | 两者分离（见 §4.3） |
| 智能吸底 / 跳到底部按钮 | ✅ | ✅（自动滚动开关 + 跳底按钮） | 保留 |
| 暂停轮询 | ❌ | ❌ | **新增**（移动端必要） |
| 虚拟滚动 | ❌（全量 innerHTML 重建） | ✅（自研 useVirtualScroll） | 保留（用 `@vueuse/core` 的 `useVirtualList`） |
| 半行拼接（trailingFragment） | ❌（跨轮询断行） | ✅ | 保留 |
| 窗口控制/拖拽标题栏/毛玻璃 | ✅ | ❌ | 裁剪（移动端无窗口概念，UI 宪法禁毛玻璃） |

### 设置持久化

- 桌面版 localStorage 键：`vcp-log-center-line-limit`、`vcp-log-center-reverse-order`；
- AdminPanel-Vue 键：`vcp_log_limit`、`vcp_log_reverse`、`vcp_log_autoscroll`。
- 移动端：沿用 localStorage（与主题等前端偏好同级），键名建议统一为 `vcp_log_*` 系列。

## 2. 后端 API 契约（已核实：`VCPToolBox-main/routes/admin/logs.js`）

日志由 `modules/logger.js` 劫持 console 写入 `DebugLog/ServerLog.txt`，
5MB 或跨天轮转到 archive，保留 7 天。**纯 HTTP 轮询，无 WebSocket/SSE。**

### GET `/admin_api/server-log`

查询参数：
- `incremental=true`：增量模式；
- `offset=N`：字节偏移（上次响应返回的 offset）。

响应（200）：

```json
{
  "content": "…日志文本…",
  "offset": 123456,
  "path": "/abs/path/DebugLog/ServerLog.txt",
  "fileSize": 123456,
  "needFullReload": false
}
```

行为细节：
- 全量模式：文件 >2MB 时只读尾部 2MB，并跳过第一行（可能不完整）；
- 增量模式：从 `offset` 读到文件尾；
- 轮转检测：服务端按 `path` 记忆 inode，inode 变化或 `offset > fileSize` 时
  返回 `{ "needFullReload": true, "path", "offset": 0 }`（无 content）；
- 错误：503（日志路径未就绪，带可读 content）、404（文件不存在）、500。

### POST `/admin_api/server-log/clear`

- 清空服务器日志文件本体，响应 `{ "success": true, "message": "日志已清空" }`。
- **危险操作**：影响所有客户端，移动端必须二次确认。

### 认证

与日记中心一致：admin_api 走 Basic Auth（`settings.admin_username` / `admin_password`），
移动端 Rust 侧已有同款实现可复用（`diary_service.rs` 的 `.basic_auth(...)` 模式）。
补充事实：`/admin_api/server-log` 在后端 `readOnlyDashboardPaths` 白名单内，
不受 IP 临时封禁影响；主服务器与独立管理进程（PORT+1）均挂载该路由。
日志行格式为 `[时间戳] [LEVEL] message`（`modules/logger.js` 劫持 console 生成）。

## 3. 数据流与移动端分层

```
ServerLog.txt (VCPToolBox)
   │  HTTP GET /admin_api/server-log?incremental&offset   (Basic Auth)
   ▼
Rust: vcp_modules/logcenter/log_service.rs        ← 新增模块
   │  Tauri commands: logcenter_fetch / logcenter_clear_server
   ▼
TS:  src/features/logcenter/logCenterStore.ts     ← Pinia，持有 lines/offset/fragment
   ▼
Vue: LogCenterView.vue (SlidePage) + useVirtualList
```

**为什么增量状态机放前端 Store 而非 Rust**：
offset/trailingFragment/lines 都是 UI 态，轮询由页面打开/关闭驱动，
放 Pinia 最简单；Rust 层只做"带认证的 HTTP 代理 + 大小防护"，与
`emoticon_manager.rs` 同款定位。Rust 侧职责：
- `logcenter_fetch(incremental: bool, offset: u64) -> LogFetchResult`：
  拼 URL、Basic Auth、超时（connect 10s / total 30s）、
  响应体上限（如 4MB JSON）防护、错误字符串化；
- `logcenter_clear_server() -> String`。

**安全红线**：日志内容可能含敏感信息（路径、key 片段），
Rust 侧不落盘、不写日志转发；前端渲染必须转义（见 §4.4）。

## 4. 移动端 UI/UX 方案

### 4.1 页面骨架（SlidePage，z-page 层）

```
┌─────────────────────────────┐
│ ← 日志中心        ⏸ 🔄 ⋯   │  顶栏：返回 / 暂停 / 刷新 / 溢出菜单
├─────────────────────────────┤
│ 🔍 筛选…            ⇅ 倒序  │  工具行：筛选输入 + 倒序切换
│ 总行 12,340 · 显示 500 · 匹配 36 │  统计条（Monospace 数字，灰度）
├─────────────────────────────┤
│  虚拟滚动日志区（等宽字体）   │
│  级别着色：红=ERROR 黄=WARN  │
│         蓝=INFO 灰=其余      │
├─────────────────────────────┤
│        ↓ 跳到底部（浮钮）     │  仅当不在底部时出现
└─────────────────────────────┘
```

溢出菜单（BottomSheet）：行数限制（滑块或档位 100/300/500/1000/3000）、
自动滚动开关、复制可见日志、清空本地显示、**清空服务器日志（红字危险项，二次确认）**。

平板/宽屏（≥768px）：统计条与工具行合并为一行；日志区最大宽度限 960px 居中，
保持行长约 80–120 字符的可读性。

### 4.2 关键交互决策

1. **智能吸底**：`autoScroll` 开启且有新内容时滚到底；用户上滑离开底部 >100px
   自动暂停吸底并显示「跳到底部」浮钮（AdminPanel-Vue 已有此逻辑，直接搬）。
2. **暂停开关**：顶栏 ⏸ 显式暂停轮询（桌面端没有），暂停时统计条显示「已暂停」态。
3. **级别着色**：遵守 UI 美学宪法——灰度优先，彩色仅用于状态指示；
   行样式用 2px accent bar + 单色文本。级别判定**融合两个上游实现**：
   取 log.js 正则的覆盖度（`LOG|INFO|WARN|WARNING|ERROR|FATAL|DEBUG`，
   含 FATAL/WARNING，Vue 版的朴素 `includes` 会漏）+
   Vue 版的整行 accent bar 视觉语言（收敛为 2px）。
4. **筛选高亮**：避免 `v-html`。将每行按关键词 split 成文本段 + `<mark>` 节点数组渲染，
   天然免疫 XSS，也不需要 DOMPurify（虽然依赖已存在，但能不用就不用）。

### 4.3 「清空」语义分离（相对桌面端的改进）

- **清空本地显示**：仅清空前端缓冲，轻确认或直接执行 + Toast；
- **清空服务器日志**：红色危险项 → BottomSheet 二次确认（说明影响所有客户端）
  → `POST /server-log/clear` → 重置本地 offset=0 重新全量拉取。

### 4.4 渲染安全

日志文本不可信（可能包含 HTML 片段、ANSI 转义）。约束：
- 一律按纯文本渲染（`{{ }}` 插值或文本节点），禁止 `v-html`；
- ANSI 转义序列在 Rust 或 TS 层剥除（正则 `\x1b\[[0-9;]*m`），避免控制字符污染布局。

### 4.5 虚拟滚动

复用项目既有方案 `@vueuse/core` 的 `useVirtualList`（DiaryNoteList / TopicList 已用），
固定行高（约 22px）+ overscan 10–20。等宽字体 + `white-space: pre` +
横向滚动（不换行，与桌面端一致；长行横滑查看）。

## 5. 生命周期感知轮询（移动端新增价值）

桌面端 1.8s/3s 固定轮询在移动端不可接受（耗电、后台无意义）：

1. **页面关闭即停**：SlidePage close → 停止定时器（组件 `onBeforeUnmount` / watch isOpen）；
2. **前后台感知**：复用 `vcp-lifecycle-changed` 事件（插件已桥接）——
   退后台暂停，回前台立即补拉一次增量再恢复定时器；
3. **轮询间隔**：移动端建议 3s；屏幕常亮/充电场景不变；
4. **错误退避**：连续失败（如服务器不可达）指数退避 3s→6s→12s→封顶 30s，
   统计条显示「连接失败，重试中」。

## 6. 桌面端短板 → 移动端修复对照表

| 桌面端短板 | 移动端方案 |
| --- | --- |
| 全量 innerHTML 重建，20000 行性能灾难 | `useVirtualList` 固定行高虚拟滚动 |
| 增量字节切片导致跨轮询断行 | trailingFragment 半行拼接（AdminPanel-Vue 版已实现，照搬） |
| 无暂停开关 | 顶栏 ⏸ + 前后台自动暂停 |
| trimLines 静默裁剪导致阅读位置跳动 | 裁剪仅在达到上限时发生；筛选/裁剪后保持滚动锚点 |
| 行号是渲染序号（筛选后无意义） | 行号保留渲染序号但筛选时隐藏，避免误导 |
| 筛选只作用于已裁剪缓冲 | 同（协议限制），但在 UI 上明示「仅搜索已加载的 N 行」 |
| 大面积 `backdrop-filter: blur(22px)` | 违反 UI 宪法，一律不引入 |
| 清空服务器文件无足够警示 | 危险项红字 + BottomSheet 二次确认 |
| 预筛选 chip 覆盖式（点击改写输入框，不可取消/组合） | chips 可再点取消；或折叠进筛选面板（P1） |
| 复制粒度只有「全部可见」 | P1 增加长按单行复制 |
| 归档日志（`DebugLog/archive/`，保留 7 天）无 API | 本期不做；作为后端增强建议提出，UI 预留入口位 |
| 筛选仅单关键词子串 | P1 可扩展多关键词/排除语法（`-foo bar`） |
| 无「有新日志」徽标，切走后不知错过多少 | 暂停/离开底部时累计新行数，「跳到底部」浮钮附带 `+N` 徽标 |
| 轮询节奏写死（1.8s/3s） | 3s 默认 + 失败退避；暂停开关即节奏控制，不做用户可调间隔（避免过度设计） |
