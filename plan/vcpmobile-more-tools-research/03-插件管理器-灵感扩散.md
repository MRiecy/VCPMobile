# 03 · VCP 插件管理器 —— 灵感扩散（不改代码）

> 本篇只做设计灵感提炼，**不涉及任何代码改动**。
> 移动端已有「插件中心」（`src/features/distributed/DistributedView.vue`，右边栏主按钮入口），
> 管理的是本机分布式工具/设备能力；VCPChat 桌面端的「VCP 插件管理器」管理的是
> `VCPDistributedServer/Plugin/` 目录下的 VCPToolBox 后端插件。两者管理对象不同，

## 1. 桌面端插件管理器事实摘要

来源：`/home/dudu/VCPChat/PluginManagerModules/plugin-manager.{html,js,css}`
+ `modules/ipc/desktopHandlers.js`（5 个专用 IPC）。

### 1.1 功能清单

| 功能 | 数据流 | 要点 |
| --- | --- | --- |
| 扫描/列出插件 | IPC → `readdir(Plugin/)` 逐目录读 `plugin-manifest.json`（或 `.block`）+ `config.env` 全文 | manifest 解析失败**不丢弃**，置 `parseError` 返回 |
| 启用/禁用 | `fs.move` 在 `plugin-manifest.json` ↔ `plugin-manifest.json.block` 之间改名 | **文件系统即状态**，幂等、`overwrite:false` |
| 编辑 Manifest | textarea 编辑完整 JSON，前端预校验 + 主进程二次 `JSON.parse` 自检 | 禁用态编辑保留 `.block` 后缀，不意外启用 |
| 编辑命令描述 | Tab 2 结构化表单 ↔ Tab 1 原始 JSON **双视图实时同步** | 全套编辑体验的最大亮点 |
| 编辑 config.env | 独立保存按钮、独立 IPC | **保存粒度分离** |
| 打开插件目录 | `shell.openPath` | 高级用户逃生舱 |
| 分布式服务器总开关 | 拨动只改本地态 → 显式「保存开关」→ toast 提示需重启生效 | 三段式防误触；read-modify-write |

### 1.2 信息架构（自上而下四层）

1. **Hero 区**：说明管理对象（哪个运行时、哪些文件）+ 全局运行时开关卡；
2. **工具栏**：全文搜索（可搜插件/命令/描述/**配置项内容**）+ 类型筛选 + 状态筛选（含「异常」）；
3. **统计仪表盘**：总插件 / 已启用 / 已禁用 / 异常 / 命令数 / 含配置数，6 张数字卡；
4. **分组插件网格**：按主类型分组（static / messagePreprocessor / synchronous / asynchronous / service / hybridservice / unknown），组头中文语义标签 + 计数；单卡含状态徽章、类型徽章、描述（2 行截断）、版本/作者/有无 env 三格元信息、命令预览 chips（最多 5 个 + 「+N」）。

### 1.3 安全边界

- 所有写 IPC 走 `basename` 校验 + `path.relative` 越界校验**双重防目录穿越**；
- 渲染侧所有插值经 `escapeHtml` / `escapeAttr` 转义防 XSS；
- 每个功能调用前做 IPC 能力探测，缺失时给明确提示而非白屏。

## 2. 移动端插件中心可借鉴的 10 条灵感

按落地价值排序。是否采纳、何时采纳由后续迭代单独评估，本篇不构成施工承诺。

1. **引入「异常」第三态，坏插件不静默消失。**
   manifest/元数据解析失败时：红色徽章 + 整卡降透明度 + 错误信息就地展示（放在描述位），
   详情页内提供修复/重新拉取入口。让用户看出「插件坏了」而不是「插件丢了」。

2. **顶部统计仪表盘横幅。**
   4–6 个紧凑统计项（总数/启用/禁用/异常/含配置数），一屏给出全局健康度。
   落地形态遵守 UI 宪法：Monospace 大数字 + 灰色小标签的线性横排，不用彩色卡片。

3. **按类型分组 + 组头计数。**
   移动端落地形态建议**可折叠分组的线性列表**（高密度线性布局），
   而非桌面端的卡片网格；组头 = 中文语义标签 + 「N 个插件」。

4. **全文搜索覆盖配置内容与命令描述。**
   haystack 预拼名称/描述/命令标识符/命令 example/配置键值全文，`includes` 即可，
   成本极低，反查能力极强。

5. **「配置编辑」与「元信息编辑」分离保存。**
   保存粒度 = 按钮粒度 = 独立 command，避免一次误保存覆盖未打算提交的另一半改动。

6. **双视图编辑的移动端变体：结构化优先 + 专家 JSON 模式。**
   桌面端证明了双视图同步对降低编辑门槛极有效；移动端把默认视图反过来——
   默认结构化表单（键值对列表），另设「查看/编辑原始 JSON」专家入口，
   两视图保存前互相校验同步。

7. **运行时开关三段式防护：拨动 + 显式保存 + 生效提示。**
   适用于分布式连接、后台服务等全局开关。危险操作按项目美学用红色 2px
   accent bar / 红色描边按钮表达，不用大圆角色块。

8. **为高级用户留「逃生舱」。**
   移动端等价物：查看插件文件列表、复制插件路径/ID、
   导出插件调试包（manifest + 配置 + 日志打包分享）。

9. **文件系统即状态的启停语义。**
   若移动端插件启用状态也需本地落盘，推荐文件名后缀/单文件标记约定（如 `.block`）
   而非数据库字段：天然随 VCP Sync 同步、桌面与移动互认同一约定、
   用户可用文件管理器直接理解和修复。

10. **写路径双重校验 + 前端转义。**
    Rust command 入口等价实现：拒绝含 `..`/路径分隔符的输入，
    `Path::strip_prefix` 校验未越出插件根目录；前端列表渲染所有插值转义，
    防止恶意 manifest 注入 HTML。
