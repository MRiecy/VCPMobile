## 1. 概念模型

- **AgentAssistant (AA)**：定义 Agent 身份（模型标识、回复阈值、核心指令）。
- **TaskAssistant (FA / 任务派发中心)**：把任务按调度派发给 AA 的 Agent。
  两者同进程，FA 直接 `require('../AgentAssistant/AgentAssistant.js')` 调用。
- **任务 (Task)**：持久化于 `Plugin/VCPTaskAssistant/task-center-data.json`，
  由 node-schedule 驱动定时器，派发 = 调 `agentAssistant.processToolCall({agent_name, prompt, maid, ...})`（3 分钟超时）。
- **异步委托 (Delegation)**：AA 侧的后台长任务追踪，FA 页面的「异步委托任务追踪」区块展示。

**本期移植范围建议：只做 TaskAssistant 部分 + 委托只读追踪；Agent 管理（AA 配置）不进入 MVP**（桌面端两个 Tab，移动端拆开，AA 配置编辑复杂度高、使用频率低）。

## 2. 数据模型（逐字段，源自 `normalizeTask` 等函数）

顶层 `task-center-data.json`：

```json
{
  "version": 1,
  "globalEnabled": false,
  "settings": { "maxHistory": 200 },
  "tasks": [ /* Task */ ],
  "history": [ /* RunRecord，尾部保留 maxHistory 条 */ ]
}
```

Task 对象：

| 字段 | 类型 | 说明 / 默认 |
| --- | --- | --- |
| `id` | string | `task_{slug(type)}_{slug(name)}_{ts}`，**可含中文**，URL 中必须 `encodeURIComponent` |
| `name` | string | 默认「未命名任务」 |
| `type` | `'forum_patrol' \| 'custom_prompt'` | 非法值回落 `forum_patrol` |
| `enabled` | bool | 默认 true；once 任务执行后自动置 false |
| `schedule.mode` | `'interval' \| 'once' \| 'manual' \| 'cron'` | 非法回落 `interval` |
| `schedule.intervalMinutes` | int | **后端强制下限 10 分钟**（`MIN_INTERVAL_MINUTES`），默认 60 |
| `schedule.runAt` | ISO string | once 模式必填，过期显示「时间无效或已过」 |
| `schedule.cronValue` | string | cron 模式必填（node-schedule 语法：秒 分 时 日 月 周） |
| `schedule.jitterSeconds` | int | ≥0，当前调度实现中未实际使用（字段保留） |
| `targets.agents` | string[] | 至少 1 个；支持魔法字符串 `randomN`（从候选中随机抽 N 个，Fisher-Yates） |
| `dispatch.channel` | string | 固定 `'AgentAssistant'` |
| `dispatch.temporaryContact` | bool | 默认 true |
| `dispatch.maid` | string | 默认 `'VCP系统'`（派发者署名） |
| `dispatch.taskDelegation` | bool | 默认 false；true = 异步委托模式 |
| `payload`（forum_patrol） | object | `promptTemplate` / `includeForumPostList`(默认 true) / `forumListPlaceholder`(默认 `{{forum_post_list}}`) / `maxPosts`(默认 200) / `availablePlaceholders` |
| `payload`（custom_prompt） | object | `promptTemplate`（必填，否则 sanitize 报错）/ `availablePlaceholders` |
| `runtime` | object | 运行时态：`running` / `lastRunTime` / `lastFinishTime` / `lastResult` / `lastError` / `lastDurationMs` / `runCount` / `successCount` / `errorCount` / `nextRunTime` |
| `meta` | object | `createdAt` / `updatedAt` |

RunRecord（history 项）：
`id`(`run_{ts}`) / `taskId` / `taskName` / `type` / `triggerSource`(`scheduler` `manual-trigger` `once-scheduler` `interval-scheduler` `cron-scheduler`) /
`startedAt` / `finishedAt` / `durationMs` / `status`(`success` `partial_success` `error`) /
`agents` / `failedAgents` / `originalAgents` / `randomTag` / `message`。

**卡死自愈**（后端已做，前端只需展示）：
- 启动时重置所有遗留 `running=true`；
- 运行中 `running=true` 且距 `lastRunTime` >10 分钟 → 强制重置并记 error。

## 3. 后端 API 契约（已核实）

全部挂在 `/admin_api` 下，Basic Auth（与日志中心/日记中心同一套 admin 凭据）。
`routes/admin/taskAssistant.js` + `routes/admin/agentAssistant.js`。

### 任务调度（8 端点）

| 方法/路径 | 请求体 | 响应 | 备注 |
| --- | --- | --- | --- |
| GET `/task-assistant/config` | — | `{ config, availableTaskTypes, taskTemplates }` | config 即完整 task-center-data |
| POST `/task-assistant/config` | 完整 config | `{ success, message }` | **全量覆盖**（桌面端用；有删除不落盘风险，见 §6.10） |
| GET `/task-assistant/status` | — | `{ globalEnabled, activeTimerCount, activeTimers, tasks[](含 runtime), history(最近20条倒序) }` | 轻量轮询用 |
| POST `/task-assistant/trigger` | `{ taskId }` 或 `{ agentName }` | `{ success, message, result }` | 手动触发，忽略调度时间；agentName 模式仅匹配 forum_patrol 任务 |
| GET `/task-assistant/tasks` | — | `{ success, tasks, availableTaskTypes, taskTemplates }` | |
| POST `/task-assistant/tasks` | Task（无 id） | `{ success, task }` | 细粒度创建 |
| PATCH `/task-assistant/tasks/:taskId` | 部分 Task 字段 | `{ success, task }` | 细粒度更新（合并式，runtime/meta 保留） |
| DELETE `/task-assistant/tasks/:taskId` | — | `{ success, removed }` | |

503 = VCPTaskAssistant 插件未加载（移动端要专门处理这个态）。

### 异步委托（3 端点，`/agent-assistant` 下）

| 方法/路径 | 响应 |
| --- | --- |
| GET `/agent-assistant/delegations` | 委托列表（running / waiting / cancelling / completed / failed / cancelled） |
| GET `/agent-assistant/delegations/:id` | 委托详情（含最近回复） |
| POST `/agent-assistant/delegations/:id/cancel` | 请求取消，body 可带 `reason` |

### 移动端调用策略（重要）

桌面端 task.js 只用全量 `GET/POST /config` 4 个端点；**移动端应直接用细粒度
`POST/PATCH/DELETE /tasks/:id`**：
- 避免全量读改写大 payload（移动端网络弱）；
- 避免桌面端已存在的「全量保存模型下删除不落盘」类 bug；
- 启停单任务 = `PATCH { enabled: false }`，一行 JSON，天然适配「拨动开关」交互。

## 4. 桌面端 UI 结构（对照用）

单窗口 + Tab（任务巡航 / Agent 管理）：
- 任务巡航 Tab：操作行（刷新/新建/保存所有配置）→ 状态仪表盘（全局开关、
  活跃定时器、任务计数）→ 异步委托追踪（运行中 + 最近完成两个网格）→ 任务卡片网格；
- 任务卡片：名称、类型徽章、启用开关、调度摘要、runtime（上次结果/耗时/计数/下次运行）、
  点击进入 600px 模态编辑器（data-keypath 动态表单）；
- 模态编辑器内含「强制触发(忽略时间)」按钮；
- 状态轮询：定时 `GET /status` 刷新仪表盘与卡片 runtime。

桌面端交互在移动端的具体问题，见 §6。

## 5. 移动端 UI/UX 方案（本篇核心难点）

### 5.1 信息架构（SlidePage + 内部分段）

```
┌─────────────────────────────┐
│ ← 任务调度中心      🔄 ⋯    │
├─────────────────────────────┤
│ ● 全局运行中 · 定时器 3      │  状态条（全局开关拨钮内联）
│ 任务 5 · 运行中 1 · 失败 0   │  统计行（Monospace）
├─────────────────────────────┤
│ [任务] [执行历史] [异步委托] │  分段控件（segmented）
├─────────────────────────────┤
│ 任务线性列表（高密度）        │
│ ┌─────────────────────────┐ │
│ │▎晨间论坛巡航      ⏻ 启用 │ │  2px accent bar = 状态色
│ │ 每 60 分钟 · 2 Agents    │ │  绿=启用 灰=禁用 蓝=运行中
│ │ 上次成功 · 12:30 · 34s   │ │  红=上次失败
│ │ 下次 13:30      ▶ 触发   │ │
│ └─────────────────────────┘ │
│            ＋ 新建任务       │
└─────────────────────────────┘
```

**为什么是分段控件而不是桌面端的双 Tab**：移动端视宽不足；「任务/历史/委托」
是同一页内的三个视图，共享顶栏状态条。AA 的 Agent 管理不进来（MVP 外）。

### 5.2 任务编辑器（全屏 SlidePage 子页，而非模态框）

桌面端 600px 三列模态表单在手机上不可用。移动端改为：
点任务卡 → 编辑器**作为新一级 SlidePage 推入 pageStack**（或页内全屏替换），
分节表单（复用 `components/settings/` 原子组件）：

1. **基本**：名称、类型选择（论坛巡航 / 通用提示词，带说明文案）；
2. **调度**：模式四选一（分段控件）→ 按模式显示对应字段：
   - interval：分钟数步进器（**步进 10，下限 10**，与后端对齐并注释原因）；
   - once：日期时间选择（移动端需要自研滚轮或用 `<input type="datetime-local">`）；
   - cron：表达式输入 + 常用预设 chips（每小时/每天 9 点/工作日…）+ 下次运行预览；
   - manual：无字段，提示「仅手动触发」；
3. **目标 Agent**：chip 列表 + 添加（从 AA Agent 列表选择，
   数据源见 §7 开放问题 O-2）+ 「随机抽取」开关 + 数量步进器
   （**消除 randomN 魔法字符串**，前端组装/解析）；
4. **派发选项**：maid 署名、temporaryContact、taskDelegation 开关（带解释文案）；
5. **提示词模板**：全屏编辑器（复用 overlay `openEditor` 全屏编辑能力），
   可用占位符以 chips 形式点击插入（解决软键盘下输入 `{{...}}` 的痛苦）；
   forum_patrol 额外字段：包含帖子列表开关、maxPosts、占位符名；
6. 底部固定操作条：保存（主按钮）/ 强制触发（次按钮）/ 删除（红色，收溢出菜单）。

### 5.3 状态与轮询

桌面端对照：task.js 常驻 15s 全量刷新 + 5s 状态轮询，无生命周期感知。移动端方案：

- 页面打开：`GET /config`（首次）→ 之后每 5s `GET /status`（轻量）刷新 runtime；
  前后台感知（`vcp-lifecycle-changed`），退后台停轮询，回前台立即补拉；
- 有任务 `running=true` 时缩短到 2.5s，让「运行中」态更鲜活；
- 委托追踪 Tab 激活时才轮询 `/agent-assistant/delegations`（8s），不激活不拉。

### 5.4 触屏交互要点

- 所有可点区域 ≥44px；任务卡整卡可点进编辑，卡上直接操作只有「启用拨钮」和「▶ 触发」；
- 触发后 Toast 反馈派发结果（success/partial_success/error 三色）；
- 删除任务：卡片溢出菜单（长按或 ⋯）→ BottomSheet 二次确认；
- 全局开关：拨动即 `POST /config { globalEnabled }`（只改该字段，直接落盘，
  因为语义简单且无其他字段耦合；配合 Toast「全局调度已暂停」）；
- 错误态：503（插件未加载）→ 整页空态「TaskAssistant 插件未在服务器加载」+ 重试按钮。

### 5.5 平板/宽屏适配（≥768px）

- 任务列表与编辑器**双栏**：左列表（320px）右编辑器，选中高亮 2px accent bar；
- 执行历史/委托 Tab 内容同样在右栏展示；
- 统计条横排展开为一行 4–6 项；
- 遵循 `docs/ANDROID_UI_COMPATIBILITY.md` 的窗口宽度响应式规范。

## 6. 桌面端短板/陷阱清单（移动端必须规避）

1. **全量保存模型**：桌面端「保存所有配置」整体 POST config，曾有「删除不落盘」类风险；
   移动端用细粒度 CRUD 规避（§3）。
2. **randomN 魔法字符串**：直接暴露在 agents 数组里，UI 无表达；移动端做成显式「随机抽取 N 人」控件。
3. **hover 依赖**：桌面端卡片操作 hover 才显现；移动端所有操作常显或进溢出菜单。
4. **模态框表单**：600px 固定宽、内部滚动；移动端改全屏分节表单。
5. **confirm/alert 原生弹窗**：全部替换为 BottomSheet + Toast。
6. **提示词编辑无占位符辅助**：移动端必须做占位符 chips 点击插入。
7. **cron 裸输入无校验无预览**：移动端加预设 + 下次运行时间展示（前端可做简单解析或仅回显后端 nextRunTime）。
8. **interval 下限不对齐**：桌面端填 5 分钟会被后端静默改 10；移动端步进器直接 ≥10。
9. **轮询无生命周期感知**：移动端必须前后台暂停。
10. **中文 taskId 未编码**：`PATCH /tasks/task_巡航_xxx` 需 `encodeURIComponent`，Rust 代理层统一处理。

## 7. 开放问题

- **O-1 调度状态推送**：后端 `broadcastStatusUpdate()` 目前只是日志占位，
  状态靠轮询。本期维持轮询；若后续后端接 WebSocket/SSE 再升级。
- **O-2 Agent 列表数据源**：目标 Agent 选择器需要 Agent 清单。
  候选：`/admin_api/agent-assistant/config`（AA 配置内含 agents）。
  需在施工前确认该端点响应结构（ForumAssistantConfig.vue 中有 fetch agent list 的先例）。
- **O-3 cron 预览**：是否在前端引入轻量 cron 解析器做「未来 3 次运行时间」预览，
  还是只展示后端 `runtime.nextRunTime`（cron 模式下后端会给 ISO 时间）。建议 MVP 只回显。
- **O-4 AA 管理是否入移动端**：建议另立迭代，不与本期耦合。
